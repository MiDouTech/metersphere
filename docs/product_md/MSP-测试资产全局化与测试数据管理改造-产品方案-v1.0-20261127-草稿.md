# MSP 测试资产全局化与测试数据管理改造

版本：v1.0；日期：2026-11-27；状态：产品方案草稿，待整版批准。本文不是实现或测试通过报告，不修改此前获批文档。

## 1. 需求来源及目标

用户已明确：测试资产内容属于全局，不属于当前项目；关联追溯保留项目级。测试数据需供人查看、管理、治理：名称和详情按钮进入详情页；增加上传、修改、删除，修改和删除支持批量；上传位于左上角；每行常驻详情、修改、删除，其他操作收纳到“…”；左侧分类树、右侧条目。

本方案同时处理公共配置及其他资产仍按项目隔离的问题。历史同步两个失败项目、低权限账号专项测试继续按已有要求排除，不以其阻塞本方案。

建议将“全局”落为当前组织内跨业务项目共享，保留组织间隔离，不默认把敏感配置开放给其他组织。该边界为方案建议，尚非用户对跨组织共享的授权。资产全局不等于所有用户可写、所有人可读取秘密。

## 2. 现状与缺陷范围

以下来自当前代码审计，线上逐模块验证另行执行。

|模块|当前问题|目标|
|公共配置|shared-configuration.vue 使用 currentProjectId；SharedConfigurationService 按 project_id 保存、查询、检查版本和执行器解析|组织级全局内容、版本、文件和命名空间；项目只保留使用关系|
|业务资产|business-assets.vue、BusinessAssetService 的列表、内容、归并、归档、版本均绑定项目|全局业务理解及稳定业务身份，来源项目仅为追溯信息|
|测试数据|datasets.vue 仅包装 catalog.vue；目录查询、权限和源内容依赖项目；名称不能直接打开内容；缺少独立管理闭环|独立全局数据资产，支持可读详情、上传、内容修改和删除|
|资产版本|新业务资产、公共配置及旧资产版本查询均有项目约束|版本跟随全局资产，切换项目不改变资产版本列表|
|环境、公共步骤、接口、证据、缺陷等兼容资产视图|通用目录仍按当前项目查询，不能提供全局视图|在现有权限下提供全局资产索引；来源业务记录仍保留真实项目和原权限|
|用例资产|目录已有组织共享；来源、引用和回写仍涉及项目|保留双目录；确认全局内容及分类不受当前项目选择影响，不移除来源回写校验|
|关联追溯|当前按项目查询|按用户补充保留项目级，不纳入全局化缺陷|

测试资产全局化不自动迁移项目业务模块的执行结果、缺陷工作流、接口执行配置。它们作为资产来源或引用时仍保留原项目身份；全局列表不得泄露无权访问的源内容。

## 3. 方案选择

推荐独立全局资产模型，项目通过引用使用。优点是职责清楚，可统一版本、分类、管理及执行器协议；成本是迁移和兼容改造较多。

仅删除前端项目参数不能解决后端归属、权限和重复身份问题；简单聚合各项目记录只适合作为过渡读取，无法满足跨项目统一修改、去重和删除，因此不作为最终方案。将所有记录塞入一个伪业务项目也不采用，避免继续把全局权限和项目权限混用。

## 4. 全局与项目的明确边界

- 全局层：资产身份、名称、内容、分类、当前版本、历史版本、来源说明、管理审计。
- 项目层：本项目引用哪份资产及哪个版本、在哪个计划/任务使用、关联缺陷、执行结果及关联追溯。
- 顶部项目切换：全局资产列表、详情、分类数量保持一致，不重新按该项目过滤。明确标识“全局资产”；进入关联追溯后显示具体项目并使用项目权限。
- 全局资产可被多项目引用。引用记录包含 projectId、assetId、versionId、引用类型和资源ID；不复制资产内容作为另一个可编辑主记录。
- 来源项目可展示为可读元信息；源记录权限不足时只显示允许公开的元信息，不暴露源正文、附件或凭据。

## 5. 测试数据列表与分类

页面布局：顶栏左侧“上传”，可并列放置“新建数据”；下方左侧分类树，右侧筛选、批量工具栏和条目表格。新建数据作为便于人工录入的建议补充，上传必须实现。

分类树包含全部、未分类和自定义分类；支持新增、改名、移动、删除，禁止循环父子关系。选中分类显示直属条目，提供“含子分类”开关；数量口径与列表一致。分类属于测试数据资产，不复用业务资产的业务身份树数据，但沿用交互和组件风格。

删除空分类可确认执行；非空分类要求选择迁移目标或迁入未分类，不级联删除数据。分类重名按同一父级校验，跨分支允许同名。分类深度和名称长度沿用平台现有约束，前后端一致。

表格：复选框、名称、内容摘要、数据格式、所属分类、解析状态、当前版本、更新人、更新时间、操作。摘要必须可理解，例如“订单金额样本，3列/20行”，不得用内部JSON或ID堆叠替代。

名称为可点击链接，与“详情”进入同一详情页。每行常驻“详情 / 修改 / 删除 / …”，不依赖鼠标悬停才出现。无写权限的修改/删除禁用并给出原因。其他现有能力如下载、版本、发布、用于任务、治理来源、追溯放在“…”中；追溯点击后进入项目选择/已有引用项目，不静默使用任意项目。

批量工具栏在有选择时出现：批量修改、批量删除、取消选择。默认仅当前页选择；如支持跨页必须明确列出已选数量与范围，不用“全选”暗示隐藏全库操作。筛选条件变化清空选择并提示。

## 6. 数据详情页

新增独立路由 `/test-assets/datasets/:id`，列表返回保留分类、筛选和页码。分区包括基本信息、数据内容、版本记录、来源及项目引用摘要。项目引用摘要可链接项目级关联追溯，不将追溯全局化。

数据内容按格式呈现：CSV/XLSX为列名和行表格，XLSX支持工作表切换；JSON提供树形/格式化视图，对象数组可切换表格；文本提供保留换行的正文。不得仅显示资产快照JSON作为详情。JSON字符串不当HTML执行，Excel公式不执行，上传文件不执行宏或外部链接。

首期建议上传支持 CSV、XLSX、JSON、TXT；与存量不匹配的格式仍允许元信息查看及有权限原文件下载，明确说明暂不支持在线预览和编辑，不冒充已解析。后续格式不是本期验收必需。

展示文件名、大小、格式、行列统计、解析状态和安全错误提示。大文件由后端分页预览，显示当前范围及总量；不得静默截断并让用户误以为已查看全部数据。原文件下载与内容读取均需权限校验。

## 7. 上传、新建与修改

上传：选择文件→填写名称、分类、用途说明→校验和预览→确认→持久化原文件→异步解析→显示状态和可读内容。上传按钮固定在左上角；进入分类后默认该分类，可调整。关闭页面不停止服务端解析，重进可查询结果。

同名不静默覆盖，提示创建独立资产或明确选择已有资产上传新版本；仅标题相同不足以自动合并。提交具有幂等标识，网络重试不得产生重复资产/版本。文件扩展名、实际格式、大小、编码、恶意压缩和解析预算均由服务端检查；上线前将具体限额写入界面、配置及测试，禁止前后端分别硬编码不同值。

修改包括名称、用途说明、分类和实际内容。结构化内容支持逐行/字段编辑和增删行；文本支持正文编辑；复杂工作簿可通过替换文件产生新版本，明确提示不能在线编辑的结构。保存预览差异并校验，提交 expectedVersion 防止覆盖并发修改；成功生成新版本，旧引用继续使用原versionId。

“新建数据”建议允许选择表格、JSON或文本，编辑后走同一校验和版本链路，不维护另一套无版本数据。

## 8. 批量修改与删除

批量修改首期包括分类、用途说明等共有字段，未选字段保持不变，显式区分“不修改”和“清空”。不提供对不同结构数据正文盲目覆盖：批量内容修改通过逐资产编辑队列完成，每项展示原值、差异和版本校验。该定义是方案建议，确保“批量修改”不被缩减成仅批量归类。

批量提交前预检权限、版本、结构和引用状态。返回每项成功/失败/冲突及原因、稳定批次ID；成功项不重复执行，失败项可单独重试。批次处理中刷新或关闭页面不丢任务，不以统一成功提示隐藏部分失败。

删除使用逻辑删除。确认窗口展示名称、数量及引用情况；运行任务正在使用的数据禁止删除并给出定位入口；已有历史引用保留不可变快照及审计，资产删除后不能再建立新引用。仅文件尚无有效资产/版本引用时才允许后续清理实体，避免破坏历史结果。

批量删除同样逐项校验、明确部分失败和重试边界，不因一个条目失败反复删除已成功条目；不自动解除项目引用、不自动删除项目业务数据。

## 9. 接口与数据设计（拟新增，非现有可用接口）

|链路|拟议接口|校验及持久化|
|全局数据列表/详情|GET /test-data-assets、GET /test-data-assets/{id}|组织/全局资产角色、分类、分页；不依赖当前项目|
|上传/新建|POST /test-data-assets/uploads、POST /test-data-assets|文件和结构检查、幂等、初始版本及解析任务|
|修改|PUT /test-data-assets/{id}|expectedVersion、字段和内容校验、新版本|
|批量修改/删除|POST /test-data-assets/batches|操作类型、显式资源集合、逐项权限与版本、幂等|
|批次/解析进度|GET /test-data-assets/jobs/{id}|任务归属、状态、逐项结果、安全错误|
|删除|DELETE /test-data-assets/{id}|版本、运行引用保护、逻辑删除|
|内容/文件/版本|GET /test-data-assets/{id}/content、/file、/versions|预览分页与预算、文件下载权限、不可变版本|
|分类|/test-data-categories|组织归属、树校验、非空迁移|

复用现有接口可兼容时优先复用，上述路径为职责示例，实施时冻结最终契约并同步前端、MCP和接入说明。不得仅新建UI再跳回项目文件模块完成操作。

建议独立数据资产表、不可变版本表、解析任务表；复用支持全局范围的分类及审计基础设施。所有资产有明确scope/organizationId，来源projectId作为元信息，不再作为全局内容查询的主过滤。项目引用独立存储；公共配置的密文、密钥引用和版本继续保留，迁移不解密后写入普通文档。

## 10. 权限、执行器与安全

全局权限读取/上传/修改/删除/分类管理按当前用户角色判断，不因切换到高权限项目扩大能力。秘密解析保留独立业务授权和审计。没有权限的批量资源逐项拒绝，不从前端禁用代替后端校验。

MCP沿用Token绑定用户身份，无新增逐功能Token Scope。全局资产工具不再要求任意项目才能查询/写入；执行器会话仍可绑定执行项目，读取全局资产时记录实际versionId及使用项目。项目白名单继续限制项目操作；全局资源授权必须由全局权限明确判断，不能用“白名单空”或伪项目绕过。

外部提示使用统一安全错误协议，不展示SQL、堆栈、私密文件地址或密文。日志记录任务ID、阶段、时间、错误分类、安全根因类型和traceId；禁止记录数据正文、认证信息及秘密。上传解析失败可定位、重试，不伪装为空数据或成功。

## 11. 存量迁移与回滚

1. 只读盘点各项目资产、版本、分类、来源和引用，输出数量/大小/哈希/冲突，不修改线上数据。
2. 建立旧项目+旧ID→全局ID映射；内容相同不能仅凭名称合并，敏感配置还需核对业务身份和访问范围。冲突项保留两份并标记待治理。
3. 先迁移内容和历史版本，再迁移分类、引用、来源及审计；保留旧ID兼容解析和下载，验证旧任务固定版本仍可读。
4. 迁移校验通过后切换读写，切换窗口禁止旧新入口双向独立修改；重复执行迁移必须幂等。
5. 回滚保留映射和已生成版本，不删除新数据后简单恢复旧库。若切换后产生新写入，应冻结写入并按审计回放，回滚步骤须演练。
6. 数据总数、原文件哈希、版本数、引用数、敏感值脱敏、权限及抽样内容均需前后核对；无法映射的条目明确报告，不计迁移成功。

## 13. 实施与交付顺序

整版产品方案确认→冻结全局范围及批量修改语义→建立需求/入口/API/数据/测试追踪表→隔离分支完成数据模型和迁移→公共配置/业务资产及兼容目录全局化→测试数据完整交互→MCP和文档同步→相关单元、真实数据库集成、前端类型/lint、前后端打包及E2E→指定独立审查、修复及复审→按既定仓库流程提交合并推送及上游PR→用户部署通知后真实验收。

Docker镜像构建按用户既有要求不作为强制项；容器健康及部署后核心路径仍需真实证据。未执行的检查必须列出原因、风险和准确恢复命令，不把编译通过当交付通过。

待确认的设计建议只有三项核心边界：全局按组织隔离；批量内容修改采用逐资产编辑队列；新增人工录入支持表格/JSON/文本。未经确认不将这些建议冒充用户批准，也不据此开始生产改造。
