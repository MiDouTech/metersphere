## 1. 平台职责与导航

MSP 接入执行器，提供业务上下文和公共配置，收集执行过程与证据，发现偏差并向 AI 下发纠正信息。执行器负责实际探索和测试。业务资产沉淀不依赖平台预先冻结动作，不要求经过旧受控执行流程。

测试资产导航调整为：

| Tab | 职责 |
| --- | --- |
| 业务资产 | 按系统、模块、页面和业务流程组织业务理解文档 |
| 用例资产 | 管理测试用例及其业务依据 |
| 测试数据 | 管理执行所需的数据 |
| 公共配置 | 管理地址、账号、密码及配置文档 |
| 资产版本 | 统一查看历史版本、比较差异、切换当前版本 |

删除原“业务知识”“业务文档”两个 Tab，由新的“业务资产”替代。移除业务知识页上的“测试环境、资产版本、关联追溯、公共步骤、接口资产、执行证据、缺陷资产”整排导航。

测试环境相关配置归入公共配置；资产版本独立；关联追溯放入资产详情；公共步骤和接口资产保留在对应测试能力中；执行证据和缺陷通过资产详情关联查看，原有业务入口不因此删除。

## 2. 业务理解的形成与治理

核心资产是一份持续更新的业务理解文档。不是每次执行一份报告，也不是每个按钮一份文档。

业务链路：AI 读取当前业务理解 → 探索或执行 → 形成新增理解或变更 → 上传结构化 JSON 与文档 → MSP 归入现有资产或建立新资产 → 生成新版本 → 后续任务读取当前版本。

人工也能创建、编辑、上传和纠正业务理解，采用同一套分类、文档及版本机制。

### 2.1 归并规则

1. 同一页面或模块的不同操作归入同一文档，在文档内形成不同分支。
2. 前后关联操作按完整业务流程归入同一文档，例如创建申请、审批、撤回。
3. 流程跨页面时，以业务流程为主文档，记录涉及页面和模块。
4. 同一页面参与多个独立流程时，可关联多份流程文档；共享规则引用已有内容。
5. 优先用稳定业务标识匹配已有资产，标题和页面 URL 仅辅助匹配；动态 URL 参数不作为独立业务身份。
6. 无法明确归属时进入“待归类”，保留内容和来源，不自动覆盖已有文档。

### 2.2 文档结构

| 内容 | 要求 |
| --- | --- |
| 业务范围 | 系统、模块、页面、流程 |
| 业务目标 | 用户通过业务完成什么 |
| 前置条件 | 角色、权限、数据、配置条件 |
| 操作分支 | 正常、异常、边界、不同状态下的操作 |
| 关联流程 | 上下游操作、状态变化、依赖 |
| 业务规则 | 校验、计算、权限和限制 |
| 理解依据 | 来源任务、执行器、观察时间、证据引用 |
| 待确认内容 | 推测、冲突、未验证结论，不混写为已确认事实 |
| 本次变化 | 相比上一版新增、修改、废弃的内容 |

### 2.3 页面与统计

左侧系统、模块、页面／流程分类树及数量，右侧资产列表。支持搜索、筛选、新建、上传、编辑、归类、合并、归档和查看版本。

详情提供业务理解、操作分支、关联关系、来源与证据、变更记录。用户可直接维护内容。统计区分文档数与操作分支数：一份文档十个分支，计一份资产、十个分支。

## 3. AI 业务资产 JSON 协议

任务上下文提供机器可读协议，要求 AI：执行前查询相关资产及当前版本；发现新规则或变化时上传；同一业务更新原资产；提交完整新版本文档、结构化分支及基于的旧版本；区分事实、推断、待确认内容并关联证据；不上传密码和 Token 等秘密到业务文档。

```json
{
  "schemaVersion": "1.0",
  "operation": "UPDATE",
  "assetId": "business-asset-id",
  "baseVersion": 3,
  "idempotencyKey": "task-observation-unique-id",
  "scope": {
    "systemKey": "dealer",
    "moduleKey": "order",
    "pageKeys": ["order-create", "order-detail"],
    "flowKey": "order-submit"
  },
  "title": "订单创建与提交业务理解",
  "document": {"format": "markdown", "content": "完整业务理解文档"},
  "branches": [{
    "branchKey": "submit-with-insufficient-stock",
    "title": "库存不足时提交",
    "understandingStatus": "OBSERVED",
    "evidenceRefs": ["evidence-id"]
  }],
  "changeSummary": "补充库存不足时的提交限制",
  "source": {"taskId": "task-id", "executorId": "executor-id"}
}
```

以上为产品协议示例，不是已发布接口。身份、项目权限及来源归属由服务端验证，不仅依赖 JSON 自报。上传成功返回资产 ID、版本 ID、当前生效版本、归并结果。重复提交返回同一结果；并发旧版本冲突时保留提交内容，返回差异，要求 AI 读取新版本后重新合并，禁止静默覆盖。

## 4. 资产版本与替换

每份资产有稳定身份，历史版本统一进入资产版本。

- 更新内容生成新版本，历史版本不可原地修改。
- 支持查看、比较、下载，将任意保留版本设为当前版本；记录操作人、时间、原因。
- 新任务默认读取当前版本，并记录实际使用版本。
- 执行中的任务继续使用已读取版本；更新上下文须显式通知并留痕。
- 回切只改变当前版本指向，不删除后续版本。
- AI 上传无冲突且校验通过后成为当前版本；未解决冲突的内容保留为待处理版本。
- 版本替换和归并不走旧受控执行审批。

## 5. 公共配置

支持结构化配置及配置文档，按项目、系统、环境组织。

| 类型 | 示例 | 使用方式 |
| --- | --- | --- |
| 普通配置 | 平台地址、租户、默认超时 | 授权后提供给 AI 或执行器 |
| 敏感配置 | 账号、密码、Token | 加密保存、页面脱敏、按任务授权提供 |
| 配置文档 | 环境说明、登录步骤、配置指南 | 上传、下载、版本管理、关联适用范围 |

支持新增、编辑、批量导入、连接引用、版本记录。配置文档保留原文件及解析状态，失败可重新处理，不显示虚假成功。

秘密不进入业务理解文档、普通 JSON 上下文或日志。AI 获得配置名称和引用，执行器按权限解析实际值；需要 AI 参与登录时，由授权执行通道按需提供。配置修改、版本切换保留审计；敏感值不能通过历史版本页面泄露。

## 6. 受控执行彻底清理

| 范围 | 要求 |
| --- | --- |
| 前端 | 删除菜单、页面、路由、专属组件、权限点、提示 |
| 后端 | 删除专属接口、服务、冻结动作状态机、专属调度 |
| 执行器契约 | 移除必须认领旧受控任务、冻结动作、旧租约等前置依赖 |
| 资产能力 | 发布、读取、版本管理解除受控执行权限及状态依赖 |
| MCP／技能／JSON | 删除引导进入受控执行的工具和说明，改为执行器接入及资产沉淀协议 |
| 配置与数据 | 迁移有保留价值的数据后，清理专属开关、配置、表和字段 |
| 测试与文档 | 删除失效测试，更新有效说明，历史记录明确标记废止 |

复用的事件、证据上传、身份校验、幂等和纠偏能力，先解除旧模块依赖，归入独立执行器接入链路，再删除旧实现。不得破坏平台监控 AI 的能力。

历史数据库迁移保留可重放性，通过新增迁移清理旧结构；当前有效代码、接口和配置不得继续依赖受控执行。

## 7. 需求追踪与验收

| 需求 | 入口 | 后端与数据 | 验收证据 |
| --- | --- | --- | --- |
| 删除受控执行 | 旧入口移除 | 专属实现清理，共享能力解耦 | 旧接口不可用，新执行器上报与纠偏正常 |
| 业务资产 | 分类树、列表、详情 | 资产、分支、来源、关联持久化 | AI 上传后可查询、编辑、归类 |
| 更新理解 | 变更记录、冲突处理 | 幂等、并发校验、版本生成 | 重复不重建，并发不丢内容 |
| 版本替换 | 独立资产版本 Tab | 快照与当前版本指向 | 切换后新任务读取指定版本 |
| 公共配置 | 配置及文档管理 | 加密、权限、文件存储、版本 | 授权可用，越权拒绝，日志无秘密 |
| 监控纠偏 | 执行过程、纠偏结果 | 事件、指令、响应、恢复记录 | 真实执行发现偏差并完成一次纠正 |

异常验收覆盖上传失败、解析失败、权限拒绝、重复提交、并发冲突、错误归并、证据失效、配置解密失败、执行器断连和纠偏失败。服务端记录可关联阶段、错误分类及安全根因，不记录秘密或原始敏感报文。

实施顺序：盘点旧依赖和存量数据 → 建立独立执行器契约 → 清理受控执行 → 重建业务资产与公共配置 → 更新 AI 协议 → 完整自测和独立审查。

交付必须提供需求对应实现及证据，执行相关单元、集成、类型、lint、构建、迁移、容器及核心端到端检查。未运行项说明原因、风险与准确命令。产品批准不替代开发审查和部署后的正式验收。
