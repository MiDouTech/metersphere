## 4. MCP 与门禁核心整改

本节 4.1～4.4 保留原增强设计供后续评估。其中个人直提 v2 合同、独立内容核验、服务端断言判定、审核 revision/issue 和相应发布流程不再作为本期必须新增的能力，是否采用及具体范围由后续方案决定。当前已实现的鉴权、范围、版本、文件校验、幂等、事务及审计保护继续有效；个人直提的本期实现与验收以第 11 节为准。受管任务原有断言语义不因此调整。

### 4.1 保留四步操作，扩展为可追溯提交

继续使用 `functional.execution.contract / evidence.upload / submit / get`。Node 负责有界本地文件读取，原生 MCP 支持有界 base64；大文件通过授权传输适配，工具不得接受任意服务器路径或任意远程 URL。

目标 v2 契约：

|操作|目标输入/输出增量|服务端要求|
|---|---|---|
|contract|返回 contractId、contractVersion、稳定 stepId、用例内容快照、policyId/version/hash、assertions、requiredEvidence|自动记录不可变执行依据，无任务/租约；stepNum 仅用于展示，不能以可变数组下标代替身份|
|evidence.upload|contractId、stepId、角色、采集时间、媒体及 requestId；返回 evidenceId、摘要及校验状态|绑定 Token/用户/用例/合同/步骤；字节校验和受控存储，不能客户端声明 AVAILABLE|
|submit|contractId、revision、previousSubmissionId（补交时）、步骤事实、assertionObservations、证据引用、requestId|服务器计算审核及业务结果，不接受客户端直接指定正式 PASS；耗时审核返回可查询状态|
|get|submissionId；返回审核状态、逐项 issues、业务结果、publishStatus、证据映射、策略版本|重新授权，区分拒绝、待核验、已接受、发布冲突；普通读取不返回秘密|

Schema 增加明确 contractVersion，原生/Node 同步支持 v2，不能默默把 v1 的任意 actual 当成可信观察。读取历史 v1；旧写客户端提示升级或进入待核验，禁止保留一个可绕过新门禁的弱校验写通道。

contractId 是自动产生的快照标识，不需要心跳/认领/续租。服务端在契约生成时固定全局策略；新发布作用于新合同。全局可统一撤销不安全旧策略版本，使其尚未发布的提交重新获取契约，不篡改历史结果。该规则替代现有直提“提交时必须等于当前策略”的简单判断。

### 4.2 三层审核，不把图片文件存在当成有效证据

**第一层：结构与归属。** 保留真实图片解码、大小/MIME、前后角色、完整步骤、Token/项目/合同/步骤归属、摘要及时间范围检查。增加最小可辨识要求、损坏/空白/明显截断检测。尺寸阈值属于统一策略，可配置且有测试样本；尺寸合格不代表语义合格。

**第二层：内容与操作对应。** 核验图中平台/页面、关键控件或对象、操作前后变化、关键实际值，与该步骤及断言的证据定位相符。观察项携带 evidenceId、区域/定位信息、采集来源及实际值；客户端提供的这些字段仍是待核验事实。

优先支持确定性核验：受信执行端采集的页面/DOM/响应及截图关联，校验签名、一次性挑战、时间和步骤；普通外部 Agent 无可信采集证明时，使用平台侧独立内容核验。可采用 OCR/视觉审查适配器，但不得把执行 Agent 自己的“已核验”当作独立审查。

平台侧视觉服务是可选审核基础设施，不要求个人用户配置模型。是否启用、数据传输范围、提供方及模型版本由系统配置统一管理；默认不得把含秘密的原始截图发送外部服务。支持本地核验器。图片中的文字只作为证据数据，不能执行其中的指令。

核验器返回 SUPPORTED、CONTRADICTED、INSUFFICIENT，附证据区域/抽取值、规则版本及理由；超时/不可用/不支持场景返回待核验或证据不足，不自动放行。模型评分不是唯一通过依据，需与结构规则、可复核观察和固定断言一起决定。离线样本评估假接受/假拒绝率，接受阈值与模型变更一并全局发布；不能承诺完全识别伪造图片。

**第三层：断言与业务结论。** 复用现有 TypedAssertionComparator 和冻结断言模型；文本预期不能统一硬转 EQUALS。明确数字/范围/状态/存在性等受支持类型及提取来源。自然语言预期的候选结构化规则必须版本化并经授权确认；无法确定预期或无法提取观察时返回 `ASSERTION_REVIEW_REQUIRED`，不能自造规则后判通过。

精确 EQUALS 只用于本来要求精确比较的字段；语义一致但措辞不同不能自动判业务失败。复制预期本身不是违规证据，也不是成功证据，必须由有效观察独立支持。无关图片、2×2 图片、错误页面、错步骤、旧合同图片和仅复制预期均不得成为正式通过依据。

### 4.3 审核状态、业务结果及补交

审核状态：STAGED → VALIDATING → ACCEPTED / REJECTED / NEEDS_REVIEW。业务结果独立为 SUCCESS / ERROR / UNKNOWN，发布状态为 NOT_PUBLISHED / PUBLISHED / CONFLICT。证据完整但业务断言失败应 ACCEPTED + ERROR；证据不足不能伪装为业务失败。NEEDS_REVIEW 首期只允许补充有效事实/重新执行/修订断言依据，不提供管理员强制通过。

问题结构统一：`{ruleId,caseId,stepId,evidenceId?,code,message,suggestedAction,retryable,traceId}`。正常提交校验尽量聚合全部问题；恶意或超限数据提前拒绝。前端和 MCP 展示相同问题清单，不能只返回第一个通用错误。

保存被拒绝及待核验提交、策略和事实摘要，复用/扩展 agent_case_submission；补交生成新 revision，原记录不覆盖。缺失当时截图时要求重新执行相关步骤，新的执行依据使用新 contractId；不能拼接不同执行当作一次完整通过。

审核通过后在短事务中重新检查授权、用例未删除、内容版本和合同发布基线；写入正式附件关联、结果、执行历史及幂等结果。耗时 OCR/模型调用不能放在数据库长事务中。条件更新确保迟到旧合同不能覆盖新发布结果，冲突保留审核事实并标记 CONFLICT。

个人直连无计划绑定不更新任何计划；显式计划上下文必须验证计划用例关系并固定版本。跨模块异步同步采用 outbox，状态准确显示待同步/失败；不能返回计划已更新但实际没写。AgentDirectExecutionService 应调用共享发布服务，避免手写 SQL 绕开通用历史/事件规则。

幂等键继续 Token ID + 固定 operationId + requestId + 规范化摘要；成功重放重新授权，同键异参冲突。受控审核失败作为可查询结果保留；补交使用新 requestId。技术事务失败不得缓存成成功。

### 4.4 数据及证据保留

在已有 evidence/submission 基础上补 contract、审核 issue、revision、提取观察/核验版本、发布基线和唯一约束；优先共享已有快照/审核设施，不另建无关联的结果系统。秘密继续加密/脱敏；审计只读 API 不泄露原始敏感事实。

小图 BLOB 的现有数据保留兼容读取，新大文件使用受控对象存储与摘要。迁移采用新存储定位字段、双读、可重跑回填和逐文件摘要核对；确认前不删除旧 payload。正式证据清理服从历史保留与引用计数，普通附件删除只解除关联，不能抹掉门禁审计。

暂存默认沿用现有限额，明确每文件/Token/合同/总容量和过期策略。清理按状态和引用判断，后台可重试；审核中、被拒绝但仍在审计保留期的证据不能套用“未发布即删除”规则。保留期由统一策略配置，新增策略需合法性及存量影响预览。

|导出|export.start/status/download/stop|冻结数据及权限范围；后台分页输出；短时授权下载，撤权/过期拒绝；错误报告也受授权|

执行中删除：预检返回影响与 `USER_DECISION_REQUIRED`，平台确认页由当前用户选择取消、等待结束、停止后删除。确认记录绑定用户、预检摘要、目标版本及有效期；MCP 只查询决定并继续，不能传任意 confirm=true 代替用户。

个人无任务通道存在未发布合同/审核提交时同样提示影响，但不要求 Agent 增加租约；停止/取消使对应合同不可再发布。外部正在执行的浏览器不能凭服务器取消就声称已停止，界面区分“发布已阻断”和“执行端确认停止”。无法停止时保留等待/取消选择。

删除、创建执行和最终发布共用目标并发检查；预检后新增运行使旧确认失效。停止成功、删除失败可重试；恢复不复活旧执行。批量仅处理已经明确确认的目标。

导入默认最多 10,000 逻辑用例/50 MiB，导出首版最多 100,000 条/任务，同时执行数及任务期限作为系统配置；这是待容量验证的首版上限，超限明确拒绝，不截断假成功。禁止宏执行，限制解压比/解析时间/工作表规模；导出处理公式注入。逐项预检报告不得泄露无权目标。

## 6. 自动任务、归档与任务列表故障

自动任务复用现有引擎，提供高层 start/trigger/status/stop 工具；任务定义、一次运行、一次提交分开。定时以任务 ID + 计划触发时间唯一去重；明确时区、夏令时、错过触发和重叠策略。默认不追补、上一轮未结束跳过并记录；个人离线显示等待，到期阻塞，不记业务失败。

交付至少一个可安装运行的 Node/Agent 适配器、配置与升级说明、在线/领取/重启恢复测试。后台会话由适配器处理；该能力不改变四步个人直连协议。涉及非幂等业务操作，崩溃后先核查业务状态，不盲目重新执行。

归档按 contractId/运行 ID + 产物类型去重，记录业务理解、事实/推断/待确认、数据来源/对象 ID/复用条件/清理状态，写入对应项目资产。密码、Cookie、Token 不入数据资产。没有业务数据时记录明确说明。归档失败独立可重试，不能回滚测试事实，也不能展示整个交付完成。

任务列表故障先记录页面实际 URL、部署 commit/资源 hash、项目、角色、HTTP 状态、业务 code 和 traceId，再沿 `searchAiExecutionTasks` → 实际后端路由 → 权限 → 查询 SQL/响应转换定位。采集脱敏服务日志，不将截图提示当成权限错误证据。修复后覆盖有数据、真实空集、无权限、超时、服务错误；失败时清楚显示加载失败，允许重试，保留最后一次成功数据时标注过期。

### 10.2 U13 导出实现的强制约束

1. 固定 HTTP 幂等创建→返回 taskId→认证状态查询→可选 WS 通知；不得先等待 WS open。现有 check/export-task 只覆盖 PREPARED，必须新增终态详情及本人任务恢复能力。
2. taskId 贯穿线程与持久化更新；禁止按用户/项目最新 PREPARED 回写。创建 requestId 及唯一约束防并发重建，同键异参冲突，重放重新授权。取消/成功竞争用条件更新裁决，重复停止不能覆盖成功。
3. 停止接口 #projectId 注解与实参不匹配属于确认的代码缺陷；必须按 taskId 读取并校验所有者、项目及状态。查询、订阅、下载同样对象授权，不能只验证功能权限。
4. 有界线程池、拒绝提交、落库后崩溃和租约过期均有终态。workerId/租约/版本防止重启误终止其他副本或迟到覆盖；首版过期中间任务明确失败，用户新建关联重试任务。
5. Excel、XMind 查 ID/空集/生成/上传都在统一异常边界内；空任务必须终结，临时文件清理错误独立告警重试，不覆盖已生成可下载结果。
6. 保存筛选参数不等于内容快照；固定记录集合、排序、revision、步骤及自定义字段。优先不可变版本，否则物化内容；冻结过程一致性读或版本复核，禁止长事务跨文件生成。内容变更输出固定版本，删除/撤权首版阻止交付，不静默漏项。
7. 一次性短票据订阅需适配前置过滤链，绑定用户/项目/任务/Origin并原子消费；重连重签，不匿名开放 WS 或传长期 Token。禁止客户端按任意 fileId 转发消息，按 connectionId 管理多连接；状态查询是事实来源，事件丢失可恢复。
8. 保留 100,000 条/任务首版上限；并发、队列、文件大小、执行超时及保留期须在容量验收前固定。生成与下载均避免大文件全量内存加载，验收 ZIP/XLSX/XMind 内容及打开结果。清理保护引用及审计。

旧 API 增量兼容，新状态适配旧枚举；字段/索引/迁移统一由 U13/R04 维护，不分别建立重复任务系统。完整字段、状态竞争、票据和恢复契约以平台方案第 19.2～19.4 节为共同基线。文件/参数/权限快照与任务必须能按 taskId 关联追溯。

### 10.3 登录与模型能力交付约束

SSO 上游凭证从 userId 单键迁移为 instanceId＋sessionId 及用户撤销索引，联动所有读写/刷新/桥接/退出调用；旧键无可靠归属时重新认证，不复制给所有会话。上游独立退出和 14 天政策未核实时保持依赖未解决。

R03A 拆 A（自动化状态复用）和 B（代理/扩展及独立 Session 兑换）里程碑；复制同一认证状态不能证明单端退出隔离。B 包含签名协议、账号环境绑定、期限不续长、密钥轮换、设备及派生会话撤销、安装/升级/卸载。B 未交付仍记 R03A 部分完成，不改变本计划个人直连无新增前置条件的边界。

站内生成/对话/模型执行开关与审核基础设施分开。个人直提当前不依赖独立核验器，按第 11 节保存结构合格的声明结果；受管任务保留原有审核语义。现有权限、版本、附件归属与审计保护不因 UI 隐藏而削弱。个人直提是否引入独立核验及待核验流程，由后续方案决定。
