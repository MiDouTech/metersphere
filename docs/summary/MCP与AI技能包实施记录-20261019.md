## 关键设计和兼容边界

- 事务幂等键为 tokenId + 服务端固定 operationId + requestId。对象键递归排序、数组保持顺序；业务数据库副作用和成功结果在同一事务提交。事务隔离 READ_COMMITTED；并发重复请求最多产生一次被测试的数据库副作用。
- 已接入的操作：case_review.create、case_review.associate_cases、functional.case.update、functional.comment.create。历史公共工具名下已有键返回 IDEMPOTENCY_LEGACY_RECONCILIATION_REQUIRED，避免改名后重复写入。
- 对任务领取、续租、释放、步骤、事件、终态、证据及人工介入，不通过通用响应缓存重放。此举不等同于已经实现领取丢失响应恢复；调用方先查询任务状态。
- 评审 HTTP 的 Idempotency-Key 与请求体 requestId 不一致时拒绝。当前 HTTP 查询兼容 FUNCTIONAL_READ/REVIEW_WRITE，远程 MCP get 仍按原目录要求 FUNCTIONAL_READ；该 Scope 差异、计划的兼容期限与新增授权版本尚待统一。
- 评论附件 `uploadFileIds` 为临时 attachmentId；服务端验证主体和用途后转换 storage fileId。旧客户端直接传 fileId 会被拒绝，需先走临时上传。
- 用例更新必须提供 expectedUpdateTime、requestId 和非空 patch。当前尚非独立 revision 协议；普通页面和其他写入入口的并发回归未完成。
- 既有通知/对象存储是外部副作用，数据库事务并不自动回滚它们；不能以幂等基础测试宣称这些链路已经完整原子化。
