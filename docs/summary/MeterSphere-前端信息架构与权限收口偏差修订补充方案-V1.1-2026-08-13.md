# MeterSphere 前端信息架构与权限收口偏差修订补充方案

> 版本：V1.1  
> 日期：2026-08-13  
> 状态：已确认，作为 V1.0 的补充实现与验收基线  
> 原始基线：`MeterSphere-前端信息架构与权限收口改造方案-2026-08-13.md`

## 1. 修订目标

本补充方案不改变 V1.0 已确认的信息架构，专门修复实现审查中发现的缺口：

1. 成员角色迁移必须真正幂等、可审计，且初始业务权限与管理员一致。
2. 角色基本信息、接口权限和 UI 权限必须原子保存。
3. 新建角色首次打开即可配置全部权限。
4. 权限依赖、删除影响、未保存提示和中文化必须形成完整闭环。
5. 项目列表和用例资产补齐字段、权限交互、双层分页与路由状态。
6. 测试用例历史地址和无当前项目场景必须安全回落。

## 2. 成员角色迁移修订

### 2.1 幂等约束

- `user_role_permission` 增加 `(role_id, permission_id)` 联合唯一约束；加约束前清理历史重复关系。
- 所有成员关系、接口权限和 UI 权限写入均同时使用唯一约束或 `NOT EXISTS`。
- 旧角色迁移标记只允许写入一次，不得重复叠加。
- 重复执行迁移后，角色数、成员关系数、接口权限数和 UI 权限数必须保持不变。

### 2.2 权威权限源

- SQL 迁移负责创建 `permission_member`、合并成员关系、写入可确定的已有权限及全部启用 UI 资源。
- 应用运行时以统一 `PermissionCache` 权限定义为权威源补齐成员角色接口权限。
- “与管理员一致”指全部普通业务权限一致；管理员角色的不可修改保护继续由稳定角色 ID 强制执行，成员角色不得绕过。

### 2.3 审计

- 批次和角色审计记录旧角色 ID、名称、原成员数、迁移数、跳过管理员数、目标角色、版本和时间。
- 增加失败明细表，记录用户、来源角色、失败阶段和失败原因。

## 3. 角色权限闭环修订

### 3.1 原子保存

新增统一保存接口，一次提交：

- 角色 ID（编辑时）、名称、权限范围、状态、描述；
- 接口/数据权限；
- 页面、页签、按钮和接口 UI 权限。

后端在单一事务内完成角色校验、角色新增或更新、权限依赖规范化、接口权限保存和 UI 权限保存，任一步失败全部回滚。旧分步接口仅保留兼容，新页面不得继续调用。

### 3.2 新建角色

- 新建时按权限范围读取完整权限定义，不依赖已生成的角色 ID。
- 默认权限不勾选；用户可在首次保存前完成全部配置。

### 3.3 权限依赖

- 写权限依赖同资源查询权限；关闭查询时联动关闭写权限。
- 按钮/API 可操作依赖可见。
- 子资源可见递归依赖父资源可见。
- 关闭父资源前展示受影响子资源；确认后递归关闭。
- 前端负责即时联动和影响提示，后端再次规范化及校验，不能信任前端提交结果。

### 3.4 变更与离开提醒

- 保存前展示新增、移除及联动变更数量和摘要。
- 抽屉关闭、页面路由离开或切换权限范围时，存在未保存修改必须二次确认。

### 3.5 删除影响

- 删除前请求影响信息，至少返回关联成员数、删除后无其他有效业务角色的用户数。
- 有关联成员时展示人数并二次确认。
- 删除角色、权限和成员关系在同一事务内完成；用户可获得空权限兜底关系，但不得提升为管理员。

### 3.6 中文化

- 角色范围、资源类型、权限动作和组合权限名称集中维护。
- 所有用户可见权限表达使用中文。
- 未识别编码显示“未配置中文名称”，并输出包含原始编码和资源信息的警告日志。

## 4. 项目列表修订

- 项目 ID 支持复制。
- 成员列展示数量，悬浮展示前若干成员姓名及剩余人数。
- 创建人展示用户名称。
- 添加成员按目标项目权限控制；切换失败不得继续跳转。
- 项目搜索、状态筛选和分页继续由服务端完成，列表与 count 使用同一权限条件。

## 5. 测试用例与用例资产修订

### 5.1 测试用例

- 页面初始化立即移除废弃的 `dimension` 参数并回落项目维度。
- 无当前项目时展示项目选择提示，不请求模块树、列表和回收站数据。

### 5.2 用例资产

- 使用 `/test-assets/cases/project` 和 `/test-assets/cases/system` 表达独立路由状态。
- `/test-assets/cases` 重定向项目页，并兼容旧地址。
- 项目和用例分别使用服务端分页；禁止固定加载前 500 个项目。
- 项目搜索和分页状态独立于用例搜索和分页状态。
- 用例列表补齐所属模块、状态；深层查看先成功切换目标项目再进入详情。
- 系统页正常进入，只展示“系统级用例资产暂未开放”。

## 8. 实施与验证记录

- 角色页面改用 `/permission-control/role/save` 原子接口；新增和编辑分支均由后端再次校验具体权限。
- 新角色使用完整权限定义加载数据操作项，不再要求先保存再打开。
- 数据权限实现写权限与查询权限联动；UI 权限实现可操作与可见、子资源与父资源联动。
- 角色删除前展示关联成员数及删除后无其他业务角色人数。
- `permission_member` 使用统一权限定义缓存进行一次性初始化，以初始化记录避免应用重启覆盖管理员的后续人工调整。
- `user_role_permission` 清理重复关系并增加联合唯一约束；迁移写入增加 `NOT EXISTS`，旧角色标记不重复叠加。
- 项目切换和跨项目用例查询统一使用“全项目系统权限或有效项目成员关系”的可访问口径。
- 用例资产项目列表和用例列表分别分页，项目、系统使用独立 URL。
- 已增加角色保存依赖与删除影响单元测试，路由校验增加用例资产双路由及禁止固定 500 条加载断言。
- 原子保存接口新增角色类型不可变、接口权限范围和 UI 资源范围的服务端白名单校验，禁止构造请求跨范围授权。
- 成员权限初始化失败审计使用独立事务写入，主初始化事务回滚时仍保留失败阶段和原因；成功标记仅在权限全部写入后提交。
- 项目访问统一增加“项目存在、未删除且启用”的前置条件；即使拥有全项目读取权限也不能切换到停用项目。
- 项目成员数量与悬浮信息仅统计启用的项目角色及有效用户，避免其他层级关系误计入项目成员。
- 自动化结果：前端 `vue-tsc` 类型检查通过；Agent/测试资产路由、原子保存调用、权限中文映射全集、迁移幂等结构、跨项目访问交集静态回归通过；后端 system-setting、project-management、case-management 编译通过；角色、迁移失败审计与项目访问 6 个定向单元测试通过。
