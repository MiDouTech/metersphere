# MeterSphere 信息架构与权限闭环补齐方案 V1.4

> 日期：2026-08-14  
> 状态：已实施并完成自检  
> 基线：V1.0、V1.1、V1.2、V1.3 及 2026-08-14 复检结论

## 1. 目标

本轮按以下顺序消除已确认偏差，并以真实前端入口、后端授权、数据库资源和自动化测试四方一致作为完成标准：

1. 统一角色写入口及清除旧用户组产品入口。
2. 新增“可访问项目与用例读取权限交集”的项目分页接口。
3. 修复无当前项目时无法进入项目管理的问题。
4. 补齐项目列表按钮资源和角色成员作用域校验。
5. 对齐 Agent 集成页面与后端接口权限。
6. 重写静态验收脚本并增加浏览器测试。

## 2. 强制实现规则

### 2.1 角色与用户组收口

- 新产品页面只使用 `/permission-control/role/save`、启停、删除和成员关系接口。
- `/permission-control/role/add`、`/permission-control/role/update` 及旧 `/user/role/global/add|update` 不再形成独立写策略；兼容请求必须委托统一策略，或明确拒绝已下线写法。
- 兼容入口不得继续接受仅旧 `SYSTEM_USER_ROLE:*` 权限执行角色写操作。
- 系统用户、组织成员、项目成员页面不再显示“用户组”选择、批量加入用户组或快捷编辑用户组。
- 角色成员统一由“系统设置 / 系统 / 权限控制 / 角色设置 / 成员”维护。
- 清理指向已删除用户组路由的 pathMap、枚举消费和页面跳转。

### 2.2 用例资产项目交集

- 新增专用分页接口，服务端一次性完成：项目有效、用户可访问、项目内具有 `FUNCTIONAL_CASE:READ` 三项校验。
- 项目数量统计与分页列表使用同一权限条件。
- 用例资产页面不得使用通用 `/project/page` 作为项目数据源。
- 指定项目用例分页接口继续进行二次授权，防止篡改项目 ID 越权。

### 2.3 项目管理入口

- “项目管理 / 项目列表”不依赖当前项目存在。
- 没有当前项目但存在可访问项目时，用户可以进入列表并选择项目。
- 具体项目配置页面仍要求有效当前项目和对应项目权限。

### 2.4 UI 按钮资源与作用域

- 项目列表至少登记并落地：添加成员、进入项目、复制项目 ID 三个按钮资源。
- 已无真实控件的旧项目新建、归档按钮资源停用，不能继续出现在角色权限树。
- 添加成员同时满足按钮可见/可操作权限和 `PROJECT_USER:READ+ADD` 接口权限。
- 组织、项目角色的成员查询必须校验调用者对目标作用域的只读权限；修改继续校验更新权限。
- 组织/项目 ID 使用可访问作用域选择器，不允许依赖任意自由文本作为正常产品入口。

### 2.5 Agent 集成权限

- Agent 集成页面路由权限应覆盖页面实际展示能力，不能仅凭 `AI_EXECUTION:READ` 进入后无条件调用系统 Token 接口。
- Token、用户 Agent、安装包治理各区块按自己的接口权限加载；无权限区块不请求接口。
- 页面至少存在一个可见区块时才允许进入；完全无相关权限时路由不可见。
- 既有 `/agent/access` 路由保持兼容，显示名称仍为“Agent 集成”。

### 2.6 自动化验收

- 静态脚本解析真实路由、真实模板指令和接口调用，禁止以“字符串在任意文件出现”代替资源落地。
- 禁止用未被页面引用的 Tab 组件作为重复 Tab 验收依据。
- 浏览器测试覆盖项目管理、测试资产用例资产、Agent 集成、权限控制四个入口及关键字段/按钮。
- 浏览器测试必须支持复用登录态；测试环境不可用时保留可执行用例并将运行结果标记为阻断，不得标记通过。

## 3. 前后端接口与资源变更

| 项目 | 前端 | 后端/数据 | 验收 |
|---|---|---|---|
| 角色写入口 | 只保留原子保存与统一成员入口 | 兼容写接口复用统一校验并移除旧权限授权 | 无第二套角色写策略 |
| 用户组入口 | 移除系统/组织/项目成员页用户组控件及失效跳转 | 旧表和只读核对接口保留观察期兼容 | 产品 UI 不再出现权限型用户组 |
| 用例资产项目 | 调用专用项目分页接口 | 权限交集分页查询 | 列表中每个项目均可查询用例 |
| 项目管理 | 无项目也可进入项目列表 | 项目切换继续二次校验 | 首次用户可从列表进入项目 |
| 项目列表按钮 | 绑定三个稳定资源码 | DML 登记/停用资源 | 角色设置可控制真实按钮 |
| 角色成员 | 作用域选择器 | 读写分别校验目标作用域 | 不能枚举无权组织/项目成员 |
| Agent 集成 | 分区权限门禁和按需请求 | 保持接口权限强校验 | 页面不产生预期外 403 |

## 4. 测试矩阵

### 4.1 静态与单元测试

- 角色页面只调用原子保存接口。
- 旧用户组路由、pathMap、成员页控件和失效跳转不存在。
- 用例资产调用专用交集分页接口。
- 无项目时项目管理路由仍可访问。
- 每个启用 BUTTON 资源都存在对应资源码指令或明确的兼容绑定；停用资源不计入覆盖。
- 角色成员查询对组织/项目只读权限进行服务端校验。
- Agent 无 Token 读取权限时不调用 Token 列表。
- 后端新增项目交集、成员只读作用域和兼容写入口测试。

### 4.2 浏览器测试

- 项目管理入口可见，项目列表包含进入项目、项目 ID、名称、成员、状态、描述、创建人、创建时间、操作。
- 测试资产只显示一套模块 Tab；用例资产包含项目/系统页签；系统页为空状态。
- 测试用例页面不出现项目/系统维度页签。
- Agent 只显示一套模块 Tab，存在机器人图标和“Agent 集成”。
- 权限控制首先显示角色列表，管理员只读，普通角色存在编辑、删除、成员入口。
- 页面不存在系统、组织、项目“用户组”菜单入口。

## 5. 完成判定

只有同时满足以下条件才可标记完成：

1. 代码与本方案逐条一致。
2. 前端类型检查通过。
3. 后端目标模块编译及新增定向测试通过。
4. 路由、资源、API 闭环静态脚本通过且不存在已知误判规则。
5. 浏览器测试实际通过；若环境阻断，必须如实保留“待运行”，不得宣称浏览器验收完成。
6. 最终复检再次确认没有仅前端、仅后端或前后端不完整的需求内功能。

最终双向核对结论：本方案新增的前端接口均存在对应后端控制器与服务实现；新增后端产品接口均存在前端调用入口；按钮资源同时具备数据库登记、前端资源码绑定和后端权限校验。未发现需求范围内仅前端、仅后端或前后端实现不完整的遗留项。
