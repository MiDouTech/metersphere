# MSP 复测问题修复与交互优化方案（评审稿）

日期：2026-10-28。状态：已按用户确认进入实施，详见 msp-weekly-remediation-implementation-20261028.md；未执行的验收不计通过。基线为[本周复测报告](msp-weekly-commit-regression-results-20261028.md)、[40 条需求追踪](../testing/msp-weekly-regression-20261028/scope.md)及用户本次截图。

## 1. 范围和判定规则

40 条主需求中，15 条通过，7 条失败，16 条部分完成，2 条阻塞。本方案覆盖其余 25 条，并纳入补充检查中的 Token 裁切、历史详情异常及本次两项交互要求。7 条失败需求合并后为 6 个主要修复主题：导入两条需求共享同一个状态机缺陷。不能将所有“部分完成”都解释为代码未实现。

原因分三级：**已证实**指代码路径与实测互相印证；**待定位**指实测已失败但缺日志/数据证明具体原因；**验收缺口**指尚未执行必要场景，没有证据证明代码错误。历史报告不改写；本次新增标准作为后续验收补充。

通过必须同时满足：入口可用、权限正确、真实请求成功且持久化可读、异常行为正确、自动化检查及部署后端到端证据齐全。任务状态 SUCCESS 不能代替字段一致；截图美观不能代替操作可达；未执行不能计通过。以下时间和像素值为建议验收门槛，实施前固化到测试，不代表历史需求已有该 SLA。

## 2. 修复主题、影响及通过标准

### R1：执行事实敏感识别与脱敏（P1，AC-028）

**已证实原因**：`AgentFactCipher.sensitiveNode` 递归对象/数组，但不解析字符串节点中的 JSON；`AgentSensitiveDataSanitizer.redact` 对字符串仅使用普通键值正则。两者识别规则也不完全一致，例如 set-cookie。实测嵌套 JSON 字符串中的合成 password 绕过缺密钥保护，查询又返回原字符串。未查数据库，不认定已证实数据库明文。

**修改范围/内容**：agent-integration 的上述两类、执行事实存取/响应转换调用处及对应测试。抽取统一敏感分类器：结构化 JSON 递归；文本保留普通键值、Bearer 等规则；文本可解析为 JSON 时继续受限递归，输出仍保持原字符串字段类型。建议最大解析嵌套 8 层，超限、超字节限制或无法安全处理时拒绝敏感事实写入，不能按无敏感内容放行。加密保存原始事实，展示使用脱敏副本，不改变用于校验的原始输入。错误返回安全业务码和 traceId；日志不能记录原内容。

**配置/历史数据**：通过 Secret 注入 32 字节 Base64 facts-key，先验证 readiness，不在仓库保存密钥；保留现有加密版本兼容。对受影响时间段做授权范围内扫描和修复，使用审计/备份，不在日志导出原文。密钥丢失不能靠重新生成解决历史解密。

**通过尺度**：普通文本、对象、数组、字符串 JSON、多层转义、大小写键、set-cookie、畸形/超限各有测试；缺密钥所有敏感变体均失败且无业务写入；有密钥持久化为密文，授权读取脱敏，非授权拒绝；重启后仍可读取历史数据。合成标记不得出现在响应、日志及明文持久化字段中。

### R2：导入停止与重试状态机（P1，AC-019、NEW-03，并影响 AC-027）

**已证实原因**：`AgentCaseImportService.action` 将 PRECHECKED/QUEUED/RUNNING 统一改为 STOPPED，丢失停止前阶段；retry 接受所有 STOPPED 后直接 QUEUED，没有提交事实和关联决策门禁。修复 policy 参数误校验并未覆盖业务状态机。

**修改范围/内容**：导入服务、Web 提交控制器/请求、followup 协调器、导入弹框/任务页，以及数据库迁移。新增持久化的提交时间、停止前阶段、决策版本或同等语义字段，复用现有 group/policy 数据。只有明确提交才原子锁定关联策略并可入队；未提交任务恢复到 PRECHECKED，提示“请确认关联方式并提交”，不写用例。已提交任务重试仅重置失败/未完成项，已成功项不重复写；followup 独立重试，不重复建计划/评审。客户端不得用隐藏按钮替代服务端校验。

**兼容与并发**：不能把旧任务默认推断为已提交；依据可信提交记录回填，无法判定的旧 STOPPED 回到待确认，保留成功项。提交、停止、重试、worker 抢占在事务/行锁下比较状态及决策版本。重新选择已归档/删除关联组必须重新校验。

**通过尺度**：预检→停止→重试，新增用例/计划/评审均为 0；提交 IMPORT_ONLY、新建组、追加组三分支均只执行各自行为；双击及两个客户端并发重试不重复写；停止运行任务后成功项保留，重试只补剩余项；崩溃恢复不重复创建关联对象，逐项错误可见。Web、原生 MCP、Node 均执行同一业务服务。

### R3：资产同步一致性（P1，AC-021）

**已证实范围与待定位原因**：`CaseAssetService` 的 readiness 通过 missing/pending/failed 判断 UP_TO_DATE，不能证明已存在镜像的字段最新；实测为 UP_TO_DATE 时，执行状态及外部图片不一致。具体漏事件或消费映射位置仍需沿变更事务及 worker 日志定位，不能直接认定只有一个 outbox 调用漏写。

**修改范围/内容**：源用例/执行提交/附件绑定解绑/缺陷关联的变更入口、资产镜像投影与历史同步 worker、readiness DTO、资产列表状态展示。定义共享字段清单和版本：名称、正文/步骤、等级、标签、执行事实及状态、附件引用、缺陷关联、软删/恢复；目录分类和来源绑定规则单列，不能被源同步覆盖。成功同步记录 appliedRevision；源 revision 领先、字段缺失或消费失败均不得 UP_TO_DATE。复用现有可靠事件机制，事件与源事务一致；外部导图成功关联也发变更，失败导图不发虚假成功。

**数据/失败行为**：先部署写入事件，再分批校准历史镜像；按来源身份唯一 upsert，旧事件不得覆盖新版，软删使用墓碑。失败项展示安全业务原因、对象及 traceId、可重试状态。分页批次和游标持久化，避免全量驻内存；执行事实保留引用/投影边界，不复制成用例定义。

**通过尺度**：每个共享字段新增、更新、解除关联、删除/恢复分别比对源、计划、资产；自动同步建议 10 秒内可见，达到时限未收敛必须显示处理中/失败而非最新；网络失败及重启后可补偿、重复消费无重复记录；执行/附件故意落后时 readiness 必须能识别。校准前后计数及失败清单可审计。

### R4：资产导出等级为空（P2，AC-023）

**现象已证实，具体映射原因待定位**：同一资产列表/API 显示 P3，实际 XLSX 等级为空。`CaseAssetExportAccess` 是范围鉴权层，不负责等级映射，不能在该类硬编码 P3 修补。

**修改范围/内容**：沿资产导出请求到通用 FunctionalCase 导出服务、模板自定义字段取值及 Excel 行转换定位；统一等级的字段标识、选项值/显示值转换，缺失与非法值明确处理。保留资产目录和组织权限边界，分类/标签映射一并核验。已有数据若真缺映射先生成修复清单，禁止默认补成某一等级。

**通过尺度**：P0/P1/P2/P3/未设置分别导出，单元格与页面、API 一致；来源绑定与手工资产、不同模板均覆盖；选择范围内记录数、ID、名称、等级、标签、分类、步骤、预期逐字段比较；无权限、跨目录、部分失败安全提示。文件可打开或任务成功不单独计通过。

### R5：MCP 两端契约不一致（P2，AC-033）

**已证实**：当前连接器 schema 仍要求 hash/步骤证据且缺创建 requestId，原生 schema 已更新。仓库 Node 包并不等同客户端实际加载版本；具体是发布、绑定端点还是缓存，尚待确认。

**修改范围/内容**：核对原生 Tools 定义、Node 工具注册、技能包/下载包模板、连接器实际来源和发布配置；使用同一规范化 schema 作契约快照，检查 required、字段类型、默认值、错误码。Node 透传 requestId、顶层 evidenceIds，保留兼容性可选 hash/stepNum/purpose；刷新客户端工具绑定前记录版本/端点，避免仅重启服务却继续使用旧 schema。

**通过尺度**：生产产物的原生 tools/list、Node 实际启动后的 tools/list、下载包示例语义一致；两个客户端都实际执行“创建→用例级上传→无 hash 提交→读取→相同 key 回放”；相同业务失败返回一致业务码；旧客户端能力边界有清晰提示。只检查仓库源码不计通过。

### R6：旧用例详情及带步骤查询报错（P1，补充 W05）

**待定位原因**：100025～100021 单条带步骤查询可复现，新导入首尾记录正常。搜索走 `AgentFunctionalCaseSearchService → AgentFunctionalCaseExportService.enrichWithSteps → FunctionalCaseService.getAgentCaseDetails`，网页详情也失败，说明不是只修 MCP schema 能解决。模板/版本/步骤兼容是待证假设。

**修改范围/内容**：按报告 traceId 找服务日志，保留故障记录的脱敏字段结构，与新记录对比模板存在性、所属项目、版本、步骤格式、自定义字段。先做只读诊断，再确定兼容解析或数据修复迁移。历史空/非法数据不能无提示伪装为空步骤成功。列表 enrichment 允许按既定协议返回逐项 warnings/部分结果，但详情必须展示明确“历史数据需修复”及 traceId，不能永久加载。

**通过尺度**：上述 5 条逐条网页详情、MCP get、分页 includeSteps=true 全部返回正确字段；混合正常/异常记录不令整页不可用；无效结构、失效模板、无权限分别正确报错；修复不改写历史执行定义。日志及原始记录证据确认根因后才冻结具体数据补丁。

### R7：Token 列表、Demo 样式及窄屏可操作性（P2，AC-018、AC-036、W01）

**原因边界**：三种视口的 Token 右侧列超出个人窗口已量测；需检查个人窗口→内容区→表格的 min-width/overflow 链路，不能仅把列宽缩小。计划列表窄屏固定操作列覆盖名称，属于宽度分配与固定列问题。Demo 的表头、按钮高度、间距尚未完整应用。

**修改范围/内容**：个人中心 Agent 配置真实 Token 表及父容器、测试用例 caseTable、计划/评审真实列表 SFC、必要的 MsTable 滚动适配。容器 min-width:0，表格承载横向溢出，启用/操作列右固定；横向滚动条在内容区域可达，不依赖整页向右移。修复滚动层后再安排列宽。样式以已批准 Demo 为基准：批量常驻按钮 32px、间隔 8px，浅灰表头 #f8f9fc、紧凑但可读的行距、清晰禁用态；权限、原有按钮及路由行为不变。通用组件改动用开关隔离，检查所有调用者。

**通过尺度**：971/1366/1908 宽和 125% 缩放验证；Token 所有列可通过局部滚动查看，启用及操作可点击；计划名称不被固定列覆盖，编辑/组行不误导航；零选择按钮常驻但禁用，原权限一致。关键元素坐标中心命中正确目标，无矩形重叠；真实组件截图与 Demo 在表头、按钮尺寸、间距逐项核对，不只看静态仿图。

## 3. 新交互：全选按钮切换（UX-ALL-TOGGLE）

**现有代码根因**：`batchAction.vue` 固定显示 `msTable.all`；`base-table.vue` 顶部/底部两处入口固定调用 ALL。`useTable.ts` 已有 CANCEL_ALL 和清空排除项逻辑，中文 `msTable.cancelAll` 已存在，无需新增后端接口或再建独立选择状态。

**拟实现**：从 base-table 传入现有 selectorStatus，按钮文案由 `selectorStatus === ALL` 派生；点击时 ALL→CANCEL_ALL，否则→ALL。顶部、底部及旧下拉箭头调用同一选择处理器，不能只改文案。未启用此入口的其他表格保持原行为，原下拉箭头保留。

|当前状态|文案与点击行为|选择结果|
|---|---|---|
|无选择/仅当前页选择|全选所有页 → ALL|当前筛选范围所有页选中，排除项清空|
|跨页全选，含手工排除若干行|取消全选所有页 → CANCEL_ALL|清空所有已选、排除项及跨页模式，数量为 0|
|取消后再次点击|全选所有页 → ALL|重新选择当前筛选范围全部记录，不继承旧排除项|
|切换项目、目录或筛选|按原规则清空|按钮恢复“全选所有页”，不能跨范围选择|

无数据/加载时禁用；有选择时保留原“清空”。排除部分行后仍处跨页模式，因此仍显示“取消全选所有页”，避免误导为再次扩大选择。建议加 aria-pressed，键盘可操作。按钮仍放在导出右侧，常驻，不收进更多菜单。

**通过尺度**：至少 3 页数据，全选后逐页复选框及总数正确；排除一条再取消，三页均无勾选、selectedKeys/excludeKeys 清空、selectorStatus 退出 ALL；此时不能发送 selectAll=true 的批量请求。旧箭头先全选时新按钮同步切换；新按钮取消时旧箭头状态同步。局部选择、0 条、加载、筛选、翻页、再次全选均有组件及真实浏览器测试。

## 4. 新交互：计划概览横向对齐与美化（UX-PLAN-OVERVIEW）

截图展示了下拉框独占一行、紫色轨道下一行且右侧信息被挤出。当前 `.case-list-overview-content .case-progress-item` 明确 `flex-wrap:wrap`，内部允许拆行；缺少稳定分配宽度及完整分组约束。源码的 select 宽度与此前实页量测也不一致，应检查打包来源、Arco 内层及最终 computed style，不能宣称一个 CSS 属性就能保证上线修好。

**建议视觉布局**（保留现有含义，不更换统计口径）：

```text
测试计划  [计划名称（100005）▾] 通过率 [━━━━━━────] 60%     
个人执行 12/20 [━━━━────] 60%
```

计划区域用单一 grid/flex 分组：标签、select、通过率、进度条、百分比在同一水平中心线。容器不够宽时，把整个个人执行分组移至下一行；绝不单独把计划进度条挤到下拉框下面。极窄内容区允许两个完整分组纵排并局部横向滚动，不把页面整体撑宽。

**建议尺寸与色彩**：概览白/极浅中性底、1px 浅边框、8px 圆角、内边距 12px 16px；控件高 32px；select 按当前名称实际文本宽度自适应，不设固定 240/360px 上限，仅受父容器剩余空间约束、最小 160px、文本省略并保留完整 title；进度条 100～140px、6px 高、不可挤成 0；数字宽 44px，等宽数字对齐。轨道浅灰，已完成段使用原成功绿，未完成段不再大面积紫色，紫色只用于焦点/主题强调。0% 全灰轨道、100% 满填充，百分比与 tooltip 同一数据源。

保持最多一个计划、搜索切换、完整名称 tooltip；切换时以 planId 绑定数据，请求进行中显示局部 loading，不能短暂拼接旧计划百分比。空数据显示“暂无关联计划”，请求失败展示重试，不用 0% 伪装失败；个人进度空值保留原业务定义，不擅自算成 0%。建议计划进度增加 role=progressbar 和 aria-valuenow/min/max。

**修改范围**：`caseTable.vue` 的概览模板、局部 Less、必要的 i18n 和组件/浏览器测试；继续复用当前选中计划和统计 API，不新增业务接口/数据库。不能把个人执行进度改成所选计划执行进度，除非原接口就是该语义。

**通过尺度**：971/1366/1908 宽及 125% 缩放；计划 select、进度轨道、百分比中心线误差 ≤2px；不同名称长度和 0/1/60/99/100% 都不换出半个分组、不重叠、不撑破容器；至少两个不同非零进度计划切换，名称与统计始终属于同一计划；按 Demo 实际组件截图确认，按钮常驻、权限和功能不变。增加组件容器宽度测试，不能只以浏览器视口判断左目录占宽后的实际空间。

## 6. 实施顺序与交付门禁

1. R1 敏感处理与密钥 readiness、R2 导入状态机、R6 历史详情优先；再修 R3 数据一致性与补偿。
2. R4 导出字段、R5 实际客户端契约；R7 布局与两个 UX 小项可独立小批交付，避免混在一次大改中。
3. 每个改动记录需求→前端入口/组件→API→服务→持久化/配置→正反边界测试。前两项 UX 不新增后端接口；R2 需要状态迁移；R3 视现有 revision 字段复用情况确定迁移，不先虚构表字段。
4. 修复前先增加可复现失败测试；完成相关单测/集成、前端类型检查和 lint、生产构建、后端打包；有迁移验证升级和旧数据。按资源条件串行镜像/单实例健康检查，不同时启动多环境。部署后使用新 manifest 核对构建身份，再测真实 UI/MCP，不以本地样式替代上线验收。
5. 采用本轮专用项目与合成敏感内容，删除须遵守人工确认；不以修改业务数据来掩盖历史问题。旧报告中保留的测试数据先列清单再清理。

最终报告逐条附成功与失败证据、字段对比、构建身份和未执行项；任一关键门槛未满足仍标“部分完成”。本稿只完成原因梳理和建议设计，未运行修复后测试，未提交产品代码。
