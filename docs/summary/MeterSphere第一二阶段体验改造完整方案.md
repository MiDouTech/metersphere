# MeterSphere 第一、第二阶段使用体验改造完整方案

## 1. 文档概述

| 项目 | 内容 |
| --- | --- |
| 文档状态 | 待评审 |
| 方案范围 | 第一阶段高风险体验整改、第二阶段交互一致性治理 |
| 适用对象 | 产品、设计、前端、后端、测试、项目负责人 |
| 明确排除 | 第三阶段信息架构重组、一级导航调整、“测试用例”改名 |

MeterSphere 已具备完整测试管理能力，但错误反馈、复杂页面布局、操作状态、列表交互和业务术语仍存在不一致。本方案保持现有一级导航和核心业务模型，先解决影响任务完成和数据安全的高风险问题，再通过公共组件、页面模板和工程规则建立长期一致性。

## 2. 改造目标

### 2.1 第一阶段

1. 错误信息可理解、可恢复、可追踪，不暴露内部技术细节。
2. 用例执行等核心页面在常用分辨率下不发生页面级横向溢出。
3. 编辑、执行和异步任务具备持续可见的状态反馈。
4. 对未保存数据、危险操作和部分失败结果提供保护机制。

### 2.2 第二阶段

1. 统一列表、详情、表单、弹窗和抽屉的页面结构。
2. 统一搜索、筛选、创建、保存、删除及批量操作规则。
3. 统一业务术语、状态名称、状态颜色和反馈文案。
4. 新增可见文案全部纳入国际化体系。
5. 建立页面模板、公共组件和验收规范，防止问题继续扩散。

## 3. 范围边界

### 3.1 本次包含

- 全局异常脱敏、错误码和错误恢复。
- 登录、项目、组织、测试计划、测试用例等高频模块的错误处理。
- 用例执行页、计划详情页和任务中心的布局治理。
- 自动保存、保存失败、离开保护和重试。
- 导入、导出、执行、解析等异步任务反馈。
- 列表、搜索、筛选、分页和批量操作规范。
- 状态、颜色、文案、术语和国际化治理。
- 新增交互的基础可访问性要求。

### 3.2 本次不包含

- 一级导航及整体信息架构重组。
- “测试用例”整体改名为“测试执行”。
- 工作台、测试设计、质量分析等新工作流导航。
- 大规模视觉品牌升级和完整移动端适配。
- 核心业务数据模型重构。

## 4. 设计原则

- **用户可控：** 用户始终知道操作处于进行中、成功、失败还是部分成功，并可采取下一步动作。
- **就近反馈：** 字段问题显示在字段旁，局部问题显示在局部区域，避免用全局消息替代所有反馈。
- **可恢复：** 保存失败保留输入；网络失败提供重试；未保存离开需要确认。
- **降低认知负荷：** 默认只展示完成当前任务所需的信息，次要内容渐进展开。
- **行为一致：** 同类操作在不同模块中保持相同名称、位置和反馈方式。
- **渐进实施：** 优先扩展现有 Ms 组件和 Arco Design 主题，不新增并行 UI 框架。

## 5. 第一阶段：高风险体验整改

### 5.1 统一错误反馈

#### 当前问题

- SQL、Java 异常、Mapper 路径和数据库字段可能直接展示。
- 错误与发生问题的字段或区域缺乏关联。
- 用户无法判断错误影响，也不知道如何恢复。
- 不同页面混用 Message、Notification、弹窗和页面文字。

#### 用户可见错误结构

每条错误统一包含：

1. 业务标题，例如“项目成员加载失败”。
2. 影响说明，例如“暂时无法选择项目管理员”。
3. 恢复动作，例如“重试”“返回”或“修改输入”。
4. 错误编号，例如 `MS-PROJECT-3065`。
5. 可选诊断信息，仅按需展开或复制。

推荐文案：

> 项目成员加载失败，暂时无法选择项目管理员。请重试后再创建项目。错误编号：MS-PROJECT-3065。

#### 展示层级

| 类型 | 展示位置 | 示例 | 页面行为 |
| --- | --- | --- | --- |
| 字段校验 | 字段下方 | 项目名称不能为空 | 阻止提交 |
| 局部加载失败 | 当前模块内部 | 成员列表加载失败 | 仅阻止相关操作 |
| 页面加载失败 | 页面内容区 | 测试计划加载失败 | 提供重试 |
| 短暂操作失败 | 消息或通知 | 复制失败 | 不影响页面 |
| 不可恢复错误 | 结果页或弹窗 | 当前对象已被删除 | 阻止继续 |
| 后台任务失败 | 状态区域及任务中心 | 导入失败 3 条 | 提供明细与重试 |

#### 后端错误模型

```json
{
  "success": false,
  "code": "MS-PROJECT-3065",
  "messageKey": "project.member.loadFailed",
  "message": "项目成员加载失败",
  "requestId": "d9ae8f0a",
  "retryable": true,
  "fieldErrors": [
    {
      "field": "projectAdmin",
      "messageKey": "project.admin.optionsUnavailable"
    }
  ]
}
```

约束：

- 用户响应不得包含 SQL、堆栈、Mapper 路径、数据库字段或内部服务地址。
- 完整异常只进入服务端日志，并通过 `requestId` 关联。
- 未识别异常转换为通用错误编号。
- 字段错误使用结构化 `fieldErrors`，前端不解析异常字符串。
- `retryable` 决定前端是否展示重试操作。

#### 前端公共能力

- 请求拦截器：把服务端异常转换为统一 `AppError`。
- `MsErrorNotice`：展示标题、影响、恢复动作和错误编号。
- `MsErrorBoundary`：处理页面和局部渲染错误。
- `MsResultState`：统一加载失败、无权限、内容不存在等状态。
- `useRequestError`：封装页面错误处理。
- 诊断复制：只复制错误编号、请求编号、时间及接口名称。

业务页面不得直接展示 `error.message`、`response.data` 或异常堆栈。

### 5.2 核心页面布局治理

#### 目标布局

本阶段保留现有导航和入口，只调整页面内部结构：

1. 模块树使用可折叠弹性侧栏，建议宽度 220～320px。
2. 详情和执行区占据剩余空间，不使用多层固定宽度。
3. 操作区固定在当前内容容器底部，不采用页面级固定定位。
4. 步骤在窄宽度下从多列重排为纵向结构。
5. 附件、需求、缺陷等次要内容可进入折叠区或抽屉。
6. 只有表格容器可以按需横向滚动，页面整体不得横向滚动。

#### 执行页关键交互

- 模块树可折叠，并记住个人偏好。
- “通过、失败、阻塞”同时使用文字和颜色表达。
- 页面底部持续展示自动保存状态。
- “通过并下一条”必须在保存成功后跳转。
- 保存失败时停止自动跳转，并提供重试。

#### 表格治理

- 默认展示完成判断所需的 5～7 列。
- 名称列承载名称、编号和简短上下文。
- 次要属性进入展开行、详情抽屉或列设置。
- 操作列只直接展示一个高频操作，其他操作进入“更多”。
- 提供按角色或场景设置的合理默认列配置。

### 5.3 保存状态和离开保护

统一状态模型：

| 状态 | 文案 | 行为 |
| --- | --- | --- |
| `idle` | 无修改 | 可正常离开 |
| `dirty` | 有未保存的更改 | 离开时提示 |
| `saving` | 正在保存… | 禁止重复提交 |
| `saved` | 所有更改已保存 · 14:36 | 可继续或离开 |
| `failed` | 保存失败，请重试 | 保留输入并停止跳转 |

实现要求：

- 使用 `useSaveState` 统一管理状态。
- 路由守卫处理站内离开，`beforeunload` 处理刷新或关闭。
- 自动保存使用防抖，并明确展示保存开始和结束。
- 保存失败不得清除用户输入。
- 并发修改需要版本号或更新时间校验，并提供冲突提示。

### 5.4 异步任务反馈

适用于批量执行、接口测试、导入、导出、文档解析和报告生成。

统一任务状态：排队中、执行中、已完成、部分成功、已失败、已取消。

产品要求：

- 操作发起后立即告知任务已创建。
- 当前页面显示简要进度，离开后仍可在任务中心追踪。
- 完成后显示成功、失败和跳过数量。
- 失败项支持下载、过滤或单独重试。
- Toast 只表示请求已接收，不承担长期状态展示。

### 5.5 危险操作与批量结果

删除、停用、停止任务等操作必须说明影响对象、数量、可恢复性及对执行任务的影响，避免仅显示“是否确认删除”。

批量操作必须展示总数、成功数、失败数、跳过数和失败原因。部分成功不得简单提示“操作成功”或“操作失败”。

## 6. 第二阶段：交互与表达一致性

### 6.1 页面结构规范

#### 列表页

统一为：页面标题与说明 → 页面主操作 → 快捷搜索和常用筛选 → 高级筛选 → 内容表格 → 批量操作 → 分页。

一个列表页原则上只有一个高强调主操作。

#### 详情页

- 标题区展示名称、编号、状态和核心操作。
- 基础信息和业务内容明确分区。
- 页签名称保持稳定并使用名词。
- 危险操作与常规操作分层。
- 返回列表时恢复筛选、分页和滚动位置。

#### 新建和编辑载体

| 场景 | 推荐载体 |
| --- | --- |
| 字段少且无需切换上下文 | 弹窗 |
| 字段多、复杂校验或多个步骤 | 独立页面 |
| 当前上下文中的查看和少量修改 | 抽屉 |
| 不可逆或危险确认 | 确认弹窗 |

同一对象的新建和编辑应尽量使用同一种载体。

### 6.2 搜索与筛选

- 文本搜索统一按 Enter 或点击搜索按钮提交。
- 清空搜索词后自动恢复列表。
- Placeholder 明确可搜索字段，如“搜索计划名称或编号”。
- 枚举值必须使用选择器，不能使用自由输入。
- 常用筛选直接展示，高级条件进入筛选抽屉。
- 筛选变化后即时生效，并展示已生效条件数量。
- “重置”恢复页面默认条件，而不是无差别清空。
- 返回列表时恢复查询状态。

### 6.3 操作层级

- 页面级只保留一个主按钮，例如“新建测试计划”。
- 次要操作使用普通按钮，低频操作进入“更多”。
- 行级直接展示一个最高频操作，其他操作进入“更多”。
- 删除、停用等危险操作置于菜单底部并使用危险样式。
- 图标按钮必须有可见标签或辅助名称。

### 6.4 状态和颜色

颜色不得作为唯一信息载体，必须同时显示文字。

| 语义 | 状态示例 |
| --- | --- |
| 中性 | 未开始、草稿、已取消 |
| 进行中 | 执行中、处理中、解析中 |
| 成功 | 已完成、已通过、已保存 |
| 警告 | 部分成功、待确认、即将超期 |
| 危险 | 失败、阻塞、严重缺陷 |

同一个状态在不同页面使用相同名称和颜色语义。

### 6.5 业务术语

| 术语 | 定义 | 不应混用 |
| --- | --- | --- |
| 负责人 | 对对象整体负责的人 | 管理员、责任人 |
| 执行人 | 实际执行测试的人 | 处理人 |
| 处理人 | 当前负责处理缺陷或工单的人 | 执行人 |
| 创建人 | 创建记录的人 | 发起人，除非确为任务发起 |
| 测试计划 | 组织测试范围、周期和人员 | 执行任务 |
| 执行任务 | 一次具体的人工或自动执行 | 测试计划 |
| 执行结果 | 一次执行产生的结果记录 | 测试报告 |
| 测试报告 | 对一组结果的分析总结 | 执行结果 |

术语表需映射到国际化 Key、接口枚举、页面文案和帮助文档。

### 6.6 国际化治理

- 新增用户可见文本必须使用国际化 Key。
- 业务术语引用公共词条，不允许各模块重复创建近义词。
- 后端错误信息不拼接最终界面文案。
- 日期、时间和数字使用统一格式化函数。
- 增加 Vue 模板中文硬编码检查。
- 历史代码建立白名单，新增代码不得扩大白名单。
- CI 输出新增硬编码位置并阻止不合规代码合入。

### 6.7 基础可访问性

- 可点击区域优先使用 `button`、`a`、`input` 等语义元素。
- 所有操作可通过 Tab 到达，并保留清晰焦点样式。
- Enter 和 Space 行为符合控件语义。
- 图标按钮具有 `aria-label`。
- 弹窗打开后焦点进入弹窗，关闭后回到触发元素。
- 表单错误与对应字段建立程序化关联。
- 状态不能只依赖颜色表达。

## 7. 技术实现建议

### 7.1 前端能力

```text
frontend/src/components/pure/
├── ms-error-notice/
├── ms-result-state/
├── ms-save-status/
├── ms-async-task-status/
├── ms-danger-confirm/
└── ms-batch-result/

frontend/src/hooks/
├── useRequestError.ts
├── useSaveState.ts
├── useLeaveGuard.ts
├── useAsyncTask.ts
└── useListQueryState.ts
```

实际目录遵循当前工程结构，以上表示能力边界。

### 7.2 后端能力

- 建立错误码目录、命名规则和维护责任人。
- 全局异常处理器完成异常分类、脱敏及日志关联。
- 字段校验使用统一结构。
- 异步接口返回任务 ID 和状态查询方式。
- 批量接口统一返回成功、失败及跳过明细。
- 禁止将底层异常消息直接作为用户响应文案。

### 7.3 迁移策略

1. 新功能直接使用新规范。
2. 高频页面随对应迭代迁移。
3. 低频页面在后续需求触达时迁移。
4. 旧组件先标记废弃，不立即删除。
5. 新旧组件并存期间保持视觉和接口兼容。

建议周期：1～2 周。

- 模块树支持折叠和宽度记忆。
- 固定执行操作区和保存状态区。
- 治理测试计划详情及任务中心的横向溢出。

- 建立主要分辨率视觉回归基线。

### 迭代三：状态反馈闭环

建议周期：1 周。

- 实现保存状态和离开保护。
- 统一异步任务状态。

## 10. 测试方案

### 单元测试

- 错误模型转换。
- 保存状态转换。
- 查询条件序列化和恢复。
- 批量结果统计。

### 组件测试

- 错误重试和诊断展开。
- 离开保护。
- 异步任务状态变化。
- 危险操作确认。
- 键盘导航和焦点返回。

### 端到端测试

- 项目创建时局部加载失败并恢复。
- 用例执行、自动保存、失败重试和下一条。
- 批量操作部分成功。
- 异步任务离开页面后继续追踪。
- 列表筛选后进入详情再返回。

### 视觉回归

覆盖 1366×768、1440×900 和 1920×1080；同时验证导航展开与折叠、中英文长度，以及正常、加载、空数据、失败和无权限状态。

## 11. 验收标准

### 错误安全

- 界面不出现 SQL、Java 堆栈、Mapper 路径、数据库字段或内部服务地址。
- 技术排查错误具有错误编号或请求编号。
- 可重试错误提供重试入口。
- 字段错误显示在对应字段附近。

### 布局稳定

- 1366×768 和 1920×1080 下核心页面没有页面级横向滚动。
- 主要操作按钮不会被遮挡。
- 模块树展开或折叠后内容区自适应。
- 表格横向滚动只发生在表格容器内。

### 状态明确

- 编辑和执行页面始终可以判断保存状态。
- 保存失败不会丢失用户输入。
- 未保存离开页面时必须提示。
- 异步任务离开页面后仍可追踪。
- 批量操作展示成功和失败明细。

### 交互与文案一致

- 高频列表页的搜索、筛选、清空和分页行为一致。
- 同类新建和编辑使用一致载体。
- 危险操作说明影响范围和可恢复性。
- 同一状态使用相同名称和颜色语义。
- 新增可见文案全部使用国际化 Key。
- CI 可以识别新增中文硬编码。

### 基础可访问性

- 新增交互可通过键盘访问。
- 焦点状态清晰可见。
- 图标按钮具有辅助名称。
- 状态不只依赖颜色。
- 弹窗焦点进入和返回行为正确。

## 12. 效果衡量

建议在改造前建立以下基线：

- 核心任务完成时间。
- 表单重复提交次数。
- 自动保存失败后的数据丢失反馈数。
- 用户主动刷新或重复点击次数。
- 前端直接展示后端异常的数量。
- 批量任务失败后的重试成功率。
- 高频页面横向滚动出现率。
- “找不到、看不懂、不知道是否成功”类反馈数量。

## 13. 风险与应对

| 风险 | 应对方式 |
| --- | --- |
| 新旧错误结构并存 | 拦截器兼容旧结构，后端按模块迁移 |
| 公共组件影响范围大 | 保持接口兼容，优先灰度接入高频页面 |
| 固定宽度存量多 | 先治理核心路径，增加静态扫描和新增约束 |
| 术语存在历史成本 | 发布术语映射表，按版本渐进迁移 |
| 国际化存量规模大 | 禁止新增、分模块清理，不要求一次清零 |
| 自动保存存在并发冲突 | 增加版本校验和冲突提示 |

## 14. 评审决策点

开发前需要确认：

1. 错误码规范的维护团队。
2. 首批接入统一错误模型的后端服务范围。
3. 第一批高频页面最终名单。
4. 用例执行页允许调整的边界及必须默认可见的信息。
5. 自动保存间隔、触发条件和冲突处理方式。
6. 业务术语表的最终审批角色。
7. 中文硬编码检查是否设为 CI 阻断规则。
8. 四个迭代采用同一版本还是多个小版本发布。
