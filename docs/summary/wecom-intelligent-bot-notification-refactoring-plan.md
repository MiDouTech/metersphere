# 企微智能机器人通知改造方案

## 1. 文档概述

### 1.1 改造背景

本次改造涉及企微智能机器人“缺陷解决时间”“测试报告生成”两类通知，并统一调整所有通知类型的用户组配置方式，主要解决模板参数难理解、定时推送能力不足、时间范围字段冗余、接收人 `@` 规则不完整，以及用户组配置与现有岗位和角色体系不一致等问题。

### 1.2 改造目标

1. 为 Markdown 模板参数提供清晰的中文说明。
2. 支持一条通知配置维护多条每日或每周定时推送计划，并支持手动触发。
3. 删除“缺陷解决时间”和“测试报告生成”通知中的开始时间、结束时间。
4. 完善测试报告通知中个人接收人和项目成员的 `@` 规则。
5. 将所有通知类型的原用户组配置替换为岗位和角色选择。

## 2. 改造范围

| 改造对象 | 改造内容 |
| --- | --- |
| 缺陷解决时间通知 | 模板参数中文说明、多定时计划、手动触发、删除开始和结束时间 |
| 测试报告生成通知 | 删除开始和结束时间、完善个人接收人与项目成员的 `@` 规则 |
| 所有通知类型 | 清除原用户组配置，改为选择岗位和角色 |
| 通知调度服务 | 支持多计划调度、启停、幂等和执行记录 |
| 企微发送服务 | 动态解析接收人、成员去重、企微身份匹配和异常记录 |

## 3. 缺陷解决时间通知改造

### 3.1 Markdown 模板参数中文化

在 Markdown 模板编辑区域展示系统支持的变量，并为每个变量补充中文名称、用途说明和示例值。变量标识本身保持不变，确保历史模板继续兼容。

参数展示形式建议如下：

| 模板参数示例 | 中文名称 | 参数说明 | 示例值 |
| --- | --- | --- | --- |
| `${projectName}` | 项目名称 | 当前缺陷所属项目名称 | MeterSphere |
| `${bugName}` | 缺陷名称 | 缺陷标题 | 登录接口返回异常 |
| `${bugNo}` | 缺陷编号 | 缺陷唯一编号 | BUG-001 |
| `${handlerName}` | 处理人 | 当前缺陷负责人 | 张三 |
| `${status}` | 缺陷状态 | 当前缺陷处理状态 | 待修复 |
| `${expectedResolveTime}` | 预计解决时间 | 缺陷计划解决时间 | 2026-08-21 18:00 |
| `${remainingTime}` | 剩余时间 | 距预计解决时间的剩余时长 | 2小时 |
| `${bugUrl}` | 缺陷链接 | 缺陷详情页访问地址 | https://example.com/bug/1 |

> 最终参数清单以系统实际支持的模板变量为准，上表仅用于说明设计形式。

交互要求：

- 参数列表支持一键复制变量。
- 参数旁展示中文名称，悬浮或点击后展示详细说明和示例。
- 保存时校验无法识别或已经废弃的参数，并给出明确提示。
- 历史模板不自动修改，不因中文说明改造而改变已有内容。

### 3.2 多条定时推送计划

将原有单一时间配置改为定时计划列表。一条通知配置可以同时关联多条定时计划，每条计划独立维护和执行。

每条计划包含以下配置：

| 配置项 | 说明 |
| --- | --- |
| 周期类型 | 支持“每日”和“每周” |
| 执行日期 | 每周模式下选择周一至周日，支持多选 |
| 执行时间 | 精确到“时:分” |
| 时区 | 默认使用系统或组织时区，并在页面明确展示 |
| 启用状态 | 单独启用或停用当前计划 |
| 操作 | 编辑、删除、手动触发 |

配置示例：

- 每日 09:00 推送。
- 每周一、周三、周五 10:30 推送。
- 每周五 17:00 推送。

操作规则：

- **新增**：新增一条定时计划，不影响其他计划。
- **修改**：修改周期、星期、时间或启用状态后，重新计算下次执行时间。
- **删除**：删除前进行二次确认，删除后取消对应调度任务。
- **启用/停用**：只影响当前计划，不影响通知配置下的其他计划。
- **重复校验**：相同通知下不允许存在完全相同且同时启用的计划，避免重复发送。

### 3.3 手动触发

通知配置提供“立即发送”操作，用户不需要等待定时计划即可手动触发。

手动触发规则：

1. 使用当前已保存的筛选条件、Markdown 模板和接收范围。
2. 不受定时计划启用状态限制。
3. 发送前展示确认提示，防止误操作。
4. 记录触发人、触发时间、通知内容摘要、实际接收人和发送结果。
5. 手动触发不改变任何定时计划的下次执行时间。

### 3.4 删除开始时间和结束时间

从缺陷解决时间通知配置中删除“开始时间”和“结束时间”。

改造要求：

- 前端表单不再展示这两个字段。
- 创建和编辑接口不再要求传入或校验这两个字段。
- 缺陷查询和通知发送逻辑不再使用该时间区间。
- 历史数据中的字段可暂时保留但停止使用，避免直接删除字段造成兼容风险。
- 旧版本请求仍传入这两个字段时，后端忽略处理。
- 通知执行时，根据实时缺陷数据及通知配置中的其他筛选条件确定发送内容。

## 4. 测试报告生成通知改造

### 4.1 删除开始时间和结束时间

测试报告生成通知以“报告生成事件”为触发依据，不再依赖开始时间和结束时间。

改造要求：

- 前端删除开始时间和结束时间。
- 创建、编辑接口取消对应字段校验。
- 消息生成和发送逻辑不再读取时间范围。
- 历史配置继续正常加载，旧字段不再生效。

### 4.2 个人接收人与 `@` 规则

#### 4.2.1 已选择个人接收人

用户显式选择个人接收人时，以所选人员为准：

1. 消息发送至配置的企微群。
2. 对所选个人接收人进行去重。
3. 如果所选人员不在当前项目成员中，补充 `@此人`。
4. 如果所选人员已经是项目成员，保持现有项目成员处理逻辑。
5. 项目成员关系不应阻止显式选择的人员接收提醒。

按照需求原文，本次新增规则重点是补充 `@非项目成员`。所选项目成员是否需要显式 `@`，继续遵循系统现有逻辑，避免改变既有通知行为。

#### 4.2.2 未选择个人接收人

未选择个人接收人时：

1. 消息发送至配置的企微群。
2. 默认 `@` 当前项目的成员。
3. 项目成员按通知触发时的实时数据获取，不保存成员快照。
4. 对项目成员进行去重后再生成最终 `@` 列表。

#### 4.2.3 处理流程

```text
如果选择了个人接收人：
    发送群消息
    对个人接收人去重
    按现有规则处理项目成员
    对不属于项目成员的个人接收人补充 @
否则：
    发送群消息
    获取当前项目成员
    去重后默认 @ 项目成员
```

#### 4.2.4 异常处理

当系统用户没有有效的企微身份映射时：

- 群消息仍正常发送。
- 无法完成该用户的企微 `@`。
- 发送结果标记为“部分成功”，并记录未匹配人员及原因。
- 在发送记录或配置检查结果中提示管理员补充企微账号映射。

## 5. 所有通知类型的用户组改造

### 5.1 配置方式调整

所有通知类型中，用户组原有配置内容全部清除，改为从以下两个维度选择接收对象：

- 岗位列表中的岗位。
- 角色列表中的角色。

页面字段建议由“用户组”更名为“接收范围”或“接收对象”，使名称与实际配置含义一致。

### 5.2 交互设计

- 岗位和角色均支持多选、搜索和清空。
- 已选内容以标签形式展示。
- 角色展示所属范围，区分项目角色、组织角色和工作空间角色。
- 同名角色增加范围标识，例如“测试人员（项目角色）”。
- 提供“接收人预览”，展示当前岗位和角色解析出的实际用户。
- 没有解析到有效接收人时，保存或启用通知需给出明确警告。

### 5.3 数据结构建议

前端提交岗位 ID 和角色 ID，后端不保存岗位或角色名称。

```json
{
  "positions": ["position-id-1", "position-id-2"],
  "roles": ["role-id-1", "role-id-2"]
}
```

### 5.4 接收人解析规则

通知触发时动态解析岗位和角色对应的用户：

1. 查询选中岗位下的有效用户。
2. 查询选中角色下的有效用户。
3. 岗位与角色采用并集关系。
4. 按用户 ID 合并去重。
5. 过滤已禁用、已离职或已失效的用户。
6. 根据企微通知渠道匹配用户的企微身份。
7. 生成最终接收人和 `@` 人员列表。

岗位或角色成员发生变化后，后续通知使用最新人员关系，无需重新保存通知配置。

### 5.5 历史配置迁移

由于需求明确要求清除原用户组内容，建议采用以下迁移方式：

1. 升级后，历史通知配置中的原用户组不再参与接收人解析。
2. 岗位和角色默认置空，不在缺乏映射关系时自动转换。
3. 对受影响的历史通知增加“待完善”状态或配置告警。
4. 管理员重新选择岗位或角色后，方可重新启用或正常发送。
5. 升级前提供受影响通知配置清单，降低通知中断风险。

## 6. 页面改造建议

通知配置页面建议按以下结构组织：

1. 基本信息。
2. 通知类型。
3. 触发方式。
4. 定时推送计划，仅在支持定时推送的类型下展示。
5. 接收范围，包括个人接收人、岗位、角色和企微群。
6. Markdown 消息模板。
7. 模板参数中文说明。
8. 手动触发操作。
9. 发送记录。

切换通知类型时，页面动态展示当前类型支持的配置项，隐藏无效字段。

## 7. 后端与调度设计

### 7.1 数据模型

建议新增独立的通知调度计划表，使一条通知配置关联多条计划。主要字段包括：

| 字段 | 说明 |
| --- | --- |
| 通知配置 ID | 关联通知主配置 |
| 周期类型 | 每日或每周 |
| 星期配置 | 每周模式下的执行日期集合 |
| 执行时间 | 计划执行的时和分 |
| 时区 | 计算执行时间使用的时区 |
| 启用状态 | 当前计划是否有效 |
| 下次执行时间 | 调度器计算出的下一执行时间 |
| 最近执行时间 | 最近一次实际执行时间 |
| 创建人/更新人 | 审计信息 |

岗位和角色接收范围可使用关联表存储，便于查询、约束和后续扩展。

### 7.2 调度执行要求

- 新增或修改计划后，重新计算下一次执行时间。
- 删除或停用计划后，取消对应的待执行任务。
- 多节点部署时增加分布式锁，避免同一计划重复执行。
- 同一通知短时间内被多计划同时命中时，使用幂等键避免重复发送。
- 调度失败支持有限次数重试，并记录最终失败原因。

### 7.3 发送记录

定时发送和手动发送均记录以下信息：

- 通知类型。
- 触发方式。
- 触发人。
- 计划执行时间与实际执行时间。
- 企微群目标。
- 配置的个人接收人。
- 岗位和角色解析出的接收人。
- 实际 `@` 人员。
- 发送状态。
- 失败或部分失败原因。
- 消息内容摘要。

## 8. 接口改造建议

### 8.1 通知配置接口

- 删除开始时间和结束时间的必填及业务校验。
- 增加岗位 ID、角色 ID 集合。
- 保持对旧字段的兼容读取，旧字段停止参与业务处理。

### 8.2 定时计划接口

建议提供以下能力：

- 查询通知下的计划列表。
- 新增计划。
- 修改计划。
- 删除计划。
- 启用或停用计划。
- 手动触发通知。
- 查询计划执行记录。

### 8.3 接收人预览接口

根据项目、岗位、角色及个人接收人配置，返回：

- 最终用户列表。
- 项目成员标识。
- 企微身份绑定状态。
- 预计 `@` 人员。
- 无法接收或无法 `@` 的原因。

## 9. 权限与审计

- 只有具备通知配置权限的用户可以新增、修改、删除或启停计划。
- 手动触发应复用通知发送权限，必要时增加独立权限点。
- 配置修改、计划删除、手动发送均写入操作日志。
- 操作日志记录操作人、操作时间、修改前后内容和执行结果。

## 10. 风险与控制措施

| 风险 | 控制措施 |
| --- | --- |
| 删除时间字段后历史通知筛选范围发生变化 | 升级说明中明确行为变化，并补充回归测试 |
| 清除原用户组后通知没有接收人 | 提供受影响配置清单、待完善状态和无接收人告警 |
| 岗位或角色人数过多 | 校验企微接口人数和消息长度限制，必要时分批处理 |
| 用户未绑定企微身份 | 群消息继续发送，记录部分成功和未匹配人员 |
| 多条计划时间相同导致重复消息 | 配置重复校验和发送幂等控制 |
| 项目成员实时变化导致预览与实际发送不一致 | 页面注明预览仅代表当前状态，发送时重新解析 |
| 调度服务多节点重复执行 | 使用分布式锁和业务幂等键 |

## 11. 验收标准

### 11.1 缺陷解决时间通知

- Markdown 模板所有可用参数均有准确的中文说明。
- 可以新增、修改、删除、启用和停用多条每日或每周计划。
- 多条计划能够独立且准确执行。
- 支持手动触发，并可查询发送结果。
- 页面、接口校验及业务逻辑不再使用开始时间和结束时间。
- 相同通知下的重复启用计划能够被识别和阻止。

### 11.2 测试报告生成通知

- 页面、接口校验及业务逻辑不再使用开始时间和结束时间。
- 选择非项目成员作为个人接收人时，群消息能够补充 `@此人`。
- 未选择个人接收人时，默认 `@` 当前项目成员。
- 重复人员不会被重复 `@`。
- 用户缺少企微身份映射时，发送记录包含明确结果和原因。

### 11.3 所有通知类型

- 原用户组内容被清除且不再参与通知发送。
- 可以从岗位和角色列表中进行多选。
- 实际接收人为岗位和角色对应用户的去重并集。
- 岗位或角色成员变化后，后续通知按最新关系发送。
- 历史配置能够正常加载，不出现页面或接口异常。
- 无有效接收人时，系统能够提示并避免无效发送。

## 12. 建议实施顺序

1. 确认模板参数清单、角色权限域及个人接收人的既有 `@` 规则。
2. 完成通知配置、调度计划、岗位角色关联的数据模型设计。
3. 改造后端配置接口、接收人解析服务和企微发送服务。
4. 实现多计划调度、手动触发、幂等和发送记录。
5. 改造前端通知配置页面和参数中文说明。
6. 编写历史数据处理脚本及受影响配置清单。
7. 完成功能、兼容性、调度准确性和企微发送回归测试。
8. 灰度发布并观察调度任务、发送成功率和未绑定企微身份数据。
