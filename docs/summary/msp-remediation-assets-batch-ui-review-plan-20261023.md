## 一、评审结论建议

1. 先修复影响数据可信度和操作可达性的 P1 问题，再交付资产批量与导出，最后推广 UI。UI 调整不得掩盖同步、导出或接口缺陷。
2. 测试用例、测试计划采用同一套列表、详情、执行事实展示规范。保留紫色品牌，减少大面积紫色链接、重复按钮与空白。
3. 批量操作默认仅作用于明确选中的资产；跨页选择与“全部筛选结果”必须明确区分。删除受引用保护，不连带删除业务项目副本。
4. 附件、执行结果、缺陷、步骤事实由统一读模型提供。定义步骤与实际执行事实分区，不能用作者定义冒充已执行记录。
5. 本文接口名称、字段和数值上限为建议契约，进入实施前按现有公共任务、权限、错误协议落定；不把建议接口当成已经存在。

## 二、14 项问题的具体修复方案

### F01 / REG-UI-01：Agent Token 右侧列不可达（P1）

证据：1908px 视口表格右边界2099，启用/操作列在1858～2098；1366px同样裁切。定位到个人抽屉与表格宽度链，不能通过隐藏操作列规避。

- 修改 `frontend/src/views/setting/system/agentIntegration/index.vue`：按列宽设置数值型最小横向宽度，启用与操作固定右侧，名称弹性截断并可查看全文。
- 检查 `frontend/src/components/business/ms-personal-drawer/index.vue` 至 Card/table 的每层 flex：`min-width:0; width:100%; max-width:100%`，横向滚动归表格可见容器，不归整个抽屉；避免父级裁切滚动条。
- 开关提交中禁用；失败恢复原状态并显示安全原因；停用/删除沿用既有权限和确认流程。
- 验收：1908/1366/1280、长名称、多权限、200%缩放、键盘操作均能看到并触达启用和操作；有数据和空态均验证。

### F02 / REG-ASSET-01：历史资产同步重复失败（P1）

证据：任务1636867424404733952两项持续失败，项目1569980988170592256、1569996467232727040已有枢纽同名根模块但缺少资产目录。源码 `CaseAssetService.upsertCatalog` 的插入及唯一冲突恢复路径与现象高度吻合；**尚未取得服务端异常栈，根因须用 traceId 日志最终确认**。

1. 先按失败任务/项目读取日志，核对模块类型、所属组织、源项目映射、目录、lineage 和已有用例数量，形成只读修复清单。
2. 对可信历史模块补建目录映射；只有组织、项目来源、FOLDER用途匹配时才能复用。同名异源模块不得直接认领，返回可理解冲突或使用带稳定来源标识的内部唯一名称。
3. `prepareHistoricalProject/upsertCatalog` 在一个事务内完成模块、目录及来源映射；并发唯一冲突按规范化名称和可信来源重新查询，禁止仅重查目录后原样抛异常。失败回滚本次新增对象，不删除原有数据。
4. 提供可重复执行的数据修复迁移/管理脚本：预检→备份受影响行→条件更新→校验，记录修复前后ID，支持反向恢复映射；不直接重建全库或清空资产。
5. 仅重试失败项，成功/跳过项不重复复制；通过来源关联与版本确保不新增重复资产。

验收：两失败项目分别成功；同名异源、并发重试、中断后重试、目录已有/模块已有四种组合；核对源/资产/引用数量及ID不丢失。重复运行结果应为更新或跳过。

### F03 / REG-ASSET-02：失败原因不可用（P1）

- `CaseAssetHistorySyncWorker` 记录结构化 `stage/errorCode/projectId/caseId/message/traceId/retryable`。预期异常分类为目录冲突、权限不足、项目已删除、模板缺失、字段不兼容、存储失败、超时；未知异常给安全通用信息，详细堆栈只进日志。
- 项目准备失败也必须记录阶段；不能仅统计0条而丢失原因。失败表按任务+项目/用例分页查询，任务汇总与失败明细同源。
- `frontend/src/views/test-asset/cases.vue` 显示“成功5项、跳过1项、失败2项”，展开失败抽屉，展示对象、阶段、原因、建议、错误编号和重试入口。复制诊断信息需脱敏。
- 旧泛化错误标明“历史记录未保留具体原因，请重试获取”，不伪造诊断；重试形成新记录并保留历史。
- 验收每种可预期错误、未知错误、重试成功/仍失败、分页、无权限及服务断连；页面不展示SQL、类名或堆栈。

### F04 / REG-MCP-01：写工具幂等契约缺口（P1）

- 逐工具建立115项工具契约清单，核对20个缺少requestId的写工具候选；区分通用幂等层与上传/执行等自有状态机，不能一刀切。
- 对通用层强制幂等的工具（已复现 `test_plan.create`）在严格schema加入必填requestId，并在参数解析层传递至通用层；标准客户端无需私自增加HTTP头。
- requestId建议限定长度/字符，按actor+tool+scope隔离；保留相同键相同参数重放、不同参数冲突，头/参数不一致明确拒绝。缓存命中前仍鉴权，撤权后不能重放敏感数据。
- 验收原生 tools/list → 无自定义头创建 → 重放 → 改参冲突；漏键、头参冲突、并发、撤权、状态机工具均覆盖。已有项目/用例创建通过项仅做受影响回归。

### F05 / REG-MCP-02 与 F06 / REG-SYNC-01：执行事实读模型不统一（P1，两项）

证据：同一直接提交含3条乱序/重复事实，REST计划可读完整事实，但MCP只有2条定义步骤且执行值为空；源详情也仅显示两条未执行定义步骤。

- 提取统一有效执行读取服务，复用既有计划 effective execution provider；源详情、计划详情、MCP mapper共同消费 `executionRef/result/executedAt/executionFacts/attachments/defectSummary/caseVersion`。
- 读模型分别返回 `definition.steps` 和 `execution.facts`。事实按实际序号展示，保留重复和额外步骤、前后证据及原始步骤位置；不可覆盖定义或从总体SUCCESS推断每一步成功。
- direct/managed/manual三来源统一排序与“当前执行”选择规则；历史记录不可因源定义更新重写，显示绑定版本及版本差异。
- 前端增加“用例定义 / 当前执行 / 执行历史”，旧执行无事实时显示“该记录未保存步骤事实”；AGENT_REPORTED与STRUCTURE_ONLY_V1保留可理解的来源/校验说明。
- 同步附件以关联ID/文件ID去重并处理解除关联；缺陷以bugId与上下文关系区分；空值、删除、失败执行不能被旧缓存覆盖。
- 验收同一case/version/executionRef下源、计划REST、页面、MCP四端一致；乱序/重复、无执行、旧版本、附件移除、缺陷解除、并发新执行、计划独立执行覆盖规则均测试。

### F07 / REG-REL-01：发布版本不可验证（P2）

检查 `frontend/scripts/write-build-manifest.mjs`、package scripts、实际CI构建命令、镜像COPY及网关。生成清单绑定真实Git SHA、构建时间、index hash及资源清单；无Git信息时构建明确失败或标为unknown，禁止编造SHA。manifest响应application/json、短缓存/不缓存；不存在静态文件返回404，避免SPA HTML200。index短缓存，带hash资源长期缓存。部署后对比Git SHA、清单、index实际引用三者，再运行关键冒烟；不可凭页面看起来更新判断发布完整。

### F08 / REG-MCP-CLIENT-01：连接器缓存旧schema（P1）

服务端用例创建schema已支持requestId而连接器仍缺失，不能重复修改服务端掩盖客户端缓存。刷新/重连测试连接器，核对tools/list版本指纹及必填字段；增加客户端接入自检和schema升级说明，发布后检测旧指纹给出重新连接提示。只重建连接授权，不删除用户Token；密钥不写文档。验收连接器真实创建及重放，确认与原生契约一致。

### F09 / REG-ORG-01：组织成员分页失效（P1）

`OrgStructureMemberController/Service` 将权限校验移至分页开始前，PageHelper紧贴成员Mapper查询，中间不得有用户/权限SQL；使用受控分页作用域并finally清理ThreadLocal。COUNT和列表使用相同组织/部门/搜索条件。响应 `current/pageSize/total/list` 遵循统一分页协议。测试154条数据下1/2/末页、10/20条、不足一页、空搜索、普通成员及拒绝权限；日志核对COUNT与LIMIT仅作用目标SQL。

### F10 / REG-MCP-03：导出非法参数被当内部异常（P2）

`AgentCaseExportTools` 为request增加完整嵌套schema（systemFields等为`{id,name}`对象数组）、数量限制、允许字段和互斥选择校验；DTO转换错误归一AGENT_VALIDATION_ERROR，返回安全字段路径。后端同样校验，不依赖客户端schema。测试字符串数组、null、未知字段、非法ID、空选择及超限；预期错误不记作系统内部故障，合法请求不受影响。

### F11 / REG-EXP-01 与 F12 / REG-EXP-02：导出成功却丢内容（P1，两项）

修正 `FunctionalCaseFileService.parseExcelData2List` 及导出列映射：按稳定字段ID（如num/name）提取值，翻译仅负责列标题，不复用导入表头匹配逻辑。request保存明确locale，异步worker恢复locale并在finally清理；未传语言使用受支持默认语言，缺资源使用安全列名。用例编号num与数据库ID分字段，确保不混淆。支持动态字段按internalFieldKey映射，未知列前置拒绝。任务成功前验证文件非空、行数与有效目标一致，文件下载重新鉴权。验收不传语言/zh-CN/en-US、编号名称非空、0/1/多行、标签/步骤/自定义字段、Excel公式字符转义；读取真实XLSX单元格断言，不能只检查SUCCEEDED。

### F13 / REG-FE-01：缓存计划错误监听其他页面ID（P1）

`frontend/src/views/test-plan/testPlan/detail/index.vue` 的watch和请求入口统一校验当前路由身份、项目、planId；deactivated停止监听/轮询，activated按当前上下文刷新。请求带上下文序号或AbortController，旧响应不得回填新计划；保存中的文档草稿不被后台刷新覆盖，提示服务端更新并允许比较。后端不存在/不属于项目计划按统一not-found/permission错误处理，不返回NPE500。验收计划→用例深链接不发计划请求；A/B快速切换、切项目、返回缓存、慢响应、草稿冲突、计划已删除均覆盖。

### F14 / REG-UI-02：资产空态裁切（P2）

空态放在表格可见viewport或独立覆盖层，宽度不继承1630px最小表格；有数据时列横向滚动，空态不随宽内容居中到屏幕外。统一表格容器规范并检查个人设置、组织、计划、用例及资产同类组件。验收1366/1280、折叠左栏、空/加载/错误/无权限，滚动前即可读完整提示及操作。

## 三、刷新和同步的统一约束

进入或重新激活计划详情立即请求最新数据；页面可见期间按现有刷新机制低频拉取或事件通知，隐藏页面停止，避免每行请求。刷新SLA建议可见页面30秒内，需实测后承诺。标题、列表、统计及详情使用同一上下文版本；只收到更新通知而未取到数据不能显示“已同步”。

源定义字段（名称、步骤、标签、附件关系等）与计划自身数据（计划备注、计划独立执行、计划关联ID）建立字段归属矩阵。源执行和计划独立执行必须有明确优先规则与来源，禁止无差别覆盖。手工“同步状态至测试计划”调用相同领域同步服务，返回任务ID、目标计划、更新/跳过/失败数量及明细；同步范围包含定义、附件、执行、缺陷的新增/变更/解除，不只成功状态。

待明确口径的建议：缺陷数量按唯一bugId统计，关系另展示；带testPlanId的MCP读取采用严格计划上下文，不属于该计划返回明确CASE_NOT_IN_PLAN。若保留补充上下文模式，必须显式contextMatched=false并说明原因。这两项是建议契约，尚未作为确认缺陷统计。

## 四、用例资产批量与导出需求

### 4.1 范围及现状

现有 `cases.vue` 及 `CaseAssetController` 已有单条增改删、目录、导入、历史同步；没有资产批量/导出路由。`CaseAssetSaveRequest`已有tags/customFields，等级须按模板的稳定优先级字段映射；分类的单选规则沿用当前实现，不直接改为多分类。业务项目用例批量接口不得直接绕过资产组织权限复用。

| 操作 | 首期建议行为 | 失败/边界 |
| --- | --- | --- |
| 批量删除 | 预览可删除/被引用/无权限/版本变化数量，二次确认后软删除可删除项 | 被业务项目引用默认阻止删除并展示引用去向；不删副本、附件实体或执行历史；建议增加归档替代 |
| 修改资产分类 | 替换为同组织有效分类；明确“清空分类”选项 | 分类被删除/越权/目标版本变化逐项失败；不允许空表单隐式清空 |
| 修改用例等级 | P0/P1/P2/P3，以目标模板稳定字段标识存储 | 模板不支持/字段非法展示具体对象；不依赖中文字段名 |
| 修改标签 | 增加、移除、替换三模式；默认增加 | 替换提示会覆盖旧标签；去重、数量/长度限制；空替换需再次确认 |
| 批量导出 | 选中项或全部筛选结果，默认XLSX；可选字段和语言 | 独立导出权限；无权限项排除并告知；无合法目标拒绝；文件下载鉴权 |
| 归档/恢复（建议补充） | 从可选资产中移除但保留历史引用，支持恢复 | 不改已导入业务项目副本；恢复时重新校验目录和权限 |

跨目录移动、批量复制、XMind导出、附件打包放第二期，避免首期扩大来源/引用改造；资产批量操作不提供“改执行成功”等修改业务执行事实功能。

### 4.2 选择及交互

表头复选框默认“选择本页”，选中后出现工具条与已选数量。跨页保留同目录选择；切组织/目录清空，搜索或筛选变化提示重新选择。另有“选择全部筛选结果N条”，与本页选择分开确认；服务端冻结目标ID和版本、生成selectionToken，新增数据不自动纳入，排除项可追踪。

执行前预览目标数量、修改前后值、受影响引用和不可处理项；0条禁用，提交中防重复。首期建议同步预览最多1000项、大量任务每批100项串行处理，超过上限提示缩小范围；最终上限用小规模性能验证调整。不得一次把全部对象放入浏览器。

任务可查看进度和失败明细，取消只停止尚未执行项，已成功项不自动回滚；重试只针对失败且重新鉴权的项。网络断开后凭requestId查任务，不重新创建。结果明确成功/失败/跳过，部分成功不展示全绿“成功”。

### 4.3 建议接口与数据契约

建议在`/case-asset`下新增，不冒充现有API：

| 建议接口 | 责任 |
| --- | --- |
| POST /case/batch/preview | 接收catalogId、选择条件、operation、patch；鉴权后冻结目标，返回previewId、版本、数量和影响 |
| POST /case/batch/jobs | 接收previewId、requestId与确认内容；再次鉴权、校验版本，建立持久任务 |
| GET /case/batch/jobs/{jobId} | 进度及分项分页；仅创建人或授权管理员可读 |
| POST /case/batch/jobs/{jobId}/retry、/cancel | 仅失败项重试/停止未执行项，遵守状态机及幂等 |
| POST /case/export/jobs | 接收选择快照、字段ID、locale、格式，创建导出任务 |
| GET /case/export/jobs/{jobId}、/{jobId}/download | 状态及安全下载，重新校验资产范围和文件有效期 |

统一错误沿用现有协议，含安全message、业务code、可选details/traceId。按CASE_ASSET_UPDATE/DELETE分别授权；新增CASE_ASSET_EXPORT需迁移角色权限，默认不自动向所有人开放。预览、执行、重试、下载都校验组织、目录和每条资产，不因底层defaultHub项目可读而放开整库。

优先复用已存在的持久任务/分项/导出设施，通过资产scope适配器限定目标；确需新增表时迁移包含组织、操作者、选择快照、操作参数、幂等键、状态、计数、租约/恢复信息及分项版本/失败原因，唯一键覆盖组织+操作者+operation+requestId。逐项事务、乐观锁、审计前后值，进程重启可恢复且不重复执行。审计与导出文件按现有保留策略清理。

资产被源项目再次同步时，人工批量编辑字段必须有本地覆盖标志和字段来源；默认保留人工覆盖，可显式“恢复跟随来源”。源内容变化生成待比较状态，不能静默覆盖。资产改动不自动改写已导入业务项目副本；引用关系展示来源和版本。

### 4.4 导出验收

默认列：用例编号、名称、目录、分类、等级、标签、前置条件、步骤、预期、建立方式、来源项目、引用数、更新时间；数据库内部ID可选。结构化步骤采用可还原文本/独立明细sheet，附件首期只导出受控关联信息，不公开永久下载地址。无语言头也有正常标题；编号不空、行数正确、文本不变公式。选中3条应只导出3条；全筛选含排除项、空结果、删除/撤权发生在排队期间、文件过期和超大任务均验证。

## 五、UI 优化意见与 Demo 阅读方式

### 5.1 共用规范

- 保留紫色作为主操作/选中态，普通文本用深灰，成功/警告/失败只表达状态，减少所有名称都紫色造成的噪声。
- 页面标题、项目上下文、主操作放同一层；次要动作归更多菜单。搜索/筛选一行，选中后出现批量工具条，避免常驻大量按钮。
- 左目录固定合理宽度并可折叠；中间内容`min-width:0`；表格自身横向滚动，名称和操作固定，名称支持全文查看。分页和批量条位于可见区域。
- 统一8px间距、40px交互控件、清楚的表头/悬停/选中态；加载、空、无权限、失败有独立提示。颜色之外用文字识别状态，焦点清晰，支持键盘和缩放。
- 1366/1280可用，较窄时筛选折行；不缩小到难读，也不把关键操作挤出视口。避免首屏放多张无决策价值统计卡。

### 5.2 测试用例试点

目录+高密度列表保留；标题下显示数量，筛选与批量工具条合并。列优先级：编号/名称/等级/执行状态/缺陷/附件/更新时间，低频字段可配置。点击名称打开详情侧栏，定义与执行事实分区；执行来源和版本可见。源变更同步状态用简短提示，失败可展开。

### 5.3 测试计划试点

列表展示计划名、进度、通过率、负责人、最近更新，详情顶部简洁展示进度及最新同步时间。详情内保留用例、缺陷、文档、历史入口，当前用例与执行事实同屏。后台刷新不闪空列表、不覆盖草稿；正在取最新值时显示状态，失败保留上次数据并标“更新失败”。生成报告继续隐藏。

### 5.4 Demo 可操作内容及边界

左侧切换三个模块；搜索、状态筛选、目录切换、选择本页、批量修改等级/分类/标签、删除确认、打开详情、切换定义/执行、模拟计划刷新、资产失败原因、示例CSV下载。原型使用CSV仅便于无依赖演示，**正式需求仍为异步XLSX**；原型只模拟状态，不能替代MCP/后端/权限验收。
