# MeterSphere 前端信息架构与权限收口前后端闭环补齐方案

> 版本：V1.2

## 1. 自检方法

本次不以“页面能打开”作为完成标准，而是对每项需求执行以下闭环核对：

1. 需求条款和验收标准。
2. 路由、菜单、Tab、按钮等前端入口。
3. 前端 API 封装与请求参数。
4. Controller 路由、后端鉴权、Service 校验和事务。
5. Mapper/SQL 的分页、数据范围和幂等约束。
6. 回归脚本、单元测试和编译/类型检查。

## 2. 复检结论

### 2.1 已形成前后端闭环

| 需求 | 前端 | 后端/数据 | 结论 |
|---|---|---|---|
| 项目列表 | 独立路由、搜索、状态、分页、复制 ID、成员预览、添加成员、进入项目 | `/project/page` 服务端分页、可访问项目过滤、成员聚合、项目切换二次鉴权 | 已闭环 |
| 角色权限 | 角色列表、新增/编辑/删除/启停、权限矩阵、中文化、变更摘要、未保存提示 | 原子保存、范围白名单、依赖规范化、管理员保护、删除影响和事务删除 | 已闭环 |
| 成员角色迁移 | 成员角色可查看、编辑、禁用和删除 | 幂等迁移、关系去重、管理员跳过、权限初始化和审计 | 已闭环 |
| 跨项目用例资产 | 项目/用例双层分页、只读列表、深层查看先切项目 | `/functional/case/asset/page` 同时校验项目可访问性与用例查询权限 | 已闭环 |
| Agent 集成 | Agent 模块内唯一入口、统一命名、机器人图标 | Token/安装包/接入类接口均有 Agent 集成页调用 | 已闭环 |

### 2.2 发现的实质偏差

#### 偏差 A：角色成员管理只存在后端

- 数据库权限资源已登记 `PERMISSION_ROLE_ASSIGN_MEMBER_BUTTON`。
- 后端已实现角色成员列表、添加、移除接口。
- 当前角色列表和角色编辑页均没有成员入口，导致非迁移场景无法通过新权限控制页维护“用户—角色”关系。
- 后端成员列表虽接收分页参数，但 Controller 未启动分页且只返回 `List`，不符合列表闭环要求。

#### 偏差 B：新增/改造页面的 UI 权限资源未完整接入

- 项目列表已改为新路由，但旧 `PROJECT_LIST_PAGE.route_name` 仍指向项目基本信息路由，新路由也未绑定 `resourceCode`。
- 测试资产/用例资产没有完整的菜单、页面、项目 Tab、系统 Tab 资源，与“系统页预留独立权限资源”存在偏差。
- Agent 的五个顶层页面依赖旧接口权限，未进入新 UI 权限树；“Agent 集成”因而无法被角色单独配置页面可见性。

#### 偏差 C：关联接口权限的中文主体可能取错

- 当前操作名已中文化，但 UI 资源行使用“页面/按钮名称”作为接口权限主体。
- 例如 `SYSTEM_USER:READ` 应优先使用后端权限定义中的“系统用户”，而不应因挂载资源不同显示为“新增用户按钮：只读”。

## 3. 补齐实现方案

### 3.1 角色成员闭环

1. 角色列表增加“成员”入口，仅系统范围角色可维护全局成员关系。
2. 成员弹窗提供服务端分页、名称/邮箱搜索、添加和移除。
3. 添加成员候选项通过权限控制专用接口获取，前端不再依赖已下线的用户组页面 API 封装。
4. 管理员角色成员允许查看，但在本页禁止添加和移除；后端同样强制保护。
5. 后端对角色存在性、全局范围、系统角色类型和管理员保护进行二次校验。

### 3.2 UI 权限资源闭环

1. 新增幂等 DML，登记测试资产、用例资产项目/系统 Tab、Agent 五个页面资源。
2. 更新 `PROJECT_LIST_PAGE` 的 `route_name`，使其指向实际项目列表路由。
3. 所有对应路由绑定 `resourceCode`，内层用例资产 Tab 绑定各自的 Tab 可见性。
4. 兼容规则仍生效：旧角色未配置 UI 资源时不因空配置被全部拒绝；配置后同时受 UI 权限和接口权限限制。

### 3.3 权限中文化闭环

1. 从完整数据权限定义构建“权限编码主体 → 中文业务名称”字典。
2. UI 资源的“关联接口权限”优先使用该字典，再由集中操作映射输出“系统用户：只读”类文案。
3. 资源名称中的 `Tab/Page/Button/API` 后缀统一显示为“页签/页面/按钮/接口”；未知编码仍显示“未配置中文名称”并警告。

## 4. 不判定为偏差的单边实现

| 项目 | 原因 | 处理 |
|---|---|---|
| 旧用户组 Controller、数据表和关系 | V1.0 明确要求迁移观察期保留，用于回滚与核对 | 保留后端，不恢复前端入口 |
| 角色旧分步保存接口 | V1.1 明确仅作兼容，新页必须使用原子保存 | 后端保留；移除新页未使用的前端封装，防止误用 |
| 按组织岗位自动分配角色接口 | 为既有的高级自动分配预留能力，本次需求只要求角色成员的查看、手工添加和移除 | 保留后端兼容接口；不作为已交付的前端业务能力，后续如启用需单独立项 |
| 流程控制的部分预留接口 | V1.0 第 9 节明确“流程控制全部未完成项重做”不在本次范围 | 保留现有后端，不扩大本次前端范围 |
| 用例资产/系统无业务查询接口 | V1.0 明确第一期置空且不加载业务数据 | 保留可进入空页与独立 UI 权限资源，不新增伪后端逻辑 |
| 数据迁移和迁移审计无前端页 | 属于部署阶段、一次性可重入的运维能力，不是用户业务入口 | 保留 SQL/运行时初始化和审计，不新增页面 |

## 5. 验证标准

1. 角色页能查看系统角色成员，普通系统角色能添加和移除成员，管理员仅可查看。
2. 成员列表服务端分页；非系统角色、管理员变更、越权请求均被后端拒绝。
3. 权限资源树包含项目列表、测试资产/用例资产及 Agent 页面，路由与资源编码一一对应。
4. 用例资产“项目”和“系统”分别受独立 Tab 权限控制，系统页仍不发起业务查询。
5. 角色页不展示 `MENU`、`Tab`、`SYSTEM_USER:READ` 等英文业务文案。
6. 前端类型检查、路由/资源静态回归、后端目标模块编译和权限服务定向测试全部通过。
