# 执行事实加密密钥部署与验收

适用 E01。代码继续拒绝无密钥的敏感事实写入，不降级为明文。此文档不表示测试环境已经配置。

1. 由部署管理员在受控密钥库生成并保存 32 字节随机密钥的 Base64；不要存入仓库、构建参数日志、测试截图或聊天。
2. 在应用运行环境注入 `AGENT_EXECUTION_FACTS_KEY`，对应 Spring `agent.execution.facts-key`。现有 `deploy/*verify.compose.yml` 已由 `QUALITY_FACTS_KEY` 注入此变量。所有应用实例必须使用相同密钥。
3. 登录具有 `AI_EXECUTION:READ` 权限的账号，查询 `GET /ai/recovery/status/facts-readiness`，只返回 ready 和安全状态码；它不验证历史密文能否解密，不能替代后续验收。
4. 密钥必须与数据库备份一同受控备份；已有 `factenc:v1:` 数据依赖原密钥，不可直接替换。当前格式没有 keyId，轮换须另立迁移方案。
5. 滚动重启后，用隔离测试用例提交含敏感键的事实，确认成功持久化且数据库值为 `factenc:v1:`；列表、详情和 MCP 响应只显示脱敏值；验证服务能够解密并校验。不得将真实密码作为测试数据。
6. 验证缺失、非法 Base64、解码非32字节时返回 `QUALITY_FACTS_KEY_NOT_CONFIGURED`；错误响应不得泄露密钥。配置不正确时停止本项验收，保留原密钥恢复服务。

本轮未访问部署密钥库或变更测试环境配置；敏感事实端到端验收仍待部署步骤完成。
