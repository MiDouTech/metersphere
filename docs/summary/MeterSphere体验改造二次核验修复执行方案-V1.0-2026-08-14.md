## 2. 二次核验结论

当前公共错误基础设施已经建立，但不能据此认定业务闭环完成。主要问题如下：

| 编号 | 问题 | 类型 | 优先级 | 当前状态 |
| --- | --- | --- | --- | --- |
| R01 | 对象级校验错误被强制转换为 `FieldError`，可能由 400 变为 500 | 后端边界缺陷 | P0 | 本批修复 |
| R02 | 静态资源 `EofException` 返回空 500，无请求编号和错误体 | 后端协议缺口 | P0 | 本批修复 |
| R03 | 通用 `api.businessError` 覆盖安全、具体的业务文案 | 前后端语义偏差 | P0 | 本批修复 |
| R04 | 用户字段错误同时触发全局 Toast 和表单回填 | 前端反馈冲突 | P0 | 本批修复 |
| R05 | 任意旧 `messageDetail` 对象可能被误判为字段错误 | 前端兼容缺陷 | P0 | 本批修复 |
| R06 | 字段错误仅接入系统用户，项目、计划、缺陷未接入 | 前端入口不足 | P0 | 已完成 |

## 3. 统一完成定义

每个问题只有同时满足以下条件才可关闭：

1. 后端接口具有稳定请求、响应和错误契约。
2. 前端 API 类型与后端 DTO 一致，不依赖非白名单字段猜测。
3. 至少一个真实业务页面完整接入；需求指定的首批页面必须全部接入。
4. 加载、成功、校验失败、权限失败、服务失败、重试和并发状态均有明确反馈。
5. 同一错误只出现一个主要反馈渠道。
6. 单元测试、组件测试或 E2E 能阻止同类问题回归。
7. 静态检查不得只验证字符串存在，还要验证调用、HTTP 方法和响应消费。

## 4. 批次 1：错误协议可靠性修复

### 4.1 后端

- 校验异常分别处理 `FieldError` 与对象级 `ObjectError`。
- 字段错误写入 `fieldErrors`；对象级错误写入白名单上下文或稳定的 `_global` 字段。
- 所有 4xx/5xx，包括静态资源断连，都返回结构化错误和 `X-Request-ID`。
- 认证、授权及未知异常继续使用安全文案，不返回异常消息。
- 日志保留请求编号、方法、路径、用户、组织和项目。

### 4.2 前端

- 只有“键和值均为字符串”的旧 Map 才允许兼容转换为 `fieldErrors`。
- `api.businessError` 保留后端安全业务文案；具体稳定 Key 仍优先国际化。
- 表单自行消费字段错误时使用 `errorMessageMode: 'none'`。
- 网络异常继续统一为 `AppError`。

### 4.3 测试

- 字段级校验错误返回 400 和 `fieldErrors`。
- 对象级校验错误不会转成 500。
- 静态资源 `EofException` 也具有请求编号。
- 401、403 不包含 Shiro 信息。
- 业务错误不会被通用文案覆盖。

### 4.4 验收

- 任意异常响应均可通过请求编号检索。
- 字段错误不会重复显示 Toast。
- 旧详情对象不会被误标成表单字段。

## 5. 批次 2：真实页面和权限入口闭环

### 5.1 字段错误首批页面

- 创建、编辑项目。
- 创建、编辑用户。
- 创建测试计划。
- 新建、编辑缺陷。

每个页面必须关闭自动 Toast，调用 `useServerFieldErrors`，支持字段映射、首错聚焦及输入后清除单字段错误。

### 5.2 局部错误组件

将 `MsErrorNotice` 接入项目列表、用户和用户组、任务中心、接口执行结果。重试必须复用原查询参数，成功后清除错误。

### 5.3 权限入口

- 为岗位分配规则补充前端 API、角色编辑入口和规则回显。
- 403 响应携带可公开的缺失权限码和来源路径。
- 无权限页展示缺失权限、返回入口，并保留授权后返回路径。
- 若单角色详情接口确认无调用价值，则标记废弃并在兼容版本后删除。

## 6. 批次 3：执行结果草稿闭环

### 6.1 数据模型

新增 `test_plan_case_execution_draft`，至少包含计划用例、用户、草稿内容、版本、更新时间和过期时间；对“计划用例 + 用户”建立唯一约束。

### 6.2 接口

```text
GET    /test-plan/case/{id}/execution-draft
PUT    /test-plan/case/{id}/execution-draft
DELETE /test-plan/case/{id}/execution-draft
POST   /test-plan/case/{id}/execution-submit
```

- PUT 使用乐观锁版本号。
- 提交与删除草稿在同一事务中完成。
- 冲突返回稳定错误码、最新版本和更新时间。
- 删除计划用例时同步清理草稿。

### 6.3 页面

- 实际结果、步骤状态、备注和附件变化后防抖保存。
- 展示未保存、保存中、已保存、失败和冲突状态。
- 刷新后提示恢复草稿。
- “通过并下一条”必须等待保存与正式提交成功。

## 7. 批次 4：统一异步任务与批量结果

### 7.1 统一任务

提供任务摘要、详情、取消、失败项重试和失败明细接口；状态统一为 `QUEUED`、`RUNNING`、`SUCCESS`、`PARTIAL_SUCCESS`、`FAILED`、`CANCELED`。

前端新增 `useAsyncTask` 与 `MsAsyncTaskStatus`，首批接入功能用例导入导出、接口与场景执行、文档解析和报告生成。

### 7.2 批量结果

后端统一返回总数、成功数、失败数、跳过数和逐项失败原因；前端新增 `MsBatchResult`，支持查看、复制、下载失败明细及仅重试可重试项。

首批接入任务停止、任务删除、用户导入、用例移动删除和缺陷批量修改。

## 8. 批次 5：危险操作与存量治理

- 删除计划、项目、用户、批量用例以及停止任务均先查询影响范围。
- 新增统一 `MsDangerConfirm`，展示对象、影响数量、运行任务、可恢复性和明确动作名称。
- 高风险操作要求输入对象名称。
- UI 一致性基线按具体位置记录，只允许减少。
- 逐步清理固定宽度、中文硬编码、非语义点击元素、缺少可访问名称和 `console.log(error)`。

## 9. 测试与发布策略

| 层级 | 必测内容 |
| --- | --- |
| 后端单元测试 | 错误映射、草稿乐观锁、任务状态映射、批量逐项结果、影响评估 |
| 前端单元测试 | `AppError`、字段错误绑定、任务轮询停止条件、批量结果计算 |
| 组件测试 | 错误诊断复制、重试、保存状态、危险操作确认 |
| E2E | 项目/用户/计划/缺陷校验、草稿恢复、部分成功、权限失败、影响确认 |
| 视觉回归 | 中英文、1366/1440/1920、加载/空/失败/无权限 |

错误协议先双读，记录旧协议命中；命中归零后删除 `messageDetail` 猜测。草稿、统一任务和批量结果使用功能开关灰度发布。

## 11. 最终验收门槛

- 不存在需求指定 UI 能力只有前端占位或只有后端接口。
- 主要业务错误均有稳定 Key，未知异常完全脱敏。
- 执行内容刷新不丢失，批量部分成功可见且可重试。
- 危险操作执行前展示真实影响。
- 前端全量类型检查、后端相关模块测试、闭环检查和视觉回归全部通过。
