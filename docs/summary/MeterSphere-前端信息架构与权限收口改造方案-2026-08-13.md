# MeterSphere 前端信息架构与权限收口改造方案

> 文档版本：V1.0  
> 基线日期：2026-08-13  
> 状态：已确认，作为本次实现与验收基线  
> 优先级说明：本文档覆盖历史方案中与本次需求冲突的内容；未冲突部分继续参考既有权限控制重构方案。

## 1. 背景与目标

当前系统存在模块导航与页面内部重复展示同名 Tab、项目管理入口直接进入当前项目设置、新旧权限控制体系混用、用户组与权限角色职责重叠、Agent 集成重复入口、项目用例与跨项目用例资产边界不清等问题。

本次改造目标如下：

1. 每个模块只保留一套同层级导航，消除重复 Tab。
2. 项目管理恢复为“项目列表 → 进入项目”的两级结构。
3. 权限控制统一使用角色模型，不再在角色设置中嵌入旧用户组权限组件。
4. Agent 集成只保留 Agent 模块内入口，并统一名称和图标。
5. 测试用例恢复为当前项目内的用例管理页面。
6. 测试资产新增跨项目只读的用例资产入口。
7. 旧用户组中的非管理员成员统一迁移到新建“成员”角色。

## 2. 实施原则

### 2.1 单一导航原则

- 全局顶栏已经展示模块子路由时，页面内容区不再重复渲染同名 Tab。
- 页面内部仅保留业务维度必需的二级 Tab。
- 路由必须保留，可刷新、可收藏、可被权限控制。

### 2.2 上下文边界原则

- “测试用例”属于当前项目上下文，可创建和编辑当前项目用例。
- “测试资产 / 用例资产”属于跨项目资产视角，第一期只读。
- “项目管理”首页不依赖当前项目，进入具体项目后才切换项目上下文。

### 2.3 单一权限模型原则

- 角色负责权限，成员关系负责用户与角色的关联。
- 用户组不再承担系统级权限配置职责，系统级用户组入口下线；组织/项目成员分组暂保留为人员归属能力，不再作为本次角色权限入口。
- 前端显示、前端操作和后端接口都必须校验权限；前端隐藏不能代替后端鉴权。

### 2.4 兼容与可回滚原则

- 旧路由在观察期内通过重定向兼容。
- 旧用户组数据先保留并标记迁移，不立即物理删除。
- 数据迁移要求幂等、可审计、可重复验证。

## 4. 详细需求

### 4.1 测试资产去除重复 Tab

#### 4.1.1 页面规则

- 保留全局顶栏中的“业务文档、资产版本、关联追溯、用例资产”。
- 删除三个现有页面内容区的同名 Tab。
- 页面内容从页面标题、说明、筛选区和数据区开始。
- `/test-assets` 默认进入 `/test-assets/documents`。

#### 4.1.2 验收

- 任一测试资产页面只出现一套模块 Tab。
- 切换顶栏 Tab 后 URL、页面内容和选中状态一致。

### 4.2 项目管理改为项目列表首页

#### 4.2.1 列表字段

| 字段 | 展示与交互 |
|---|---|
| 进入项目 | 行首主操作，点击后切换组织和项目上下文 |
| 项目 ID | 完整展示或省略展示，支持复制 |
| 项目名称 | 支持模糊搜索 |
| 成员 | 显示成员数，悬浮展示前若干成员 |
| 状态 | 启用、禁用 |
| 描述 | 超长省略，悬浮展示完整内容 |
| 创建人 | 显示用户名称 |
| 创建时间 | 默认按创建时间倒序 |
| 操作 | 添加成员、进入项目；其他管理操作继续受权限控制 |

#### 4.2.2 筛选与分页

- 支持项目名称或项目 ID 搜索。
- 支持状态筛选。
- 使用服务端分页，不一次加载全部项目。
- 只返回当前用户有权查看或进入的项目。

#### 4.2.3 进入项目

1. 若项目所属组织与当前组织不同，先切换组织。
2. 切换项目并刷新登录态、项目权限和项目菜单配置。
3. 进入用户在该项目中第一个有权访问的业务页面。
4. 不允许通过篡改项目 ID 越权进入项目。

#### 4.2.4 路由

- 新首页：`/project-management/projects`。
- `/project-management` 重定向到项目列表。
- 原项目设置路由在观察期内保留，进入具体项目后仍可使用。

### 4.3 权限控制统一为角色设置

#### 4.3.1 角色列表

“系统设置 / 系统 / 权限控制 / 角色设置”首先展示角色列表，不再嵌入旧 `SystemUserGroup` 页面。

| 字段 | 说明 |
|---|---|
| 角色名称 | 中文名称 |
| 权限范围 | 系统、组织或项目 |
| 启用状态 | 管理员固定启用，普通角色可修改 |
| 编辑 | 管理员仅可查看，其他角色可进入编辑页 |

页面支持：

- 新增角色。
- 按名称搜索角色。
- 查看角色。
- 编辑普通角色。
- 删除普通角色。
- 启用或禁用普通角色。

#### 4.3.2 管理员角色

- 系统默认存在。
- 不可改名、不可编辑、不可删除、不可禁用、不可修改权限。
- 前端按钮状态与后端接口必须双重保护。
- 允许以只读方式查看管理员权限。

#### 4.3.3 成员角色

- 数据迁移时新建一个“成员”角色。
- 初始权限与管理员的当前权限完全一致。
- “成员”不是受保护角色：可以查看、编辑、删除和禁用。
- 后续管理员可按实际需要自行缩减成员角色权限。
- 成员角色即使初始具有全部普通业务权限，也不能绕过管理员角色保护规则。

#### 4.3.4 角色编辑页

角色编辑页包含：

1. 基础信息：角色名称、权限范围、启用状态、描述。
2. 权限树：按系统模块和页面层级组织。
3. 权限矩阵：页面可见、Tab 可见、按钮可见、按钮可操作及数据操作权限。
4. 保存前展示或计算变更，离开未保存页面时提示。

权限能力至少覆盖：

- 页面可见性。
- Tab 可见性。
- 按钮可见性。
- 按钮可操作性。
- 查询、创建、编辑、删除、恢复。
- 添加成员、邀请成员、移除成员、编辑成员。

依赖规则：

- 编辑、删除、恢复等写权限依赖查询权限。
- 按钮可操作依赖按钮可见。
- 子资源可见依赖父页面可见。
- 取消父权限时，界面明确展示对子权限的影响。

#### 4.3.5 权限中文化

数据库和接口可继续使用稳定英文编码，但所有用户可见文本必须通过统一字典转换为中文。

| 原始编码 | 中文显示 |
|---|---|
| `MENU` | 菜单 |
| `PAGE` | 页面 |
| `TAB` | 页签 |
| `BUTTON` | 按钮 |
| `SYSTEM_USER:READ` | 系统用户：只读 |
| `SYSTEM_USER:READ+UPDATE` | 系统用户：查看、编辑 |
| `FUNCTIONAL_CASE:ADD` | 测试用例：创建 |
| `PROJECT_USER:DELETE` | 项目成员：移除 |

要求：

- 资源类型、资源名称、接口权限名称和操作名称均显示中文。
- 未识别编码显示“未配置中文名称”，并记录日志，不直接把英文编码作为正常业务文案。
- 中文映射集中维护，禁止页面分散硬编码同一权限编码。

#### 4.3.6 用户组入口处理

- 隐藏“系统设置 / 系统 / 用户组”菜单入口。
- 权限控制页面不再引用旧用户组组件。
- 旧用户组接口和数据在迁移观察期内保留，供回滚与核对。
- 若其他业务仍需要人员分组，后续应以“成员分组”能力独立设计，不再承载权限。

### 4.4 旧用户组向成员角色迁移

#### 4.4.1 迁移规则

1. 识别并保留所有管理员角色及其成员关系。
2. 新建“成员”角色（稳定 ID：`permission_member`）；若已存在则复用，迁移必须幂等；旧内置 `member` 仅作为系统兜底空权限组，不在权限控制角色列表展示。
3. 将旧用户组角色中的所有非管理员成员统一合并到“成员”角色。
4. 一个用户属于多个非管理员用户组时只生成一条成员角色关系。
5. 同时属于管理员和非管理员用户组的用户，以管理员身份为准，不再重复赋予成员角色。
6. “成员”角色的初始接口权限和 UI 资源权限复制管理员当前权限。
7. 旧非管理员用户组不逐个创建同名角色。
8. 旧数据迁移后标记为已迁移或停用，不立即物理删除。

#### 4.4.2 删除成员角色

- 无关联用户时允许直接删除。
- 有关联用户时展示受影响人数并二次确认。
- 确认删除后解除成员关系，再删除角色。
- 删除后没有其他角色的用户保留账号，但默认无业务权限。
- 不得自动将失去角色的用户提升为管理员。

#### 4.4.3 审计要求

迁移日志至少记录：

- 旧用户组 ID、名称和原成员数量。
- 去重后的迁移用户数量。
- 因管理员身份而跳过的用户数量。
- 失败用户及失败原因。
- 新成员角色 ID。
- 执行时间和迁移版本。

### 4.5 Agent 导航收口

- 删除系统设置中独立的“Agent 集成”入口。
- 保留 Agent 模块内原“接入配置”页面。
- 将“接入配置”统一重命名为“Agent 集成”。
- 删除 Agent 各页面内容区的重复模块 Tab，保留全局顶栏 Tab。
- Agent 左侧菜单使用机器人/AI 图标，图标尺寸、颜色和对齐方式与其他一级菜单一致。
- 所有“请前往接入配置”类提示同步改为“请前往 Agent 集成”。
- `/agent/access` 路由继续兼容。

### 4.6 测试用例恢复项目维度

- “测试用例 / 用例”页面取消“项目、系统”维度 Tab。
- 用例列表、模块树和回收站只读取当前项目数据。
- 保留“执行用例、XMind 用例”等原有业务 Tab。
- 移除 URL 中 `dimension=system` 的业务含义；历史地址进入时自动回到项目维度。
- 没有当前项目时展示项目选择提示，不查询跨项目或系统数据。

### 4.7 测试资产新增用例资产

#### 4.7.1 页面结构

- 测试资产顶栏新增“用例资产”。
- 用例资产页面下保留两个业务二级 Tab：“项目、系统”。
- 默认进入“项目”。

#### 4.7.2 项目页

- 读取当前用户有权访问的所有项目的测试用例。
- 第一阶段按项目分组展示，不一次性加载全部项目的全部用例。
- 先分页查询项目，再按所选项目分页查询用例。
- 数据权限为“用户可访问项目集合”与“对应项目用例查询权限”的交集。
- 页面第一期只读；查看或编辑类深层操作应先切换到目标项目，再进入项目用例页面。

建议字段：用例 ID、用例名称、所属项目、所属模块、用例等级、标签、创建人、更新人、更新时间、状态和查看操作。

#### 4.7.3 系统页

- 页面允许正常进入。
- 第一阶段不加载业务数据。
- 展示标准空状态：“系统级用例资产暂未开放”。
- 预留独立路由状态和权限资源，便于后续扩展系统公共用例库。

## 5. 接口与数据要求

### 5.1 项目列表

- 接口使用服务端权限过滤、搜索、排序和分页。
- 返回列表展示所需的成员数量、创建人和状态，不由前端逐行发起 N+1 查询。
- “进入项目”和“添加成员”继续执行后端权限校验。

### 5.2 跨项目用例资产

- 不接受前端自行提交任意项目 ID 后直接返回数据。
- 后端必须确认当前用户对目标项目具有用例查询权限。
- 列表 count 与分页查询必须使用相同权限条件。

### 5.3 角色与权限

- 角色 CRUD、启停、权限保存必须由后端保护管理员角色不可变规则。
- 权限保存支持接口权限和 UI 资源权限的统一提交或原子事务处理。
- 删除角色时成员关系处理必须明确且事务一致。

## 6. 兼容迁移策略

### 6.1 路由兼容

- 旧项目管理首页重定向到项目列表。
- `/agent/access` 保持不变，仅更新显示名称。
- 带 `dimension=system` 的测试用例历史链接回落到项目维度。

### 6.2 权限兼容

- 已迁移资源以新 UI 权限与接口权限共同生效。
- 未迁移资源在观察期内继续走旧接口权限，不能因空 UI 配置误拒绝全部访问。
- 管理员保护规则不依赖权限编码，使用稳定的内置角色标识在后端强制执行。

### 6.3 数据回滚

- 迁移前不删除旧用户组及旧成员关系。
- 回滚时可停用新“成员”角色并恢复旧入口。
- 迁移脚本重复执行不得重复创建角色或成员关系。

## 7. 实施范围与任务映射

| 需求 | 前端 | 后端/数据 | 核心验证 |
|---|---|---|---|
| 测试资产重复 Tab | 删除页面内公共 Tab，调整默认路由 | 无 | 每页只显示一套 Tab |
| 项目管理列表 | 新列表页、搜索、操作、路由 | 权限过滤分页及聚合字段 | 进入项目后权限立即刷新 |
| 角色设置 | 角色列表、详情/编辑、权限矩阵 | CRUD、管理员保护、权限保存 | 管理员不可变，普通角色可维护 |
| 用户组迁移 | 隐藏旧入口 | 新建成员角色并合并成员 | 去重、幂等、权限一致 |
| Agent 收口 | 删除重复 Tab、改名、图标 | 无或权限资源名称更新 | 只保留一个入口和一套 Tab |
| 测试用例恢复 | 删除项目/系统维度 Tab | 查询固定当前项目 | 不再出现系统维度 |
| 用例资产 | 新页面、项目/系统 Tab | 跨项目授权查询 | 只读且不越权 |

## 8. 验收标准

### 8.1 导航与页面

- 测试资产和 Agent 页面不再出现双重同名 Tab。
- Agent 只保留模块内“Agent 集成”，且一级菜单显示机器人图标。
- 项目管理点击后首先显示项目列表。
- 测试用例页面不再显示“项目、系统”Tab。
- 测试资产存在“用例资产”，其“系统”页可进入并为空。

### 8.2 权限

- 权限列表不向普通用户显示 `MENU`、`SYSTEM_USER:READ` 等原始英文表达。
- 管理员角色前后端均不可编辑、删除、禁用和修改权限。
- 成员角色初始权限与管理员一致，且可以查看、编辑、删除和禁用。
- 删除有关联用户的普通角色必须提示影响并按确认结果处理。

### 8.3 数据迁移

- 所有旧非管理员用户组成员均进入同一个“成员”角色。
- 多用户组成员关系去重。
- 管理员不重复迁移为成员。
- 重复执行迁移不会产生重复角色或重复成员关系。
- 迁移结果可通过审计记录核对。

### 8.4 安全与性能

- 项目列表和跨项目用例列表不存在越权查询。
- 后端接口不能通过绕过前端修改管理员角色。
- 项目列表不产生逐行成员查询。
- 跨项目用例按项目和用例分别分页，不进行全库一次性加载。

## 9. 明确不在本次范围内

- “用例资产 / 系统”公共用例库的实际业务数据与编辑能力。
- 删除旧用户组表和历史关系数据。
- 流程控制全部未完成项的重做；本次保证其与角色设置解耦，既有流程控制按原专项方案继续演进。
- 一次性完成全系统所有历史按钮的 UI 权限迁移；本次新增和改造页面必须接入，其他模块继续按迁移清单推进。

## 10. 实现偏差控制

开发和评审必须遵循以下规则：

1. 每个提交项都对照第 7 节任务映射和第 8 节验收标准。
2. 如代码现状与本文档冲突，以本文档为准；无法实现时先更新方案并确认，不得静默改变需求。
3. 特别禁止将旧非管理员用户组逐个迁移成同名角色。
4. 特别禁止把“成员”实现成与管理员一样不可维护的内置保护角色。
5. 特别禁止仅在前端保护管理员角色。
6. 完成后输出逐条验收记录、未完成项和已知风险。

## 11. 本次实施记录（2026-08-13）
