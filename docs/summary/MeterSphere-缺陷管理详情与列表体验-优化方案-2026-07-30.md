# MeterSphere 缺陷管理详情与列表体验优化方案

> 日期：2026-07-30
> 范围：缺陷管理详情、缺陷列表、全局可进入详情对象的名称交互
> 方案性质：产品与研发改造方案

## 一、改造目标

本次改造聚焦三个方向：

1. 整合缺陷详情的信息与评论，减少 Tab 切换和重复操作入口。
2. 提升缺陷列表的直接操作能力，包括名称进入详情、状态快捷变更和表格字段配置。
3. 建立全局统一的“点击名称进入详情”交互规范，避免不同模块行为不一致。

## 二、范围与关键口径

### 2.1 本次范围

- 缺陷详情抽屉及详情 Tab。
- 缺陷列表及表格设置。
- 缺陷预计解决时间的数据、接口和页面展示。
- 全局具有详情能力的业务对象名称。
- 附件图片预览交互。

### 2.2 表格设置中“排序”的口径

本方案将需求“可排序字段按处理人、严重程度……”理解为：

- 调整表格设置抽屉内可拖拽字段的初始排列顺序；
- 同时调整这些字段在缺陷列表中的默认列顺序；
- 不等同于点击表头后的数据升序、降序排序能力。

如还需上述字段支持服务端数据排序，应另行补充各字段的升降序规则、空值位置以及自定义字段排序口径。

## 三、总体页面方案

### 3.1 缺陷详情目标结构

```text
缺陷详情抽屉
├─ 标题区：缺陷 ID + 完整缺陷标题（自动换行）
├─ Tab
│  ├─ 详情
│  │  ├─ 缺陷描述
│  │  ├─ 附件
│  │  └─ 评论
│  ├─ 关联用例
│  └─ 操作历史
└─ 右侧基础信息
   ├─ 状态
   ├─ 处理人
   ├─ 预计解决时间
   └─ 其他系统字段及自定义字段
```

原“评论”Tab 删除，评论列表和评论输入区统一放在“详情”Tab 的附件区域之后。

### 3.2 缺陷列表目标结构

- ID 和缺陷名称保持固定展示。
- 缺陷名称可点击进入详情。
- 状态列启用后，点击状态可直接变更。
- 表格设置按新的默认字段顺序展示。
- 用户已保存的个性化表格配置原则上保留；新用户或点击“恢复默认”时应用新默认配置。

## 四、详细改造方案

### 4.1 将评论功能全部移动至详情 Tab

#### 页面调整

- 删除详情抽屉中的“评论”Tab。
- 在“详情”Tab 底部新增评论区域，建议顺序为“缺陷描述 → 附件 → 评论”。
- 评论区域包含：
  - 评论输入框；
  - 发布评论；
  - 评论列表；
  - 回复、@用户、删除等现有已支持能力；
  - 评论附件及加载更多能力（若当前评论已支持，则完整迁移，不削减能力）。
- 发布成功后只刷新评论区域及评论数量，不刷新整个缺陷详情。
- 评论为空时展示统一空状态，但评论输入框仍可使用。

#### 兼容处理

- 旧地址、历史记录或站内链接若携带 `comment` Tab 参数，打开时自动切换至“详情”Tab，并滚动到评论区域。
- 删除原抽屉底部仅在评论 Tab 出现的输入区，避免详情中同时出现两个评论输入框。
- 评论权限沿用现有权限模型：无评论权限时只读展示；无查看权限时不展示评论内容。

#### 建议实现

将现有评论列表与输入能力抽成独立的 `BugCommentSection`，由详情 Tab 组合使用，避免将评论逻辑直接堆入详情描述组件。

### 4.2 基础信息新增“预计解决时间”

#### 字段定义

| 项目 | 设计 |
| --- | --- |
| 中文名称 | 预计解决时间 |
| 建议字段名 | `expectedResolveTime` |
| 数据库字段 | `expected_resolve_time` |
| 类型 | 时间戳，可为空 |
| 是否必填 | 否 |
| 页面控件 | 日期时间选择器 |
| 展示格式 | `YYYY-MM-DD HH:mm`，按用户时区展示 |
| 清空 | 支持 |

预计解决时间建议作为缺陷系统字段，而不是模板自定义字段，以保证不同缺陷模板下均有稳定的数据语义。

#### 页面行为

- 在详情右侧“基础信息”中展示并允许有编辑权限的用户修改。
- 无值时展示“-”或“未设置”，点击后进入日期时间选择。
- 允许清空，不把“早于当前时间”作为保存拦截条件，以便保留已经逾期的真实计划时间。
- 创建、编辑缺陷页面同步增加该非必填字段，避免只能在创建后补录。
- 第三方平台缺陷：
  - 适配器支持对应字段时进行双向映射；
  - 不支持时作为 MeterSphere 本地扩展信息保存，不阻断缺陷同步；
  - 页面应避免让用户误认为该字段一定会同步到第三方平台。

#### 数据与接口

- 缺陷表新增可空字段，并补齐实体、创建/更新请求、详情 DTO、导入导出映射。
- 继续使用现有缺陷更新接口时，应确保未提交该字段不会覆盖旧值；显式传 `null` 才表示清空。
- 变更写入缺陷操作历史，记录修改前、修改后的时间。

### 4.3 全局支持点击名称进入详情

#### 统一规则

所有“存在可访问详情页或详情抽屉”的业务对象，其名称均展示为可交互文本：

- 鼠标点击名称，进入与现有“查看详情”操作相同的详情页面或抽屉。
- 原有 ID 入口可以保留，名称入口与其指向同一对象。
- 鼠标悬停显示链接态；支持键盘 Tab 聚焦及 Enter/Space 打开。
- 点击名称不得误触发行选择、展开行或其他父级点击事件。
- 可配合 Ctrl/Cmd 点击新页面的路由型详情支持新标签页；仅抽屉型详情不强行支持新标签页。

#### 不适用场景

- 当前用户无详情查看权限；
- 对象已删除、失效且无历史详情页；
- 名称处于输入、编辑、选择器选项或纯展示标签中；
- 该业务对象本身没有详情能力。

以上场景继续按普通文本展示，避免出现点击后无结果的“伪链接”。

#### 技术方案

- 建议提供统一的 `MsDetailLink` 组件或表格列 `detailLink` 元数据。
- 组件统一处理权限、路由/抽屉、事件阻止、键盘可访问性和无权限降级。
- 分模块逐步替换当前散落的名称点击逻辑，首批至少覆盖缺陷、测试用例、测试计划、任务、需求等已有详情能力的核心对象。

### 4.4 缺陷详情仅保留一个预览按钮

- 盘点附件行中组件默认预览入口和业务自定义预览入口，删除重复入口。
- 图片附件每行仅保留一个显式“预览”按钮。
- 预览按钮和图片文件名共用同一个预览方法及同一组图片预览数据，避免两套预览行为不一致。
- 非图片附件不显示“预览”按钮，继续提供下载等适用操作。
- 本地附件和关联平台附件使用相同的操作区布局，不因数据来源出现重复按钮。

### 4.5 缺陷详情完整展示标题

- 详情抽屉标题区取消单行省略，允许根据标题长度自动换行。
- 标题文本设置：
  - `white-space: normal`；
  - `overflow-wrap: anywhere`；
  - 不使用行数截断。
- 标题与右侧关闭、更多操作按钮采用弹性布局；操作按钮固定在右侧，不被长标题挤出可视区域。
- 标题换行后抽屉正文整体下移，不能覆盖 Tab 或基础信息。
- 对超长连续字符、中文英文混排、带 URL 标题进行专项验证。

### 4.6 点击图片附件名称打开预览

- 图片附件名称展示为可点击文本，点击后打开当前缺陷附件的图片预览器。
- 预览器支持前一张、后一张、缩放、旋转及关闭等现有已具备能力。
- 图片识别优先使用服务端 MIME 类型，文件后缀作为兼容判断。
- 非图片文件名保持原下载或普通文本行为，不尝试进入图片预览。
- 图片加载失败时给出明确提示，并保留下载入口。
- 文件名点击和唯一的“预览”按钮调用同一方法，结果完全一致。

### 4.7 缺陷列表支持点击状态变更

#### 交互

- 状态列启用后，状态显示为可点击的状态标签。
- 点击状态标签弹出可选状态列表，只展示当前缺陷允许流转到的状态。
- 选中状态后即时提交；提交期间禁用重复操作并展示加载态。
- 更新成功后局部更新当前行，不刷新或重置列表分页、筛选、列宽和滚动位置。
- 更新失败时回滚为原状态，并提示具体失败原因。
- 无编辑权限、已归档项目、不可编辑的第三方缺陷或无可用流转状态时，状态按只读标签展示。

#### 服务端规则

- 建议提供缺陷状态轻量更新接口，例如：

```http
PATCH /bug/{id}/status
Content-Type: application/json

{
  "status": "targetStatus",
  "updateTime": 1785379200000
}
```

- 服务端必须校验：
  - 项目及缺陷编辑权限；
  - 当前状态到目标状态的合法流转；
  - 缺陷是否仍存在且可编辑；
  - 乐观锁或更新时间，避免覆盖他人的并发修改；
  - 第三方平台同步能力。
- 成功后统一触发操作历史、通知、Webhook/事件及第三方平台同步，不能只更新数据库状态。
- 若已有字段级更新接口能够满足以上约束，可复用，不必重复新增接口。

### 4.8 调整缺陷列表表格设置

#### 固定字段

以下字段固定展示，不进入可拖拽排序区：

1. ID
2. 缺陷名称

如系统存在固定操作列，操作列继续固定在最右侧。

#### 默认开启及排列顺序

可拖拽字段按照以下顺序排列，且默认开启：

1. 处理人
2. 严重程度
3. 优先级
4. 缺陷类型
5. 责任人
6. 创建时间
7. 创建人
8. 更新时间
9. 更新人

状态、用例数、所属平台、标签以及其他系统字段、自定义字段默认关闭。用户仍可在表格设置中手动开启并拖动位置。

#### 配置兼容策略

- 新用户：直接使用新默认配置。
- 已有用户且存在个人列配置：保留个人配置，避免上线后打乱其工作视图。
- 已有用户点击“恢复默认”：应用本次新的默认字段和顺序。
- 如果业务要求所有存量用户强制切换，则需要升级表格配置版本并执行一次迁移；该方式会覆盖个人偏好，实施前需单独确认。
- 自定义字段应按稳定的字段 ID 匹配“严重程度、优先级、缺陷类型、责任人”，不能依赖可修改或可国际化的字段名称。

## 五、数据与接口改造清单

| 层级 | 改造内容 |
| --- | --- |
| 数据库 | 缺陷表新增 `expected_resolve_time` 可空字段及升级脚本 |
| 后端实体/DTO | 增加 `expectedResolveTime`，补齐详情、创建、编辑及导入导出模型 |
| 状态接口 | 新增或复用字段级状态更新接口，增加流转、权限及并发校验 |
| 操作历史 | 记录预计解决时间和状态的修改内容 |
| 第三方适配 | 增加预计解决时间映射能力声明；状态更新继续走平台适配器 |
| 前端详情 | 评论嵌入详情、标题换行、预计解决时间、附件入口合并 |
| 前端列表 | 名称详情入口、状态快捷更新、新默认列顺序 |
| 公共组件 | 统一名称详情链接；视情况增强文件列表的图片文件名预览能力 |

## 六、建议代码影响范围

结合当前工程结构，主要涉及：

- `frontend/src/views/bug-management/index.vue`
- `frontend/src/views/bug-management/components/bug-detail-drawer.vue`
- `frontend/src/views/bug-management/components/bugDetailTab.vue`
- `frontend/src/views/bug-management/components/basicInfo.vue`
- `frontend/src/views/bug-management/components/commentTab.vue`
- 公共文件列表、详情抽屉标题及表格设置相关组件
- 缺陷实体、请求/响应 DTO、缺陷更新服务、状态流转服务及数据库升级脚本

评论组件建议由 `commentTab.vue` 重构为可嵌入式区域组件；完成调用迁移后再删除旧 Tab 入口。

## 七、权限、审计与异常处理

- 名称详情入口只改变访问方式，不绕过原详情权限校验。
- 列表状态变更必须与详情中的状态变更使用相同权限和流转规则。
- 预计解决时间、状态、评论的新增或修改均保留现有审计记录。
- 第三方平台同步失败时：
  - 明确显示同步失败原因；
  - 不静默假装成功；
  - 按现有平台一致性策略决定本地回滚或标记待同步。
- 列表局部更新不能清空用户筛选、分页、排序、选中行及滚动位置。

## 八、实施顺序

1. 数据库字段、DTO、预计解决时间及状态更新接口。
2. 评论组件重构并嵌入详情，删除评论 Tab。
3. 标题换行、附件预览入口合并及文件名预览。
4. 缺陷列表名称入口、状态快捷变更。
5. 表格设置默认顺序及配置兼容。
6. 建设全局名称详情链接组件，并按模块分批接入。
7. 完成单元测试、接口测试、UI 回归、权限及第三方平台回归。

全局名称入口涉及多个业务模块，建议与缺陷模块改造同版本建立公共能力，随后按模块清单逐项验收，避免一次性修改过大导致遗漏。

## 九、验收标准

### 9.1 详情与评论

- 详情中不再出现“评论”Tab。
- 详情 Tab 底部可查看全部评论并可完成原有评论操作。
- 发布评论后不刷新整个详情，已填写或展开的信息不丢失。
- 旧评论链接仍能打开详情并定位评论区。

### 9.2 预计解决时间

- 字段非必填，可设置、修改、清空并正确保存。
- 详情、创建和编辑页面显示一致，时区转换正确。
- 修改记录可在操作历史中追溯。

### 9.3 名称进入详情

- 具有详情能力且有权限的对象，名称均可点击进入正确详情。
- 点击不会误触发行选择等其他操作。
- 无权限或无详情对象不展示伪链接。

### 9.4 标题和附件

- 任意长度的缺陷标题均完整展示，不使用省略号截断。
- 每个图片附件仅有一个显式预览按钮。
- 点击图片名称与点击预览按钮打开同一预览结果。
- 非图片文件不会错误打开图片预览。

### 9.5 列表状态

- 有权限且允许流转时可直接修改状态。
- 非法流转不会出现在选项中，服务端仍能阻止绕过前端的非法请求。
- 成功后仅更新当前行；失败后正确回滚且列表上下文不丢失。
- 操作历史、通知和第三方同步行为与详情修改状态一致。

### 9.6 表格设置

- ID、缺陷名称固定展示。
- 默认字段严格按“处理人、严重程度、优先级、缺陷类型、责任人、创建时间、创建人、更新时间、更新人”排列并开启。
- 其他字段默认关闭，但用户可以手动开启和拖动。
- 新用户、存量个人配置和“恢复默认”分别符合配置兼容策略。

## 十、需产品确认项

1. 表格设置中的“排序”是否仅指字段排列顺序；若还要求列表数据升降序，需要补充数据排序规则。
2. 新默认表格配置是否仅作用于新用户及“恢复默认”，还是强制覆盖存量用户个人配置。建议保留存量个人配置。
3. 第三方缺陷平台不支持“预计解决时间”时，是否接受该字段仅保存在 MeterSphere 本地。建议接受并在页面标明不同步。
4. 全局名称入口的首批覆盖模块清单。建议优先覆盖缺陷、测试用例、测试计划、任务和需求等高频对象。
