# 三、3W 项目定义（黄金圈法则）

## ① Why — 为什么做（价值与初心）★

### 1. 痛点 & 不做后果

当前公司内部测试协作与质量保障场景存在以下核心痛点：

+ **测试资产管理松散：** 测试用例、执行结果分散在语雀、Excel、XMind、群消息与个人本地文件中，无法有效检索、复用与版本追溯，同类场景反复重写，历史资产沉睡
+ **测试过程管理不透明：** 执行进度全靠询问测试人员，测试人员说多少就是多少，缺少可视化、可证明的有力证据；管理者无法基于统一视图判断覆盖、阻塞与发布风险
+ **自动化缺少统一调度与质量门禁：** 没有统一发放 / 领取任务的平台，缺少强力控制结果质量的门禁机制；AI / Agent 执行后若只报结论、不交 step 与截图，结果缺少保管、校验与评价闭环，正式通过结论不可信、不可审计

**不做后果：** 随着业务线与版本节奏加快，分散式文档管理会导致用例重复建设、进度口径不一、发布决策缺少证据；自动化与 AI 执行无法纳入统一治理，结果可随意回写或无法回写，质量结论失真，最终团队人效被「找文档、追进度、补证据」消耗，测试资产无法沉淀为组织能力。

### 2. 遗产（可复用、可沉淀、长期受益）

+ **产品能力遗产：** 一套可自由配置、可扩展的自动化与测试用例管理平台；以米多星球后台为标杆案例落地后，后续可复制用于在线巡查 / 回归其他平台系统，如 BDE、IMP 等
+ **流程方法论遗产：** 「用例资产化 + 任务闭环 + 自动化任务领取 + Agent 受控执行 + step/截图质量门禁」的边界方法论，为公司其他质量与协作系统建设提供可复制范式（正式结果只能在证据校验通过后由平台受保护服务采用，Agent 不能自行认定通过）
+ **数据资产遗产：** 全量用例、计划、执行 step、截图证据、缺陷与报告沉淀，形成组织级可检索、可追溯、可复核的测试知识库，支撑持续复用、遗漏分析与 AI 赋能
+ **集成能力遗产：** MeterSphere MCP / Agent Token、Browser Runner、企微通知等标准接入能力与插件契约，可复用于后续业务系统对接、CI 触发与多 Agent 协作

### 3. 越级 & AI in All

作为测试工程师主导本产品型项目，从「质量保障执行者」延伸到「测试平台从 0 到 1 落地」，在以下维度体现超出本职预期：

+ **角色跨界越级：** 从测试工程师到产品推动者，独立完成需求调研、方案设计、平台改造与项目推动全链路，突破「只测不建」的职能边界
+ **AI 赋能跨界：** 测试工程师借助 AI 完成产品设计与开发交付，突破技术栈边界；同时在 MSP 全链路嵌入 Agent 辅助（检索用例、领取任务、受控执行、step/截图留证、门禁校验回写），让系统从「测试台账」升级为「可调度、可证明、可治理的智能测试资产云平台」

## ② How — 怎么做（路径与打法）★

**整体节奏：** 周汇报 → 月复盘 → 里程碑验收 → 项目总结

### 1. 行动策略与里程碑

本期在原有「资产统一 → 过程闭环 → Agent 智能执行 → 巡检延伸」主线上，**融合补充**自动化任务领取、结果质量门禁（step + 截图上传校验）以及米多星球后台落地案例，形成可核查的平台能力与业务验证闭环。

| **序号** | **里程碑** | **目标 / 产出** | **计划时间** |
| :--- | :--- | :--- | :--- |
| 1 | **M1 测试资产统一沉淀、复用与追溯** | 统一资产目录、项目空间、文档与用例管理、标签检索、资产版本与全链路关联；让用例、执行结果从散落文件变为可搜索、可复用、可追溯的组织级资产，为后续任务领取与 AI 执行提供结构化输入 | 2026-09-18 |
| 2 | **M2 测试任务、执行、缺陷与改进闭环** | 打通「计划分配 → 在线执行 → 结果留证 → 缺陷关联 → 复验改进」主链路；进度实时可见，替代口头追问；失败证据完整可审计；为自动化任务发放 / 领取提供计划、责任人与范围底座 | 2026-10-23 |
| 3 | **M3 Agent 统一调度 + 任务领取通道 + 质量门禁** | 在原有 Agent / Runner 统一调度与结果评价基础上，重点建设并验收：① **自动化任务领取通道**（平台发放/冻结范围，Agent 鉴权领取、心跳续租、取消与回收，执行中状态可见）；② **自动化结果质量门禁**（要求 AI 按步骤写下实际执行 step，并上传对应截图等证据；上传时校验步骤完整性、步骤—截图关联、证据一致性、必测范围未被删减；区分「上传成功」与「正式通过」）；保管执行证据与评价结论，对外叙事为「可证明的智能测试」，而非可随意改写的电子台账 | 2026-12-04 |
| 4 | **M4 米多星球后台 AI 自动化落地案例** | 以米多星球为标杆案例，完成星球后台核心链路的 AI 自动化测试接入：用例入库 / 计划关联 → 任务领取 → AI 执行留证（step + 截图）→ 门禁校验 → 可信结果回写；输出可演示、可复核的执行报告与证据包，证明「能跑、跑得真、结果可信有质量」，并为后续复制到 BDE、IMP 等系统沉淀范式 | 2026-12-26 |

> 说明：原规划中的「AI 定时巡检与主动质量预警」（原 M4，计划约 2027-01-15）调整为考核期后的**延伸目标**，不纳入本期结案硬门槛；本期在 M3 架构上预留调度、告警与复验能力，确保不推倒重来。考核结案以 **M1～M4** 可核查证据为准。

### 2. 是否善用 AI 提升效率或质量？

| **场景** | **如何用 AI** | **收益** |
| :--- | :--- | :--- |
| **规范约束**（.cursor/rules、skills 约束） | 通过 .cursor/rules 定义 MSP 开发规范与边界，通过 skills 封装 MeterSphere Agent 工作流（用例提取、任务领取、执行回写、缺陷关联等），让 AI 输出始终符合团队规范与技术栈要求 | AI 输出质量可控，符合团队规范，减少返工，降低代码评审成本 |
| **AI 制定功能设计方案** | AI 基于项目背景、业务需求和技术栈，自动生成功能设计方案、接口定义、数据模型与验收矩阵，人工审核调整后落地 | 设计效率提升，方案更全面，减少遗漏，加速从需求到设计的转化 |
| **AI 自动开发修复重构** | AI 辅助代码生成、Bug 定位与修复、代码重构优化；测试工程师也能高效完成平台功能开发与质量保障 | 开发效率大幅提升，测试工程师突破技术栈边界，独立完成功能开发交付 |
| **AI / Agent 执行与评价** | Agent 通过任务领取通道领取任务，按步骤执行并写下 step + 截图；上传时经质量门禁校验，平台保管原始提交、门禁结论与正式采用记录 | 重复执行工时下降；结果可追溯、可校验，避免 AI「只报结论不交证据」 |

### 4. 主要风险点与应对

| **风险点** | **影响** | **应对措施** |
| :--- | :--- | :--- |
| 存量资产迁移成本高、结构不统一 | M1 延期，复用与 AI 执行输入质量打折 | 优先迁移高频回归与核心链路用例；统一标题/步骤/优先级/标签规范；迁移前后做数量与关联核对 |
| 任务领取协议不稳定 / Agent 掉线 | M3 任务通道不可用，执行中状态失真 | 租约心跳 + 超时回收；幂等领取；状态机明确；掉线可重领或转人工 |
| AI 只回写结论、缺 step / 截图或结果不可信 | M3 门禁形同虚设，干系人不买单 | 上传强校验：缺 step、缺关联截图、证据不一致一律拒绝正式采用；原始提交与正式采用分离；高风险操作转人工 |
| 米多星球后台页面复杂、选择器易变 | M4 案例跑不通或维护成本高 | 先锁定核心后台链路（登录 / 关键菜单 / 高频业务）；有限自愈 + 人工接管；用例与环境隔离账号 |
| 权限与跨项目数据泄露 | 敏感用例 / 证据泄露，信任崩塌 | 严格最小权限与项目隔离；Agent Token Scope 默认拒绝；操作留痕可审计；越权场景验收清零 |
| 试点部门使用意愿不足 | 「使用」结案门槛无法满足 | 以米多星球真实痛点先跑通端到端；周报晒进度与效率数据；主验收人推动纳入版本流程 |

### 5. 过程衡量指标（如何判断进展是否健康）

+ 4 个核心里程碑（M1～M4）按期达成率 ≥ 80%
+ 核心功能模块验收通过率 ≥ 95%
+ 试点期间 P0 缺陷清零
+ 周报、月复盘、里程碑总结按时归档
+ 试点部门周活跃使用率 ≥ 70%
+ 试点计划内失败用例有效证据完整率 ≥ 95%
+ 任务领取通道：鉴权领取成功率 100%（验收用例集）；非法 Token / 越权领取拦截率 100%
+ 质量门禁：缺 step / 缺截图 / 证据不一致的提交拒绝正式采用率 100%（抽检）；步骤—截图关联完整率 ≥ 95%
+ Agent / 人工正式结果回写准确率 100%（抽检）
+ 米多星球后台：约定核心链路 AI 自动化可执行，且门禁通过后的正式结果可复核
