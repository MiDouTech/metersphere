## 3. UX-01：目录移动

目录“更多”增加“移动”，打开目录选择弹窗：当前路径、目标父目录、目标路径预览，提供“项目根目录（移出当前目录）”。一次移动整个子树；用例ID、附件、执行和关联不变。目标中禁选当前节点及全部后代，不能跨项目。此处“下方”按成为目标目录的子目录理解；同级前后排序沿用原拖拽排序，不混淆父子移动。

仓库已有`POST /functional/case/module/move`和领域`moveToParent`。实施时核对NodeMoveRequest语义，优先复用；若拖拽接口不能直接表达目标父目录，增加显式parent DTO适配到同一领域方法，禁止前端猜造drag/drop节点。服务端校验当前/目标组织项目、修改权限、循环、根保留目录、同父重名、并发版本及最大层级；事务内更新parent/pos/path（如有），不改用例归属ID。冲突保留原位置，返回可理解原因。

成功后刷新树、面包屑、父子数量及当前选择；失败保留弹窗。不能移动“全部用例/回收站/未规划”等虚拟节点。验收移动有子节点目录、移根、同名冲突、两个用户同时移动、目标刚删除、刷新重入。

## 4. UX-02：全选所有页

顺序固定为“导出 / 全选所有页 / 编辑 / 修改执行结果 / 修改执行人 / 移动到 / 复制到 / 清空”。按钮不以已选数量作为出现条件；无匹配数据时禁用。原复选框及下拉箭头继续提供当前页/所有页选择。

新按钮复用`select-all.vue`的同一状态与`base-table.vue`选择事件，不另维护布尔值。选中所有页后明确显示“已选择当前筛选结果N条（所有页）”，手工取消某行计入excludeIds；“清空”同时清理两入口。切页保持，切项目/目录/搜索/筛选后清空并提示范围变化；不能默认全项目替代当前过滤条件。

只对当前权限范围内结果操作。批量后端使用selectAll+condition+excludeIds或冻结selectionToken，而不是前端下载所有ID。异步执行需冻结预览时ID/版本；此后新增用例不纳入。复用之前资产批量的范围快照和权限原则，但两个业务scope分开。

## 5. UX-03：名称链接

计划名称复用`openDetail(record.id)`；评审名称复用现有评审`openDetail`，不拼接另一套URL，不改ID和详情按钮。名称采用真实button/link，超长省略配全文提示，支持Enter/焦点。排除拖拽句柄、行复选框、分组展开按钮的点击冒泡；计划组名称保留组语义，不能当计划ID打开。普通用户无详情权限按现有规则禁用/隐藏；失效实体展示安全not-found。

## 6. IMP-01/02：导入→计划与评审编排

### 6.1 判定范围与默认规则

“再次导入”建议按**当前项目+导入用户的导入关联组**判断，不按文件名或项目内任意计划判断。首次成功导入创建一个group，绑定planId/reviewId/importJobId；名称默认“文件名-测试计划/评审-导入时间”，限制长度并确保可区分。其他用户导入不自动改写当前用户已有计划；允许授权用户显式选已有组。此范围是建议默认，评审可调整为项目共用组，但不得用模糊名称匹配。

适用测试用例模块中已存在的Excel、XMind、用例资产导入入口；旧版入口统一接入完成事件。MCP无交互，后续同一契约增加明确policy/targetGroupId，禁止让无UI任务等待弹窗。业务导入功能不因UI皮肤改造而删减。

### 6.2 完整流程

1. 上传/解析/预检，获取本次可成功行、源项目、操作者、已有可用关联组；0条成功不创建空计划/评审。
2. 无历史组：提示“导入后将创建测试计划和评审计划并关联成功用例”，按用户要求默认创建，不另加不必要询问。若没有创建或关联权限，预检明确告知并阻止默认流程，用户可明确选择仅导入；不能静默绕过权限或假报全成功。
3. 有历史组：第一问“检测到再次导入，是否更新已有测试计划和评审计划？”展示目标名称与ID，多个组须明确选定，不默默猜目标。选择是→APPEND_EXISTING。
4. 第一问否：第二问“是否新建测试计划和评审计划并关联本次导入用例？”是→CREATE_NEW_PAIR；否→IMPORT_ONLY。
5. 确认decisionToken和requestId后提交导入；成功行落库→持久化成功caseId集合→编排创建/关联→汇总结果。部分行失败只关联成功行，并显示失败明细；纯覆盖更新也应包含实际成功的已有caseId。
6. 展示分别的“用例导入 / 测试计划 / 评审”状态和可点击名称。导入成功但关联失败为PARTIAL_SUCCESS，可只重试关联，不重复导入。

APPEND为**增量关联并按caseId去重**，不清空原有关联、执行结果、评审意见和成员；不覆盖旧历史。选择IMPORT_ONLY仍正常导入并参与源资产同步。重复导入不等于同ID覆盖，沿用导入既有去重规则，新增成功ID应作为新关联。

目标归档/删除/撤权时失效decisionToken，要求重新选择新建/仅导入，不能自动复活归档计划。若只有plan或review一方缺失，在预检明确展示，允许为缺失一方补建或改为新建一对；不得让一个“是”产生隐含删除。评审成员默认当前导入人为负责人/评审人（必须符合模板约束），有必填项时由预检补齐，正式业务校验仍在服务端。

### 6.3 后端、数据和一致性

在现有异步导入服务之上增加`ImportFollowupOrchestrator`（建议名），复用计划与评审创建/associate领域服务。仓库已有`/case/review/add`、`/associate`与计划相关接口；worker调用服务/授权客户端，不伪造用户HTTP会话。

建议扩展导入预检响应：`historyGroups/allowedPolicies/requiredFields/decisionToken`；提交增加`followupPolicy/targetGroupId/decisionToken/requestId`，查询返回两类目标ID/分项状态/安全失败原因。新增查历史组和仅重试后处理接口，具体路径按当前导入入口归一；不重复造两套导入任务。

增加或扩展group、job-followup与分项关系：orgId/projectId/actorId/groupId/planId/reviewId/importJobId/caseId/version/status/traceId。对`importJobId+targetType+caseId`及创建目标的requestId设唯一约束。用例导入事务只提交用例与outbox，后处理可恢复，避免跨模块大事务；先创建的计划/评审ID持久化后再关联，失败重试复用ID，不产生空壳副本。轮询不触发创建。

创建计划、创建评审、关联三类权限分开校验；后台worker执行时重新校验委托身份及组织项目。并发重复导入用组版本锁定，过期决策返回冲突重新确认。审计保留决策、目标及成功caseId，不记录敏感文件内容。

## 7. DEL-01：源用例删除后更新关联

用户原文“测试模块”按测试用例模块理解。单条、批量、目录删除和MCP删除统一进入DeleteFunctionalCaseService领域链路；不能只在某个前端按钮补解绑。

软删除源用例后，活动计划/评审的当前关联标记删除或解除，立即刷新列表与计数；保留历史执行、原始步骤、证据与评审意见的快照/审计，不物理级联抹除证据。统计不再计入当前用例数；空计划/评审保留并显示0条，不自动删整个计划。事件幂等，失败可补偿，页面提示“关联更新中/部分失败”。

恢复源用例默认不自动复活已解除关联，提供恢复预览与明确确认，避免恢复后隐式改变已结束评审。归档计划历史按快照保留，标注源已删除，不重新写历史。若现有删除流程已有解绑必须复用并测试，避免重复处理。

## 8. AST-01：项目目录与资产持续同步

“新增项目名称”按业务项目创建理解：ProjectService提交项目后产生PROJECT_CREATED事件，为同组织建立以projectId唯一映射的资产根目录；项目同名仍有不同来源ID，不以name作为同步键。项目改名同步目录显示名，手工资产目录不被误匹配；现有两失败项目按F02先修复可信映射。

源用例是权威来源。源创建/编辑/导入/目录移动/附件变化/删除产生带caseVersion的事件，资产侧按lineage upsert并同步源目录层级、定义字段、等级、标签和附件关联。源执行/缺陷若资产页提供展示，则读取统一当前模型，不能把业务项目执行写成资产定义；不新增“资产执行”含义。

用户最新要求“始终同步”优先于此前方案的默认本地覆盖：**来源绑定字段设为只读、来源变化自动更新**；人工资产、资产专属分类/标签/备注可继续编辑，源标签与本地标签分开存储和展示，不静默混合。已绑定源资产的批量等级/源标签操作应禁用并说明“请在源用例修改”，可显式申请脱离来源转人工资产，需单独确认且记录lineage历史。这样既保留批量需求，又不制造双向同步循环。

源删除使资产失效/归档并从可导入列表移除；保留引用与历史版本，不删除业务副本。项目删除同理，项目恢复需重新校验。同步是单向“源→资产”，从资产导入项目生成明确新来源/引用关系，禁止事件回环；枢纽项目及系统镜像目录排除自动反向采集。

采用事务outbox+按org/project/case分区串行消费，版本单调更新、旧事件丢弃、删除墓碑防乱序复活，失败指数退避/死信+原因明细；定期按版本对账补漏。多实例以租约/唯一消费键防重复。建议可见更新30秒内（需实测才承诺），详情展示最近同步时间/延迟/失败/重试，不宣称跨模块零延迟。历史一次性同步成为补齐入口，正常使用不再依赖手工点击。

## 9. AST-02：置顶

资产目录更多菜单增加置顶/取消置顶，置顶项位于目录列表上方并有图标。默认**个人偏好**，按orgId+userId+catalogId保存pinOrder，唯一约束防重复；不会影响他人。多个置顶按置顶顺序排序，取消后回到原业务排序。分页先应用置顶排序再分页，不仅排序当前页；搜索仍遵守关键词，置顶不绕过过滤和权限。目录失权/删除不返回偏好对应内容，后台可清理残留。组织共享置顶如未来需要应另加管理权限，不混用。

## 11. 实施顺序、迁移和验收

1. 先处理P1执行读模型、路由、MCP、导出及资产冲突；并行工作不意味着同时启动环境。
2. UI样式、目录移动、名称链接、同一选择状态入口；低风险先独立提交。
3. 导入group与后处理任务、删除关联事件；灰度开关逐项目启用，失败可回退为原导入但必须明确告知未创建关联。
4. 项目→资产持续同步、置顶、资产批量/导出；历史回填先预检备份，只补可信映射。
