## 1. 范围与目标

本方案中的“测试用例”专指项目左侧功能模块【测试用例】中的用例库，包括其目录、用例详情、步骤、附件、评论和用例执行结果。

测试计划中的用例是用例库用例的关联记录，具有计划执行上下文，不能代替用例库的查询和管理。所有本次用例库操作均不应要求提供 testPlanId，也不能以查询测试计划关联用例作为项目用例库提取方案。

目标：

1. 按项目名称、项目 ID 匹配项目，搜索、筛选和提取该项目用例库中的用例。
2. 上传、查询和删除用例附件。
3. 导入、导出用例，编辑和移动目录，编辑和删除评论；通过质量门禁认可的受管链路提交事实、查询结果，不开放直接修改正式结果的工具。
4. 删除、批量删除和恢复用例。
5. 隐藏【测试用例】模块中的“AI自动化执行”按钮。
6. AI 能通过原生 MCP、Node MCP 客户端及必要的授权文件传输完成本方案能力清单中的日常操作和数据提取。不得把“网页可操作”或“有接口定义”当作 AI 已具备能力；覆盖范围和例外以 §4.1 清单验收。

## 5. 详细改造设计

### 5.1 项目解析与用例库查询

支持项目内部 ID 和项目名称，兼容现有项目编号约定：

- ID 精确定位，名称精确匹配；模糊项目搜索仅用于返回候选。
- 名称重名时返回候选项目，要求使用 ID，不自动选择第一个。
- 同时提供 ID 和名称时校验一致性。
- 仅在当前用户有权限的项目范围内解析。
- 不传项目时，仅在明确有默认项目的情况下使用默认值，并返回实际解析的 projectId。

functional.search 必须调用用例库查询服务，不依赖测试计划。支持关键词、目录、优先级、标签和状态筛选；明确多个条件的组合逻辑、子目录范围和稳定排序。

列表至少返回 projectId、caseId、编号、名称、moduleId、modulePath、优先级、标签、状态及 updateTime。详情返回前置条件、描述、步骤、预期结果及自定义字段。执行结果字段沿用现有业务模型。

兼容现有请求 `current` 和响应 `cases`、matchedBy、matchedModules、warnings，不直接改名为 page/items。新增 page 别名时与 current 同传必须一致；需要新响应结构时显式版本化并保留迁移期。补充真实 total、实际页码、pageSize、hasMore。

源码已确认 MCP 直接调用业务服务，而网页分页在 Controller 启动；MCP 使用 `cases.size()` 作为 total 并在查询后过滤标签/优先级。应将全部筛选、计数及分页下推到统一查询链路，禁止分页后再过滤。该问题不等于已定位线上内部错误。

建议边界：不同筛选维度 AND，同一维度多个值 OR；标签匹配显式提供 ANY/ALL，默认 ANY；目录包含子目录默认 true。区分用例状态、评审状态和执行结果；默认读取平台认定的当前版本且排除回收站，历史版本通过明确参数读取。采用带唯一 ID 的稳定排序，页大小及提取容量在阶段零固定为配置和 Schema。

普通列表允许实时变化并说明语义；完整提取/导出冻结授权范围内的 ID、版本及规范化内容快照，返回 snapshotId、有效期和游标，重试不重复或遗漏。后续分页/下载仍重新授权；已删除或撤权内容不能因快照绕过访问限制，返回范围失效并要求重建，不能悄悄跳过后仍声称完整。

项目解析复用 AgentProjectService，补充明确的 identityType（ID/NUMBER/NAME）；兼容旧单字段输入时遇到多种解释必须返回歧义，不自动选择。精确匹配应直接查询完整授权集合，不依赖候选搜索第一页。modulePath 按实际用例项目解析，不以会话默认项目替代。

首先通过 traceId 定位 functional.search 的请求解析、项目解析、权限校验、业务查询及响应转换异常，修复后增加对应回归测试。不能仅修改错误提示而保留查询故障。

### 5.2 附件上传、关联与删除

补齐准备上传、传输文件、完成校验、关联用例的链路：

- 小文件可提供受大小限制的 MCP 内容上传工具。
- 较大文件由 MCP 返回短时上传地址，客户端传输后调用完成接口；文件字节通过 HTTP 传输应在工具说明中明确。
- 完成接口返回能用于 attachment.attach 的临时附件 ID。
- 明确区分临时附件 ID、存储文件 ID、用例附件关联 ID。
- 校验用户、项目、用例归属，以及文件大小、类型、实际内容和完整性。
- 上传和关联支持幂等，失败后的临时文件自动过期清理。
- 删除复用平台文件引用及生命周期规则，不误删其他资源引用的文件。

不得将受管执行 artifact.prepare/commit 直接视为普通用例附件上传能力；两者的资源类型和关联规则需要独立确认。

下载通过鉴权代理或授权签发的短期凭证；签发及可控的后续请求重新校验权限，凭证有效期及撤销延迟明确披露。客户端不得接收任意存储路径；文件名安全处理，类型按内容校验，大小与哈希由服务端确认。上传凭证绑定 Token、用户、项目、用途、对象及到期时间，不落入普通幂等结果长期重放。

关联时通过原子消费防止临时 ID 被重复或跨用途使用；关联失败按事务结果保留可重试状态或进入孤儿清理。删除先移除目标关联，只有无引用且满足保留规则的文件才进入可靠清理队列；对象存储失败可重试并有状态可查，不删除历史执行证据。

### 5.3 导入和导出

优先复用平台已有模板、解析器和导入导出业务服务。

导入分为预校验和正式执行。预校验返回行号、字段错误、目录映射、预计新增及更新数量。明确同名、编号冲突、目录不存在和重复执行策略，默认不静默覆盖既有用例。

正式执行返回任务 ID、进度、逐行结果及失败原因。部分失败必须显式呈现，不返回整体成功冒充全部导入成功。

导出支持指定用例或筛选范围；固定任务范围，异步生成文件并提供限时下载。验证前置条件、步骤、预期结果、标签、自定义字段及目录映射的往返一致性；附件是否随包导出需单独定义，不默认包含。

导入承接上一版 `precheck/commit/get` 命名。预检冻结文件哈希、模板/解析器版本、工作表、目录映射、规范化逻辑条目、重复处理模式、目标版本及有效期；commit 仅引用 previewId、requestId 和明确覆盖授权。文件或目标变化必须重新预检。CREATE_ONLY 为默认；UPDATE_MATCHED 只按稳定用例 ID 匹配并校验更新权限和版本，同名不能作为覆盖依据。

多行步骤归为一个逻辑用例，物理行号仅用于定位；`importId + itemId` 唯一。第一版限定模板工作表，其他非空工作表明确拒绝。限制文件大小、ZIP 展开量/条目数、行列数、单元格长度、合并区域、内存和解析时长，并确保超时能终止工作而非仅返回 HTTP 超时。表格导出处理公式注入，同时保证文字字段安全往返。

导出第一版不包含附件文件，返回该限制；固定内容快照而不只固定 ID。任务文件、原文件和错误报告均需授权下载、到期清理，不能使用公开永久地址。大任务分块执行并报告容量限制，禁止无界加载全部用例。

任务状态至少包括 QUEUED、RUNNING、SUCCEEDED、PARTIAL_FAILED、FAILED、CANCEL_REQUESTED、CANCELLED；明确终态及剩余条目 NOT_PROCESSED。工作者采用租约、心跳和 fencing，逐逻辑条目事务提交，重启从持久化结果恢复。每项开始前重新授权，撤权停止后续项；新请求恢复前重做失效预检，不能用后台管理员替代原用户。停止只在当前原子条目结束后生效，已提交结果保留；下载和查询权限独立校验。

### 5.4 编辑和移动目录

增加目录改名及移动工具，参数包含项目、目录、目标父目录、并发版本及请求 ID。

校验同项目归属、目标存在、同级重名规则，禁止移动到自身或子目录。复用现有层级、排序及路径维护机制，保证子目录和用例归属一致，失败时不留下半更新状态。

本次目录移动不等同跨项目移动用例；跨项目移动不在本次明确需求内。

目录移动在同一项目树锁或等价串行化机制内复查祖先关系、目标与树版本，覆盖并发 A→B、B→A 成环情形。根目录不可移动，排序及路径原子更新。另补齐用例同项目移动能力，校验目标模块、用例版本及批量逐项结果；所有写入口维护一致的版本协议。

### 5.5 编辑和删除评论

增加 comment.update/delete。验证评论属于目标用例，遵循现有作者和管理员权限规则，使用版本校验防止覆盖并发编辑。清理或保留附件引用时遵循现有平台规则，保留必要审计记录。

普通作者须仍有当前用例评论权限；管理员以实际平台权限点鉴定，不凭角色名称放行。默认编辑仅限作者，管理删除按现有授权模型执行；若网页规则不同须统一契约并回归。父评论删除建议保留墓碑及回复关系、隐藏正文，不能无提示级联删除他人回复；附件按引用清理。通知在事务提交后可靠发送，重试不重复通知，审计保留修改前后摘要而不公开敏感内容。

### 5.6 执行事实与质量门禁结果

冲突以质量门禁方案为准：不新增 `functional.result.update` 或直接设置 PASS 的工具，不解除 `QUALITY_LEGACY_SUBMIT_FORBIDDEN`。人工确认、管理员身份、来源标记都不能替代事实和证据，不允许直接覆盖聚合结果。

AI 使用既有受管链路：准入检查 → 创建/认领任务 → 获取租约和冻结合同 → 提交证据及实际观察值 → 完成任务 → 查询门禁判定和正式回写状态。步骤事实、用例结论、同步状态分别展示，不能把工具调用成功解释成执行通过。缺少上下文或证据时返回可操作的缺失项，不自动构造通过结果。

错误结果通过质量门禁允许的新尝试、补充事实或复核流程处理，保留原尝试、评估和审计，不直接改历史。计划结果仅按既有冻结关联及授权规则回写；无计划关联不得伪造关联或更新其他计划。新增一般人工结果维护不在本方案范围内。

### 5.7 删除、批量删除和恢复

默认软删除进入回收站。批量接口返回逐条结果，定义请求规模限制并支持幂等重试。

删除前明确与计划、评审、缺陷、附件及历史记录的关联处理规则，优先沿用网页业务规则。恢复时处理原目录不存在、编号冲突等情况，返回明确失败原因或要求指定目标目录，不静默改变归属。

永久删除不是本次明确要求，不与普通删除混用。

**预检与版本范围：** 禁止透传现有 deleteAll=true 默认值。默认 versionScope=CURRENT，ALL 必须显式指定。delete_preview 返回目标版本、计划/评审/缺陷/附件影响、可恢复性、执行任务状态、摘要、短期 previewId；提交携带 previewId、expectedVersion、reason、confirm 和 requestId，再次授权并比较摘要。批量预检和确认绑定明确目标集合，不因分页或筛选变化扩张范围。

**正在执行的用例由用户决定：** 发现排队、认领、运行、等待人工或结束/回写中的任务时，先返回结构化 `USER_DECISION_REQUIRED`，列出任务、受影响目标、操作后果及可选项。网页显示确认流程；AI 将相同信息呈现给用户并等待选择，不能自行替用户填 confirm。通过绑定目标、预检版本、选择、操作者和有效期的确认记录恢复操作；API 不能把任意布尔值当作已获用户决定的证据。首版优先使用平台确认页签发确认凭证，MCP 查询确认状态后继续。

| 用户选择 | 处理方式 |
| --- | --- |
| 取消删除 | 不改变任务或用例 |
| 等执行结束后再删除 | 保存删除意图；任务结束后重新预检，影响变化要求重新确认；仍须校验当前授权 |
| 停止相关执行后删除 | 需同时具备删除和任务停止权限，明确提示可能影响同任务其他用例；停止当前尝试并使旧租约失效，确认停止落库后才软删除 |

首版不提供“继续执行并立即删除”，以遵守质量门禁实时安全条件和证据保留要求。没有停止权限时仍允许取消/等待选择，不自动提权。外部 Runner 未确认停止、租约未失效或无法保证迟到回调被拒绝时，返回等待/失败状态，不能先删除再宣称停止成功。

删除与新任务创建/认领/完成回写共享同一目标的并发协调机制；执行集合变化使旧预检失效。停止与删除采用持久化状态推进，不能假设跨外部执行器的数据库事务原子性；停止成功但删除失败必须明确展示并支持安全重试。已产生的事实、证据和审计保留；删除不改成 PASS/FAIL，恢复不重新激活旧任务或旧租约。批量中未获确认项标记 WAITING_CONFIRMATION/NOT_PROCESSED，其他项按明确的逐项事务返回结果。

### 5.8 隐藏“AI自动化执行”按钮

检查【测试用例】列表工具栏、批量选择工具栏和详情页中实际存在的入口，移除对应按钮及配置。

覆盖管理员、普通用户、空列表、单选和多选状态。本项不顺带删除其他模块的执行能力；隐藏前端按钮也不替代后端权限控制。

## 6. 权限、错误与一致性

- 对所有资源执行项目范围、操作权限和资源归属校验。
- 用例修改、目录移动、评论编辑及删除恢复采用并发版本校验；执行事实遵守质量门禁的租约、attempt 和幂等规则。
- 写入工具支持 requestId 幂等，重复请求不产生重复附件、评论或任务。
- 批量操作明确逐条结果和事务边界。
- 统一返回 `{ code, message, details?, traceId? }`。
- 参数错误、权限不足、资源不存在、冲突、业务拒绝和内部错误应可区分。
- message 使用用户可理解的文本，堆栈和数据库细节只写日志。
- 前端覆盖 loading、empty、success、validation-error、permission-denied、network-error 和 server-error；未知错误显示通用提示并保留 traceId。
- 前后端字段、类型、状态码及错误协议保持一致。

### 6.1 授权与幂等的实施要求

有效权限为当前 Token Scope、Token 项目范围、当前用户业务权限和资源归属的交集；读取、写入、下载、任务查询和幂等重放都重新检查 Token/用户启用状态。工具发现过滤不代替调用时授权。

新增高风险能力必须先落实上一版 authorizationContractVersion 方案：旧 AGENT_ALL 不自动获得新增删除/恢复/导入等权限。Scope 与平台权限逐工具登记，并覆盖 HTTP、原生 MCP、Node 及异步工作者，统一使用共享授权服务。

普通写操作使用服务端固定 operationId、Token、requestId 和规范化请求摘要；同键不同内容冲突，同键成功返回原结果且重新授权。数据库副作用与幂等结果同事务提交，不能执行完后才写缓存。外部文件、通知、任务调度采用可靠事件/补偿，不以长事务包住外部调用。租约和短时上传凭证不能按普通资源结果永久缓存。明确幂等保留期、清理与过期重试规则。

版本需覆盖正文、步骤、自定义字段及模块等变更；网页、导入及 MCP 均维护同一版本机制，现有 updateTime 不能充分覆盖时增加 revision。每个原子条目失败完全回滚，不吞异常后报成功。

### 6.2 客户端契约、发布与回退

原生 MCP Schema、HTTP DTO、Node Schema 和技能包示例同步生成或执行一致性测试；工具发现、实际调用和错误语义一致。发布更新能力版本、包版本、技能包摘要和兼容说明；旧工具迁移需明确替代路径，未知字段或不支持能力不能静默忽略。

工具级开关在应用服务生效，关闭后拒绝新写请求及新任务领取，当前原子条目结束后停止后续项；查询、审计和恢复诊断仍可访问。分阶段启用，回退保留已提交数据、快照、逐项结果及审计；数据库变更采用兼容迁移，不以删除新增业务数据作为回滚。

## 7. 分阶段实施

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| 阶段零 | 固定能力清单、Scope/版本、幂等及兼容契约、容量限制、迁移和回退设计 | 高风险权限不会被旧 Token 自动获得；所有必选项有文件及测试映射 |
| 第一阶段 | 定位搜索故障，修复项目解析、用例库查询、详情和分页 | 未关联任何计划的用例可按项目名称和 ID 搜索提取 |
| 第二阶段 | 附件上传删除、评论编辑删除、目录编辑移动、隐藏按钮 | 各链路写入、回读、权限和失败行为验证通过 |
| 第三阶段 | 导入导出、删除恢复及执行中删除确认 | 预检、授权确认、任务恢复、关联数据、幂等验收通过 |
| 第四阶段 | 受管执行链路与全部 AI 能力验收 | 原生 MCP、实际安装的 Node 包及下载技能包完成 §4.1 全部必选路径；证据不完整不能通过门禁 |

每阶段先阅读现有入口、路由、API、业务服务和数据模型，补全实际文件及需求追踪，再修改代码。需要迁移时先准备可重复执行的迁移及回滚方案。
