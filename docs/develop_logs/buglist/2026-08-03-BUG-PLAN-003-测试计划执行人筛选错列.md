# BUG-PLAN-003：测试计划「执行人」高级筛选错列 / 未生效

> **日期**：2026-08-03  
> **关联任务**：UI 自检（测试计划 → 执行用例筛选）；与 MCP task008 无关  
> **影响范围**：测试计划详情 · 功能执行用例 / API 用例 / API 场景 · 筛选模式「执行人」  
> **严重程度**：P1（功能执行用例筛选结果错误；API 用例/场景可能 SQL 异常或结果异常）  
> **状态**：已修复（2026-08-03）

---

## 1. 问题现象

测试计划详情 →「执行用例」→ 筛选模式 → 选择「执行人」（如周香）后：

- 列表仍接近全量（如约 490 条），筛选看起来未生效或结果错误；
- 左侧模块树数量在高级筛选下可能不刷新，进一步误导为「筛了也没变」。

**关联 API（示例）**：

- `POST /test-plan/functional/case/page`（及计划内 API 用例 / API 场景分页同类接口）

**前端入口**：

- `frontend/src/views/test-plan/testPlan/detail/featureCase/components/caseTable.vue`（高级筛字段 `executeUser`）
- `.../apiCase/components/caseTable.vue`、`.../apiScenario/components/scenarioTable.vue`（同上）

---

## 2. 根因分析

### 2.1 核心根因（三类列表共用）

`BaseMapper.baseSystemFieldConditions` 将高级筛字段 `executeUser` **固定映射**为：

```text
${tablePrefix}.execute_user
```

测试计划三类 Mapper 调用该片段时，`tablePrefix` 传的是**资源主表**（用例/场景表），同时又在本文件内手写了计划关联表上的正确条件，导致：

1. **错列**：先按资源表 `execute_user` 过滤（功能用例表该列语义≠计划指派人；API 用例/场景表甚至**无此列**）；
2. **条件重复**：再按 `test_plan_*.execute_user` 过滤；
3. 最终 AND/OR 组合后表现成「未生效」或「结果不对」，API 侧还可能直接 SQL 失败。

### 2.2 分模块明细

| 编号 | 模块 | Mapper | 错误列（通用分支） | 正确列（本地分支） |
|------|------|--------|--------------------|--------------------|
| PLAN-003-A | 计划 · 功能执行用例 | `ExtTestPlanFunctionalCaseMapper.xml` | `functional_case.execute_user` | `test_plan_functional_case.execute_user` |
| PLAN-003-B | 计划 · API 用例 | `ExtTestPlanApiCaseMapper.xml` | `atc.execute_user`（无此列） | `t.execute_user` |
| PLAN-003-C | 计划 · API 场景 | `ExtTestPlanApiScenarioMapper.xml` | `api_scenario.execute_user`（无此列） | `test_plan_api_scenario.execute_user` |

---

## 3. 修复方案（已落地）

1. **`BaseMapper.xml`**：`executeUser` 分支增加 `skipExecuteUser` 开关；`skipExecuteUser=true` 时不生成 `${tablePrefix}.execute_user`。
2. **计划三类 Mapper** + **`ExtApiTestCaseMapper`**（`api_test_case` 无该列）：include 时传 `skipExecuteUser=true`，仅保留本地/业务侧对 `execute_user` 的正确映射（计划侧为 `test_plan_*`）。
3. **PLAN-003-D**：计划功能执行用例高级筛增加「最后执行人」`lastExecuteUser` → `functional_case.last_execute_user`；表头列筛同步支持 `lastExecuteUserName`。
4. **PLAN-003-F**：功能用例库表头「执行人 / 最后执行人」`dataIndex` 对齐为 `executeUser` / `lastExecuteUser`，并配置 `filterConfig`（与创建人/更新人一致）。
5. **PLAN-003-E**：高级筛选模式下左侧模块树本身隐藏（`MsSplitBox :not-show-first`），属产品设计，未改。

**勿**：删除 `BaseMapper` 的 `executeUser` 默认分支——功能用例库等正确场景仍依赖它。

## 5. 验证步骤

1. 准备计划内数据：多名执行人指派、含未指派；API 用例/场景各至少若干条。  
2. 筛选模式选「执行人 = 指定用户」→ 列表条数与指派一致；切换用户结果变化。  
3. 清空筛选 → 恢复全量。  
4. API 用例 / API 场景页重复 2–3，确认无 SQL 报错。  
5. 对比表头列筛「执行人」与高级筛结果一致。  
6. 计划功能用例：高级筛「最后执行人」；功能用例库：表头执行人/最后执行人列筛可用。  
7. 失败定位：生成 SQL 不应再出现资源表 `execute_user` 与 `test_plan_*.execute_user` 并存。
