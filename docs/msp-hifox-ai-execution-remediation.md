# MSP × HiFox AI 测试执行整改实施方案

版本 v0.2（草案） · 2026-11-18

## 1. 背景与交付目标

测试评审通过后，MSP 向 HiFox 交接计划。测试人员在 HiFox 分配 Agent，Agent 用已配置的 MCP 接入 MSP，读取用例，操作本地或远程浏览器，最后回写结果并上传证据。

原始反馈是浏览器连通且已登录、人工能跑通的情况下，120 条中有 110 条被 AI 标为阻塞。这个数字是用户报告，尚未复核逐条根因。典型问题包括找不到首选数据就停止、重复执行已失败的动作、逐条执行时不复用已验证链路、中断后丢失进度。参见 [原需求对话](codex://threads/01a1e702-4c64-7ac0-9ff8-43f743899005)。

**交付目标是让普通测试人员分配 Agent 后，执行器直接按 JSON 规则推进现有测试任务。** 常规执行沿用 MSP 项目权限和 MCP 认证，取消自然人登记、Agent 主体绑定、逐环境能力授权、来源授权、治理责任人及强制独立复核等额外前置条件。任务详情说明 AI 做了什么、用了什么数据、为什么停、如何继续。已有受控会话和执行证据继续可查。

## 3. 实际运行流程

1. **评审交接。** MSP 现有事件已包含 event_id、business_key、项目 ID、计划 ID、评审关系、成员版本和快照摘要。保留现有事件。首先在 HiFox 核实接收后实际保留的字段、稳定任务 ID、分配的 Agent 如何取得任务参数和 MCP 身份，以及已有状态回传机制。
2. **启动批次。** Agent 用现有 MCP 身份提交计划与评审引用。MSP 根据权威数据确认计划范围、项目权限及测试环境，一次性固定计划用例关系、用例版本或快照、契约版本和知识引用。同一启动请求复用已有批次，明确重跑才新建批次。
3. **逐条执行。** 调度器选择一条前置满足的用例。执行器根据当前步骤、数据绑定和历史观察返回下一步。Agent 用已有浏览器执行操作并提交实际观察。执行器判定断言、继续、换数据、重新观察、核实写入结果或等待人工。
4. **恢复和回写。** 各用例独立推进。单个用例暂停时其余可执行用例继续；有共享前置依赖的条目关联同一个失败原因。每条结束后保存结果，再同步到 MSP 对应的计划用例并上传证据。补传读取保存的结果，避免重新执行浏览器动作。
5. **用户查看。** HiFox 展示批次链接、完成数和待协助数。MSP 计划详情展示具体步骤、停止原因、已尝试方法、证据及同步状态。若 HiFox 尚无状态回传接口，首版以任务中携带的 MSP 执行链接验收，状态回传单独确认。

## 5. 接口、数据和权限

### 5.1 服务边界

| 操作 | 请求要点 | 返回与失败行为 |
|---|---|---|
| 启动或恢复批次 | 计划 ID、交接事件或任务引用、预期范围版本、环境配置 ID（可由任务解析）、请求幂等键 | 批次 ID、固定范围和契约摘要、各用例初始状态。范围冲突返回当前版本及受影响摘要；环境有歧义时返回可选项 |
| 读取下一步 | 批次 ID、当前用例关系 ID、检查点版本 | 返回步骤、允许操作、断言或恢复指令；依赖未就绪时返回原因及受影响条目 |
| 提交观察 | 批次、关系 ID、步骤 ID、动作 ID、检查点版本、实际观察及证据引用 | 返回新检查点和后续状态；重复提交相同请求返回原回执，同键不同内容拒绝 |
| 接力及续跑 | 批次、关系 ID、待协助事项 ID、完成信号 | 验证真实完成条件，再恢复未确认步骤；完成信号与实际状态不符时继续等待并说明原因 |
| 提交结果或补传 | 批次、关系 ID、结果版本、证据引用及幂等键 | 返回保存、上传及同步状态；计划关系已失效时保留执行事实并记录同步失败原因 |

项目归属、计划关系、环境和访问权限由 MSP 服务端校验。执行权限复用现有项目角色和 Token scope；结果写入、证据读写继续使用对应权限。启动、续跑、写入及读取均重新核对，避免授权撤销后继续写入。HiFox 任务标识用于关联和去重。历史受控协议的权限校验、回避要求及审计语义按现有路径保留。

### 5.2 持久化与并发

- **批次**记录任务引用、项目和计划、评审范围快照、环境、发起身份、状态和起止时间。去重键按项目、稳定任务引用和启动请求确定。
- **用例执行实例**固定 testPlanCaseId、用例版本、执行契约及引用版本，记录当前步骤、已绑定数据、检查点版本和状态。
- **动作回执**保存动作 ID、预期效果、业务关联标识、关闭状态及核实证据。同一动作结果未知时，登记为待核实。下一次执行先读回执，确认是否允许继续。
- **结果与证据**关联批次、实例及结果版本，分别保存事实、证据处理及正式同步状态。同一结果版本重复回写复用回执；新一次明确重跑有独立批次。
- 单用例同一时间只允许一个有效执行者写入，使用现有租约或版本机制。Agent 失联后由新执行者接续时校验租约及检查点，过期执行者的迟到写入拒绝。优先检查现有表和事务能否复用，只有缺少必要约束时才新增迁移。历史批次和原结果保持可追溯。

## 6. JSON 与恢复规则示例

下面是执行语义示例。它说明字段如何驱动执行，最终字段名需映射到现有结构化契约。

```json
{
  "schemaVersion": 1,
  "goal": "验证待支付订单可以取消",
  "inputs": {
    "order": {
      "requiredState": "PENDING_PAYMENT",
      "selection": ["findMatchingOrder", "prepareTestOrder"],
      "bind": "orderId"
    }
  },
  "steps": [
    {
      "id": "cancel",
      "operation": "cancelOrder",
      "target": "orderId",
      "expectedEffect": "CANCELLED",
      "checkAfterUncertainResult": "queryOrderStatus",
      "retryWhen": "confirmedNoEffectAndNewObservation",
      "evidence": ["orderId", "observedStatus"]
    }
  ],
  "assertions": [
    {"id": "order-cancelled", "field": "order.status", "equals": "CANCELLED"}
  ]
}
```

操作名引用已实现且经项目配置允许的方法。执行器依据实际查询和页面观察判断断言，期望值只参与比对。查询不到首选对象时，按策略查询其他候选；允许准备数据时，创建后要验证状态。取消超时后先查询，已取消则继续断言，确认未生效且满足新观察和重试条件才允许再操作。结果仍未知时，保存证据并挂起该步骤。

| 情形 | 执行器行为 | 用户看到的状态 |
|---|---|---|
| 页面定位失败但可重新识别 | 重新观察页面，确认所在业务状态，按规则换定位 | 恢复中；保留失败和新观察 |
| 数据暂缺且存在准备方法 | 换候选或准备并验证，不改变业务断言 | 数据准备中 |
| 临时网络或浏览器异常 | 保存检查点；恢复后核实页面与数据再继续 | 执行异常或恢复中 |
| 操作可能已经生效 | 先查业务对象，结果不明时挂起 | 待核实；记录原动作及证据 |
| 必须人工扫码 | 显示所需动作和恢复点，其他用例继续 | 待协助 |
| 已观察到业务结果与断言不符 | 保存实际值和证据 | 功能失败 |
| 必要条件无法准备，恢复路径已用尽 | 保留步骤、条件、尝试及影响范围 | 真实阻塞 |
| 未进入执行 | 保留待执行原因，例如范围待确认 | 未执行 |

## 7. 产品文档与执行知识

**产品文档库**以正文在线阅读、创建和编辑为主，复用原件上传、查看、下载和删除。草稿允许编辑，发布产生固定版本；版本差异可在线查看。用例可引用具体需求版本，允许新用例选用最新版本，历史用例和结果继续打开已引用版本。删除和停用前显示影响，已有历史引用保留。多人并发编辑使用版本校验提示冲突。

**执行知识库**保存已验证的导航、操作步骤、数据准备、清理和恢复方法。组织内可跨项目检索有权读取的内容，并校验来源权限。执行时保存版本引用，分别记录找到、读取、采用和实际结果。实际采用记录关联用例、步骤和证据。Agent 可提交修订候选并关联已有知识，现有维护人员按权限编辑和发布。依赖缺失时仅提示该知识所关联的步骤。

产品文档和执行知识可分阶段上线。普通测试任务直接使用已有用例和契约。引用文档或知识的任务在开跑时固定版本，运行过程中出现源权限变化时按现有访问规则处理并记录原因。

## 8. 诊断、实施顺序与验收

记录批次、用例、步骤、阶段、时间、错误分类、traceId 和安全根因类型。覆盖启动校验、数据准备失败、未知写入、恢复耗尽、权限撤销、证据补传及计划同步失败。数据库故障保留经校验的 SQLState 与错误码。日志字段采用白名单，凭据、完整私密 URL、密文、原始报文与含敏感信息的异常内容不得进入日志。通过超时、失联、重复提交和权限撤销故障注入检查诊断及脱敏效果。

## 9. 本方案的核对状态

MSP 交接载荷、计划用例查询、现有受控权限检查、MCP 操作及回写工具、产品文档和知识页面已通过前序源码阅读核对。HiFox 的实际任务字段映射、Agent 运行入口和状态回传尚待核实。本文为实施草案，本轮只新增 Markdown，未修改业务代码或运行应用验证。

### 9.1 开发进度

MSP 计划用例读取已支持可选参数 `includeContractVersion: true`，覆盖内置 MCP 与 Node MCP 转发。返回的 `structuredContractVersion` 是同一项目、用例及来源版本的最新已发布契约版本。缺少匹配版本时省略字段。旧调用保持原响应，查询复用计划用例读取权限及已有契约表。

这个字段只提供版本定位。契约正文读取、批次冻结、HiFox Agent 调用及日常执行权限路径仍待接通。旧的受控协议授权行为保持原样。本次新增查找行为的验证场景包括草稿、旧来源版本及其他项目的契约均不会被返回。

### 9.2 契约正文读取

普通 MCP Agent 先调用 `metersphere.test_plan.cases` 并传入 `includeContractVersion: true`。对于返回 `structuredContractVersion` 的条目，再调用 `metersphere.test_plan.execution_contract`，传入 `projectId`、`testPlanId`、`testPlanCaseId` 和该版本号。HTTP 对应 `GET /api/agent/v1/test-plan/{id}/cases/{relationId}/execution-contract`。返回固定契约版本、来源用例版本、内容摘要和契约正文。正文中的知识引用仍须通过各自的读取权限解析。

服务端使用现有功能用例读取 scope 并校验项目权限和测试计划访问权限。查询同时约束项目、计划关系、当前用例版本、已发布状态和请求的契约版本。关系不存在、版本失配、旧草稿或越权时拒绝返回正文；Agent 应重新读取计划范围确认版本。该入口不创建执行批次，也不授予动作或结果写入权限。

### 9.3 个人 MCP 执行入口

Node MCP 创建执行改为调用现有原生 `metersphere.execution.create`，服务端进入 `createPersonalMcp`，使用个人任务预检、环境和用例范围校验。调用需提供通过预检返回的 `preflightId` 和对应 `environmentProfileId`。查询详情、读取事件、取消及人工登录后继续同样走原生个人任务入口。Node MCP 已新增原生检查点创建工具，已有检查点恢复工具可接续使用。

本阶段复用既有个人任务流程和服务端权限。第 9.2 节读取的结构化契约尚未绑定到个人任务的执行快照，也没有进入 Agent 逐步判断。真实浏览器执行和计划结果回写需要在两者接通后一起验收。

### 9.4 个人任务固定契约版本

在创建个人 MCP 计划任务时，MSP 按本次用例来源版本查找已发布契约，把关系 ID、契约版本及来源版本写入现有执行快照，并随执行合同计算摘要。没有匹配契约的用例继续使用现有执行定义。快照只存版本引用，正文依旧通过现有加密存储读取。

Agent 拿到 taskId 后，可调用 `metersphere.execution.contract.get`，传入 taskId 和 testPlanCaseId 获取冻结契约。服务端检查任务创建者、当前项目及计划读取权限、计划用例关系和契约适用环境。用例随后发布新版本时，既有任务仍读取原先固定的契约；用例从计划移除或权限撤销后，服务端拒绝读取。该入口只读取正文，执行循环尚需消费此正文后提交实际观察。

验证记录：MCP 测试 46 项通过；AgentExecutionServiceTests 与 AgentTestPlanContractLookupTests 共 7 项通过，覆盖快照写入、有效关系、旧版本回读、跨用户拒绝和环境不匹配。没有真实浏览器执行或回写验收记录。

### 9.5 浏览器观察驱动步骤判断

Node MCP 提供 `metersphere.execution.step.decide`。Codex 或其他 MCP 客户端提交任务 ID、计划用例关系 ID、当前契约步骤 ID 和结构化浏览器观察。工具从 MSP 读取任务固定的契约，按契约返回执行下一步、查询其他候选、调用已声明的数据准备方法、核实未知写入结果、重试或复查恢复点。最后一个步骤结束时返回提交观察的指令，执行结果仍由现有服务端事实校验判定。

本工具的输入由浏览器客户端提交，返回判断不会自动操作浏览器、持久化决策或验证证据引用，也不会代替现有的步骤提交与检查点工具。重试分支目前采用一次重试的保守默认值，并要求客户端提交未生效的核查证据引用及条件已变化的观察。已验证 Node MCP 测试 49 项；新增测试按观察序列覆盖数据替换、写入结果核实及恢复判断，尚无真实浏览器至 MSP 回写的验收证据。

### 9.6 读取已保存的执行观察和证据

`metersphere.execution.step.decide` 现在要求传入当前 executionId。MCP 用任务记录校验当前执行代次；需要证据的观察还会检查截图已上传、已脱敏，并且属于同一任务、执行代次和用例。步骤推进额外用 requestId 读取 MSP 的实际步骤结果，只有成功回执与提交证据匹配才返回下一步。契约中的 sourcePosition 对应任务执行步骤的顺序位置；没有映射时停止推进。

对于未确定是否生效的写入，仍先查询业务对象。客户端声称未生效，或只上传截图时，工具只会返回待核实。后续需要能够记录并校验终态无副作用的事实，才能安全放行重试。当前步骤判断仍需要浏览器客户端调用，尚未有真实环境端到端证据。

恢复判断补充：MSP 从当前 executionId 下已保存的最新步骤事实推导已验证步骤。READY 必须按契约顺序请求第一条未完成步骤；RESUMING 返回需重新核实的步骤。旧执行代次的回执不会被当作当前事实。现有后端检查点恢复可能签发新的 executionId，跨执行代次恢复仍需明确继承及核查规则，不能声称已支持完整续跑。

恢复时如 MSP 已签发新 executionId，工具区分当前步骤事实和上次已确认的步骤。来自已恢复检查点的成功步骤返回复核指令，要求浏览器客户端验证其效果并为本次执行提交事实，避免重复执行业务写入。相关规则已通过 Node 回归测试。真正的浏览器操作、当前执行回执和结果回写仍需在已部署测试实例中验证。

### 9.7 产品文档及历史授权入口

业务文档页增加“在线新建”。标题和 Markdown 正文校验后通过现有文档上传接口提交，沿用项目上传权限、后端扫描、异步解析和资产版本生成。提交失败保留正文；切换项目关闭编辑器并清空原项目草稿。产品文档在线编辑、版本差异和用例引用尚未交付。

受控会话授权设置从资产顶部菜单移出，改为从受控会话页进入，并沿用旧路由的角色及可见性校验。这个调整只影响入口，旧会话后端授权校验仍生效。

### 9.8 历史版本对比与步骤提交

资产版本页支持选择同一文档的两个历史版本并并排阅读。分别通过既有来源快照接口读取，权限校验和快照哈希校验在后端完成。切换项目或关闭对话框后忽略上一次的响应。当前实现提供并排阅读，尚无逐行差异标记与在线编辑新版能力。

Node MCP 增加 `metersphere.execution.step.submit_and_advance`，可把当前冻结步骤的实际断言事实和已上传证据交给 MSP。工具使用当前执行及活跃租约提交，随后通过现有步骤回执与证据检查决定下一步。重复调用时读取既有回执，已验证步骤不会再次写入。MCP 测试 56 项通过，其中新增回归覆盖禁止跳步、首次提交和相同请求重读回执。

### 9.9 Markdown 正文修订

已解析的 Markdown 可从业务文档列表打开“编辑正文”。首次编辑读取已上传的 Markdown 原件；之后读取当前发布的正文快照。发布走 `POST /test-assets/documents/{assetId}/revisions`，服务端校验项目上传权限、源文档状态及预期父版本，使用源文档行锁串行发布。旧正文快照与上传原件保留。重复保存相同正文复用当前版本；并发编辑导致版本变化时保留本地草稿并提示。后续解析事件不得覆盖在线修订。

两个在线修订版使用已有只读差异编辑器突出显示正文变化。含旧格式快照时显示两份历史内容供对照。

### 9.10 用例引用产品文档版本

普通项目用例详情增加“引用文档版本”，通过版本列表选择已发布的文档快照。新接口 `POST /test-assets/cases/{caseId}/document-references` 校验项目用例编辑权限、产品文档读取权限和版本归属，按稳定用例 ID 保存引用。重复选择同一个版本不会产生第二条关系。测试资产的关联追溯可按“引用文档版本”筛选。

执行前检查及任务上下文读取基于稳定用例 ID 的文档关系，手动引用只对有文档读取权限的执行主体生效；使用保存的快照版本。删除或停用的文档版本不作为新任务的手动引用来源。已创建任务持有的上下文按原有快照规则处理。

### 9.11 测试计划的 AI 执行记录

普通测试计划详情增加“AI 执行记录”入口，仅对执行记录可见角色展示，并带入当前项目及计划 ID。现有任务搜索接口 `POST /ai/execution/task/search` 同时按项目和计划精确筛选记录及总数。列表可清除计划筛选查看全部任务。个人 MCP 日常任务详情不显示受控授权快捷操作，历史受控会话可从原入口直接访问。

### 9.12 Agent 从任务状态定位下一步

`metersphere.execution.step.decide` 的 READY 和 RESUMING 可省略 stepId；MSP 当前执行的回执决定第一条未完成步骤。执行结果与异常观察仍需指定步骤，避免把证据归给错误用例步骤。读取旧步骤回执时也按服务器当前进度决定去向，已完成步骤不会因较早的回执重放而重复执行；上一代执行已完成的步骤优先返回复核指令。

本地自检 `npm.cmd --prefix metersphere-mcp test` 通过 59 项。新增进程级回归启动真实 MCP stdio 进程并转发至本地 HTTP 测试服务，验证不传 stepId 时实际工具发现、转发、状态解析和选择下一步。HTTP 服务为测试替身；未据此认定真实 MSP 回写验收通过。

### 9.13 按冻结契约读取数据准备方法

个人 MCP 任务通过 `metersphere.execution.data_preparation.get` 读取任务契约中某个数据项固定的方法版本。接口按 taskId、testPlanCaseId、dataKey 定位；不接受任意知识 ID。后端校验活跃令牌、项目与任务归属，使用既有知识读者与来源资产权限检查。步骤判断返回查找候选或准备数据时附上授权方法的步骤及准备内容，无需 Agent 再猜知识入口或版本。实际浏览器执行和数据状态确认仍由执行客户端采集。

### 9.14 批量选择与租约收尾

`metersphere.execution.batch.next` 从 MSP 读取个人任务当前 executionId、实际用例范围和固定契约。它从可执行用例返回下一条未完成步骤。暂停、待人工或缺少结构化契约的用例记录具体原因，随后检查其他用例；若没有可继续用例但仍有待处理项，返回 WAIT_FOR_CASES。已暂停的整个任务返回 WAIT_FOR_TASK。

`metersphere.execution.batch.finish` 重新检查批次，仅在返回 REQUEST_FINALIZATION 时转发 MSP 的完成请求。服务端验证活跃租约对应的任务和执行代次，仍由原有质量判定及写回流程确定最终结果。工具不会把等待或缺少契约直接当作通过。旧文字用例适配及真实环境验收仍有缺项。

### 9.15 单用例等待与旧步骤兼容

`metersphere.execution.step.defer` 用当前租约保存单条步骤的 WAITING_HUMAN 或 WAITING_DATA，要求写入实际观察和证据。它不释放整批租约。批次选择读取当前执行代次最新的步骤事实，保留等待原因并选择其余用例；等待解除后调用 RESUMING 重新核查，再提交本次执行的事实。

未发布独立契约的既有用例可以读取任务创建时固定的运行步骤和断言，返回 contractSource=TASK_LEGACY_SNAPSHOT。后端仍要求用例关联属于原计划，运行步骤 ID 必须与任务快照一致。如果任务明确固定了独立版本，其失效会返回拒绝，不能通过旧格式绕过。旧用例缺失步骤、计划关系失效或读权限异常时返回待处理原因，不计作通过。

本地组合自检通过了真实 MCP stdio 进程中的“第一条等待 → 第二条执行 → 第一条恢复 → 两条事实均已保存后请求收尾”。测试使用独立 HTTP 测试服务替代 MSP，覆盖工具注册、请求转发、状态分支和证据回执读取。它不代表正式部署后的浏览器、数据库写回或证据存储验收。

### 9.16 MCP 批次调用顺序

1. 使用普通项目身份调用 `metersphere.execution.preflight`。用相同计划、用例范围、环境和凭据调用 `metersphere.execution.create`，再领取任务取得 executionId 和租约。
2. 调用 `metersphere.execution.batch.next` 取得首条或下一条用例及步骤。Agent 通过自己的浏览器执行动作并观察真实结果。成功时上传证据并调用 `metersphere.execution.step.submit_and_advance`。结果未知时使用步骤判断要求核实，禁止根据截图直接授权重放。
3. 需要人工或补数据时，使用 `metersphere.execution.step.defer` 保存当次观察，继续调用 batch.next。待依赖恢复，用 RESUMING 取得需复核的步骤后提交新事实。
4. 当批次准备完成，调用 `metersphere.execution.batch.finish` 提交当前任务和租约。用任务状态和事件接口查看最终写回结果，完成接口返回成功仅表示收尾请求已受理。

组合回归执行了真实 MCP 进程的这段工具调用流程，HTTP 端使用测试替身，并校验了收尾锁定当前任务和执行代次。最新定向 Java 测试 32 项及 Node MCP 测试 66 项通过。

### 9.17 冻结独立契约的判定规则及未知写入

个人计划任务创建时，用独立契约的必填断言生成最终质量判定读取的规则，按 sourcePosition 匹配运行步骤。MCP 的步骤指令带回同一份规则。环境不一致、步骤无法完整映射、没有对应必填断言，或契约明确要求独立人工复核时，在任务快照内记录用例级原因。该用例不使用旧规则降级，也不会被计为通过。同批其他用例继续。当前 v2 转换支持文本和布尔相等判定。任务内嵌旧合同继续使用原断言结构。

未知写入可以用单步骤等待工具保存 WAITING_WRITE_RECONCILIATION。再次选用例时暂缓该步骤；恢复时优先要求查询业务状态。通过检查点轮换执行代次后继续继承这项等待，直到当前代次持有验证成功的事实。截图与客户端单方面的未生效声明不自动授权重放。允许确证未生效后重试的通用可信核实能力仍待补齐。

写入超时后，Agent 可调用 `metersphere.execution.step.defer`，填写 WAITING_WRITE_RECONCILIATION、证据引用及用于本次查询的业务标识。只有等待原因成功保存后，工具才返回 QUERY_BUSINESS_STATE。尚未查询的写入在当前代次与检查点恢复后均保持等待。业务标识只透传给本次调用，恢复时可用保留的操作证据定位原对象。

### 未知写入的核实与一次性重试

待核实步骤保存目标业务键的 SHA-256 和证据引用。恢复后的查询指令提供原执行 ID、待核实请求 ID 和运行时步骤 ID。若业务查询确认操作已生效，Agent 提交现状、断言事实和证据，按正常步骤继续。查不到对象或查询超时，继续保留待核实，其他用例可继续。

需要启用自动重试的步骤在结构化 JSON 中设置 `writeRecovery` 为 `SIGNED_TERMINAL_NO_EFFECT_ONCE`。目标系统或可信查询适配器须核实原写入已终态且无副作用，并确认重试条件已改变。适配器保留私钥，MSP 以 `agent.execution.write-recovery-public-key` 配置对应的 Base64 编码 X.509 Ed25519 公钥。常规用户、Agent 和环境授权页均无需逐人配置。

凭据格式为 `expiresMillis.base64urlSignature`。签名消息是以下 UTF-8 紧凑 JSON 数组，所有元素都是字符串，时间用 Unix 毫秒表示。MSP 只接受两分钟有效窗口内的凭据。

```json
["MSP_TERMINAL_NO_EFFECT_AND_CONDITION_CHANGED_V1","taskId","executionId","leaseId","executionStepId","waitingExecutionId","waitingRequestId","businessKeySha256","expiresMillis"]
```

Agent 上传脱敏查询证据后，通过 `metersphere.execution.step.decide` 的 `WRITE_NOT_APPLIED` 观察提交 `recovery`。MSP 校验任务归属、当前租约、冻结规则、最新待核实记录和签名。唯一回执记录在现有步骤结果表，并在同一任务锁内消费。只有首次成功才返回 `RETRY_WRITE_ONCE`。重试许可响应丢失或重试再次超时，仍先查询业务状态。应用未接入可信查询适配器时，该步骤继续等待核实。

### 执行批次与知识采用

从 HiFox 交接启动时，Agent 用普通项目 MCP 身份把通知里的 `source.project_id`、`plan.id`、`event_id` 分别传为预检的 `projectId`、`testPlanId`、`handoffEventId`。MSP 核对已交接事件里的评审成员及当前计划范围，范围变动时在创建任务前返回异常。Codex 独立测试可以直接用项目、计划和测试环境配置发起预检。测试计划的个人 MCP 批次上限为 200 条，用例缺少明确步骤或必要的资产时将单条留给复核，其余用例继续。满足原用例步骤要求的历史文字用例在任务创建时保存快照。

Agent 使用冻结契约引用的知识并完成步骤后，在提交观察时传 `usedKnowledgeRefs`，格式如 `knowledge-id:v2`。MSP 只为通过校验且确认使用的版本保存采用记录。业务知识的版本历史可追溯到步骤结果；搜索或读取知识时不会生成采用记录。

## 日常操作

| 谁 | 做什么 |
|---|---|
| 项目维护者 | 在 MSP 项目配置目标测试环境和入口地址。已有可用环境可直接复用。只有项目要求自动登录时才配置凭据引用。 |
| 测试同事 | 评审通过后在 HiFox 分配 Agent。用现有项目账号和 MCP 凭据即可运行。 |
| Agent | 用预检固定计划和环境，以同一请求 ID 处理网络重试。创建和领取任务后循环调用 `execution.batch.next`、`execution.step.decide` 和 `execution.step.submit_and_advance`。能继续的用例先跑，需要扫码、核实或补传的用例留在任务中。 |
| 测试同事 | 在 MSP 测试计划查看 AI 执行任务、结果和证据，从单条用例追查阻塞原因。文档在测试资产中维护，用例引用指定发布版本。 |

同一逻辑启动重发时复用预检请求 ID、预检记录和创建幂等键。明确重跑时使用新预检和新键。浏览器由当前 Agent 使用，MSP 提供冻结步骤、判断和结果回执。Codex 与 HiFox 分配的 Agent 使用同一组 MCP 工具。直连 MSP 的远程 MCP 和 Node MCP 均提供批次推进、步骤决策、等待、回写和完成入口。
