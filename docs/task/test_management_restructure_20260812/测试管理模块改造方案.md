# 测试管理模块改造方案

## 1. 改造目标

- 将测试用例升级为工作空间级资产，不再受当前项目上下文限制。
- 测试用例支持“项目”和“系统”两种独立组织视角。
- 将用例评审、测试报告迁移至测试计划模块。
- 隐藏测试计划当前已有的报告入口，避免双报告入口并存。
- 将项目管理重构为“项目列表 → 项目详情”，并区分查看详情与进入项目。

## 2. 目标信息架构

```text
测试用例
├─ 用例
│  ├─ 项目
│  └─ 系统
├─ 生成用例
└─ 自动化执行

测试计划
├─ 测试计划
├─ 用例评审
└─ 测试报告

项目管理
├─ 项目列表
└─ 项目详情
   ├─ 基本信息
   ├─ 项目权限
   ├─ 菜单管理
   ├─ 项目版本
   ├─ 成员
   └─ 用户组
```

## 3. 测试用例全局化

### 3.1 数据归属

用例调整为工作空间级资产，其归属关系为：

```text
工作空间
└─ 测试用例
   ├─ 所属项目：非必填
   ├─ 所属系统：非必填
   └─ 所属目录：根据项目或系统视角分别维护
```

允许以下状态：

| 所属项目 | 所属系统 | 含义 |
|---|---|---|
| 有 | 无 | 已按项目管理，尚未按系统分类 |
| 无 | 有 | 全局系统用例，不归属于具体项目 |
| 有 | 有 | 同时参与项目交付和系统资产沉淀 |
| 无 | 无 | 工作空间未分类用例 |

新建、导入和生成用例时，项目与系统均不强制填写，但至少进入“工作空间未分类”目录，确保数据可检索、可分类。取消项目必填后，项目模板、自定义字段、权限及编号规则不得再默认依赖 `projectId`。

### 3.2 项目 TAB

- 左侧展示项目及项目模块树。
- “无所属项目”集中展示未关联项目的用例。
- 延续现有按项目组织、移动、复制、导入和回收站逻辑。
- 列表展示所属项目；跨项目查询必须由服务端分页并执行数据权限过滤。

### 3.3 系统 TAB

- 左侧展示业务系统及系统模块树。
- “待人工分类”展示没有所属系统的用例。
- 支持批量分类、移动至系统模块及解除系统归属。
- 首期不实现自动分类，由用户人工维护。

### 3.4 单一数据原则

项目视角和系统视角展示同一条用例，不复制业务数据。项目目录关系和系统目录关系分别维护。项目或系统归属变化不会生成新用例 ID。

## 4. 用例评审与报告迁移

### 4.1 用例评审

- 从测试用例迁入“测试计划 → 用例评审”。
- 迁移评审列表、创建/编辑、详情及评审用例详情。
- 所属项目改为非必填；未关联项目的评审按工作空间权限控制。
- 关联测试计划为选填，历史记录保持原主键不变。

### 4.2 测试报告

- 隐藏测试计划当前的报告 TAB。
- 将测试用例现有测试报告迁入“测试计划 → 测试报告”。
- 所属项目和关联测试计划均允许为空。
- 历史报告没有计划关系时显示“未绑定计划”。
- 旧菜单地址、消息、收藏和分享链接通过重定向兼容。

## 5. 项目管理重构

### 5.1 项目列表

项目管理默认进入项目列表，字段包括：

- 快捷进入按钮
- 项目 ID
- 项目名称
- 负责人
- 成员数
- 最近更新时间
- 状态
- 操作

项目名称前提供“进入项目”按钮；操作列也提供“进入项目”按钮。项目名称和“详情”进入项目详情，不切换当前项目；“进入项目”更新全局项目上下文并进入项目工作台。

### 5.2 项目详情

承接现有项目与权限页面，顶部展示返回列表、项目 ID、名称、负责人、状态及“进入此项目”按钮。基本信息、权限、菜单、版本、成员和用户组改为详情页内的二级页面。

## 6. 权限设计

- 全局用例列表返回“工作空间级用例权限”与“用户可访问项目权限”的并集。
- 有项目归属的用例，读写操作同时校验项目权限。
- 无项目归属的用例，使用新增的工作空间用例权限校验。
- 系统目录维护和用例系统分类使用独立权限点。
- 统计、导出、搜索、批量操作必须复用同一数据权限条件。

建议新增资源码：

```text
FUNCTIONAL_CASE_PROJECT_TAB
FUNCTIONAL_CASE_SYSTEM_TAB
FUNCTIONAL_CASE_WORKSPACE_READ
FUNCTIONAL_CASE_WORKSPACE_ADD
FUNCTIONAL_CASE_WORKSPACE_UPDATE
FUNCTIONAL_CASE_SYSTEM_CLASSIFY
TEST_PLAN_REVIEW_TAB
TEST_PLAN_TEST_REPORT_TAB
PROJECT_LIST_PAGE
PROJECT_DETAIL_PAGE
PROJECT_SWITCH
```

## 7. 数据模型建议

新增业务系统、系统目录及用例系统关系。`functional_case.project_id` 调整为可空，并补充工作空间 ID，确保无项目用例仍有明确的数据边界。

```text
functional_case
- id
- workspace_id            非空
- project_id              可空
- module_id               可空
- name
- status

business_system
- id
- workspace_id
- name
- status
- sort

business_system_module
- id
- system_id
- parent_id
- name
- sort

case_system_relation
- case_id
- system_id               可空
- system_module_id        可空
- classified_by
- classified_time
```

若确认一条用例只允许归属一个系统，可将系统字段放到用例表；在产品规则未完全确定前，建议使用关系表以保留扩展空间。

## 8. 接口与路由

用例查询增加 `dimension`、`projectIds`、`systemId`、`systemModuleId`、`unassignedProject`、`unclassifiedSystem` 参数；`projectId` 不再必填。

建议路由：

```text
/case-management/featureCase?dimension=project
/case-management/featureCase?dimension=system
/test-plan/caseReview
/test-plan/testReport
/project-management/projectList
/project-management/projectDetail/:projectId/basicInfo
```

旧评审、报告和项目设置路由保留重定向，并透传原查询参数。

## 9. 数据迁移

- 现有用例保留项目及项目模块关系，自动出现在项目 TAB。
- 现有用例的系统关系初始为空，在系统 TAB 的“待人工分类”中展示。
- 为所有用例回填 `workspace_id` 后，再将 `project_id` 改为可空。
- 历史评审、报告不修改主键，只迁移菜单和路由归属。
- 对旧权限点建立新权限点映射，避免升级后角色失权。

## 10. 非功能要求

- 全局列表必须服务端分页，禁止拉取全部项目数据后由前端过滤。
- 项目、系统目录计数必须遵循数据权限。
- 数据迁移脚本必须可重复执行并提供校验 SQL。
- 兼容路由至少保留一个正式版本周期。
- 重点监控全局用例列表、目录计数和跨项目筛选的查询性能。

## 11. 验收标准

- 项目和系统均为空的用例可以正常创建、查询、编辑和分类。
- 项目 TAB 展示项目目录及“无所属项目”；系统 TAB 展示系统目录及“待人工分类”。
- 两个视角中的同一用例保持同一 ID，修改结果实时一致。
- 无项目用例不会绕过工作空间权限，有项目用例不会绕过项目权限。
- 评审和测试报告只在测试计划模块显示，历史链接可访问。
- 项目管理默认进入列表，“进入项目”和“查看详情”行为明确分离。
