# task004 - P0 - 用例快照、步骤标准化与可执行性预检

> 状态：核心已实现（用例版本、完整用例 JSON 和步骤快照已固化；Runner 动作规划联调待完成）

## 目标

将平台已有功能用例转换为 Runner 可执行的稳定快照，并在执行前识别模糊步骤、不可验证预期和高风险动作。

## 实施范围

- 读取用例名称、前置条件、步骤、预期结果、测试数据、附件、版本和计划关联 ID。
- 创建任务时保存用例版本和不可变步骤快照。
- 定义 Action Schema：`NAVIGATE/CLICK/FILL/SELECT/CHECK/UPLOAD/KEYBOARD/WAIT/SCROLL`。
- 定义 Locator Schema：`testId/role+name/label/placeholder/text/css/xpath/semantic`。
- 定义 Assertion Schema：文本、可见性、状态、属性、数量、URL、标题。
- 将文本步骤结构化；模型只输出 Schema，后端完成校验和风险分类。
- 预检环境 URL、前置条件、数据引用、目标动作、预期结果和可验证性。
- 无法明确动作或断言的步骤标记 `NEEDS_REVIEW`，不补造业务预期。

## 数据与接口

- 步骤标准化结果写入 `ai_execution_step`，保存来源步骤 ID 和原始文本。
- 任务详情返回预检结果、阻塞原因和需人工确认步骤。
- 结构化失败不能改变原功能用例内容。

## 验收标准

- 任务运行期间原用例被修改或删除，不影响已确认快照。
- 标准动作和断言都能通过 Schema 严格校验。
- 密码等敏感值使用 `valueRef`，不进入动作快照明文。
- 不可执行步骤在浏览器启动前被明确提示。
- 高风险动作包含风险等级和 `retryable=false` 默认值。

## 测试要求

- 文本用例、步骤型用例、缺失预期、空步骤、重复步骤和版本变更测试。
- Schema 边界、未知动作、恶意脚本、敏感值泄漏测试。

## 当前实施记录

- 创建任务时写入用例版本、完整用例快照和逐步骤快照。
- 步骤缺少描述或预期结果时标记 `NEEDS_REVIEW`。
- 高风险步骤默认 `retryable=false`，原始用例不被修改。
- 任务详情已按执行用例聚合返回步骤快照。
