# task010 - P0 - 步骤结果回写、幂等、部分成功与对账

## 目标

将步骤实际结果、自愈轨迹、截图证据和用例最终状态准确写入计划内或计划外链路，并处理重复提交、部分失败和异步对账。

## 实施范围

- 扩展 `AgentFunctionalCaseSubmitService`/批量提交适配步骤、自愈和证据信息。
- 计划内使用 `testPlanId + testPlanCaseId`，计划外使用 `caseId`，禁止混写。
- 使用 `taskId + caseId + attempt + operation` 生成幂等键。
- 单条回写独立事务；批量部分失败不回滚已成功项。
- 保存用例实际结果、步骤状态、失败分类、附件和执行说明。
- 已完成项正常回写；取消任务的未执行项保持跳过/未执行，不写成功。
- 实现失败重试、最大重试次数、死信/人工处理和定时对账。
- 对账任务校验任务统计、用例终态、必需证据、回写记录和执行历史。
- 只有四项对账一致才能将任务置为 `SUCCESS`。

## 验收标准

- 重复上报不会生成重复执行历史或重复附件关联。
- 单例回写失败时任务为 `PARTIAL_SUCCESS`，失败项可重试。
- 计划内/计划外结果进入正确页面和历史记录。
- 自愈成功与普通成功在结果上均可通过，但报告可区分。
- 浏览器执行成功但证据/回写失败时任务不得成功。

## 测试要求

- 幂等、并发、事务回滚、部分成功、对象存储延迟和服务重启测试。
- 计划被归档、用例被删除/更新、权限变化和重复 retry 测试。

## 2026-08-06 实施记录

- Runner 事件实时更新步骤和执行用例；租约完成后任务进入 `WRITING_BACK`，再由服务端统一汇总。
- 每条用例使用独立 `REQUIRES_NEW` 事务：计划内复用测试计划执行服务，计划外更新功能用例及 Blob，并同步关联计划。
- 回写幂等键包含 task、case、attempt 和结果；单条失败不回滚已成功项，任务按事实落为 `SUCCESS/PARTIAL_SUCCESS/FAILED`。
- 失败重试仅重置失败/阻塞用例及步骤，清除旧租约并重新排队，已成功用例不会再次执行。
- 最终状态同时核对用例计数、回写和证据状态；缺项不会伪造完整成功。

计划内外真实数据、数据库故障和重复完成请求仍需集成测试验证。
