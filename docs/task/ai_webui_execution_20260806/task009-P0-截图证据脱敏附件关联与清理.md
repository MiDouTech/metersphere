# task009 - P0 - 截图证据、脱敏、附件关联与清理

## 目标

打通 Runner 截图采集、脱敏、上传、任务/用例/步骤/自愈关联、预览下载和生命周期清理闭环。

## 实施范围

- 支持步骤后按策略截图、断言失败强制截图、自愈前后截图和任务关键节点截图。
- 复用现有临时附件、正式附件和 MinIO 存储能力。
- 定义证据用途：`BEFORE_STEP/AFTER_STEP/FAILURE/HEALING_BEFORE/HEALING_AFTER`。
- 上传采用临时凭证、大小/类型限制、哈希校验和幂等关联。
- 截图前识别密码框和项目配置的敏感区域，执行遮罩；URL 和日志字段同步脱敏。
- 建立任务、用例、步骤、自愈记录与附件的可查询关联。
- 支持预览、下载权限校验、保留天数、单任务容量和清理任务。
- 上传成功但关联失败时进入对账，避免附件孤儿或证据丢失。

## 验收标准

- 每个失败步骤都可定位到失败截图和错误摘要。
- 自愈前后截图分别保存且顺序明确。
- 密码、Token、Cookie 和配置的敏感区域不出现在证据中。
- 跨项目用户无法预览或下载证据。
- 到期清理不会删除仍被有效执行记录引用的附件。

## 测试要求

- 上传中断、重复上传、哈希错误、关联失败、对象存储不可用测试。
- 截图遮罩、URL/日志脱敏、越权下载和清理边界测试。

## 2026-08-06 实施记录

- Runner 支持步骤后、失败、自愈前和自愈后截图；密码框与配置的敏感选择器在截图阶段统一遮罩。
- 上传要求活动租约和 `redacted=true`，限制 5 MB，校验图片魔数与 SHA-256，并复核 task/case/step 归属。
- 用户侧 DTO 不暴露对象存储内部标识；列表和下载接口均先执行项目权限检查。
- 默认保留 30 天，每小时分批清理；对象删除成功后才把证据状态更新为 `DELETED`。

真实 MinIO 不可用、清理重试和跨项目下载仍属于 task014 环境验收项。
