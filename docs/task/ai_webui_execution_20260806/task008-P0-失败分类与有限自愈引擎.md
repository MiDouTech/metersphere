# task008 - P0 - 失败分类与有限自愈引擎

> 状态：进行中（自愈预算、风险、唯一候选和置信阈值决策已实现；Runner 观察与候选生成待 task006/007）

## 目标

针对定位变化、短暂等待、低风险遮罩等非业务性失败提供有限自愈，同时保证不改变测试意图、不放宽断言、不造成高风险重复操作。

## 实施范围

- 失败分类：定位、不可操作、加载超时、动作无效果、登录失效、断言、业务错误、环境错误。
- 状态链：`STEP_FAILED_INITIAL → HEALING_ANALYSIS → HEALING_ATTEMPT → STEP_SUCCESS_HEALED/STEP_FAILED_FINAL/NEEDS_REVIEW`。
- 基于 DOM、可访问性树、原始定位语义、同义文本和邻近关系生成候选。
- 对候选执行唯一性、可见性、语义一致性、风险和置信度校验。
- 默认单步骤最多 2 次、单用例最多 5 次，并支持任务总预算。
- 自愈后重新执行原始断言，不允许修改预期或删除失败断言。
- 删除、支付、退款、发布、权限变更、批量提交等动作默认不可重试。
- 保存每次自愈的原定位、候选、选择理由、置信度、前后截图、耗时和结果。
- 第一阶段不自动更新原始用例；仅输出“建议维护定位信息”。

## 验收标准

- DOM 层级或非关键属性变化后，可以通过同一语义元素恢复执行。
- 候选不唯一或置信度不足时进入人工确认，不猜测点击。
- 自愈结果不覆盖首次失败记录。
- 自愈成功标记 `healed=true`，任务和报告可查看完整轨迹。
- 高风险和结果未知动作不会被自动重放。

## 测试要求

- 构造 ID 变化、DOM 重排、按钮改名、遮罩、延迟加载和登录失效场景。
- 构造语义相近的危险按钮，验证系统拒绝错误自愈。
- 自愈预算、取消竞争和模型超时测试。

## 2026-08-06 实施记录

- Runner 仅在低风险、可重试、定位类失败且全页只有一个精确语义候选时尝试一次自愈；候选不唯一时直接失败。
- 自愈事件携带 attempt、失败分类、原定位、唯一候选、置信度及前后截图 ID，并落入 `ai_execution_healing`。
- 成功动作记录为 `SUCCESS`；动作再次失败时由后续失败事件更新为 `FAILED`，同时保留耗时和证据关联。
- 高风险动作在任务预检和 Runner 契约层直接拒绝，不会进入自愈；自愈不修改原始用例或预期。

真实页面大规模 DOM 变化、同名危险按钮和结果未知提交仍需在 task014 测试站点完成专项验收。
