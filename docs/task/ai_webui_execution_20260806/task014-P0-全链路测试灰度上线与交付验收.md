# task014 - P0 - 全链路测试、灰度上线与交付验收

## 目标

对第一阶段全链路进行功能、可靠性、安全和兼容性验证，形成可复核的验收报告、灰度计划和回滚方案。

## 实施范围

- 建设稳定 Web 测试站点和 20 条标准功能用例数据集。
- 覆盖手工选例、NL 筛选、范围确认、人工登录、执行、自愈、截图、回写、取消和重试。
- 完成 Schema/协议契约、后端集成、Runner E2E、前端 E2E 和回归测试。
- 故障注入：Runner 断线、浏览器崩溃、网络超时、Provider 失败、附件失败、重复事件和回写失败。
- 安全验证：权限隔离、SSRF、Prompt Injection、敏感数据泄漏、恶意上传和令牌重放。
- 验证数据库升级、Feature Flag、Runner 版本协商和停用回滚。
- 内部测试项目灰度，收集自愈命中、错误动作、失败分类和模型成本。
- 输出已知限制、运维手册、验收证据和上线/回滚结论。

## 必测场景

1. 手工勾选单条及 20 条用例执行。
2. “用户管理 P0 最近失败，排除删除”自然语言筛选并确认。
3. DOM 重排、元素属性变化、延迟加载和低风险遮罩自愈。
4. 同名危险按钮、结果未知提交、高风险动作拒绝自愈。
5. 登录过期、验证码/MFA 转人工并恢复。
6. 计划内与计划外回写、重复上报和部分回写失败。
7. 失败截图、自愈前后截图、脱敏和跨项目访问拒绝。
8. 暂停、取消、Runner 崩溃和任务恢复。

## 发布门槛

- 20 条标准用例连续执行 10 轮，无越权、误操作和高风险重复提交。
- 确定性步骤成功率不低于 95%。
- 结果回写与证据关联准确率 100%。
- 所有失败均有明确状态、错误分类和必要证据，不伪造成功。
- 自愈没有改变原始预期，没有自动修改原始用例。
- 密码、Token、Cookie 和私钥泄漏检查为零发现。
- P0/P1 阻断缺陷清零，回滚演练通过。

## 验收产物

- 自动化测试报告和失败明细。
- 安全测试与敏感信息扫描报告。
- 性能容量基线。
- 灰度观测数据和自愈效果分析。
- 上线检查清单、回滚记录和已知限制。
