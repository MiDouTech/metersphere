# task013 - P1 - 可观测性、断线恢复、配额与运维

## 目标

使 AI Web UI 执行在灰度和生产环境中可监控、可告警、可恢复、可限流，并提供明确运维操作手册。

## 实施范围

- 指标：任务吞吐/耗时/成功率、排队时长、Runner 在线率、心跳延迟、浏览器崩溃、自愈率/误失败率、证据失败率、回写失败率、模型耗时与 Token。
- 日志关联统一使用 taskId、caseId、stepId、leaseId、attempt 和 traceId。
- 告警：Runner 容量不足、任务长时间停留、事件序号缺口、附件积压、回写积压和对账不一致。
- Runner 断线后识别最后安全点，首期按用例边界恢复；结果未知步骤转人工处理。
- 实现组织/项目并发、单任务用例数、模型调用、截图容量和每日任务配额。
- 编写部署、扩缩容、Runner 升级、证据清理、失败重放和应急停用 Runbook。
- Feature Flag 支持项目级启停和自愈独立开关。

## 验收标准

- 可从一个任务追踪到 Runner、步骤、模型调用、证据和回写记录。
- Runner 断线 60 秒内被识别，不发生双执行。
- 队列、附件或回写积压达到阈值时有告警。
- 超出配额时给出明确、可恢复的错误，不静默丢任务。
- 关闭功能开关后不再创建新任务，历史数据仍可查询。

## 测试要求

- 压力、容量、长任务、断线恢复、告警和 Feature Flag 测试。
- 演练 Runner 全部离线、MinIO 不可用、AI Provider 不可用和数据库短暂故障。

## 2026-08-06 实施记录

- 新增管理员接口 `GET /api/ai/execution/operations/summary`，按当前组织返回在线/失联 Runner、活动租约、排队任务、停滞任务、回写积压、证据积压和过期证据数，并给出 `HEALTHY/DEGRADED` 状态。
- Runner 心跳阈值为 90 秒，租约 TTL 为 60 秒；服务端每 30 秒回收过期租约，任务进入 `EXPIRED`，避免旧 Runner 继续产生副作用。
- 事件采用单调序号和事件 ID 幂等；缺口直接拒绝，重复批次跳过已接收序号。
- 证据默认保留 30 天，每小时最多清理 200 个过期对象；存储删除成功后才将数据库状态更新为 `DELETED`。
- 单任务最多 100 条用例，并复用项目 AI 模型白名单、并发和月度 Token 配额。
- 运维操作见 `runbook.md`。
