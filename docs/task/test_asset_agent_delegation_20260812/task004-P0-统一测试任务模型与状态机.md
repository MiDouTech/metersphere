# task004 - P0 - 统一测试任务模型与状态机

## 状态

部分完成（2026-08-12）：`ai_execution_task` 已承载人工、触发器和 Agent 执行并分离运行状态/业务结论；旧模块全部任务模型尚未完成物理收敛。

## 目标

将计划定义与单次执行解耦，以统一任务模型承载人工、定时、CI、事件和 Agent 执行。

## 实现范围

- 演进或适配现有 `ai_execution_task`，建立统一任务主表和任务用例快照。
- 保存来源、目标、环境、能力要求、审批策略、超时、重试和幂等信息。
- 实现 `DRAFT → WAITING_APPROVAL → QUEUED → CLAIMED → PREPARING_CONTEXT → RUNNING → WAITING_HUMAN → SUBMITTING → WAITING_REVIEW → COMPLETED` 状态机。
- 支持取消、释放、重排队和失败终止分支。
- 将运行状态与业务结论分列保存。
- 所有状态变更使用领域服务并写追加事件。

## 不应实现

- 禁止前端、MCP 或 Runner 直接写任务终态。
- 禁止任务执行中动态扩大用例范围。

## 验收标准

- 一个计划能够产生多次独立任务。
- 人工和 Agent 任务共享状态机与报告模型。
- 非法跳转被拒绝且产生审计信息。
- 取消与完成竞态具有确定结果。
- 状态机具备完整单元测试。
