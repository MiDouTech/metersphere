# task019 - P1 - AI 生成用例与变更建议闭环

## 状态

部分完成（2026-08-12）：已支持文档生成结构化草稿、项目评审队列、审核后新增发布及来源关系；修改/废弃建议发布、完整差异算法、质量与安全全套验收尚未实现。

## 目标

在测试资产中心增加 AI 生成用例能力，将业务文档和需求转换为可追溯的结构化用例草稿，并通过质量校验、差异展示和人工评审发布为正式用例版本。

该功能定位为测试资产生产与治理流程，不是独立的通用聊天助手。

## 产品入口

```text
测试资产
└─ 测试用例
   ├─ 功能用例
   ├─ 接口用例
   ├─ 用例评审
   ├─ AI 生成用例
   └─ AI 变更建议
```

同时在业务文档详情、用例列表和覆盖分析中提供带上下文的入口。

## 用户流程

```text
选择业务文档/需求及版本
→ 配置生成范围、类型和策略
→ AI 分析业务规则、风险和验收条件
→ 生成结构化用例草稿
→ 完整性、重复、冲突和可执行性检查
→ 查看来源引用及与现有用例的差异
→ 人工编辑与评审
→ 发布正式用例版本
→ 可选加入测试计划或创建测试任务
```

## 实现范围

### 1. 生成配置

- 选择一个或多个已授权业务文档、需求、章节和固定版本。
- 选择目标项目、模块、用例类型、优先级和标签策略。
- 选择正常、异常、边界、权限、兼容性和数据校验等场景。
- 支持首次生成、变更影响生成和覆盖缺口补充三种模式。
- 展示预计输入范围、生成数量上限和成本提示。

### 2. 生成批次

- 建立 `ai_case_generation_batch` 或等效实体。
- 保存来源资产版本、引用片段、生成模式、模型/Provider、提示模板版本、参数、创建人和状态。
- 支持排队、生成中、待校验、待评审、部分发布、已发布、失败和取消状态。
- 生成过程支持取消、失败重试和分批查看结果。

### 3. 结构化用例草稿

- 建立 `ai_case_generation_item` 或等效实体。
- 输出标题、模块、前置条件、步骤、预期结果、优先级、标签、测试数据、断言和证据建议。
- 每条用例保存来源文档版本、章节和引用片段。
- 保存模型原始输出与解析后的结构化结果，两者明确隔离并按策略脱敏。
- 生成项不能直接写入正式用例表。

### 4. 质量校验

- 必填字段和步骤/预期配对校验。
- 与现有正式用例进行重复和相似度检测。
- 检查同批次用例之间的重复、冲突和不可执行描述。
- 检查是否缺少前置条件、测试数据、明确断言或证据要求。
- 对来源不足、模型推断和低置信度内容进行明确标记。
- 校验结果不以单一综合分数替代具体问题清单。

### 5. 差异与评审

- 新增建议展示拟创建用例及来源依据。
- 修改建议按字段、步骤和预期结果展示旧版与新版差异。
- 废弃建议必须说明文档变更和关联执行影响。
- 支持单条/批量接受、编辑、驳回和退回重新生成。
- 批量发布前需要用例写权限和评审权限；高风险核心用例要求指定评审人。

### 6. 发布与后续动作

- 通过现有功能用例领域服务创建正式用例或发布新版本。
- 保留生成批次、生成项、审批记录和正式用例版本之间的关联。
- 发布后可选择加入用例评审、测试计划或创建测试任务。
- 已发布内容后续修改继续遵循用例版本流程，不能回写覆盖生成记录。

## 权限建议

- `AI_CASE_GENERATION:READ`
- `AI_CASE_GENERATION:RUN`
- `AI_CASE_GENERATION:REVIEW`
- `AI_CASE_GENERATION:PUBLISH`
- 同时校验来源文档读取权限和目标用例写入权限。

模型配置、敏感文档和跨项目来源应遵循组织级 AI 使用策略。

## 安全边界

- 业务文档及网页内容均视为不可信输入，不能覆盖系统指令、权限和安全策略。
- 不向未授权模型发送敏感文档；记录实际使用的 Provider 与数据边界。
- 密码、Token、Cookie、私钥和测试账号凭据不得进入提示或生成结果。
- 模型输出必须经过 Schema 和业务规则校验，禁止直接执行其中的脚本或工具调用。
- 原始输出和日志按项目隔离、脱敏并设置保留期限。

## 不应实现

- 不允许 AI 自动覆盖、删除或发布正式用例。
- 不将聊天记录直接作为正式测试资产。
- 不允许模型自行扩大文档读取和目标项目范围。
- 不把生成数量、篇幅或表面完整度作为唯一质量指标。
- 不因用例由 AI 生成而默认允许 Agent 自动执行。

## API 建议

| 接口 | 用途 |
|---|---|
| `POST /ai/case-generation/preview` | 校验来源、权限和预计生成范围 |
| `POST /ai/case-generation/batches` | 创建幂等生成批次 |
| `GET /ai/case-generation/batches/{id}` | 查询批次、进度与统计 |
| `POST /ai/case-generation/batches/{id}/cancel` | 取消生成 |
| `GET /ai/case-generation/batches/{id}/items` | 分页读取生成项与校验问题 |
| `PUT /ai/case-generation/items/{id}` | 编辑结构化草稿 |
| `POST /ai/case-generation/items/{id}/review` | 接受、驳回或退回生成项 |
| `POST /ai/case-generation/batches/{id}/publish` | 按选择项发布正式用例版本 |

写接口需要幂等键；批量发布应逐条返回成功、失败和原因，不将部分发布显示为全部成功。

## 数据建议

### `ai_case_generation_batch`

至少包含项目、来源类型、来源版本集合、生成模式、模型/Provider、模板版本、参数摘要、状态、统计、成本摘要、创建人和时间。

### `ai_case_generation_item`

至少包含批次、草稿内容、来源引用、目标模块、建议动作、目标用例/版本、相似度、质量问题、评审状态、发布用例/版本和时间。

具体表名和字段需结合现有 AI 生成用例实现盘点后确定，优先演进已有模型，避免重复建设。

## 前端页面

- 生成配置向导：来源、策略、输出目标和确认。
- 生成任务列表：状态、来源、模型、创建人、数量和成本。
- 生成结果工作台：左侧来源/规则，中间草稿，右侧质量问题与引用。
- 差异评审页：按新增、修改、废弃分组展示。
- 发布确认：权限、目标模块、冲突、评审状态和后续动作。

## 验收标准

- 每条生成用例都能追溯到具体业务文档/需求版本和引用片段。
- 未评审生成项无法发布为正式用例。
- AI 不能直接覆盖或删除已有正式用例。
- 修改建议能够展示字段和步骤级差异。
- 重复、冲突、缺失断言和来源不足能够被识别并展示。
- 批量发布部分失败时保留已成功项，并准确显示失败项。
- 发布通过现有用例领域服务并生成正式版本和审计记录。
- 无来源读取权限、无用例写权限或无发布权限的请求均被拒绝。
- 文档提示注入、敏感内容、跨项目越权和重复提交测试通过。
- 发布后的用例可以加入测试计划或创建统一测试任务。

## 验证要求

- 生成批次状态机与幂等单元测试。
- 文档版本、引用片段和用例版本关联集成测试。
- 结构化 Schema、重复检测和差异算法测试。
- 权限、提示注入和敏感信息安全测试。
- 生成、评审、部分发布、计划关联和任务创建端到端测试。
- 不同 Provider 或模型不可用时的降级与错误展示验证。
