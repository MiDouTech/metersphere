# task002 - P0 - 统一术语、领域边界、状态与协议基线

## 状态

部分完成（2026-08-12）：已统一任务运行状态、业务结论和 Agent v1 核心协议；跨执行器全部错误码与版本兼容矩阵仍待补齐。

## 目标

建立平台、MCP、Bridge、Runner 和前端共同使用的领域词汇、状态语义、错误码和协议版本，消除各组件自行解释任务的风险。

## 实现范围

- 定义测试资产、计划、任务、执行器、Agent、Runner、上下文、结果、结论和证据。
- 定义任务运行状态与测试业务结论的独立枚举。
- 定义任务来源、执行器类型、失败分类、人工介入类型和高风险级别。
- 定义事件信封、幂等键、游标、租约和协议版本字段。
- 定义向前兼容规则、废弃周期、未知枚举处理和错误码。
- 输出 JSON Schema/OpenAPI 基线及状态流转表。

## 关键约束

- `COMPLETED` 不能表达测试通过。
- `PRODUCT_FAILED`、`AGENT_FAILED`、`ENV_FAILED`、`DATA_FAILED`、`BLOCKED` 和 `INCONCLUSIVE` 必须可区分。
- 客户端不得自行扩展后端状态流转。

## 验收标准

- 同一状态在所有组件中含义一致。
- 非法状态转换、未知版本和重复事件有明确处理方式。
- 协议可支撑断线重连、重复提交和灰度升级。
- 基线文档与类型定义进入版本控制。
