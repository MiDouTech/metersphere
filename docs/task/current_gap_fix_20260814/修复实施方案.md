# 测试资产与 Agent 功能完整性修复实施方案

## 1. 背景与结论

本方案针对 2026-08-14 复核确认的功能完整性偏差实施修复。平台当前仅供内部使用，因此项目越权和资源级安全增强排在功能闭环之后，但项目归属、固定版本和敏感凭据不落快照仍是不可取消的底线。

系统级用例 Tab 不在本轮范围内。真实 MySQL、MinIO、浏览器和 Bridge 实机验收未执行前，不得把相应验收项标记为通过。

## 2. 修复原则

1. 前端存在的操作必须有真实可调用的后端逻辑，HTTP 方法、路径和关键参数一致。
2. 后端面向用户的业务能力必须有前端入口；协议、Webhook 和内部接口必须明确分类并有测试。
3. 测试资产进入任务后必须形成不可变、可执行、脱敏的版本快照，不能只保存目录元数据。
4. 大文件不直接写入任务 JSON；任务保存固定文件引用、哈希和受控读取信息。
5. 密码、Token、Cookie、私钥不写入资产版本或任务上下文，只保存凭据引用。
6. 单批修复只有在代码、测试和验收证据一致时才完成。

## 3. 第一批：核心功能可用

### 3.1 个人 Token 编辑契约

- 统一使用 `PATCH /personal/agent-tokens/{id}`。
- 前端 API 请求方法与后端 Controller 保持一致。
- 增加契约门禁，校验前后端 HTTP 方法而不只检查函数名。

### 3.2 可执行资产上下文

在现有 `TestAssetCatalogService` 中引入按类型构建快照的能力。六类快照至少包含：

| 类型 | 可执行快照 |
|---|---|
| DATASET | 文件版本行 ID、名称、格式、大小、固定文件版本和受控下载引用；当前数据表未保存文件内容哈希，不伪造 SHA-256 |
| ENVIRONMENT | 环境名称、基础地址、非敏感配置、凭据引用 |
| COMMON_STEP | 参数定义、脚本或步骤正文 |
| API_DEFINITION | 协议、方法、路径、请求参数、请求体、断言和认证引用 |
| EVIDENCE | 任务、用例、步骤、用途、MIME、SHA-256、脱敏状态和受控下载引用 |
| BUG | 标题、描述、编号、状态、标签和负责人 |

快照发布后不可修改。任务引用指定版本时只读取版本快照，不回查最新业务表。

### 3.3 环境选择和校验

- 执行工作台使用环境资产选择器，不再要求用户手填环境 ID。
- 任务创建时校验环境存在、属于当前项目且用户具备读取权限。
- 选择环境后同时写入 `environmentId` 和对应 `ENVIRONMENT assetRef`。

### 3.4 多资产任务

- 工作台支持搜索、添加、移除和清空多个资产，最多 50 项。
- 从资产目录点击“用于任务”时追加到工作台已选资产，不覆盖已有资产。
- EVIDENCE 可以作为参考资产加入任务。
- 后端一次性校验和固定所有资产；任一资产失败时任务创建整体回滚。

## 4. 第二批：页面业务闭环

### 4.1 管理员 Token 筛选

- `AgentTokenPageRequest` 增加 `status`。
- 管理员分页 SQL 同时按关键字和状态过滤。
- 未知状态返回参数错误，不得静默忽略。
- 审计导出保留独立日志筛选语义，不伪装为 Token 列表导出。

### 4.2 证据预览

- 图片和安全文本支持页面预览；其他类型保留下载。
- 预览接口校验任务归属、证据归属、脱敏状态和文件类型。
- HTML、SVG 等主动内容禁止内联执行。

### 4.3 资产关系

补齐 `PRODUCES`、`REPORTS`、`REPRODUCES`、`REFERENCES` 等关系；本轮至少保证任务创建和证据上传能生成任务、用例、步骤、证据之间的关系，并让六类资产在关系页显示真实名称。

### 4.4 路由和权限一致性

- `/test-assets` 根据当前用户权限跳转到第一个可访问页面。
- 业务文档列表、详情、下载统一使用 `FUNCTIONAL_CASE_AI:READ`。
- 上传、重试、删除统一使用 `FUNCTIONAL_CASE_AI:UPLOAD`。
- 页面只展示后端真正支持的筛选条件。

## 5. 第三批：权限、门禁和测试

### 5.1 项目与按钮权限

- 业务文档详情补项目所有权校验。
- 个人中心 Token 页面按 READ、CONNECT、REVOKE 控制入口和按钮。
- 服务层继续保留本人 Token 归属校验。

### 5.2 双向闭环门禁

- 从已分类业务根路由自动定位并扫描对应 Controller，不在 manifest 中维护文件扫描清单。
- 校验前端 API 的 HTTP 方法、路径、业务调用和页面入口。
- 校验 UI、PROTOCOL、WEBHOOK、INTERNAL、LEGACY 分类。
- 校验筛选字段在前端类型、后端 DTO 和查询层同时存在。

### 5.3 测试

- 六类资产分别覆盖目录、详情、固定版本、上下文和权限。
- 个人 Token 覆盖跨用户拒绝和 PATCH 契约。
- 业务文档覆盖列表、详情、下载、重试、删除和项目归属。
- 前端覆盖多资产选择、环境选择、状态筛选、证据预览和权限自适应跳转。

## 6. 完成定义

满足以下条件才允许把本轮代码修复标记为完成；真实环境验收状态必须单独披露：

1. 前端类型检查通过。
2. agent-integration、case-management、system-setting 定向测试通过。
3. UI/API 双向闭环门禁通过，并能拦截 HTTP 方法不一致。
4. 路由 Tab 门禁通过，并覆盖权限自适应默认页。
5. 六类资产上下文测试证明快照不只是目录元数据。
6. 未执行的真实存储、浏览器和 Bridge 验收继续记录为发布前待验收项，不得写成已通过。
