# task002 - P0 测试用例执行元数据补齐

## 目标

补齐测试用例执行相关字段，明确“责任执行人”“最后执行人”“最后执行时间”的语义，并在列表、详情、筛选、排序和变更历史中保持一致。

## 范围

- 功能用例数据模型
- 用例执行状态写入链路
- 用例列表和详情 DTO
- 高级筛选、排序、导出
- 变更历史

## 字段定义

| 字段 | 含义 | 写入规则 |
|---|---|---|
| `execute_user` | 责任执行人/被分配执行人 | 可人工维护 |
| `last_execute_user` | 最近一次更改执行状态的用户 | 仅执行状态变更时写入 |
| `last_execute_time` | 最近一次更改执行状态的时间 | 仅执行状态变更时写入 |

## 实现要点

1. 确认 Flyway 版本号不冲突，迁移脚本必须幂等。
2. 执行状态变更入口统一写入：
   - `last_execute_user = 当前登录用户`
   - `last_execute_time = 当前时间`
3. 以下操作不得更新最后执行信息：
   - 编辑用例内容
   - 修改责任执行人
   - 修改标签、模块、附件、评论
   - 导入非执行结果字段
4. 将执行状态变更写入变更历史。
5. 列表新增“最后执行时间”，详情基本信息新增“最后执行时间”。
6. 历史空值展示为 `-`。

## 验收标准

- 修改责任执行人不改变最后执行人和最后执行时间。
- 修改执行状态会同步更新最后执行人、最后执行时间，并产生变更历史。
- 用例列表、用例详情、测试计划关联用例中的最后执行时间一致。
- 排序、筛选、导出结果与数据库一致。
- Flyway 在空库、已有库、重复部署场景均可正常启动。
