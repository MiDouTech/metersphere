## 总体目标

解决模块切换导致页面状态丢失、数据刷新不一致、缺陷详情残留、测试用例详情信息分散的问题；统一动态业务页面刷新入口，并让测试计划内关联用例与测试用例模块保持字段和 UI 一致。

## 任务清单

| 任务 | 名称 | 优先级 | 依赖 |
|---|---|---|---|
| task001 | 模块状态保持与统一刷新入口 | P0 | 无 |
| task002 | 测试用例执行元数据补齐 | P0 | task001 可并行 |
| task003 | 测试用例详情聚合与交互优化 | P0 | task002 |
| task004 | 测试计划关联用例列表对齐 | P0 | task002 |
| task005 | 缺陷管理列表与详情状态修复 | P0 | task001 |
| task006 | 全链路验收、回归与防退化 | P0 | task001-task005 |

## 总体验收

- 所有动态业务页面具备统一刷新入口，刷新时保留树、筛选、排序、分页、滚动位置和已打开详情。
- 测试用例详情标题下展示评审、测试计划和个人执行进度摘要。
- 测试用例列表、详情、测试计划关联用例均展示一致的执行相关字段。
- 缺陷管理切换模块后不出现列表空白、详情残留或必须手动刷新才能恢复的问题。
- 进度条 hover 时显示明细；颜色、数量、比例与后端统计一致。
- 前端类型检查、后端相关模块编译、关键页面手工验收均通过。

## 风险控制

- 刷新只更新业务数据，不重建页面状态对象。
- 不使用 `window.location.reload()` 作为刷新手段。
- 删除或失效的数据必须有降级逻辑，不能留下空白页面。
- 旧 Tab 配置要兼容过滤，避免用户本地配置导致详情空白。
