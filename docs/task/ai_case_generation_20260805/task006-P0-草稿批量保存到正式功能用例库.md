# task006 - P0 - 草稿批量保存到正式功能用例库

## 状态

部分完成

## 目标

实现用户确认后的草稿批量入库能力。正式用例必须通过现有功能用例领域服务创建，不允许直接 Mapper 插入正式用例表。

## 实现范围

- 新增批量保存接口：`POST /functional/case/ai/draft/batch-save` 或等效接口。
- 入库前执行字段校验：
  - 项目必填。
  - 模块必填或使用默认模块。
  - 模板必填或使用项目默认模板。
  - 用例名称必填。
  - 用例等级必须属于平台枚举。
  - 步骤和预期结果必须对应。
  - 自定义字段满足模板规则。
- 复用 `FunctionalCaseService` 或其新增领域能力创建正式用例。
- 保存成功后草稿状态更新为 `SAVED`。
- 记录正式用例 ID：`formal_case_id`。
- 正式用例保留 `ai_create=true` 或等效 AI 来源标识。
- 支持部分成功、部分失败时的明细返回。

## 约束

- 未经用户确认不得创建正式用例。
- 不得绕过编号、模板、自定义字段、权限、日志、事件、附件等现有规则。
- 不得把草稿状态更新为 `SAVED` 后再执行正式入库。

## 验收标准

- 批量保存后能在【用例】Tab 查询到正式用例。
- 正式用例字段与草稿一致。
- 正式用例保留 AI 来源标识。
- 保存失败的草稿保留失败原因。
- 部分失败不会影响已成功入库的用例状态准确性。

## 验证要求

- 批量入库接口测试。
- 字段校验失败测试。
- 部分成功 / 部分失败测试。
- 正式用例列表查询验证。
- 操作日志验证。

## 执行记录

- 已新增批量保存接口：`POST /functional/case/ai/draft/batch-save`。
- 已按草稿所属项目、创建人进行保存前访问校验。
- 已在保存前校验名称、等级、编辑模式、步骤 JSON、重复提示等草稿状态。
- 已实现模块缺省回落默认模块，模板缺省回落项目默认功能用例模板。
- 已通过 `FunctionalCaseService.addFunctionalCase()` 创建正式功能用例，没有直接 Mapper 插入正式用例表。
- 已设置正式用例 `aiCreate=true`。
- 已在正式创建成功后才更新草稿 `SAVED` 与 `formal_case_id`。
