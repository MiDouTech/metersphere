# task001 P1 角色编辑独立页面

## 目标

将权限控制中的角色新增、查看、编辑从抽屉迁移为可刷新、可收藏、可直接访问的独立页面；成员维护仍保留轻量弹窗。

## 改造范围

- 路由新增 `/setting/system/permission-control/roles/new`、`/setting/system/permission-control/roles/:roleId`。
- 从 `frontend/src/views/setting/system/permissionControl/index.vue` 提取角色基础信息、权限树、权限矩阵和页面容器。
- 列表按钮统一 `router.push`；保存或取消返回列表并保留查询条件、分页和当前 Tab。
- 查看态只读；系统管理员等保护角色继续按后端规则禁改，并显示原因。
- 直接打开不存在、无权限或已删除角色时分别处理 404/403，不回落到空白表单。

## 接口与数据

- 优先复用现有角色详情、新增、更新接口，不新增重复 DTO。
- 页面刷新时按 `roleId` 拉取角色与权限，不依赖列表页内存数据。
- 保存后使用服务端返回数据刷新，避免权限树局部状态与真实结果不一致。

## 验证

- 新建、编辑、查看、浏览器刷新、前进后退和复制 URL 均可用。
- 无权限用户不能通过直接 URL 访问；保护角色不能借由接口修改。
- 权限树、矩阵和原抽屉保存结果一致，失败时保留用户输入并提示明确错误。
- 原抽屉入口及死代码删除后，角色成员弹窗不受影响。

## 完成标准

- 所有角色新增/查看/编辑入口均进入页面，不再出现角色编辑抽屉。
- 路由权限、国际化、面包屑、菜单高亮和自动化测试齐全。
