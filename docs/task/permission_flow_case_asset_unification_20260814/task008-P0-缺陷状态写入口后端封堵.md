# task008 P0 全部缺陷状态写入口后端封堵

## 依赖

task006；建议与 task007 同批联调。

## 目标

消除绕过专用流转接口任意修改缺陷状态的路径，使 Web、批量、导入、同步、Agent/MCP 等所有入口遵守同一流程运行时规则。

## 工作项

- 全仓检索 `status`、`statusId`、通用缺陷 update、批量更新、导入和连接器回写等写入口，建立清单并逐项归类。
- 通用 `updateBug` 检测到状态变化时拒绝并提示使用专用流转接口；内部可信同步若必须写状态，调用明确的领域服务而非直写 Mapper。
- 批量流转逐条校验，不因其中一条有权限而放行整批；返回成功与失败明细。
- Agent/MCP 暴露的状态更新使用 `transitionId` 语义，并返回当前可执行流转供 Agent 选择。
- 删除“找不到角色授权即兼容放行”的默认行为；如需短期兼容开关，默认关闭、记录告警并设删除版本。
- 数据库更新层尽可能增加当前状态条件，禁止最后写入覆盖并发变更。

## 特殊入口

- 新建缺陷可写流程初始状态，不视为状态流转，但必须绑定流程版本且禁止指定非初始状态。
- 数据迁移走 task005 的受控批次，不复用普通业务接口绕过校验。
- 第三方同步与用户主动流转分开标识，均写来源和审计。

## 验证与完成标准

- 建立“写入口—统一服务—测试用例”覆盖矩阵，清单无未处理项。
- 直接调用旧通用接口、批量接口或 Agent 接口提交非法状态均失败。
- 合法流转历史、通知、审计与专用接口一致。
- 兼容开关关闭情况下不存在无角色放行路径。
