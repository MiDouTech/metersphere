# task006 P0 缺陷流程运行时与专用流转接口

## 依赖

task004。

## 目标

由后端针对“用户 + 缺陷 + 当前状态 + 绑定流程版本”统一计算可执行下一步，并通过专用接口完成带并发控制、历史和审计的原子流转。

## 接口

- `GET /bug/{bugId}/transitions`：返回当前状态、绑定流程版本及可见/可操作流转。
- `POST /bug/transitions/batch`：按当前页批量计算，避免列表 N+1；限制批量大小并按数据权限过滤。
- `POST /bug/{bugId}/transition`：接收 `transitionId`、`targetStatusId`、预期更新时间/状态、备注、`override`、`overrideReason`。

## 核心规则

1. 校验缺陷存在、可访问及绑定流程版本有效。
2. 校验请求起点等于数据库当前状态，目标是启用的直接下一步。
3. 普通用户必须命中至少一个流程角色。
4. 系统管理员可绕过角色，但不能绕过前述规则；绕过时原因必填，审计记录前后状态、流转、操作者和原因。
5. 使用乐观锁/条件更新保证并发仅一个成功；冲突返回 409 和最新状态。
6. 状态更新、流转历史和审计在同一事务内完成，事务成功后再触发通知。

## 第三方缺陷

- 第三方连接器提供远端可达状态，运行时再叠加 MeterSphere 流程角色授权。
- 管理员只可绕过角色，不能增加远端未返回的目标状态。
- 先成功调用第三方，再按同步策略回写本地；失败时不得制造本地已成功假象，并记录可重试状态。

## 错误语义

- 403：数据可见但无流程角色操作权。
- 404：缺陷不存在或按安全策略不可见。
- 409：状态已变化、非法下一步、流程版本冲突。
- 422：管理员绕过原因缺失、流转参数不完整。

## 验证与完成标准

- 普通角色、非流程人员、管理员普通命中、管理员绕过均有测试。
- 跨级、停用流转、历史版本、并发、第三方失败和批量权限隔离均被覆盖。
- 查询和执行使用同一规则服务，不出现“菜单可见但提交被另一套规则拒绝”。
