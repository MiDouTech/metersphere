# task004 P0 全局流程模型、版本与发布校验

## 目标

在权限控制中建立平台级唯一的本地缺陷流程定义，完整管理流程自己的状态、流转、角色、授权、版本和发布生命周期。

## 冻结约束

- 平台全部组织共用一个默认已发布流程。
- 已发布版本不可原地破坏性修改；编辑产生草稿新版本。
- 新缺陷绑定创建时的 `workflow_id + workflow_version`，历史缺陷不自动切换。
- 流程中的状态、流转和角色必须按 `flow_id/version` 隔离，禁止复用项目模板状态 ID 形成隐式耦合。

## 后端与数据

- 完善 `workflow_definition` 生命周期：DRAFT、PUBLISHED、ARCHIVED，以及版本、默认标记、发布人和发布时间。
- 为状态、流转、流程角色及授权建立完整流程归属和必要唯一索引、外键/逻辑约束。
- 采用事务和唯一约束保证同一时刻仅一个默认已发布本地 BUG 流程。
- 新建/复制流程必须深复制状态、流转、角色与授权，并重建内部 ID 映射。
- 发布前校验：唯一初始状态、至少一个结束状态、边端点存在、无孤立引用、角色存在、授权引用合法、稳定编码唯一、无不可达必需节点。
- 发布、归档、复制和校验失败写操作日志；发布失败不得留下半发布版本。

## 前端

- 流程控制页参考缺陷模板工作流交互，提供流程列表、版本、草稿/发布/归档状态和画布/矩阵编辑。
- 支持保存草稿、复制、发布前校验结果定位；已发布版本只读并可基于其创建新草稿。
- 明确显示“系统全局生效”，避免误认为只作用于当前组织或项目。

## API 建议

- 流程列表/详情、创建/复制、保存草稿、校验、发布、归档分别建模。
- 发布接口携带预期版本号，冲突返回 409；校验结果返回错误码、对象类型、对象 ID 和可定位字段。

## 测试与完成标准

- 并发发布只能成功一个默认版本。
- 不完整流程不可发布；复制后修改不污染源版本。
- 不同流程相同状态名称互不影响。
- 新建缺陷准确绑定当时发布版本；发布新版本不改变历史缺陷绑定。
- 数据升级、索引、回滚说明和接口测试齐全。
