# task007 P0 缺陷列表/详情共用状态流转组件

## 依赖

task006。

## 目标

让缺陷列表状态列与详情基础信息使用同一运行时接口和同一交互组件，只展示当前缺陷、当前用户可执行的直接下一步。

## 前端实现

- 新建共用 `BugStatusTransitionSelect`，输入缺陷 ID/当前状态，输出流转成功事件，不接收全量状态选项作为业务依据。
- 列表按页调用批量接口；打开单行菜单时允许刷新该行，缓存键包含缺陷 ID、更新时间、用户和流程版本。
- 详情使用单条接口；状态从通用字段编辑中分离，优先采用即时流转。
- 无可执行流转时只显示状态标签，不显示假下拉。
- 管理员因绕过角色才可操作时，选择目标后弹出原因输入框；空原因不可提交。
- 成功后刷新该行/详情和统计；409 时提示状态已变化并加载最新数据。

## 一致性约束

- 组件按 `transitionId` 提交，不能仅提交目标状态文本或任意状态 ID。
- 前端不根据岗位名称自行推导权限，不缓存跨用户结果。
- 基础信息保存失败与状态流转失败分别呈现，不显示整体成功；避免状态混入通用 update 请求。

## 验证与完成标准

- 同一用户、同一缺陷在列表和详情看到完全相同的目标状态。
- 新建只显示配置的“处理中/已拒绝”等直接下一步，非流程人员无入口。
- 管理员绕过弹框、取消、必填、提交和审计关联通过测试。
- 快速连续点击、分页切换、并发冲突和接口失败不会留下错误显示状态。
