# task011 P0 资产导入血缘与引用项目聚合

## 依赖

task010。

## 目标

记录资产源用例与导入后项目用例副本的稳定血缘，并按已确认口径展示“已引用项目”：项目副本实际进入测试计划才计入，项目去重。

## 数据与服务

- 建立资产源用例、目标项目用例、目标项目、导入批次、导入时间和创建人的映射表；目标副本唯一性策略须与导入冲突策略一致。
- 所有从资产导入路径必须在同一业务事务/可靠补偿流程中写血缘，禁止成功导入却永久缺失映射。
- 引用项目查询链路固定为：资产源 → 项目副本血缘 → 测试计划用例关系 → 项目；仅有血缘但无测试计划关系时不计数。
- 同一项目多个测试计划、同一计划多次关联均只返回一次项目。
- 资产软删除不删除血缘、项目副本或历史引用结果；列表默认仍可展示历史引用项目。

## 接口与性能

- 资产分页接口返回去重项目摘要、总数和可按需展开的明细，不由前端逐行请求。
- 为源用例 ID、目标用例 ID、项目 ID、计划用例关系建立查询索引。
- 大量项目时返回前 N 个名称和总数，明细独立分页；禁止一次加载无限列表。

## 历史数据

- `default_hub_case_map` 可确定的映射迁入新表。
- 对唯一内容哈希和审计可确定的记录提供预览后回填；无法可靠判断的标记“历史来源未知”，不得猜测。

## 验证与完成标准

- 仅导入未入计划显示 0；进入计划后显示 1；同项目多个计划仍为 1；不同项目分别计数。
- 删除计划关联后按当前引用口径实时减少，历史审计不删除。
- 跨组织数据不泄露，分页无 N+1，典型大数据量查询满足项目性能基线。
- 导入失败、血缘补偿、资产软删除和历史回填均有测试。
