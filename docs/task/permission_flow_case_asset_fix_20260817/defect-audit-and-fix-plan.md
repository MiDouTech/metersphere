## 缺陷清单

| 编号 | 严重度 | 模块 | 缺陷 | 修复目标 |
| --- | --- | --- | --- | --- |
| DF-01 | P0 | Flyway | V71 发布后修改，已成功执行旧脚本的环境可能 checksum 不一致 | 保持当前脚本不再变更，提供部署前 checksum 检查与 repair 流程 |
| DF-02 | P0 | Flyway | V72 中 DDL 无条件执行，部分执行失败后不能安全重跑 | 改为基于 `information_schema` 的条件 DDL，支持失败记录清理后重跑 |
| DF-03 | P1 | 历史缺陷 | 前端只能按项目整批关联，缺少缺陷级筛选、分页和跨页勾选 | 增加候选缺陷分页接口和筛选条件，前端按缺陷勾选并提交 `bugIds` |
| DF-04 | P1 | 企微岗位 | 预览接口无前端入口，点击按钮直接同步 | 增加岗位预览确认弹窗，显示人数、已存在状态和同步结果 |
| DF-05 | P1 | 用例资产 | 历史同步为同步长事务，无进度、失败明细、重试和断点续跑 | 改为后台批次任务，提供状态查询、失败重试和分项目事务执行 |
| DF-06 | P1 | 用例资产 | 已同步源用例后续修改永远被跳过 | 根据 `source_update_time` 识别变化并更新资产副本 |
| DF-07 | P1 | 权限 | 历史同步使用 IMPORT 权限，与方案 ADD 权限不一致 | 统一为 `CASE_ASSET:READ+ADD`，前后端保持一致 |
| DF-08 | P1 | 缺陷状态 | 测试计划报告直接把状态快照作为 `statusName` | 按状态项/旧状态字典解析中文名称，未知值使用明确兜底 |
| DF-09 | P1 | 服务异常 | 十类页面缺少逐接口 requestId、根因和真实回归记录 | 建立回归矩阵，禁止以单个 Mapper 修改代替全部链路验证 |
| DF-10 | P2 | 权限控制 | 开启、归档、关联、企微同步按钮缺少完整前端权限约束 | 为按钮补齐可见和可操作权限指令 |
| DF-11 | P2 | 缺陷流转 | 无合法下一步时仅通过原生 title 暗示原因 | 显示明确的不可操作原因及提示图标 |
| DF-12 | P2 | 测试 | 核心流程仅有少量单元测试，无真实 MySQL/Flyway/容器验证 | 增加服务测试并保留部署后验证清单 |

## 验收标准

1. Flyway V72 在未执行和部分执行两种状态下均可安全完成。
2. 历史缺陷支持项目、原状态、创建时间、ID/标题筛选，支持分页和跨页勾选。
3. 企微岗位同步前可预览，同步结果清晰可见。
4. 历史用例同步异步执行，可查询进度、失败原因并重试；重复执行不产生重复资产用例。
5. 缺陷列表、详情、回收站、关联页面和报告统一显示中文状态名称。
6. 无权限用户不显示或不能操作对应按钮，后端仍保留最终权限校验。
7. 后端联合编译、专项测试、前端类型检查、XML 和 Flyway 版本检查全部通过。
8. 发布环境完成空库、存量库、失败记录清理后重跑和容器重启验证。

## 部署前必须执行

```sql
SELECT installed_rank, version, script, checksum, success
FROM flyway_schema_history
WHERE version IN ('3.7.2.71', '3.7.2.72', '3.7.2.73')
ORDER BY installed_rank;
```

如果 V71 为成功记录但 checksum 与当前制品不一致，应先备份数据库，再使用与当前制品一致的 Flyway 执行 `repair`；不得直接删除成功记录。失败记录可以在确认实际 DDL 状态后清理并重跑。
