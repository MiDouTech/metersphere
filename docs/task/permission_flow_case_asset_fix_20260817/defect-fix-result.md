## 4. 容器启动与数据库风险

### 4.1 已消除的代码风险

- V72 条件 DDL 可在 Flyway 失败记录清理后安全重跑，避免 MySQL DDL 隐式提交造成二次启动失败。
- 新增迁移版本扫描无重复版本号。
- 三个变更 Mapper XML 均可被 XML 解析器正常加载。
- 历史同步空任务统计使用 `COALESCE`，避免异步任务因空集合产生空指针。
- 历史资产关系断链时不再尝试更新不存在的用例。

### 4.2 发布前必须检查

```sql
SELECT installed_rank, version, script, checksum, success
FROM flyway_schema_history
WHERE version IN ('3.7.2.71', '3.7.2.72', '3.7.2.73')
ORDER BY installed_rank;
```

- V71 若为成功记录但 checksum 与当前制品不一致：先备份数据库，再用与当前制品一致的 Flyway 执行 `repair`；不要删除成功记录。
- V72/V73 若存在失败记录：先核对数据库实际列、索引和表状态，再删除失败记录并重启。V72 已具备重入能力。
- 发布后确认 V72、V73 的 `success=1`，并至少连续重启应用容器两次。

| 编号 | 根因或风险 | 最终处理 |
