# task004 - P0 - 登录态有效 UI 权限聚合与兼容策略

## 状态

未开始

## 目标

在用户登录态中返回当前用户有效 UI 权限集合，支撑前端页面可见、按钮可见和按钮可操作判断，同时保持旧权限兼容。

## 实现范围

- 扩展 `/is-login` 返回用户信息 DTO。
- 按当前用户角色关系聚合 UI 权限。
- 管理员直接返回全权限标识或由前端按 `isAdmin` 短路。
- 按 scope 维度返回权限：
  - system
  - organization
  - project
- 支持旧权限兜底：
  - 未配置 UI 权限时，沿用 `user_role_permission`。
  - 页面可见默认兼容 `READ` 权限。
  - 按钮可操作默认兼容现有操作权限。

## 返回结构建议

```json
{
  "uiPermissions": {
    "system": {
      "visible": [],
      "operable": []
    },
    "organization": {
      "visible": [],
      "operable": []
    },
    "project": {
      "visible": [],
      "operable": []
    }
  }
}
```

## 兼容规则

- 若角色没有任何 `user_role_ui_permission` 记录，进入兼容模式。
- 若角色存在部分 UI 权限记录，只对已配置资源按新规则执行，未配置资源按旧规则兜底。
- 管理员不依赖该集合判断权限。

## 不应实现的内容

- 不在登录态返回全部资源详情，避免 payload 过大。
- 不返回无效、禁用资源。
- 不把单条业务数据权限混入 UI 权限集合。

## 验收标准

- 普通用户登录后能拿到可见与可操作资源编码集合。
- 管理员登录后仍拥有全部权限。
- 未配置 UI 权限的旧角色行为不变。
- 项目切换、组织切换后 UI 权限能重新计算。

## 验证要求

- 多角色合并验证。
- 系统/组织/项目 scope 隔离验证。
- 管理员短路验证。
- 旧权限兼容验证。
