# task007 - P0 - 管理员全权限与存量成员兼容保护

## 状态

未开始

## 目标

确保权限改造不破坏现有管理员成员、内置管理员角色和旧权限体系，避免升级后出现管理员被降权或普通用户权限突然丢失。

## 实现范围

- 明确管理员判定仍基于现有 `admin` 内置角色。
- 前端 `userStore.isAdmin` 保持短路全权限。
- 后端 `SessionUtils.hasPermission` 保持管理员直接通过。
- 权限配置页面对管理员角色只读或禁止保存降权配置。
- 迁移脚本不得删除现有角色关系。
- 对旧角色生成兼容 UI 权限或执行旧权限兜底。

## 风险点

- 部分角色无 UI 权限记录时，若未做兼容，会导致页面或按钮不可见。
- 如果 UI 权限错误写入管理员角色，可能出现前端误隐藏按钮。
- 多角色合并时，需采用“任一角色允许即可允许”的策略。

## 不应实现的内容

- 不修改现有管理员成员关系。
- 不重命名 `admin` 角色。
- 不把管理员全权限依赖于初始化资源是否完整。

## 验收标准

- 升级前已有管理员升级后仍拥有所有权限。
- 管理员不依赖 `user_role_ui_permission` 也可看到全部页面和按钮。
- 旧角色没有 UI 权限记录时，行为与升级前一致。
- 多角色用户权限按并集计算。

## 验证要求

- 存量管理员账号登录验证。
- 新建普通角色旧权限兼容验证。
- 多角色叠加验证。
- 升级迁移后角色关系 diff 检查。
