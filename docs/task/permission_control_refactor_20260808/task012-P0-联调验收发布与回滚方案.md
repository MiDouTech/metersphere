# task012 - P0 - 联调验收、发布与回滚方案

## 状态

未开始

## 目标

建立权限改造的验收矩阵、发布步骤和回滚方案，降低权限系统改造对生产环境的风险。

## 验收账号矩阵

| 账号类型 | 预期 |
| --- | --- |
| 系统管理员 | 所有页面可见，所有按钮可见且可操作 |
| 旧普通角色 | 未配置 UI 权限时行为与升级前一致 |
| 页面不可见角色 | 菜单隐藏，直连拦截 |
| 按钮不可见角色 | 页面可见，按钮不展示 |
| 按钮可见不可操作角色 | 按钮展示但禁用，提示无操作权限 |
| 完整操作角色 | 按钮展示且接口操作成功 |

## 发布步骤

1. 合并数据库迁移脚本。
2. 部署后端服务。
3. 验证新表和初始化资源目录。
4. 部署前端。
5. 使用管理员账号验证全权限。
6. 使用普通账号验证旧权限兼容。
7. 使用测试角色验证新 UI 权限。
8. 验证后端无权限接口返回 403。

## 回滚策略

- 前端回滚：
  - 保留 `v-permission` 兼容旧逻辑。
  - 可通过开关禁用新 UI 权限判断，回到旧权限模式。
- 后端回滚：
  - 保留新增表，不参与权限判断。
  - `/is-login` 可停止返回 UI 权限字段，前端使用旧逻辑兜底。
- 数据回滚：
  - 不删除已有角色关系。
  - 新增 UI 权限表可清空或忽略。

## 风险与应对

| 风险 | 应对 |
| --- | --- |
| 管理员被误降权 | 管理员前后端双重短路，全权限通过 |
| 普通用户升级后页面消失 | 未配置 UI 权限时走旧权限兜底 |
| 前后端权限不一致 | task010 输出权限映射表并补接口测试 |
| 初始化资源缺失 | 未配置资源时旧逻辑兜底，资源目录支持补录 |

## 验收标准

- 发布后管理员权限不变。
- 旧角色权限不变。
- 新 UI 权限配置生效。
- 直接调用无权限接口仍返回 403。
- 出现异常时可通过配置或前端回滚恢复旧权限模式。

## 验证要求

- 生产前预发环境全链路验证。
- 发布后抽检管理员和普通用户。
- 留存验收截图和接口响应记录。
