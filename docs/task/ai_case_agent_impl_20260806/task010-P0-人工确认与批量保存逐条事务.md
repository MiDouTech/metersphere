# task010 - P0 - 人工确认与批量保存逐条事务

## 状态

进行中。已增加显式人工确认标记和前端确认弹窗，并将每条草稿保存改为 `REQUIRES_NEW` 独立事务；待补服务端确认记录、版本快照失效和 Agent `save_case_drafts` 确认状态机。

## 目标

建立草稿到正式功能用例的人工确认边界，并修正批量保存事务，确保未经确认不保存、确认后逐条提交、单条失败不回滚其他成功项。

## 依赖

- task007 草稿工具与校验。

## 实现范围

### 1. Agent 确认边界

- `save_case_drafts` 标记 `requiresUserConfirmation=true`。
- Agent 只能生成保存建议，编排器进入 WAITING_CONFIRMATION。
- 确认记录包含 requestId、toolCallId、draftIds、确认用户和时间。
- 用户修改草稿后，旧确认失效或重新校验版本。

### 2. 保存预览

返回：

- 可保存项。
- 有重复或其他 warning 的项。
- 校验失败项。
- 目标模块、模板和自定义字段摘要。

### 3. 权限

- 保存接口要求 `FUNCTIONAL_CASE_AI:SAVE` 和项目成员校验。
- 确认人必须是当前登录用户。
- 草稿必须属于当前用户、项目和会话。

### 4. 逐条事务

- 每条草稿保存使用独立事务，例如独立 Bean 的 `REQUIRES_NEW`。
- 正式用例创建和草稿 SAVED/formalCaseId 更新在同一单条事务中。
- 单条失败回滚该条并记录失败状态，不影响其他成功项。
- 使用 draftId + version 或幂等键防止重复保存。

### 5. 正式用例领域服务

- 继续调用 `FunctionalCaseService.addFunctionalCase()`。
- 设置 `ai_create=true`。
- 不绕过模块、模板、自定义字段和名称等领域校验。
- 记录来源会话、生成任务或审计关联，不污染正式用例控制字段。

## 验收标准

- 模型无法绕过用户确认创建正式用例。
- 无 SAVE 权限用户不能确认保存。
- 草稿版本变化后不能沿用旧确认。
- 批次中一条失败时，其他成功项仍能查询到。
- 重复提交同一草稿不会创建两条正式用例。
- 成功用例 `ai_create=true`，并可在【用例】页面查询。
- 返回每条草稿的正式用例 ID 或稳定失败原因。

## 测试要求

- 未确认、确认过期、版本变化测试。
- SAVE 权限和跨用户越权测试。
- 批量保存部分成功真实数据库事务测试。
- 重复请求幂等测试。
- 正式用例字段、自定义字段和 `ai_create` 测试。
- 浏览器确认预览到用例查询 E2E。
