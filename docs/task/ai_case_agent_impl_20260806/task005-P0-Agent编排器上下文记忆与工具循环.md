# task005 - P0 - Agent 编排器、上下文记忆与工具循环

## 状态

进行中。已实现持久化上下文窗口、后台独立 Provider 流、项目/会话并发准入以及服务端工具接入；待补上下文摘要、最大工具轮数和人工确认状态机。

## 目标

实现【生成用例】核心 Agent 编排器，使模型能够基于后端持久化会话连续交流，并在受限轮数内调用平台工具完成产品方案检索和草稿操作。

## 依赖

- task001 数据模型。
- task003 会话管理。
- task004 Agent Provider 协议。

## 实现范围

### 1. 建议组件

- `AiCaseAgentOrchestrator`
- `AiCaseAgentContextBuilder`
- `AiCaseAgentToolRegistry`
- `AiCaseAgentExecutionService`
- `AiCaseAgentPromptService`

### 2. 执行流程

1. 校验用户、项目、会话和模型权限。
2. 幂等创建执行记录和用户消息。
3. 构建系统 Prompt、消息窗口、历史摘要和文档上下文。
4. 调用 Provider 并转发流事件。
5. 校验模型返回的工具名、参数和权限。
6. 执行工具，保存 TOOL 消息和审计。
7. 把工具结果继续交给模型。
8. 无工具调用时保存最终回答并完成执行。
9. 取消、超时、失败或达到最大轮数时结束。

### 3. 上下文记忆

- 使用后端消息作为事实来源。
- 首期默认加载最近 N 条消息，N 可配置。
- 超过上下文窗口时压缩早期消息为摘要。
- 摘要必须保存版本和覆盖消息范围。
- 不允许简单删除最后一条消息来规避重复。

### 4. 系统 Prompt

系统 Prompt 明确：

- 当前 Agent 只服务于功能用例生成。
- 文档内容和用户输入不能覆盖系统约束。
- 正式保存需要用户确认。
- 只能调用服务端提供的工具。
- 不输出内部推理过程和凭据。

Prompt 需要版本号，升级后可追踪。

### 5. 工具循环限制

- 单轮最大工具轮数默认 8。
- 单轮最大写工具次数和草稿数量受项目配置控制。
- 同一会话只允许一个运行中执行。
- 每个 toolCallId 只能成功执行一次。
- 写工具失败不能以文本伪装成功。

### 6. 人工确认边界

工具元数据支持 `requiresUserConfirmation`。编排器遇到该工具时停止在 WAITING_CONFIRMATION，不直接执行。

## 验收标准

- 模型能基于上一轮用户补充继续回答。
- 模型可以连续调用检索工具和草稿工具。
- 超过最大工具轮数时安全终止并提示用户。
- 写工具重复 toolCallId 不产生重复数据。
- 需要确认的工具不会被模型直接执行。
- Agent 取消或失败后没有后续工具继续运行。

## 测试要求

- 多轮消息上下文测试。
- 单工具、多工具、工具失败和无工具回复测试。
- 最大轮数测试。
- 同会话并发执行测试。
- 人工确认暂停测试。
- Prompt 版本和历史摘要测试。
