# task015 - P1 - 草稿表单对齐、来源引用与重复检测增强

## 状态

未开始。

## 目标

提升 Agent 草稿的可编辑性、可解释性和质量，使草稿字段体验与手工创建功能用例一致，并增强来源引用和重复识别。

## 依赖

- task007 草稿工具。
- task009 前端工作台。
- task010 正式保存。

## 实现范围

### 1. 表单组件对齐

- 复用手工新建功能用例的模块、模板、等级、编辑模式、步骤、标签和自定义字段组件。
- 避免要求用户直接编辑 steps/customFields JSON。
- STEP/TEXT 切换时提供明确转换或确认。

### 2. 自动保存

- 每个草稿独立 debounce 状态。
- 保存请求携带 version。
- 离开页面、切换会话和关闭详情前 flush。
- 保存中、已保存、冲突和失败状态可见。
- 旧响应不能覆盖更新版本。

### 3. 来源引用

- 按字段或步骤展示 document、section 和 excerpt。
- 点击引用可打开文档定位视图。
- 文档删除或重新解析后展示引用失效。
- 用户可删除错误引用，但不能伪造其他项目引用。

### 4. 重复检测

重复指纹不仅使用名称，还考虑：

- 规范化名称。
- 前置条件。
- 步骤描述和预期结果。
- 编辑模式。

支持与当前用户草稿、项目正式用例进行相似度检测。重复默认警告，项目可配置阻止阈值。

### 5. 质量提示

- 空步骤、弱预期结果、重复步骤和过长文本提示。
- P0/P1 用例缺少关键验证时提示，不自动修改用户内容。

## 验收标准

- 草稿字段与手工新建表单主要字段一致。
- 快速切换草稿不会丢失自动保存内容。
- 乐观锁冲突可以刷新、比较或重试。
- 来源引用可定位且失效状态准确。
- 名称不同但步骤高度相似的用例能产生重复警告。
- 重复警告不默认阻止保存。

## 测试要求

- 表单组件和字段转换测试。
- 多草稿并行自动保存和离开 flush 测试。
- 乐观锁乱序响应测试。
- 来源引用定位和失效测试。
- 重复检测回归样例。
