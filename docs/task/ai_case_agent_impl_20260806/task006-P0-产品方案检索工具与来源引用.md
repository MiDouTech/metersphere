# task006 - P0 - 产品方案检索工具与来源引用

## 状态

进行中。已实现按项目、会话、用户隔离的 `search_product_documents` 章节检索与引用结果；待补语义向量召回、引用真实性回查和质量评测。

## 目标

实现 `search_source_documents` Agent 工具，使模型按当前问题检索用户选中的产品方案相关章节，并为生成草稿提供可验证来源引用。

## 依赖

- task005 Agent 编排器和工具注册中心。

## 当前基础

- 已有来源文档上传、异步解析、摘要、章节和切片数据。
- 当前生成仅拼接摘要和固定 3000 字符章节内容。

## 实现范围

### 1. 工具定义

```json
{
  "name": "search_source_documents",
  "arguments": {
    "query": "string",
    "documentIds": ["string"],
    "topK": 8
  }
}
```

严格拒绝未知字段，并限制 query 长度、documentIds 数量和 topK。

### 2. 权限与范围

- documentIds 必须属于当前 projectId、userId 和会话允许范围。
- 只允许检索 PARSED 状态文档。
- 模型不能自行扩大到未选择文档。

### 3. 首期检索策略

- 基于章节标题、正文和关键词的全文检索或评分。
- 支持中文分词条件下的基本相关性排序。
- 返回片段前去重和字符总量限制。
- 检索策略封装接口，为后续向量检索保留替换点。

### 4. 返回结构

每个片段至少包含：

- documentId、documentName。
- sectionId、sectionTitle。
- excerpt、score。
- parserVersion 或内容 hash。

不得返回对象存储路径、文件服务内部凭据或其他用户文档信息。

### 5. 来源引用

- 草稿工具接收来源引用时，服务端验证 documentId、sectionId 和 excerpt/hash。
- 文档删除或重新解析后，能够识别引用失效。

## 验收标准

- 针对文档中部或后部内容提问时，Agent 不依赖固定前 3000 字也能找到相关章节。
- 无权 documentId 被拒绝。
- topK 和总上下文大小受限。
- 返回来源可追踪到原文档章节。
- 失效或伪造引用不能写入有效草稿。

## 测试要求

- 中文关键词、标题匹配和正文匹配测试。
- 多文档排序与片段去重测试。
- topK、长度和空结果测试。
- 跨用户、跨项目、未选文档和未解析文档测试。
- 来源引用真实性和文档重新解析测试。

## 非目标

- 首期不强制引入向量数据库。
