# task011 - P0 - 权限、治理、内容安全与统一审计

## 状态

进行中。已覆盖 Controller 权限、项目所有权、用户/项目/会话数据隔离、项目组织一致性、模型白名单、并发/Token 统计和关键操作审计；待补工具层统一授权器、内容分类策略和完整越权矩阵测试。

## 目标

将现有权限、模型白名单、并发、Token、文件容量和审计能力覆盖到会话、消息、流式执行和每个 Agent 工具，同时补齐内容安全控制。

## 依赖

- task002–task010 的业务接口和工具。

## 实现范围

### 1. 权限矩阵

| 操作 | 权限 |
| --- | --- |
| 查看会话、消息、草稿、文件 | FUNCTIONAL_CASE_AI:READ |
| 创建会话、聊天、重试、草稿工具 | FUNCTIONAL_CASE_AI:GENERATE |
| 上传、删除、重试解析文件 | FUNCTIONAL_CASE_AI:UPLOAD |
| 确认保存正式用例 | FUNCTIONAL_CASE_AI:SAVE |
| 配置项目模型和配额 | FUNCTIONAL_CASE_AI:CONFIG |

Controller 和 Service/Tool 两层均校验，防止内部调用绕过。

### 2. 数据隔离

- 会话、消息、执行、事件、文档和草稿绑定 projectId + currentUser。
- 个人模型和凭据仅所有者使用。
- 组织和项目模型按授权范围使用。
- 不通过客户端传入 userId 判断所有者。

### 3. 治理覆盖

- 每次 Agent 执行在项目锁内完成并发准入并创建可计数执行记录。
- 所有模型调用，包括重试、回退和摘要调用，记录 Token。
- 用户和项目速率限制使用 Redis 等共享状态；故障降级策略需明确。
- Token 配额支持请求前检查和合理预留/超额策略。
- 文件数量和容量覆盖会话实际归属。

### 4. 内容安全

- 文档内容以不可信上下文包装，不能覆盖系统指令。
- 检测常见 Prompt Injection 并记录安全事件。
- 检测和脱敏密钥、Token、Cookie、Authorization、身份证、手机号等敏感信息。
- 工具参数严格 Schema，未知字段拒绝。
- 返回模型的信息使用最小化原则，不暴露内部路径和控制字段。
- 错误和审计详情落库前脱敏。

### 5. 统一审计

至少记录：

- 会话创建、删除、重命名和模型切换。
- 执行发起、停止、重试、成功和失败。
- Provider 实际模型、回退、Token、耗时和错误码。
- 工具调用、结果、资源 ID 和确认动作。
- 文件和草稿全生命周期。
- 项目治理配置变化。

审计失败策略需要明确，不能只静默吞掉所有异常。

### 6. 配置页面

提供项目管理员可用的项目模型白名单、默认/回退模型、并发、Token 和文件配额页面，或明确首期使用现有项目设置入口。

## 验收标准

- 权限矩阵中的所有无权限调用均返回 403。
- 跨项目、跨用户资源不可读取、订阅、修改或取消。
- 并发、Token、速率和文件限制覆盖全部 Agent 入口。
- Prompt Injection 不能触发越权工具或绕过保存确认。
- 日志和审计不包含凭据及完整敏感文档内容。
- 审计可以按 requestId 还原模型和工具执行链路。

## 测试要求

- 每个权限点的正向和反向测试。
- 跨项目、跨用户、个人模型越权测试。
- 并发竞态、Token、速率和文件容量边界测试。
- Prompt Injection、敏感信息输入输出测试。
- 审计脱敏和审计落库测试。
