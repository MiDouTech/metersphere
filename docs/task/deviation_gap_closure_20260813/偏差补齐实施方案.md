# MeterSphere 测试资产与 Agent 改造偏差补齐实施方案

## 1. 目标

本方案补齐测试资产、AI 生成用例、个人 Agent、任务委派、调度、人工介入、执行评价和安装包发布链路。所有面向用户的能力必须同时具备前端入口、API、服务端业务约束、权限、审计和测试；所有无需前端的接口必须标记为协议或内部接口并提供协议测试。

## 2. 完成定义

单项能力只有同时满足以下条件才可标记完成：

1. 数据模型和迁移可升级、可回滚或可通过功能开关停用。
2. 后端控制器、服务、数据隔离、状态机和幂等逻辑完整。
3. 用户能力有可发现的前端入口，写操作有按钮权限控制。
4. 后端写接口具有权限校验，不能依赖前端隐藏按钮。
5. 高风险操作、授权、策略和发布行为进入审计日志。
6. 后端单元/集成测试、前端类型检查和关键浏览器流程通过。
7. 文档、代码和实际验证状态一致；未验证项不得写为已完成。

## 3. 接口分类

| 类型 | 定义 | 是否要求前端入口 |
|---|---|---|
| UI | 用户或管理员直接使用的业务能力 | 必须 |
| PROTOCOL | Agent、Bridge、Runner 调用的协议接口 | 不要求，但必须有协议测试 |
| WEBHOOK | 外部系统事件接收接口 | 不要求，但必须有签名、重放与审计测试 |
| INTERNAL | 定时扫描、回收、节点路由等内部能力 | 不要求，但必须有服务测试和运行指标 |
| RESERVED | 数据兼容预留，尚未形成完整业务能力 | 不得在前端暴露，不得宣称支持 |

## 4. 目标闭环

```text
业务文档固定版本
→ AI 生成结构化草稿
→ 来源引用、质量校验和人工评审
→ 发布正式用例资产版本
→ 加入测试计划或创建测试任务/调度规则
→ Agent 按能力和权限领取冻结上下文
→ 执行、心跳、证据和结果回传
→ 人工请求、恢复与复核
→ 执行评价和运营治理
```

## 5. 纵向切片

### 5.1 来源文档上下文

- 聊天请求携带 `sourceDocumentIds`。
- 后端校验项目访问权限、文档项目归属和解析状态并限定检索范围；项目业务文档按项目成员共享，不伪装为创建者私有资产。
- 会话保存选择的文档，重试和重新进入页面仍使用同一范围。
- 不支持工具的模型/Agent由平台注入受控文档摘要；支持工具的资源只能检索选中文档。
- 草稿保存文档、章节和引用片段，正式发布生成固定版本关系。

### 5.2 Provider 开关和真实能力

- 全局和 Provider 开关默认关闭。
- 后端返回 `enabled/implemented/verified/available/reason`。
- 个人中心、AI 资源选择和调度规则使用同一能力结果。
- WorkBuddy 未实现正式适配前不可创建连接；Cursor 未满足沙箱要求前不可执行。

### 5.3 个人 Agent 权限和接入状态机

- READ、CONNECT、REVOKE 同时用于前端入口/按钮和后端接口。
- 配对恢复使用 `pairingId`，配对完成绑定返回的 `deviceId`，不选择任意在线设备。
- 授权请求和授权成功分离，只有 `CONNECTED` 才能显示完成。
- 增加连接详情、能力、刷新、影响分析和删除接口及对应前端操作。
- Bridge 版本低于最低版本时禁止执行并提示升级。

### 5.4 项目 AI 治理

- 在“Agent → 能力与授权”提供项目治理入口。
- Provider 白名单、个人 Agent、工具、并发、时长和每日次数由后端强制执行。
- `allowLocalAgentTools=false` 时拒绝工具调用，而不是只隐藏页面。

### 5.5 安装包发布

- 管理员上传、启停、下载、删除；个人用户只下载当前启用版本。
- 使用平台存储配置，不将安装包编入后端镜像。
- 校验 ZIP、manifest、版本、平台、架构、大小和 SHA-256。
- 个人向导展示版本、大小、SHA-256、最低版本和升级状态。

### 5.6 Agent 五页签

- Agent 列表：实例、能力、版本、心跳、并发、任务和隔离状态。
- 能力与授权：执行能力、个人授权、项目治理和工具策略。
- 调度队列：任务、租约、心跳、回收、触发器和历史。
- 执行评价：指标、筛选、人工评分和评价历史。
- Agent 集成：MCP Token、接入配置、Bridge 状态和安装包下载入口。

### 5.7 AI 用例和任务委派

- CREATE 保持完整闭环。
- UPDATE/DEPRECATE 在差异、审批、版本发布全部实现前作为 RESERVED，不暴露入口。
- 发布后支持加入测试计划或创建测试任务。
- 批量发布响应中的正式用例 ID 直接进入后续动作：加入当前项目未归档测试计划，或载入自动化执行工作台；后端仍负责计划归属、用例项目范围、权限、快照和大批量确认校验。
- Agent 通过受控 MCP Tool 创建、修改、停用和立即执行调度规则。

## 6. 前后端能力矩阵

| 能力 | 类型 | 前端 | 后端 | 权限 | 验收 |
|---|---|---|---|---|---|
| 来源文档选择与固定范围 | UI | AI 生成页 | Chat DTO、上下文服务、检索限制 | AI READ/GENERATE | 选 A 不可读 B |
| Provider 开关 | UI | 个人中心、资源选择、调度规则 | Feature Service | 个人 Agent READ | 三处一致 |
| 个人连接管理 | UI | 个人中心 | 连接 CRUD/刷新/能力 | READ/CONNECT/REVOKE | 跨用户拒绝 |
| Bridge 配对认证 | PROTOCOL | 向导只发起和查询 | pairing/challenge/auth/ws | 设备身份 | 重放和撤销测试 |
| 项目 AI 治理 | UI | 能力与授权 | governance | AI CONFIG | 策略强制执行 |
| 安装包管理 | UI | 系统设置 | package service | PACKAGE CRUD | 实际上传下载 |
| Runner 注册和心跳 | PROTOCOL | 仅展示实例 | runner protocol | Runner 身份 | 协议测试 |
| 租约领取与事件上报 | PROTOCOL | 运营查询 | lease protocol | Lease token | 幂等/过期测试 |
| 租约运营查询 | UI | 调度队列 | operations API | EXECUTION READ/RUN | 回收可见 |
| 人工请求响应 | UI | 执行详情 | human request API | EXECUTION RUN | 等待→恢复 |
| 人工评价 | UI | 执行评价 | evaluation API | READ/RUN | 保存和回显 |
| Webhook 触发 | WEBHOOK | 配置和历史 | signed webhook | HMAC | 防重放 |
| Agent 创建触发器 | PROTOCOL | 页面可查看结果 | MCP trigger tools | EXECUTION RUN + scope | Agent→定时任务 |
| UPDATE/DEPRECATE | RESERVED | 不展示 | 仅数据库兼容列，不进入公开 DTO/API | 无外部能力 | 不宣称完成 |
| AI 发布后续动作 | UI | 发布成功弹窗、执行工作台预载 | 正式用例发布、测试计划关联、执行任务创建 | AI SAVE / 计划关联 / EXECUTION RUN | 仅成功用例进入后续流程 |

## 7. 发布门禁

- 扫描前端 API URL，必须能映射后端 UI 接口。
- 扫描 UI 类型后端接口，必须存在前端调用点。
- PROTOCOL/WEBHOOK/INTERNAL 接口必须存在分类清单和测试。
- 所有写接口必须存在后端权限或独立机器身份认证。
- 所有写按钮必须存在前端权限控制。
- 配置字段必须存在执行逻辑消费点。
- 类型检查、后端编译、定向测试、Bridge 测试、迁移版本检查全部通过。
- 真实浏览器/存储/Agent 未验证时必须列为发布阻断项。

## 8. 实施顺序

依次执行 task020—task031。P0 闭环完成且真实环境验收通过后才开放个人 Agent；P1 能力只有在自身纵向切片完整后才能上线。
