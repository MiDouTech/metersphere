## 与需求的主要偏差

### P0 阻断偏差

1. 多节点已通过 Redis Pub/Sub 内部消息总线路由，但 Pub/Sub 不持久化；节点订阅短暂中断时仍可能丢失投递，尚未升级为 Redis Stream/ACK 重投。
2. 没有 Bridge 断线续传的最后确认序号、事件 ACK 和节点重启恢复；仅完成重复序号忽略和序号缺口中断。
3. 无工具 Agent 已复用模型 API 的 JSON 提取、Schema 校验和单次旧 Markdown 兼容修复，并继续经过草稿参数校验、重复检测和草稿创建；但缺少真实 Agent 到草稿保存的集成/E2E。
4. 取消后的迟到 `tool.call` 已显式返回 `AI_AGENT_EXECUTION_TERMINATED` 并补单测；跨用户、跨项目、设备冒用、Prompt Injection 和控制字段覆盖的完整安全自动化仍未完成。
5. 未在真实 MySQL/Redis/WSS 环境运行迁移及协议闭环，无法证明历史库升级和集群行为。

### Provider 偏差

1. WorkBuddy 会员不等同于 Managed Agent SDK 凭据。当前没有正式 SDK 凭据、费用/条款确认和真实购买账号记录，`WORKBUDDY` 保持关闭并显式失败。
2. Codex CLI 适配依赖本机官方登录缓存，但尚未使用用户真实 ChatGPT 会员完成平台聊天、停止、恢复和草稿保存闭环。
3. Cursor headless 模式可能具备文件写入和 Shell 工具；当前只有配置级拒绝，没有随 Bridge 交付的 OS 沙箱，因此不得正式开放。
4. Codex/Cursor 当前声明 `tools=false/files=false`，尚未把 Provider 原生工具事件安全映射为 MeterSphere 工具调用。

### 产品与运维偏差

1. 已提供内部使用的未签名 ZIP、SHA-256、后台版本管理和平台内下载；仍没有代码签名的 EXE/MSIX、客户端强制版本兼容检查、自动升级和分步骤安装进度。
2. 生成用例页尚未完整展示“等待设备/已接收/调用工具”等细粒度状态；不支持文件的 Agent 也缺少显式的上下文降级提示和超限阻断交互。
3. 没有 Provider/用户/项目三级灰度白名单、指标看板、告警和应急禁用演练。
4. 当前没有运行中的前后端服务，本机未发现 Java/Node/Nginx 监听端口，故无法执行浏览器 E2E；这不是代码完成的证明。
5. 本批代码未提交和推送，GitHub 不包含当前未提交实现。

## 安全边界

- 平台数据库只保存设备公钥、配对码/短令牌哈希和白名单 capability 元数据；Bridge 不上传 Cookie、网页登录 Token 或 Provider 凭据。
- Bridge 私钥使用 Windows DPAPI 或 Linux Secret Service 保存；配置文件不保存设备访问令牌。
- Bridge 仅允许出站 TLS/WSS，非 TLS 只能由显式开发开关启用。
- 子进程使用参数数组且 `shell=false`；Codex 在只读沙箱和独立临时目录运行。
- Bridge 上报的账号显示字段会拒绝疑似 Bearer/API key/token，capability JSON 只保留受控键和值类型。
- 项目默认 `allowPersonalAgent=false`，所有 Provider Feature Flag 默认关闭。
