# task012 - P0/P1 - 自动化、真实端到端验收、灰度与上线门槛

## 状态

实现中：已增加资源、配对、握手版本、WSS 序号/背压/接收超时/多节点路由、用例编排/结构修复/取消后迟到工具拒绝及 Bridge 协议单测；真实数据库/Redis、浏览器 E2E、真实 Provider、安全矩阵、性能稳定性和上线证据未完成。

## 目标

建立双通道完整测试矩阵、真实账号验收证据、灰度开关、回滚方案和上线门槛，防止再次出现“代码已存在但环境不可用”的偏差。

## 依赖

- task001–task011。

## 实现范围

### 1. 模型 API 回归基线

必须覆盖：

- 系统模型和个人 API 模型配置、启用和连接验证。
- `/models` 与旧聊天请求兼容。
- Provider 流式、取消、重试、限流、Token 和模型回退。
- 文档、草稿、Schema、重复检测和正式保存。
- Feature Flag 关闭时前后端无用户 Agent 痕迹或副作用。

### 2. Mock Bridge 自动化

构建测试专用 Mock Bridge，不接真实 Provider，用于确定性覆盖：

- 配对与设备身份。
- WSS 握手、心跳、路由和重连。
- 正常 delta、工具调用、完成和失败。
- 乱序、重复、丢失、迟到和损坏事件。
- 取消、取消 ACK、超时和取消后工具调用。
- Gateway 节点与 Redis 故障。

Mock 只用于协议和平台测试，不能替代真实 Provider 验收。

### 3. 权限与安全测试

至少准备：

```text
用户 A / 项目 A 管理员
用户 B / 项目 A 成员
用户 C / 项目 B 成员
无 AI 权限用户
系统管理员
```

覆盖跨用户连接、设备冒用、跨项目会话、伪造资源 ID、配对码重放、WSS 重放、工具越权、路径穿越、命令参数注入和 Prompt Injection。

### 4. 真实 Provider 验收

WorkBuddy 必须完成：

- 真实购买账号官方授权。
- 多轮、流式、停止和至少一个 MeterSphere 工具。
- 授权过期/撤销。
- 会员额度或独立费用确认。
- 从需求到草稿和正式用例闭环。

Codex/Cursor 各自上线前完成同等级验证；未完成则保持 Feature Flag 关闭或实验标识。

真实凭据仅放在受控测试环境的密钥库或测试设备，不进入代码、文档、截图、CI 日志和测试报告正文。

### 5. 浏览器 E2E

至少覆盖：

```text
个人中心安装/配对 Bridge
-> 授权 Agent
-> 进入生成用例
-> 选择模型 API 并聊天
-> 切换 WorkBuddy
-> 上传/选择需求文档
-> 多轮补充需求
-> 生成和修改草稿
-> 刷新页面恢复
-> 用户确认保存正式用例
-> 用例列表查询
-> 撤销 Agent 后不可继续调用
```

### 6. 性能与稳定性

- 设备在线规模和 WSS 连接容量测试。
- 单设备并发、平台多用户并发和 Redis 路由测试。
- 首事件时间、流式吞吐、事件存储增长和清理测试。
- 24 小时 Bridge 重连与心跳稳定性测试。
- Gateway 滚动升级和协议版本兼容测试。

### 7. 灰度

顺序：

```text
总开关关闭发布
-> 内部 Mock Bridge
-> 内部 WorkBuddy 白名单
-> 单项目灰度
-> 小比例用户
-> WorkBuddy 全量
-> Codex/Cursor 独立实验
```

每个 Provider 使用独立开关和用户/项目白名单。

### 8. 回滚

- 首选关闭 Provider 或总 Feature Flag。
- 停止接受新 Agent 执行，允许在安全窗口内完成或取消运行中任务。
- 断开 WSS 时保留历史消息、草稿和审计。
- 不回滚已执行数据库迁移，不删除用户连接和设备记录。
- 模型 API 通道继续服务。

## 验收证据

每项任务状态更新必须关联：

- 代码提交 SHA。
- 测试命令与通过数量。
- 数据库迁移记录。
- 浏览器 E2E 报告和必要截图。
- 真实 Provider、版本、账号类型、验证日期与脱敏结果。
- 已知限制和未完成项。

不得只写“已实现”“已补齐”而无证据。

## 上线门槛

1. task001–task005 P0 自动化全部通过。
2. 原模型 API 通道真实模型联调和浏览器回归通过。
3. 用户/项目/设备/工具越权测试无阻断问题。
4. 平台、日志和网络抓包无第三方凭据泄漏。
5. WorkBuddy 真实账号完整闭环通过。
6. WSS 断线、节点重启、Bridge 重启和取消行为通过。
7. 项目治理、审计、指标和应急禁用完成演练。
8. 用户可随时撤销连接和设备且立即生效。
9. Codex/Cursor 未完成真实验收时不得标记正式可用。
10. 任务文档、部署版本和实际运行结果一致。

## 测试要求

- 后端单元、Repository、集成、权限和安全测试。
- Bridge 单元、协议、进程管理和平台兼容测试。
- 前端组件和 Playwright E2E。
- 真实数据库、Redis、WSS Gateway、文件服务和 Provider 环境。
- CI 不执行需要个人会员的真实调用；真实调用放在受控验收流水线。

## 非目标

- 不以 Mock Provider 结果替代真实产品授权。
- 不在失败时通过关闭安全校验换取测试通过。
