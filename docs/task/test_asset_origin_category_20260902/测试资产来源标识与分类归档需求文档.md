# 测试资产来源标识与分类归档需求文档

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 需求名称 | 测试资产来源标识与分类归档 |
| 适用模块 | 测试资产 |
| 文档版本 | V1.0 |
| 编制日期 | 2026-09-02 |
| 优先级 | P1 |
| 状态 | 待评审 |

## 2. 背景与问题

测试资产当前可展示业务文档、用例资产、测试数据、测试环境、公共步骤、接口资产、执行证据和缺陷资产，并通过资产版本与关联关系进行追溯。但现有模型存在以下问题：

1. 资产列表不能稳定区分由人员建立、AI 生成、文件导入或外部系统同步的内容。
2. 当前资产目录接口中的 `category` 表示文件类型、环境类型、HTTP 方法等技术属性，无法承担业务分类职责。
3. 除用例资产目录外，其他资产类型缺少统一、可维护的分类归档能力。
4. AI 生成资产未在统一位置展示生成批次、来源文档、模型和审核记录。
5. 历史资产来源不完整，若简单默认成人工创建，会产生错误审计信息。

## 3. 目标

1. 所有纳入测试资产中心管理的资产都具有明确的建立方式标识。
2. 人工创建和 AI 创建的资产在列表、详情、筛选及导出中能够清晰区分。
3. 建立方式由可信后端链路写入，普通用户不能伪造或篡改。
4. 支持组织内统一的树形资产分类，资产可归档、筛选和批量迁移。
5. AI 创建的资产可以追溯到生成批次、来源内容、模型及人工审核记录。
6. 历史数据迁移遵循“有证据才认定”的原则，不制造错误来源。

## 4. 非目标

1. 本期不替换各业务模块已有的模块树、文件夹或用例资产目录。
2. 本期不允许 AI 绕过评审直接发布或覆盖正式资产。
3. 本期不建设通用知识库分类系统。
4. 本期不使用资产名称、创建人命名或文本内容猜测建立方式。
5. 资产分类不代替标签；一个资产只归属一个主分类，但可以拥有多个标签。

## 5. 名词定义

### 5.1 建立方式

| 枚举值 | 展示名称 | 定义 |
|---|---|---|
| `MANUAL` | 人工建立 | 用户通过平台页面或受控人工操作创建 |
| `AI` | AI 建立 | 由已登记的 AI 生成批次产生，并经过规定流程发布 |
| `IMPORT` | 导入建立 | 通过 Excel、XMind、文件或批量迁移建立 |
| `SYNC` | 同步建立 | 由外部系统、知识库或项目同步任务建立 |
| `UNKNOWN` | 来源不明 | 历史数据或证据不足，无法可靠判断 |

建立方式描述资产最初进入正式资产库的方式。后续由人工编辑 AI 资产，不改变其建立方式，但需要保留修改人与版本审计信息。

### 5.2 资产分类

资产分类是组织内用于业务归档的树形目录，与资产类型、技术类别及标签相互独立。

示例：

```text
电商平台
├─ 用户与权限
├─ 商品中心
├─ 交易链路
│  ├─ 下单
│  ├─ 支付
│  └─ 退款
└─ 运营后台
```

### 5.3 技术类别

现有 `category` 字段继续表示资产自身的技术属性，例如 `CSV`、`JSON`、`MOCK`、`HTTP/GET`，不得改作业务分类字段。

## 6. 用户角色与权限

| 角色能力 | 建议权限 | 说明 |
|---|---|---|
| 查看来源和分类 | 沿用各资产的 READ 权限 | 有权查看资产即可查看非敏感来源标识和分类 |
| 维护分类目录 | `TEST_ASSET_CATEGORY:MANAGE` | 新建、改名、移动、排序和删除分类 |
| 调整资产分类 | `TEST_ASSET_CATEGORY:ASSIGN` | 单个或批量调整资产所属分类 |
| 查看 AI 来源详情 | `FUNCTIONAL_CASE_AI:READ` 或对应 AI 读取权限 | 可查看批次、模型、来源文档和审核信息 |
| 治理历史来源 | `TEST_ASSET_SOURCE:GOVERN` | 经审计流程修正 `UNKNOWN`，不能普通编辑 |

分类权限不能扩大资产读取范围。用户只有同时具备资产读取权限时，才能看到分类下的具体资产。

## 7. 功能需求

### 7.1 资产来源标识

1. 测试资产列表新增“建立方式”列，以标签形式展示。
2. 标签建议颜色：人工建立为蓝色、AI 建立为紫色、导入建立为青色、同步建立为橙色、来源不明为灰色。
3. 列表支持按一个或多个建立方式筛选，筛选条件由后端参与分页查询。
4. 资产详情展示建立方式、首次建立人或 Agent、首次建立时间和来源说明。
5. 资产导出结果包含建立方式、分类路径和来源引用标识。
6. 来源字段由后端根据可信入口确定：
   - 页面人工新建写入 `MANUAL`；
   - AI 生成批次发布写入 `AI`；
   - 文件导入写入 `IMPORT`；
   - 同步任务写入 `SYNC`；
   - 无可靠证据的历史资产写入 `UNKNOWN`。
7. 新建接口不接受普通前端直接提交任意 `creationSource`。后端根据认证主体和调用链路赋值。
8. 来源修正只能将 `UNKNOWN` 治理为有证据的来源，并记录修改前后值、依据、操作人和时间。

### 7.2 AI 来源追溯

当建立方式为 `AI` 时，必须保存并展示以下信息：

- AI 生成批次 ID；
- Provider 与模型标识；
- 提示模板版本；
- 来源资产及固定版本；
- 来源章节或引用片段；
- 生成时间；
- 生成发起人；
- 评审状态、评审人和发布时间；
- 发布后的正式资产 ID 与版本 ID。

AI 来源详情遵守项目隔离和来源文档权限。无权查看来源正文时，只显示安全提示，不返回文档摘要、引用片段或模型原始输出。

### 7.3 分类目录管理

1. 分类按组织隔离，支持最多 5 层树形结构。
2. 同一父分类下名称不可重复，名称去除首尾空格后长度为 1～100 个字符。
3. 支持新建、改名、移动、排序和删除分类。
4. 支持分类名称关键字搜索，并展开到匹配节点。
5. 删除空分类可直接执行；删除包含资产或子分类的分类时必须选择：
   - 将资产和子分类迁移至指定分类；
   - 将直接关联资产转为“未分类”，并保留或逐级处理子分类。
6. 禁止级联删除资产。
7. 禁止把分类移动到自身或其子节点下。
8. 分类变更写入审计日志。

### 7.4 资产归类

1. 每个资产最多关联一个主分类；未设置时归入“未分类”虚拟节点。
2. 列表支持按分类及是否包含子分类筛选。
3. 支持在资产详情中修改分类。
4. 支持选择多个资产批量移动到目标分类。
5. 批量操作需要逐项进行资产权限、项目或组织边界和资产存在性校验。
6. 批量操作部分失败时，返回每项成功或失败结果，不得展示为全部成功。
7. 同一稳定资产的新版本继承资产分类；发布新版本不创建新的分类关系。
8. 跨项目复制或导入时，默认不直接复用源组织分类 ID，可按分类路径匹配或进入“未分类”。

### 7.5 各 Tab 展示要求

| Tab | 来源标识 | 分类能力 | 说明 |
|---|---|---|---|
| 业务文档 | 必须展示 | 支持 | 上传为人工或导入；知识库同步为同步 |
| 用例资产 | 必须展示 | 支持 | 现有用例资产目录继续存在，新增统一业务分类维度 |
| 测试数据 | 必须展示 | 支持 | 文件类型仍作为技术类别展示 |
| 测试环境 | 必须展示 | 支持 | 不在来源详情或分类接口中泄露密钥 |
| 资产版本 | 必须展示 | 支持按分类筛选 | 显示资产建立方式，同时显示版本创建人与发布时间 |
| 关联追溯 | 展示两端来源 | 支持按分类筛选 | 来源与分类不改变原有关联语义 |
| 公共步骤 | 必须展示 | 支持 | AI 生成脚本也必须经过受控发布链路 |
| 接口资产 | 必须展示 | 支持 | 外部接口同步标记为同步建立 |
| 执行证据 | 必须展示 | 支持 | Runner 或 Agent 自动回传标记为 AI/自动执行来源，具体取值由后端策略统一 |
| 缺陷资产 | 必须展示 | 支持 | AI 自动提缺陷标记为 AI，人工提交标记为人工 |

> “执行证据”是否归入 `AI`，或新增更通用的 `AUTOMATION` 来源，需要在技术评审中最终确认。本期若严格只区分人工与 AI，可将 Agent/Runner 自动产生的证据归为 `AI`。

## 8. 页面与交互

### 8.1 资产列表

- 筛选区增加“建立方式”和“资产分类”。
- 表格增加“建立方式”和“资产分类”两列。
- 分类显示完整路径，过长时省略并通过悬浮展示完整内容。
- 支持勾选资产后执行“批量归类”。
- 没有分类调整权限时不展示编辑入口。
- 来源不明的资产显示提示：“历史来源信息不足，待治理”。

### 8.2 资产详情

增加“资产治理信息”区域：

```text
建立方式：AI 建立
所属分类：交易链路 / 支付
首次建立：AI 用例生成任务 #GEN-1024
发起人：张三
生成模型：Provider / Model
评审人：李四
正式发布时间：2026-09-02 14:30:00
```

人工、导入和同步资产只展示与其来源相关的字段，不显示空的 AI 信息。

### 8.3 分类管理抽屉

- 左侧展示分类树，右侧展示当前分类信息。
- 支持同级新建、子级新建、改名、移动、排序和删除。
- 删除或移动前展示受影响资产与子分类数量。
- 操作成功后保留当前筛选上下文并刷新列表。

### 8.4 页面状态

前端必须处理 loading、empty、success、validation-error、permission-denied、network-error 和 server-error。未知错误显示安全的通用提示和 `traceId`，不得展示异常类名、SQL 或堆栈。

## 9. 数据模型建议

### 9.1 `test_asset_metadata`

用于保存稳定资产级别的治理元数据，不与单个版本绑定。

| 字段 | 类型建议 | 约束与说明 |
|---|---|---|
| `id` | varchar(64) | 主键 |
| `organization_id` | varchar(64) | 必填，组织隔离 |
| `project_id` | varchar(64) | 项目型资产必填；组织级资产可按模型约定为空或使用 Hub 项目 ID |
| `asset_type` | varchar(32) | 必填 |
| `asset_id` | varchar(64) | 稳定资产 ID，必填 |
| `creation_source` | varchar(16) | `MANUAL/AI/IMPORT/SYNC/UNKNOWN` |
| `category_id` | varchar(64) | 可空，关联分类 |
| `source_reference_type` | varchar(32) | 生成批次、导入任务、同步任务等 |
| `source_reference_id` | varchar(64) | 来源记录 ID |
| `created_by_actor_type` | varchar(16) | `USER/AGENT/SYSTEM` |
| `created_by_actor_id` | varchar(64) | 用户、Agent 或系统主体 ID |
| `create_time` | bigint | 首次进入正式资产库时间 |
| `update_user` | varchar(64) | 最后治理操作人 |
| `update_time` | bigint | 最后治理时间 |

唯一索引：`organization_id + project_id + asset_type + asset_id`。同时为来源筛选和分类筛选建立组合索引。

### 9.2 `test_asset_category`

| 字段 | 类型建议 | 约束与说明 |
|---|---|---|
| `id` | varchar(64) | 主键 |
| `organization_id` | varchar(64) | 必填 |
| `parent_id` | varchar(64) | 根节点为空 |
| `name` | varchar(100) | 必填 |
| `normalized_name` | varchar(100) | 用于同级名称唯一校验 |
| `path` | varchar(1024) | 可选的查询加速字段 |
| `level` | int | 1～5 |
| `sort` | bigint | 同级排序 |
| `deleted` | bit | 软删除 |
| `create_user/create_time` | - | 审计字段 |
| `update_user/update_time` | - | 审计字段 |

唯一约束：组织内同一有效父节点下 `normalized_name` 唯一。

### 9.3 AI 来源关联

优先复用已有 AI 生成批次和生成项表。`test_asset_metadata.source_reference_id` 指向发布该正式资产的生成项或批次；具体引用片段、模型和审核信息仍由 AI 生成领域保存，避免重复存储。

### 9.4 审计

来源治理、分类创建、分类移动、分类删除和资产归类必须记录统一审计事件。审计中只保存安全元数据，不保存文档正文、密钥或模型原始输出。

## 10. API 建议

### 10.1 分类接口

| 方法与路径 | 用途 |
|---|---|
| `GET /test-assets/categories/tree` | 查询当前组织分类树 |
| `POST /test-assets/categories` | 新建分类 |
| `PUT /test-assets/categories/{id}` | 修改名称或父分类 |
| `PUT /test-assets/categories/reorder` | 调整同级顺序 |
| `DELETE /test-assets/categories/{id}` | 删除并指定迁移策略 |

### 10.2 资产治理接口

| 方法与路径 | 用途 |
|---|---|
| `GET /test-assets/{assetType}/{assetId}/metadata` | 查询来源、分类和安全来源摘要 |
| `PUT /test-assets/{assetType}/{assetId}/category` | 修改单个资产分类 |
| `POST /test-assets/category-assignments/batch` | 批量归类，逐项返回结果 |
| `POST /test-assets/source-governance` | 有审计地修正历史来源 |

现有 `/test-assets/catalog`、`/test-assets/documents`、`/test-assets/versions` 和 `/test-assets/relations` 增加以下可选查询参数：

- `creationSources`；
- `categoryId`；
- `includeDescendants`。

现有返回对象增加：

- `creationSource`；
- `creationSourceLabel` 或由前端本地化映射；
- `categoryId`；
- `categoryName`；
- `categoryPath`；
- `sourceReferenceType`；
- `sourceReferenceId`，仅在有权查看时返回。

## 11. 后端规则

1. 所有读写操作校验组织、项目和资产权限。
2. 分类归属必须与资产处于同一组织。
3. 不信任客户端传入的 `organizationId`、`creationSource` 或创建主体。
4. AI 发布服务、导入服务和同步服务通过服务端上下文写入来源。
5. 业务事务与来源元数据写入应保持一致；不能出现资产创建成功但来源元数据静默失败并仍返回成功。
6. 若短期无法跨服务使用单事务，应采用事务消息、Outbox 或可重试补偿，并对外暴露明确的治理状态。
7. 删除源业务资产时，治理元数据按既有软删除和审计策略保留或归档。
8. 查询不存在、跨项目或无权限的资产时返回安全的统一错误协议 `{ code, message, details?, traceId? }`。

## 12. 历史数据迁移

1. 新建分类表和治理元数据表。
2. 为所有现存资产幂等补建 `test_asset_metadata`。
3. 仅在以下存在可靠证据时回填来源：
   - 有 AI 生成批次和正式资产关联：`AI`；
   - 有导入任务明细：`IMPORT`；
   - 有同步任务明细：`SYNC`；
   - 有明确人工页面创建审计：`MANUAL`。
4. 其他历史资产统一为 `UNKNOWN`。
5. 迁移输出各资产类型的总数、成功数、各来源数量、失败数和失败明细。
6. 迁移脚本必须支持重复执行，并验证迁移前后资产数量不变。
7. 首次上线后提供“未分类”和“来源不明”治理视图。

## 13. 异常与边界条件

| 场景 | 预期行为 |
|---|---|
| 分类名称为空或超过长度 | 前后端均拒绝并给出可理解提示 |
| 同级分类重名 | 返回冲突错误，不覆盖已有分类 |
| 分类层级超过 5 层 | 拒绝创建或移动 |
| 分类移动形成循环 | 拒绝操作 |
| 删除含资产分类 | 必须提供迁移策略 |
| 批量归类部分资产无权限 | 有权限项可成功，无权限项返回明确失败原因 |
| AI 记录缺少生成批次 | 不允许以 `AI` 正式发布，或进入明确的治理失败状态 |
| 来源文档无权访问 | 隐藏来源正文，只返回无权限提示 |
| 来源字段与可信链路冲突 | 后端拒绝并记录安全审计 |
| 历史来源无法判断 | 保持 `UNKNOWN`，不得猜测 |
| 分类已被并发删除或移动 | 返回冲突并要求刷新 |

## 15. 验收标准

1. 人工、AI、导入、同步和来源不明资产在列表和详情中有明确标识。
2. 所有资产列表可按建立方式进行服务端筛选，分页统计正确。
3. 普通前端请求不能将人工创建伪装为 AI 创建，反之亦然。
4. AI 建立资产可以追溯到生成批次、固定来源版本、模型和审核记录。
5. 无来源读取权限时，不泄露来源文档内容和模型原始输出。
6. 用户可建立最多 5 层分类，并进行改名、移动和排序。
7. 用户可对单个或多个资产归类，并按分类及子分类筛选。
8. 删除分类不会删除资产；包含内容时必须按用户选择迁移或转为未分类。
9. 资产发布新版本后继承原分类和最初建立方式。
10. 批量归类部分失败时，前端准确展示成功和失败项。
11. 历史迁移前后资产数量一致，无法证明来源的资产均标记为来源不明。
12. 所有接口满足组织隔离、项目隔离、权限校验和统一错误协议。
13. 分类及来源治理操作具备可查询审计记录。

## 16. 测试要求

### 16.1 单元测试

- 建立方式枚举和可信来源判定；
- 分类名称、层级、同级唯一和循环校验；
- 分类删除迁移策略；
- 资产分类继承和来源不可变规则；
- AI 来源权限裁剪。

### 16.2 后端集成测试

- 人工、AI、导入、同步四类创建链路写入正确来源；
- 各资产类型列表按来源和分类查询；
- 分类 CRUD、移动、删除和批量归类；
- 组织、项目和资产权限隔离；
- 批量部分成功与幂等；
- 数据迁移前后数量和关系对账。

### 16.3 前端测试

- 来源标签及筛选映射；
- 分类树创建、移动、删除和空状态；
- 单个及批量归类；
- loading、empty、validation-error、permission-denied、network-error 和 server-error；
- 长分类路径和大数据分页。

### 16.4 端到端冒烟测试

1. 人工创建资产，确认来源为人工建立并完成归类。
2. 从业务文档发起 AI 生成，经评审发布，确认来源为 AI 且追溯完整。
3. 导入资产，确认来源为导入建立。
4. 按来源与分类组合筛选，确认分页总数正确。
5. 批量移动资产分类，并验证无权限项的失败提示。
6. 删除包含资产的分类，验证资产迁移且未被删除。

### 16.5 工程验证

- 相关后端单元与集成测试；
- 前端类型检查和 lint；
- 前端生产构建；
- 后端编译或打包；
- 数据库迁移从干净库和代表性存量库执行；
- Docker 镜像构建、容器启动和健康检查；
- 核心流程端到端测试。

## 17. 发布与回滚

1. 先发布兼容性数据库结构和后端读写能力，再发布前端入口。
2. 历史元数据回填采用可观察、可重试的批处理，不阻塞核心资产读取。
3. 灰度期间允许无 metadata 的资产按 `UNKNOWN + 未分类` 安全展示。
4. 回滚前端不删除新增数据；回滚后端时保留新表，避免治理数据丢失。
5. 上线监控元数据缺失率、来源不明占比、归类失败率、越权拒绝数和迁移失败数。

## 18. 待评审决策

1. 执行证据由 Runner 自动产生时，应归为 `AI`，还是新增 `AUTOMATION` 建立方式。
2. 分类采用纯组织级，还是允许组织级模板加项目级分类。
3. 用例资产现有目录与统一分类是否需要自动映射，还是保持完全独立。
4. 来源治理是否允许将已确认来源再次修正；建议默认只允许 `UNKNOWN` 转为确定来源。
5. 跨组织复制资产时是否保留原分类路径文本用于目标组织匹配。

## 19. 完成定义

只有来源字段、分类目录、前后端查询与写入、数据迁移、权限、审计、自动化测试、构建、容器健康检查和端到端核心流程全部通过，才可标记为“完成”。任一链路缺失时必须标记为“部分完成”或“阻塞”。
