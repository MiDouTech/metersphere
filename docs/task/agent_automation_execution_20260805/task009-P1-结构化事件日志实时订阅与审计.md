# task009 - P1 - 结构化事件日志、实时订阅与审计

部分完成

- 任务创建、确认、取消、登录恢复、重试、回写成功/失败会追加结构化事件。
- 已验证：接口与前端轮询代码已落地；尚未实现 SSE/WebSocket，也未补断线重连专项测试。

## 目标

建立只追加结构化事件日志和实时订阅机制，使自动化执行过程可追踪、可恢复、可审计。

## 实现范围

- 每条事件至少包含：
  - `taskId`
  - `caseId`
  - `stepId`
  - `sequence`
  - `timestamp`
  - `level`
  - `eventType`
  - `message`
  - `artifactIds`
  - `sanitizedMetadata`
- 日志使用只追加事件流，不覆盖历史事件。
- 前端通过 SSE 或 WebSocket 按游标订阅。
- 断线后支持从最后游标继续读取。
- 所有范围确认、会话接管、登录、点击、输入、文件上传、断言、回写、取消和重试都生成审计事件。
- 支持按级别、用例、步骤筛选日志并导出。

## 不应实现的内容

- 不允许普通日志记录密码、Token、Cookie、私钥。
- 不允许前端自行伪造执行成功事件。
- 不允许事件序号重复或乱序导致恢复错误。

## 验收标准

- 执行过程可按事件流完整还原。
- 页面刷新或连接中断后可从游标继续读取事件。
- 审计事件包含操作人、时间、对象、动作和结果。
- 日志导出内容已脱敏。

## 验证要求

- 事件追加单元测试。
- SSE/WebSocket 断线重连测试。
- 日志筛选与导出测试。
- 脱敏规则测试。
