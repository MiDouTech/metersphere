## 总体目标

在 MeterSphere 中建设 Agent 自动化执行能力，形成“Agent 解析项目/计划/用例范围 → 后端确定性确认 → 创建执行任务 → 调度受控 Runner 或原生执行引擎 → 采集日志证据 → 按计划内/计划外链路回写结果”的闭环。

本次任务拆分不表示功能已实现。所有任务默认状态为“未开始”，只有完成代码实现、接口联调、页面验证和验收项验证后，才允许更新为“已完成”。部分完成必须明确记录剩余事项。

## P0 交付目标

- 外部 Agent 只能通过 MeterSphere MCP/API 访问平台数据，不得直连数据库。
- 后端集中完成项目、测试计划、用例范围解析，不允许客户端各自实现选择规则。
- 未指定项目时只提示补充项目，不猜测、不执行。
- 指定项目和具体用例时，仅执行确认匹配的用例。
- 仅指定项目时优先选择满足规则且已关联功能用例的测试计划。
- 无可执行计划时，经范围确认后才能降级执行项目全部有效功能用例。
- 新增 MCP Tools 覆盖计划检索、计划用例、执行任务创建/查询/事件/取消/恢复。
- 用例列表【AI执行】只处理已勾选用例，并经过后端权限复核。
- 计划内和计划外结果分别进入正确的现有回写链路。
- 单条回写失败时任务标记 `PARTIAL_SUCCESS`，不得显示为 `SUCCESS`。

## P1 交付目标

- 在缺陷管理一级导航下新增【自动化执行】页面。
- 页面左侧为 AI 对话和范围确认，右侧为执行视窗、步骤、日志、证据和回写状态。
- 复用【生成用例】模块的 Provider Selector、系统模型、个人模型和 OAuth/Agent 网关连接能力。
- 事件日志通过 SSE 或 WebSocket 支持按游标增量读取，断线后可继续。
- Runner 支持受控浏览器/桌面会话、已登录会话授权接管、人工登录暂停与恢复。

## P2 交付目标

- 凭据仅保存引用，不保存明文。
- Cookie、Token、密码、私钥不得进入模型上下文、普通日志或截图。
- 目标域名使用项目白名单，高风险动作默认禁止。
- 支持截图、视频、HAR、DOM 快照等证据策略与容量/保留期限治理。

## 总体验收标准

- 所有任务状态、验证证据和剩余事项必须如实记录。
- 未实现、部分实现、未测试、未验证内容不得标记为已完成。
- Agent 侧 MCP 包保持薄封装，业务规则、权限、幂等、状态机和事务必须落在 MeterSphere 后端。
- 创建任务前必须固定执行范围快照，执行过程中不得静默扩大范围。
- 执行成功但回写失败必须标记 `PARTIAL_SUCCESS` 或 `FAILED`。
- 取消、断线和 Runner 异常后可查询已完成范围，并支持安全恢复或重试。
- 所有确认、接管、登录、步骤、证据和回写均可审计。
