# task010 - P1 - Browser/Desktop Runner 协议、会话接管与登录恢复

## 状态

未开始

## 目标

实现受控 Browser/Desktop Runner 的任务协议，使平台可以安全调度浏览器自动化执行、接管已授权会话，并在人工作业登录后恢复执行。

## 实现范围

- 定义 Runner 注册、心跳、租约、任务领取、事件上报、证据上传和任务结束协议。
- Runner 使用短期一次性任务令牌，任务结束后撤销授权。
- 登录处理顺序必须按方案实现：
  1. 检查任务绑定 Runner 是否存在与目标域名匹配的已授权活动会话。
  2. 存在时向用户展示即将接管的窗口、域名和账号标识；授权后附着会话。
  3. 不存在时查询平台凭据库中当前项目、环境和域名可用的凭据引用。
  4. 凭据可用且用户有权限时，由 Runner 本地解密或注入并完成登录；模型不得获得明文凭据。
  5. 无会话且无凭据时，任务进入 `WAITING_LOGIN`。
  6. Runner 检测登录成功后只回传“会话就绪”，用户点击继续或按策略恢复执行。
- 支持 MFA、验证码、扫码、硬件密钥等人工处理场景。
- 支持 Runner 异常、断线、超时后的任务恢复或失败标记。

## 不应实现的内容

- 服务端不得直接读取用户本机浏览器进程或浏览器数据目录。
- 不得导出、复制或暴露 Cookie、LocalStorage Token、密码和私钥。
- AI 不得绕过 MFA、验证码、扫码或硬件密钥。

## 验收标准

- 已登录会话必须经用户授权后接管。
- 无会话且无凭据时任务进入 `WAITING_LOGIN`。
- 人工登录完成后可恢复执行。
- Runner 断线后可查询已完成范围并安全恢复或重试。
- 任务令牌到期或结束后不可继续上报。

## 验证要求

- Runner 协议单元测试。
- 会话授权接管测试。
- 人工登录恢复测试。
- 断线、超时、异常恢复测试。
- 敏感数据泄漏检查。
