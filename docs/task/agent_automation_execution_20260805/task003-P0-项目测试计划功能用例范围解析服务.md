# task003 - P0 - 项目、测试计划、功能用例范围解析服务

部分完成

- 已支持显式 `projectId/testPlanId/caseIds/testPlanName` 解析、测试计划候选返回、计划用例查询、无计划时项目有效用例降级确认。
- 已接入 `AgentProjectService.resolveProjectId`，复用当前用户/Agent Token 可访问项目校验。
- 已对用例执行范围重新校验项目、删除状态、最新版本。

- 未完整实现：自然语言解析能力仍为基础关键词/显式字段解析；计划“状态允许执行”的规则目前仅排除归档；多候选/大范围会返回确认但缺少更细粒度风险分类单测。

## 目标

实现后端统一的 Project / Plan / Case Resolver，将自然语言或显式参数解析为确定的执行范围，并在歧义、大范围或高风险场景下返回确认预览。

## 实现范围

- 新增解析接口能力，供平台页面和 MCP 调用复用。
- 支持按项目名称、编号、ID 精确或候选匹配。
- 支持按测试计划名称、ID、状态、更新时间和关联用例数量筛选。
- 支持按功能用例编号、名称、模块和 ID 匹配指定用例。
- 测试计划选择规则必须按方案实现：
  1. 项目精确匹配且未归档。
  2. 计划状态允许执行。
  3. 已关联功能测试用例。
  4. 当前用户或 Agent Token 具有执行权限。
  5. 用户点名计划时优先使用该计划。
  6. 未点名时按“进行中、最近更新”排序。
  7. 第一名不唯一或可能重复执行时，展示候选计划并要求用户确认。
- 未指定项目时返回补充项，不执行、不采用默认项目。
- 无可执行计划时，返回降级执行项目全部有效功能用例的确认信息。
- 用例数超过阈值（建议 20 条）时必须进入确认流程。

## 不应实现的内容

- 不在 Cursor、Codex、WorkBuddy 等客户端中复制业务选择规则。
- 不随机选择测试计划。
- 不在缺少项目、环境、账号或预期结果时猜测执行。

## 验收标准

- 未提供项目时只提示补充项目，不创建任务。
- 多项目、多计划或多用例匹配时返回候选项。
- 指定项目和具体用例时，仅返回确认匹配的用例。
- 仅指定项目时优先返回满足规则的测试计划和关联功能用例。
- 降级为项目全部有效用例时必须包含范围、数量和确认原因。

## 验证要求

- Resolver 单元测试。
- 多项目、多计划、多用例歧义测试。
- 无计划降级确认测试。
- 权限过滤测试。
