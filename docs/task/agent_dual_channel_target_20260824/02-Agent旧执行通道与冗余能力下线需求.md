# Agent 旧执行通道与冗余能力下线需求

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 需求名称 | Agent 旧执行通道与冗余能力下线 |
| 需求类型 | 迁移、收敛与删除 |
| 优先级 | P1，必须在新双通道稳定后实施 |
| 目标版本 | 待排期 |
| 前置需求 | `01-Agent双通道执行能力实现需求.md` |
| 当前状态 | 部分完成：阶段 B 已实施；物理删除仍阻塞于新通道验收、生产使用量审计和观测期 |

## 2. 需求目标

在平台模型 API + 受控 Runner、个人 Agent + Remote MCP 两条新链路通过验收后，删除平台主动调用个人 CLI 的旧通道，并收敛重复的任务接口、MCP 实现和日志存储。

本需求必须遵守：

```text
替代能力完成 → 存量迁移 → 禁止新流量 → 观测 → 只读归档 → 物理删除
```

禁止在替代链路尚未验证、活跃使用情况不明或历史数据没有读取方案时直接删代码、表、路由或配置。

## 3. 下线范围

### 3.1 Bridge 与平台主动调用个人 CLI

在确认不再支持“平台主动推送任务到用户电脑”后，下线以下能力：

- `agent-bridge` 客户端和安装包；
- 一次性配对码和设备身份；
- Challenge/Authenticate；
- Bridge WebSocket、心跳和重连；
- Redis 设备定位和跨节点消息总线；
- `execution.start`、`execution.cancel` 推送；
- 平台触发本地 Provider 登录；
- 平台远程启动、恢复或终止 `codex exec`；
- CLI JSONL 原始事件转发；
- Bridge 版本检测、上传、激活和下载；
- 个人中心中的安装、配对、在线设备和版本管理。

候选实现位置包括但不限于：

- `agent-bridge/`
- `AgentBridgeSessionRegistry`
- `AgentBridgeWebSocketHandler`
- `AgentBridgeHandshakeInterceptor`
- `AgentBridgeBusMessage`
- `AgentBridgeEnvelope`
- `BridgeUserAgentConnector`
- `UserAgentConnector`
- `UserAgentExecutionRequest`
- `AiAgentBridgePackageController/Service/Repository`
- Bridge WebSocket、Redis、Feature Flag、权限、菜单和相关数据库对象

实际删除清单必须通过代码引用、运行配置、数据库和流量审计重新确认，不能只按以上名称机械删除。

### 3.2 平台“Agent 执行”旧入口

下线平台主动选择个人 Agent 的执行方式，包括：

- 创建执行任务时的“Agent 执行”选项；
- 个人 Agent Provider、设备或连接选择；
- 平台 Agent Dispatcher；
- 平台任务使用 `USER_AGENT` 资源；
- 新任务写入 `connectionId`、`deviceId` 或等价 Bridge 路由字段；
- 平台任务失败后降级至个人 Agent 的逻辑。

替代入口为：

- 平台任务选择平台模型与受控 Runner；
- 个人任务在 Agent 接入页面配置 MCP 和 Agent Token；
- 个人 Agent 主动通过 MCP 查询或领取任务。

### 3.3 重复任务接口和状态逻辑

收敛 `AgentTaskController`、`AgentRunnerInternalController`、执行操作接口和 MCP Handler 中重复的：

- Claim；
- Lease Heartbeat/Release；
- 事件提交；
- 步骤与最终结果；
- 附件准备与提交；
- 状态转换和取消。

处理原则：

- 保留不同协议入口所必需的适配层；
- 业务逻辑全部委托给统一任务执行应用服务；
- 删除重复 DTO 前先确认协议兼容和客户端版本；
- Runner 注册、Runner 自身心跳和能力声明不是任务 Lease，不得误删。

### 3.4 Node MCP 与原生 Remote MCP 重复实现

以后端原生 Remote MCP 为目标实现。只有满足以下条件才可归档或删除 Node `metersphere-mcp`：

- 原生 MCP 完成工具能力对照；
- 工具输入输出与错误协议有版本说明；
- 主流 MCP 客户端兼容测试通过；
- Node MCP 没有独立部署用户或已完成迁移；
- 文档、安装脚本和示例已切换到原生 MCP；
- 回滚包或迁移期旧版本可获取。

如果 Node MCP 仍承担客户端兼容适配，应将其缩减为薄适配器，不得继续复制业务规则。

### 3.5 重复日志与原始事件

下线或限期保存：

- CLI 逐字符输出；
- 大量 `content.delta`；
- Bridge 上下行消息副本；
- 同一状态同时保存为原始 Codex 事件、Runner 日志和业务事件的重复记录；
- 模型思维链或不可控的完整上下文日志。

保留：

1. 安全审计记录；
2. 结构化执行事件；
3. 正式业务结果；
4. 必要且已脱敏的短期诊断附件。

必须先定义数据保留期、脱敏、归档、查询和合法删除策略。

## 4. 明确保留的能力

以下能力不属于删除范围：

- 平台模型 API 配置、Provider 适配和治理；
- Cron、Webhook 和人工触发；
- Runner 注册、凭证、能力、心跳与并发；
- Browser/API Runner；
- 统一任务、状态机、Claim、Lease 和冻结上下文；
- 幂等、取消、超时和重试；
- 事件、截图、附件、结果、评价和审计；
- Agent Token、Scope 和项目权限；
- 后端原生 Remote MCP；
- 个人 Agent 的 MCP 配置和任务执行时间线；
- 旧任务历史记录的合规读取能力。

特别注意：Runner 心跳用于报告 Runner 在线和能力；Lease 心跳用于延长某个任务的执行权，两者不能合并删除。

## 5. 删除前置门槛

### 5.1 替代能力门槛

- `01-Agent双通道执行能力实现需求.md` 全部验收通过。
- 平台定时任务不依赖 Bridge 或个人 Agent。
- 个人 Agent 可以仅通过 Remote MCP 完成完整任务生命周期。
- 新链路具备权限、并发、日志、错误和回写能力。
- 两条核心 E2E 连续通过约定观测周期。

### 5.2 使用量审计门槛

统计并形成可复核报告：

- 最近 30/60/90 天 Bridge 活跃用户和设备；
- 通过 Bridge 创建、启动和完成的任务数；
- 当前在线连接和长时间未完成任务；
- Bridge Package 下载和版本分布；
- Node MCP 活跃实例和客户端版本；
- 使用旧 `AGENT/USER_AGENT` 字段的存量任务；
- 依赖旧权限、菜单、配置和接口的外部调用方。

活跃流量不为零时，需要迁移通知、兼容期和明确负责人，不能直接删除。

### 5.3 数据门槛

- 明确旧设备、连接、会话、包版本和执行记录的数据归属。
- 保留历史结果的只读查询和导出。
- 对不再需要的数据定义合法保留期和删除作业。
- 数据库迁移支持存量升级，并有备份/恢复或可执行回滚方案。
- 外键、索引、审计记录和附件引用不存在悬挂数据。

### 5.4 运维门槛

- WebSocket 路由和 Redis Topic 不再有生产流量。
- 配置中心、环境变量、Helm/Docker、反向代理和健康检查已识别所有旧依赖。
- 监控和告警可识别误调用旧端点。
- 删除前至少经历“禁止新建”和“只读”两个阶段。

## 6. 分阶段实施方案

### 阶段 A：清单与遥测

- 建立代码、接口、数据库、配置、权限、菜单、部署和文档清单。
- 为旧接口、WebSocket、Bridge 消息和 Node MCP 增加使用计数。
- 标记任务的来源和执行通道，识别真实依赖。
- 输出迁移对象、负责人和时间窗口。

**退出条件**：所有候选删除项都有引用和流量证据。

### 阶段 B：停止新增依赖

- 前端隐藏或禁用新的“Agent 执行”和 Bridge 配对入口。
- 后端拒绝创建新的 Bridge 执行任务，并返回可理解的迁移提示。
- 不影响历史记录查询和在途任务完成。
- 文档和引导切换到平台模型 API 或 Remote MCP。

**退出条件**：新任务不再写入旧通道字段，旧入口调用量只降不升。

### 阶段 C：业务逻辑收敛

- REST、Runner API 和 MCP 委托统一任务执行服务。
- 合并重复 DTO、错误协议和状态转换。
- 原生 MCP 达到 Node MCP 功能与客户端兼容要求。
- 统一结构化事件并停止新增重复原始日志。

**退出条件**：新链路回归通过，重复入口只剩兼容适配层。

### 阶段 D：只读兼容与观测

- Bridge 设备、会话、安装包和旧任务历史只读。
- 旧接口返回弃用信息或安全的迁移响应。
- 监控误调用并处理仍存在的客户端。
- 按产品约定持续一个完整升级/发布周期或明确的观测周期。

**退出条件**：生产活跃调用归零，在途任务归零，无未迁移调用方。

### 阶段 E：物理删除

按以下顺序删除：

1. 前端入口、菜单、路由和权限展示；
2. Bridge/旧 Dispatcher API 与适配服务；
3. WebSocket、Redis 路由和安装包管理；
4. `agent-bridge` 构建、制品和部署配置；
5. Node MCP 重复业务实现；
6. 不再使用的字段、表、索引和配置；
7. 旧文档、脚本、监控和告警。

每一步都需要编译、测试和启动验证，不能将全部删除堆积为一次不可定位的大变更。

## 7. 数据与接口迁移

### 7.1 任务数据

- 将旧任务映射至新的 `taskOrigin` 和 `executorChannel`。
- 无法可靠映射的数据标记 `LEGACY` 或等价只读状态，不猜测执行来源。
- 历史 `connectionId/deviceId` 可迁移到归档表或审计快照，随后从活动模型移除。
- 所有迁移脚本需可重复执行，并输出处理、跳过和失败数量。

### 7.2 接口兼容

- 弃用阶段保留稳定错误码，例如 `AGENT_BRIDGE_DEPRECATED`。
- 错误消息说明替代方式，但不返回内部类名和堆栈。
- 外部接口如有版本承诺，先新增版本并完成客户端迁移，再删除旧版本。
- 对无法同步升级的客户端提供有期限的兼容适配层。

### 7.3 权限和配置

- 移除 Bridge 安装、配对、设备和包管理权限前，确认没有角色模板引用。
- 清理对应菜单、路由守卫、国际化文本和 API 客户端类型。
- 清理 WebSocket 地址、Redis Topic、Bridge Feature Flag 和包存储配置。
- 保留或重命名 Agent Token/MCP 权限，不能将个人 Agent 授权整体误删。

## 8. 回滚与恢复

- 阶段 B 至 D 使用 Feature Flag 或等价开关控制，不立即删除数据。
- 每次数据库删除迁移前生成可验证备份，并提供恢复步骤。
- 物理删除前固定最后一个兼容版本和升级路径。
- 回滚不得恢复“双执行权”；旧通道若临时恢复，也必须通过统一 Claim/Lease 获得执行权。
- 删除后发现历史数据不可读时，应优先恢复只读适配，不恢复平台主动控制个人 CLI。

## 10. 测试与验证要求

### 10.1 静态与自动化检查

- 全仓搜索旧类、路由、环境变量、权限码、枚举和数据库字段引用。
- 后端相关单元和集成测试通过。
- 前端类型检查、Lint 和生产构建通过。
- 数据库从空库和代表性存量库迁移通过。
- 删除后不存在 TODO、Mock、空实现或固定成功响应代替旧能力。

### 10.2 回归测试

- 平台定时模型 API + Runner 执行不受影响。
- 个人 Agent Remote MCP 完整执行不受影响。
- Agent Token、Scope 和项目权限不受误删影响。
- Runner 注册心跳与任务 Lease 心跳均正常。
- 历史 Bridge 任务仍能只读查看和导出。
- 访问已下线入口返回安全、明确的弃用响应。

### 10.3 部署验证

- 后端编译/打包通过。
- Docker 镜像构建通过。
- 容器启动、健康和就绪检查通过。
- 启动日志无缺失 Bean、表、配置、Redis Topic 或 WebSocket Route 错误。
- 生产或预发布遥测证明旧通道调用量为零。

## 11. 风险

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 活跃个人 Bridge 用户未被识别 | 用户任务突然不可用 | 30/60/90 天遥测、通知和兼容期 |
| 误删 Runner 能力 | 平台执行中断 | 区分 Runner 心跳与任务 Lease，建立保留清单 |
| 历史任务依赖设备字段 | 页面或导出失败 | 归档快照和只读转换层 |
| Node MCP 存在独立客户端 | 外部 Agent 无法连接 | 客户端矩阵与迁移公告 |
| 重复状态逻辑未先收敛 | 删除后状态流转异常 | 先统一应用服务，再删协议实现 |
| 数据迁移不可逆 | 审计和历史证据丢失 | 备份、演练、分阶段迁移 |

## 12. 完成定义

只有 DEL-01 至 DEL-10 全部具备实现和运行证据，旧通道生产调用量为零，历史数据可读取，并且构建、迁移、容器健康检查及两条新通道 E2E 均通过，才能标记为“完成”。

在新双通道未完成或观测期未结束前，本需求状态必须保持“阻塞”或“部分完成”，不得宣称冗余能力已经安全删除。

## 13. 2026-08-25 实施记录

本次按删除门槛推进至阶段 B，不执行阶段 E 物理删除。

已实施：

- Agent 接入页只保留 Agent Token/Remote MCP 入口。
- 个人中心移除 Bridge 安装、配对和设备入口。
- 用例生成资源列表只返回 `MODEL_API`，服务端拒绝新的 `USER_AGENT` 选择。
- AI 治理只接受 `MODEL_API`，读取旧配置时不再对外开放个人 Agent。
- 新建 Bridge 连接、重新授权、创建配对和消费配对统一返回 `AGENT_BRIDGE_DEPRECATED`。
- 保留旧连接查询、撤销、删除、设备心跳和状态上报，支持历史读取和在途收尾。

暂未实施：

- Bridge/WebSocket/Redis/安装包管理的物理删除。
- Node MCP 删除。
- 旧数据库表、字段、权限和配置物理删除。
- 原始日志存量清理。

阻塞原因：缺少生产 30/60/90 天使用量、在途任务、外部客户端及历史数据审计，且新双通道尚未完成容器和端到端验证。
