## 总体目标

补齐 Agent MCP 对测试用例与缺陷管理的基础维护闭环，使 Agent Token 创建的数据与普通前端、REST 接口产生的数据结构一致；同时落地已确认的缺陷管理、测试用例列表和 Agent Token 管理页面体验优化。

## P0 交付目标

- Agent Token 可上传临时附件，并关联到用例详情或缺陷详情正式附件区域。
- 新增测试用例更新、用例评论查询/新增、缺陷评论查询/新增、用例/缺陷附件查询/关联/删除能力。
- MCP 工具注册从单体 `switch` 迁移为 Handler 注册表，新增工具具备明确 JSON Schema。
- 新增 Scope 不扩大旧 Token 权限。
- 缺陷详情展示缺陷 ID，缺陷名称进入详情内容；缺陷详情不再显示评论 Tab。
- 缺陷列表状态样式统一为圆角标签。
- 测试用例列表测试计划展示为 `测试计划：测试计划名称（ID） [进度条]`。
- 测试用例列表个人执行进度与详情页保持同一数据口径。
- Agent 集成页面新增“我的 Agent Token”记录管理区，说明文字下移。

## P1 交付目标

- 支持用例软删除、恢复、批量更新、移动、复制。
- 支持缺陷删除、恢复、批量更新、关联用例和解除关联。
- 支持评论编辑、删除、模板、自定义字段、历史记录和回收站查询。
- 写操作支持幂等键、乐观锁、业务日志、通知和 Agent 审计。

## P2 交付目标

- 文件库关联和转存。
- 用例与缺陷导入导出。
- 永久删除能力，默认关闭并使用独立高风险 Scope。
- 外部缺陷平台同步，使用独立高风险 Scope。
- Agent 操作日志前端展示。

## 总体验收

- 使用 Agent Token 上传 PNG 后，可在用例详情和缺陷详情直接预览。
- 执行日志附件、用例详情附件、缺陷详情附件来源明确，不互相混入。
- 前端、普通 REST 和 MCP 产生的数据结构一致。
- 无 Scope、无 RBAC、项目越权分别返回明确错误。
- 重复 `requestId` 不产生重复附件、评论和关联。
- 缺陷详情、缺陷列表、测试用例列表和 Agent 集成页面符合第 20 章确认的预览方案。

## 风险控制

- 不允许 Agent Token 绕过用户 RBAC。
- 不允许通过资源 ID 越权访问 Token 白名单外项目。
- 不放开普通前端附件上传接口给 Agent Token。
- 删除操作第一阶段只进入回收站，不开放永久删除。
- Controller 注解中的日志、通知和归属校验需要下沉到可复用领域服务或由 Agent Facade 显式补齐。
