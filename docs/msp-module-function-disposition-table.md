# MSP 板块与功能处置明细表

日期：2026-09-23。依据：用户明确的八项需求，以及前两轮对本地路由、页面和关键服务的静态核对。

## 1. 使用口径

当前 MSP 未接入大模型；优先实现项目、计划/评审/报告、用例及执行历史、缺陷、测试资产和外部 Agent 执行验收闭环。接口测试、平台模型 API 执行保留扩展位置。

下表是产品范围建议，不是生产运行验收。标记“保留”表示业务需要，不表示已实现或已测试通过。标记“补建”是需求所需的目标能力，不把它冒充已有功能。

| 处置 | 明确含义 |
|---|---|
| 保留 | 属于核心需求，维持独立职责 |
| 改造 | 保留能力，调整入口、数据归属、流程或权限 |
| 删除入口 | 移除冗余的独立菜单/标签；能力、历史数据迁到指定位置，旧链接保持兼容 |
| 条件下线 | 当前非必需，确认没有实际消费者后隐藏/归档；不直接删表 |
| 预留 | 本阶段不扩建，标明启用条件，保留已有实现与历史 |
| 补建 | 当前需求需要，但现有实现完整性尚未证明，需补齐或验证 |

**本次可明确建议删除的是重复入口和重复职责。没有足够证据建议立即删除任何核心数据表。** 组件复用不等于业务冗余，历史记录和引用关系不能随菜单一起清理。

## 2. 总体板块结论

| 板块 | 结论 | 最终职责 |
|---|---|---|
| 工作台 | 保留、简化 | 个人待办和风险汇总 |
| 项目管理 | 保留 | 项目与权限边界、版本、环境 |
| 测试计划 | 保留 | 计划、评审、报告与执行范围 |
| 测试用例 | 保留、改造执行历史 | 用例定义、版本和历次执行 |
| 缺陷管理 | 保留 | 产品问题及验证闭环 |
| 外部 Agent/自动化执行 | 改造成执行中心 | 任务、证据、门禁、审批、反馈与重测 |
| 测试资产 | 保留、收敛 | 文档、共享用例、版本、引用和必要数据集 |
| 接口测试 | 预留 | 后续扩展，保护既有能力和数据 |
| 平台模型 API 测试 | 预留 | 后续增加执行通道，复用验收链路 |
| 接入和系统设置 | 保留、合并重复入口 | 认证、授权、资源、策略及审计 |

| C05 | 用例历次执行记录 | 保存每次尝试及事实 | 改造 | 展示运行、来源、构建、证据、提交和审批；失败与拒绝记录也保存 |
| C06 | 用例最近执行结果 | 快速概览 | 改造 | 仅作摘要，不能作为指定构建的唯一结论 |
| C07 | 回收站与恢复 | 纠正误删 | 保留 | 恢复保持历史引用，不随菜单精简取消 |

| C09 | AI 草稿列表、人工审核和入库 | 接收并审核候选用例 | 改造 | 若支持外部导入可保留；需验证无模型流程，不新造第二套正式用例库 |
| C10 | 生成页内文档维护 | 为生成提供依据 | 删除重复维护入口 | 改为选择资产文档；文档查看和引用保留 |
| B01 | 缺陷列表、创建、详情 | 产品问题管理 | 保留 | 统一缺陷主入口 |
| B02 | 缺陷分派、状态流转 | 跟踪修复 | 保留 | 角色与流转规则在服务端校验 |
| B03 | 缺陷关联用例、运行及证据 | 复现与追溯 | 改造 | 引用原始运行和验收记录，不复制一套执行事实 |
| B04 | 修复验证与关闭 | 确认问题已解决 | 改造 | 关联有效重测结果；Agent 不能靠自报直接关闭 |
| B05 | 缺陷附件、历史、回收站 | 保存过程 | 保留 | 保护审计和关联关系 |
| B06 | Agent 自动生成缺陷 | 减少录入 | 改造 | 优先生成可审查候选；门禁缺证据和上传失败不自动当产品缺陷 |

## 6. Agent 与执行链路明细

| 编号 | 当前/目标功能 | 用途 | 处置 | 理由与调整后位置 |
|---|---|---|---|---|
| E01 | Agent 独立主板块 | 混合运行、资源、授权与模型配置 | 改造 | 日常工作归执行中心；接入资源归设置；未来模型归可选能力 |
| E02 | Agent 列表 | 实际展示 Runner、心跳、版本和并发 | 改名并下沉 | 改为“执行器管理”；没有使用 Runner 时对普通用户隐藏 |
| E03 | 能力与授权独立页 | 混有能力、Token、告警和 AI 治理 | 建议删除入口 | 内容分流到接入、运维和策略设置；不删鉴权能力 |
| E04 | Agent 集成/我的 Token | 外部客户端接入和凭据 | 保留、合并 | 只保留一个主要接入入口，其他页面给链接 |
| E05 | MCP 工具和 REST 接口 | 外部 Agent 读取任务、提交结果 | 保留、改造 | 共用服务和门禁，不能以工具入口不同绕过规则 |
| E06 | 自动化执行列表与创建 | 发起和跟踪运行 | 保留、改造 | 作为执行中心主页面 |
| E07 | 调度队列里的重复任务列表 | 再次显示相同任务 | 建议删除独立入口 | 移到执行中心，保留状态/通道筛选和运维视角 |
| E08 | Agent 执行详情第二路由 | 复用 AutomationExecution 页面 | 合并主路由 | 保留兼容跳转，无需重写组件 |
| E09 | 领取、租约、心跳、释放 | 防并发重复执行并跟踪活性 | 保留 | 后端能力必要；租约细节下沉运维，不让测试员手工管理 |
| E10 | 调度规则/Webhook/定时触发 | 自动产生任务 | 条件保留 | 有实际需要且通道健康才启用；归调度设置，不与执行列表混杂 |
| E11 | 暂停、取消、超时、重试 | 控制任务生命周期 | 保留、改造 | 区分重传文件、重试分析和重执行业务，避免重复副作用 |
| E12 | 步骤、日志、证据上传与存储 | 保存执行事实 | 保留、改造 | 绑定运行/尝试/步骤及来源，控制访问和保留期 |
| E13 | 执行结果提交版本 | 固定一版待验收材料 | 补建/核验 | 不覆盖旧提交，修正形成新版本 |
| E14 | 服务端硬门禁 | 检查身份、覆盖、版本、证据与结论 | 补建 | 所有正式采用路径统一检查，包括批量、计划外和同步路径 |
| E15 | 执行结果审批 | 人工判断材料和结论可否采用 | 补建 | 页面放执行中心待审批；批准绑定版本和责任人 |
| E16 | 反馈与重测 | 让 Agent 知道怎么修复 | 补建/改造 | 放执行详情，返回结构化原因及依赖重测范围，不另建反馈中心 |
| E17 | 正式结果回写 | 更新计划及执行历史 | 改造 | 裁决/审批满足后才采用；保留未经采用的原始记录 |
| E18 | 执行评价独立主标签 | 完成率、证据率、耗时及人工评分 | 建议删除独立入口 | 指标并入执行概览；评分留作可选反馈，不作审批或门禁 |
| E19 | 执行告警 | 跟踪卡死、回写和资源异常 | 保留、迁移 | 进入执行运维和通知，移出授权页 |
| E20 | Agent 主菜单仅管理员可见 | 限制使用对象 | 改造 | 日常执行与审批按项目角色开放，资源配置仍受限 |

## 10. 优先补齐而不是删除的内容

1. 完整的外部 Agent 任务协议：授权领取、合同、步骤、证据、完成提交、反馈和重测。
2. 不可覆盖的结果提交版本，独立门禁、审批和回写状态。
3. 门禁覆盖所有正式写入出口，不只 MCP 或单个 run 方法。
4. 用例定义与执行事实分离；未批准和失败记录同样可追溯。
5. 用户能在计划、用例历史和报告看到同一版本的结果，不出现不同页面互相矛盾。
6. 普通测试员、结果审批人、接入管理员的角色边界和完整页面入口。

建议先补齐这条闭环，再合并菜单，最后处理有证据支持的代码归档。可以并行设计导航，但不要先移除唯一可用入口。
