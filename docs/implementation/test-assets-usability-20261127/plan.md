## 实施顺序与分工

- [ ] 1. 复现部署上传/系统目录/版本权限；保存安全HTTP证据和错误trace，先定位根因。
- [ ] 2. 后端存储/30MB与10万行/历史自动迁移：生产文件仓库契约先红后绿，不以mock替代真实存储。
- [ ] 3. 记录分页/复制内容/使用状态：同一资产跨元信息版本持久；记录键按内容及重复序号稳定，修改内容的新记录未使用，保留旧记录状态。用户确认允许再复制，状态不清除。使用操作按资产读取权限，不要求管理权限；保留有效Token既有授权。
- [ ] 4. 前端分类、按钮、删除Modal、详情双tab、记录选择复制与使用状态；不再出现旧资产切换与替换入口。新增真实API与错误处理。

- [ ] 6. 分层单元/集成、真实MinIO与MySQL、类型/lint、前后端编译打包；重型构建串行避免内存争用。镜像构建按用户豁免。

## 边界与失败行为

复制失败不标已使用；复制成功但状态写入失败必须提示并允许只重试标记，不能声称状态成功。允许重复复制且始终保留已使用标记。默认分类不可删除/改名，历史null数据保持兼容。数据全局按组织隔离；关联追溯仍项目级。文件路径遵守organization平台前缀；不放宽仓库全局校验。新解析限额必须贯穿字节、行、JSON/Excel和HTTP/数据库，无静默截断。自动历史迁移必须具备持久状态、权限、幂等和恢复，不丢历史源文件、不覆盖人工当前版本。

## 审查重点

真实MinIO前缀、被包装的错误响应；30MB解析/100000行内存与分页；自动迁移权限/恢复；复制成功与标记失败；重复值和元信息新版本的使用状态；默认分类绕过UI请求；系统目录跨项目查询；页面取消额外权限不泄露其他组织或私密配置。

自动历史迁移契约：每次run处理一个family，单文件30MiB，family最多50版本及150MiB；超过预算持久FAILED并保留所有来源文件。失败仅retryFailed=true重试，RUNNING超过5分钟可抢占恢复，状态更新以claim时间戳隔离。API错误提供稳定errorCode及traceId；不添加Token Scope。
