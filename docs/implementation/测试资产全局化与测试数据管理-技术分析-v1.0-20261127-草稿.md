## 1. 技术结论及边界

需要改造五条主链路：全局授权和资源范围；公共配置；业务资产及版本；独立测试数据管理；MCP/执行器及迁移。不是移除前端projectId即可完成。

当前测试数据DATASET直接映射file_metadata；TestAssetMapper.xml的DATASET分支限定project_id、latest=1，且仅识别CSV/JSON/XLS/XLSX。通用详情主要展示目录元信息和快照，不能替代数据内容解析、编辑、上传、删除。TXT支持和独立内容页必须新增，XLS存量兼容必须保留或明确提示，不能在升级后悄悄消失。

当前全局默认按组织共享是产品草案建议，不是跨组织共享授权。开发前需确认该边界；下文以organization_id为授权边界设计，不允许客户端传任意组织ID取得访问权。

保留项目级的部分：关联追溯、业务项目原文件/原接口/原缺陷、执行器会话/日志、计划及执行结果。全局化的是资产内容与管理入口；项目引用固定versionId。不得批量删除所有project_id字段或修改AgentProjectService.resolveProjectId影响全部项目工具。

解析器适配CSV/XLSX/JSON/TXT；存量XLS需受控兼容。CSV编码/分隔符、XLSX工作表/类型、JSON根结构和字段类型都有统一响应模型；数字/日期/空值不得为展示方便变成不可逆字符串。大文件服务端分页预览与持久化解析索引，正文编辑必须提交完整变更集或受控patch，不能把第一页保存成全文件。

批量内容修改采用逐资产编辑队列是待产品确认方案；实现不能只做批量分类后宣称已支持全部批量修改。物理清理延迟进行，文件仍被版本/任务引用时不得删除。

## 7. 项目文件能力复用边界

backend/services/project-management/src/main/java/io/metersphere/project/下FileManagementService.getFile/getFileMetadataRepositoryDTO、FileRepositoryService、FileMetadataService、FileManagementController/FilePreviewController是文件存储、下载与预览复用候选。必须继续读代码确认底层存储抽象与上传补偿，再抽取公共能力；不能直接调用带项目权限的Controller充当全局接口。

FileManagementService.delete/getDeleteList/getProcessList为项目文件删除逻辑，不能直接复用于全局资产删除，否则可能破坏源业务引用。全局资产逻辑删除与项目原文件独立；迁移可引用同一不可变存储对象，但需引用计数和权限隔离。
