# MSP 独立会话实施与验收

批准来源：用户2026-11-24明确“按这个范围和方案修改”。本文件覆盖同目录 sso-remediation.md 中此前讨论的强制认证、全局退出及上游续期建议；不修改其他仓库。

|需求|入口和实现|后端|配置/数据|验证|
|---|---|---|---|---|
|SSO仅验证登录身份|登录页→SSO回调；现有身份映射及账户检查保留|callback消费交换令牌后建立MSP会话，不再保存上游sessionToken；is-login不调用上游refresh|无数据库迁移；旧上游Redis记录自然过期/退出清理，不作为认证依据|上游失效/不可达、历史needReauth不影响MSP|
|14天独立有效期|前端不再根据上游needMiduoReauth跳桥|服务端绝对期限为权威；新登录设置14天、请求刷新不延长期限|登录时明确设置本地空闲期限，避免宿主旧配置使新会话提前到期；已存在绝对期限不重置|14天前有效、边界拒绝、空闲保留、刷新不延长、旧会话不重置|
|多浏览器并存|各浏览器保存独立MSP凭据|各自Shiro/Spring Session，建立B不修改A；退出只销毁当前会话|不按用户全量删除，不吊销上游业务|实际双Subject/会话验证，A退出后A旧凭据无效、B仍有效|
|自身账号权限控制保留|现有角色及项目校验入口|is-login重新读取用户及角色；禁用/删除拒绝且销毁当前会话；保留管理员撤销逻辑|无新增TokenScope|角色更新回读、禁用/删除、会话过期401|

步骤：先写能复现旧行为的回归测试→修正服务端生命周期及前端跳桥→相关测试、类型检查、lint、生产构建及后端打包→独立审查；用户部署后执行真实双浏览器、空闲与退出验收。按用户约定不执行Docker镜像构建，不将本地测试描述为已部署验收。

兼容：needMiduoReauth响应字段保留false供旧客户端使用；历史Redis上游凭据仅为兼容清理，不能恢复/延长MSP会话。MSP退出不保证SSO扫码；用户已明确不列为本次条件。
