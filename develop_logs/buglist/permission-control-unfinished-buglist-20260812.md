# 权限控制改造未完成项缺陷清单

> 来源：`docs/prototype/permission-control-prototype.html`、`docs/summary/MeterSphere-permission-control-redesign-solution.md` 与当前实现对照  
> 记录日期：2026-08-12  
> 处理要求：以下缺陷修复前，不提交本文档。

## BUG-PC-001 角色设置页面未按原型完整实现

- 严重级别：高
- 当前状态：未修复
- 原型/需求：
  - 角色设置页应为三栏布局：角色列表、角色基础信息/成员分配、权限配置。
  - 支持角色新增、删除、修改、启用/禁用、搜索、查看来源、查看成员数。
  - 支持按组织架构和岗位分配成员。
- 当前实现：
  - `frontend/src/views/setting/system/permissionControl/index.vue` 仅提供角色状态表。
  - 角色权限配置复用旧 `SystemUserGroup` 页面。
  - 未在权限控制页内形成独立的角色基础信息和成员岗位分配交互。
- 影响：
  - 用户无法按原型在权限控制页完成完整角色维护。
  - 后端已有的岗位分配接口缺少前端入口，功能不可用。
- 建议修复：
  - 重做角色设置页三栏布局。
  - 在权限控制页内接入角色 CRUD、成员手动分配、按岗位批量分配、规则查看。

## BUG-PC-002 全模块 Tab 权限仅部分运行时生效

- 严重级别：高
- 当前状态：未修复
- 原型/需求：
  - 权限设置需精细化到每一个 Tab。
  - 覆盖工作台、系统设置、测试计划、接口测试、项目管理、用例管理等所有模块。
- 当前实现：
  - 权限资源种子已覆盖较多模块。
  - 部分路由型 Tab 已通过 `resourceCode` 接入。
  - 用例管理部分内部 Tab 已接入 `hasTabVisible`。
  - 工作台内部 Tab、系统设置内部 Tab、测试计划详情内部 Tab、接口详情内部 Tab、项目管理内部 Tab 等大量组件内 Tab 尚未接入运行时控制。
- 影响：
  - 管理员在权限树中取消某些 Tab 可见性后，实际页面仍可能展示该 Tab。
- 建议修复：
  - 按资源种子逐模块扫描组件内 `<a-tab-pane>` / 动态 tabs。
  - 对每个已登记 `TAB` 资源接入 `hasTabVisible(resourceCode, scope)`。
  - 为未迁移 Tab 标注 legacy 状态，避免误判。

## BUG-PC-003 按钮可见/可用权限未全量迁移

- 严重级别：高
- 当前状态：未修复
- 原型/需求：
  - 普通角色可配置按钮可见性。
  - 普通角色可配置按钮可用性。
  - 按钮可见但不可用时，应置灰并提示原因。
  - 按钮可用必须同时满足 UI 可用权限和旧接口权限。
- 当前实现：
  - `hasButtonOperable()` 已修正为 `UI operable && old permission`。
  - 但大量业务按钮仍使用旧 `v-permission`。
  - 仅少量按钮使用 `v-visible-permission` / `v-operable-permission`。
  - 缺少统一置灰提示。
- 影响：
  - 权限树中按钮可见/可用配置对多数页面不生效。
  - 用户体验与原型不一致。
- 建议修复：
  - 按 `permission_resource` 中的 `BUTTON` 资源逐项迁移按钮。
  - 建立统一 disabled + tooltip 交互。
  - 未迁移按钮添加 `legacy-permission` 注释。

## BUG-PC-004 页面/Tab 权限兼容计算规则与方案不一致

- 严重级别：高
- 当前状态：未修复
- 原型/需求：
  - 页面可见 = 管理员 || UI 页面可见 || 旧 READ 权限兜底。
  - Tab 可见 = 管理员 || UI Tab 可见 || 未配置 Tab 时跟随父页面。
  - 未迁移页面继续走旧权限体系。
- 当前实现：
  - `frontend/src/utils/permission.ts` 中 `hasPageVisible()` / `hasTabVisible()` 仅判断 UI visible。
  - 路由过滤实际为 `hasPageVisible(resourceCode) && hasAnyPermission(meta.roles)`。
  - 有登录态 `uiPermissions` 时，旧 READ 不是兜底 OR，而是额外 AND。
  - 未配置 Tab 时不会自动跟随父页面。
- 影响：
  - 旧权限下本应可访问的页面/Tab 可能被新 UI 权限误隐藏。
  - 新旧权限隔离策略存在偏差。
- 建议修复：
  - 增加资源是否已迁移/是否存在配置的判断。
  - 对未迁移或未显式配置的 Tab 走父页面/旧权限兜底。
  - 路由层使用 `hasResourceVisible(resourceCode, meta.roles)`。

## BUG-PC-005 流程定义未真正绑定状态项和状态流

- 严重级别：阻塞
- 当前状态：未修复
- 原型/需求：
  - 流程定义应作为状态集合、状态流转、流程角色、角色授权的上层容器。
  - 支持新建/复制缺陷流程，并维护该流程下的状态和流转关系。
- 当前实现：
  - 已新增 `workflow_definition`、`workflow_role`、`status_flow_role_permission`。
  - `status_item`、`status_flow` 已新增 `flow_id` 字段。
  - 但新建流程只创建 `workflow_definition`。
  - `/permission-control/flow/matrix` 按 `scene + scopeId` 读取现有状态流，不按 `flowId` 读取。
  - 缺陷状态流转校验未约束 `status_flow.flow_id = workflow_definition.id`。
- 影响：
  - 多流程场景下，状态流转和授权可能互相串扰。
  - “新建流程”不是独立可用流程，只是新增了流程元数据。
- 建议修复：
  - 新建/复制流程时复制或创建状态项、状态流，并写入 `flow_id`。
  - 矩阵查询、授权保存、状态变更校验均按 `flowId` 过滤。
  - 缺陷需记录或解析当前使用的流程。

## BUG-PC-006 流程控制缺少状态和流转维护接口/页面

- 严重级别：高
- 当前状态：未修复
- 原型/需求：
  - 支持维护流程状态。
  - 支持维护状态流转关系。
  - 支持流程矩阵配置。
- 当前实现：
  - 已有矩阵展示和角色授权保存。
  - 缺少方案中定义的状态和流转接口：
    - `POST /permission-control/flow/status/add`
    - `POST /permission-control/flow/status/update`
    - `POST /permission-control/flow/transition/update`
  - 前端也没有状态新增/编辑、流转启用/禁用入口。
- 影响：
  - 用户无法在权限控制页真正编辑流程状态和流转关系。
- 建议修复：
  - 增加状态 CRUD 和流转关系更新接口。
  - 矩阵单元支持允许/禁止切换并持久化。
  - 对默认/内置状态增加不可删除或限制规则。

## BUG-PC-007 缺陷状态流转前端未按角色过滤

- 严重级别：高
- 当前状态：未修复
- 原型/需求：
  - 无流程权限的用户不能在前端看到或执行对应流转。
  - 可见但不可执行时置灰并提示“当前角色无流转权限”。
  - 后端提供按当前用户过滤的可流转状态接口。
- 当前实现：
  - 后端只在缺陷状态保存时执行 `assertBugTransitionOperable()`。
  - 未实现 `/bug/status/transitions?projectId=xxx&fromStatusId=xxx`。
  - 前端缺陷状态下拉未接入流程角色授权过滤。
- 影响：
  - 用户仍可能在前端看到无权执行的状态流转选项。
  - 体验与原型不一致，只能在保存阶段失败。
- 建议修复：
  - 新增缺陷可流转状态查询接口，返回 visible / operable。
  - 前端缺陷状态选择器按接口结果展示、置灰和提示。

## BUG-PC-008 状态流转拒绝未明确返回 403

- 严重级别：中
- 当前状态：未修复
- 原型/需求：
  - 用户绕过前端直接请求状态变更接口时，后端返回 403。
- 当前实现：
  - `PermissionControlService.assertBugTransitionOperable()` 抛出 `MSException("当前角色无缺陷状态流转权限")`。
  - 是否返回 HTTP 403 取决于全局异常映射，当前实现未显式保证。
- 影响：
  - 自动化测试或前端拦截可能无法按 403 做统一处理。
- 建议修复：
  - 使用权限异常类型或明确映射为 403。
  - 增加接口测试验证直接绕过前端的返回码。

## BUG-PC-009 流程范围固定为系统级，缺少项目/组织范围选择

- 严重级别：高
- 当前状态：未修复
- 原型/需求：
  - 流程控制支持项目/组织范围选择。
  - 一期主要针对缺陷管理，建议项目默认一个缺陷流程。
- 当前实现：
  - 前端 `permissionControl/index.vue` 固定：
    - `scene = BUG`
    - `scopeType = SYSTEM`
    - `scopeId = system`
  - 没有项目/组织范围切换 UI。
- 影响：
  - 无法配置项目级缺陷流程。
  - 与“按项目控制缺陷流转”场景不匹配。
- 建议修复：
  - 增加 scopeType / scopeId 选择。
  - 默认根据当前项目加载项目级流程，缺失时回退系统默认流程。

## BUG-PC-010 流程默认、复制、删除、禁用规则未完整实现

- 严重级别：中
- 当前状态：未修复
- 原型/需求：
  - 支持复制流程。
  - 支持删除未使用流程。
  - 支持设置默认流程。
  - 默认流程不可禁用，除非先切换默认流程。
  - 流程已被缺陷引用后不允许硬删除。
- 当前实现：
  - 前端有“从已有流程复制”入口，但复制内容仅限流程角色和授权，未复制状态/流转。
  - 没有设置默认流程入口。
  - 没有删除流程前端入口。
  - 后端删除只限制默认流程，未判断流程是否已被缺陷引用。
- 影响：
  - 流程生命周期管理不完整。
- 建议修复：
  - 增加默认流程切换接口和前端入口。
  - 删除前检查历史缺陷引用。
  - 禁用默认流程前要求切换默认流程。

## BUG-PC-011 管理员不可取消权限缺少后端全链路确认

- 严重级别：中
- 当前状态：未修复
- 原型/需求：
  - 管理员默认存在，不可删除、不可禁用、不可取消权限。
- 当前实现：
  - 前端 `AuthTable` 对 `admin/org_admin/project_admin` 禁用编辑。
  - 角色启停有内置角色限制。
  - 但需确认保存权限接口后端是否对管理员角色强制拒绝变更。
- 影响：
  - 如果绕过前端调用保存接口，可能存在管理员权限被修改风险。
- 建议修复：
  - 在后端角色权限保存入口校验内置管理员角色不可变更。
  - 增加单元/接口测试。

## BUG-PC-012 新旧权限迁移标记不足

- 严重级别：中
- 当前状态：未修复
- 原型/需求：
  - 原有权限控制代码不删除。
  - 迁移期间用注释和适配层隔离新旧体系。
- 当前实现：
  - 旧权限代码保留。
  - 只有少量 `ui-permission` 注释。
  - 大量 `v-permission` 未标明是 legacy 还是未迁移。
- 影响：
  - 后续无法可靠判断哪些页面已迁移、哪些仍走旧权限。
  - 容易出现新旧权限重复或冲突。
- 建议修复：
  - 为已迁移按钮/页面添加 `ui-permission` 注释。
  - 为未迁移旧权限添加 `legacy-permission` 注释。
  - 建立迁移清单。

## BUG-PC-013 权限控制页面与原型视觉/交互存在明显差异

- 严重级别：中
- 当前状态：未修复
- 原型/需求：
  - 角色页为完整三栏管理页面。
  - 流程页顶部包含模块选择、项目/组织范围、新建流程、添加流程角色、同步组织模板、保存流程。
  - 流程左侧展示流程列表和当前流程状态。
- 当前实现：
  - 角色页为两栏，且嵌入旧用户组页面。
  - 流程页无顶部范围选择和同步组织模板。
  - 流程左侧仅流程列表，不展示状态列表。
- 影响：
  - 即便部分接口可用，产品体验与原型不一致。
- 建议修复：
  - 按原型重排权限控制页面。
  - 状态列表、范围选择、同步组织模板等交互补齐。
