# 一次性项目的 Agent 测试流程

1. **项目初始化**：创建一次性项目，关联需求、环境和用例；范围与负责人明确后退出。
2. **资料摄入**：读取业务知识、方案、Demo、技术分析和权限边界；记录冲突与缺口。
3. **范围确认**：拆出核心链路、风险、优先级和不测项；明确成功标准及禁止操作。
4. **前置核验**：检查登录、开关、批次、库存、账号和客户端能力；通过或形成阻塞。
5. **基线执行**：覆盖全部关联用例；每条必须有结果或不可执行说明。
6. **发散执行**：针对资料和执行观察补充不重复的高风险场景。
7. **回写与报告**：仅在授权时回写平台，生成 Markdown 报告和证据索引。
8. **质量修补**：检查漏测、误判、弱证据和越权，执行修补或列为遗留。
9. **一次性归档**：冻结资料、配置、用例、结果和证据快照；结束后不再进入项目。

## 状态规则

- 通过：满足预期且证据充分。
- 失败：实际行为与预期不符，或必需能力缺失。
- 阻塞：环境、权限、数据、客户端或外部依赖导致无法执行。
- 跳过：明确不适用或经授权排除，不能掩盖失败和阻塞。
- 未执行：尚未尝试，必须说明风险或后续计划。

## 控制点

- 用例是覆盖基线而非测试上限；发散测试必须可追溯到风险来源。
- 状态变化、库存消耗、领奖和第三方通信前核对授权。
- 自动化不足时允许人工接力，但记录交接点及人工证据来源。
- 修复后只重测受影响链路及必要回归，并保留修复前后证据。
