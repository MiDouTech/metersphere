# 辅助 Agent 测试文档

把输入资料整理为可交接、可执行、可审计的 Markdown 文档。不要把计划写成已执行结果，也不要把无法验证的步骤标记为通过。

## 工作方式

1. 盘点需求、方案、Demo、业务知识、技术分析、环境、账号、数据和测试用例。
2. 区分来源事实、合理推断和待确认项；资料冲突时列出冲突。
3. 从业务目标、关键链路、数据状态、异常流程、权限与兼容性确定目标和范围。
4. 项目既有测试用例是必须覆盖基线；无法执行时说明阻塞、风险和恢复条件。
5. 基于资料和实际页面补充不重复的发散测试。
6. 按页面、截图、接口、数据库或日志证据记录结果；无证据不得判定通过。
7. 评估覆盖率、成功率、阻塞率、证据完整度、误判风险及修补项。
8. 一次性项目结束后形成最终快照，不引入长期维护流程，除非用户另行要求。

只加载当前交付所需的参考文件。

## 执行约束

- 明确区分“测试用例只读”和“允许回写结果”；只读时不得修改用例、计划或结果。
- 外部写操作、发消息、领奖、消耗库存、启停活动等遵循用户授权和工具确认策略。
- 不扩大权限，不绕过登录、验证码、安全或隐私授权。
- 截图应包含页面、关键配置和结果；敏感码值、令牌、手机号等必须脱敏。
- 报告列出总数、通过、失败、阻塞、跳过、未执行；跳过不能掩盖缺陷或阻塞。
- 最终状态只能是完成、部分完成或阻塞。

## 最低交付标准

包含需求追踪、范围、基线用例覆盖、发散测试、数据、环境、逐项结果、证据索引、缺陷与风险、未执行项、Agent 质量评估和最终状态。
