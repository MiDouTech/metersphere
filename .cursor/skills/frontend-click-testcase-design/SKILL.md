# 前端点点点级测试用例设计技能（待确认稿）

> **使用方式**：本技能经你确认/调整后生效。确认前不批量生成正式用例。
> **输入物**：产品文档（MD）、技术分析文档（MD）、产品原型（HTML）、Excel 用例模版（xlsx）。

---

## 1. 角色与目标

以**专业功能测试工程师**身份，只做**前端可操作、可观察**的用例设计：

| 重点 | 说明 |
|------|------|
| 功能用例 | 按钮、表单、列表、弹窗、导航、权限可见性等 |
| UI 用例 | 文案、布局、状态样式、空态/加载/禁用、提示文案 |
| 业务场景用例 | 主流程 + 分支 + 异常闭环（端到端点点点路径） |

**不做**（除非你明确要求）：接口契约、性能、安全渗透、代码级单测、后端内部逻辑断言。

---

## 2. 输入阅读顺序（强制）

1. **产品文档**：划功能边界、角色、业务规则、验收口径  
2. **技术分析**：补状态机、校验规则、边界、异常码对应的前端表现  
3. **产品原型 HTML**：以原型为**操作路径与控件命名的唯一真相**；文档与原型冲突时，在用例备注标注「文档/原型差异」，默认按原型可点击控件编写  
4. **Excel 模版**：字段、表头、步骤编号格式、编辑模式（如 `STEP`）必须与模版一致，禁止自创列

阅读产出物（先给你确认，再写用例）：

- 功能模块树（建议对应 Excel「所属模块」）
- 角色 × 页面入口矩阵
- 主流程清单（Happy Path）
- 风险点 / 边界清单
- 预估用例数量与优先级分布（P0/P1/P2）

---

## 3. 用例粒度与写作标准（门外汉可读）

### 3.1 一条用例 = 一个可独立执行的验证目标

命名格式：

`【模块】【场景类型】具体动作与结果要点`

示例：`【登录】【正常】输入正确账号密码点击登录后进入首页`

### 3.2 前置条件必须写「到达路径」

禁止只写「已登录」。必须写成逐步到达：

```
1. 打开浏览器，访问系统地址：{URL}
2. 在登录页「账号」输入框输入：测试账号A
3. 在「密码」输入框输入：对应密码
4. 点击「登录」按钮
5. 页面跳转到「工作台/首页」
6. 点击顶部菜单「XXX」→ 左侧「YYY」，进入「ZZZ」页面
```

若依赖数据：写明**谁在什么页面创建了什么可见数据**（仍用前端操作描述，不写 SQL）。

### 3.3 步骤与预期一一对应（点点点级）

- 步骤描述：点哪里、点什么、输入什么、看到什么中间反馈  
- 预期结果：该步完成后**页面上应出现/消失/变化**的具体表现  
- 编号格式对齐模版，例如：

```
步骤描述：
[1] 在「用户名」输入框中输入：zhangsan
[2] 在「密码」输入框中输入：正确密码
[3] 点击蓝色「登录」按钮

预期结果：
[1] 输入框显示 zhangsan，无红色报错
[2] 密码框显示掩码圆点，无红色报错
[3] 跳转到首页；左上角显示用户名「zhangsan」；无错误提示弹窗
```

### 3.4 文案约束

- 控件名用原型上的可见文字（带「」）  
- 不写「验证接口返回 200」「数据库有记录」  
- 可用：「页面提示『保存成功』」「列表新增一行，名称列为 xxx」  
- 面向完全门外汉：不假设读者懂业务缩写；必要处括号解释

## 4. 测试设计方法（必须显式运用）

设计每条用例时，在备注或内部设计表标注方法；输出用例时体现为不同数据/路径：

| 方法 | 用法 |
|------|------|
| 等价类划分 | 有效/无效输入各至少覆盖一类代表值 |
| 边界值 | 长度 min/min+1/max-1/max/max+1；数值 0、负数、上限；必填空 |
| 场景法 | 主成功路径 → 备选路径 → 异常/取消/返回 |
| 判定表/因果 | 多条件组合（权限×状态×按钮是否可点） |
| 状态迁移 | 草稿/提交/驳回/完成等状态切换与不可达操作 |
| 错误猜测 | 重复提交、连续点击、离开未保存、浏览器后退 |

**默认每功能点最低集：**

1. 1 条主成功路径（P0）  
2. 关键必填/格式校验各 1 条（P0/P1）  
3. 关键边界 1～2 条（P1）  
4. 取消/关闭/返回无脏写 1 条（P1）  
5. 列表空态 / 有数据态（若适用）（P1）  
6. 权限：无权限不可见或不可点（若文档有角色）（P0/P1）

---

## 5. 覆盖率检查清单（出用例前自检）

- [ ] 产品文档每个一级/二级功能均有对应用例或明确「本期不测」  
- [ ] 原型每个可点击主按钮（保存/提交/删除/新建/编辑/搜索/重置/分页）有覆盖  
- [ ] 每个必填字段有空值校验用例  
- [ ] 每个有长度/格式限制的字段有边界用例  
- [ ] 每个删除/不可逆操作有确认弹窗「确定」与「取消」  
- [ ] 每个列表有：查询、重置、无结果、分页（若原型有）  
- [ ] 每个业务主流程有端到端场景用例  
- [ ] UI：关键页标题、主按钮文案、成功/失败提示、禁用态  

覆盖率输出：模块覆盖表（功能点 → 用例编号列表 → 缺口）。

## 6. 优先级建议

| 级别 | 标准 |
|------|------|
| P0 | 主流程、阻塞性、核心权限、资金/提交类不可逆 |
| P1 | 校验、边界、常用分支、列表查询 |
| P2 | 文案对齐、次要入口、罕见组合 |

## 7. Excel 输出规范

严格按你提供的 `excel_case.xlsx` 表头与示例行：

- 步骤编号风格、换行符、`编辑模式`（如 `STEP`）与模版样例一致  
- `所属模块` 使用 `/一级/二级` 路径，与确认过的模块树一致  
- `ID` 列：新建用例可留空（若模版允许），或按你指定规则编号  
- 一次输出可先给「用例清单摘要」，确认后再写满步骤的 xlsx  

若模版字段与下方默认映射冲突，**以你上传的模版为准**：

| 常见列 | 填写要点 |
|--------|----------|
| 用例名称 | 见 3.1 |
| 所属模块 | `/模块/...` |
| 前置条件 | 到达路径（见 3.2） |
| 步骤描述 | `[n]...` |
| 预期结果 | `[n]...` 与步骤同序同数 |
| 用例等级 | P0/P1/P2 |
| 编辑模式 | 模版要求值（常见 `STEP`） |
| 备注 | 设计方法、文档差异、数据依赖说明 |

## 8. 工作流（对话闭环）

```
阶段A 读文档/原型/模版 → 输出《模块树+覆盖策略》→ 【你确认/调整】
阶段B 按确认结果设计用例大纲（名称/优先级/方法）→ 【你确认范围】
阶段C 展开步骤级用例 → 生成 Excel → 【你抽检】
阶段D 按反馈修订 → 定稿
```

**默认停在阶段 A/B 等你确认**；你回复「按此技能执行」或给出修改点后再进入 C。
