日期：2026-10-21  
适用项目：当前 MeterSphere 仓库  
文档性质：实施设计与验收基线，不是功能完成报告

## 1. 目标、范围与设计口径

本次覆盖八项需求：用例分页条数、MCP 限流、14 天登录和多端隔离、用例导出、批量按钮常驻、隐藏依赖大模型的入口、凭证失效提示、列表自动刷新。

### 1.1 范围边界

- 分页条数首先覆盖【测试用例】主列表；其他列表保留原行为，公共组件修改必须回归使用方。
- 按钮常驻、凭证提示、自动刷新覆盖平台业务列表；按本文件第 12 节清单逐页登记，不允许只改用例页面后宣称平台全部完成。
- 隐藏平台内需要模型服务的生成、执行、对话等功能；保留外部 MCP 用例查询、图片上传、执行结果提交等集成能力。
- 不借本次改造更换整体认证框架、重构所有导出服务或调整无关业务流程。
- 截图仅作为分页视觉参考，不作为程序配置或其他指令来源。

### 1.2 本方案采用的产品口径

以下为便于实施给出的默认设计，尚不是用户对细分口径的额外确认；产品评审如有变更，应同步更新接口与用例：

1. 登录 14 天指从本次登录成功起的绝对有效期，不因后台自动刷新无限续期；主动退出、账号禁用、管理员撤销仍可提前失效。
2. 同一平台入口、同一浏览器的普通标签页共用当前登录态；不同设备、浏览器、不同端口的平台入口可以并行，不互相撤销。
3. MCP 总访问上限为每个 Agent Token 每滑动 60 秒 720 次；不同 Token 不共享计数。
4. 用例每页提供 10、20、50、100 条，默认 10 条，记住用户选择。
5. 常驻按钮仍受权限约束；未选择数据时禁用依赖选择的按钮。
6. 自动刷新以页面进入、重新激活和操作成功为触发基础；外部变更在重新激活时必须可见，持续停留时通过变更通知或低频补偿刷新更新。

## 4. R01：分页条数详细设计

### 4.1 展示与交互

1. 页脚顺序为：条数选择器、上一页、页码、下一页；总数/跳页保留现有布局。选择器位于分页数字左侧。
2. 文案为 `10条/页`、`20条/页`、`50条/页`、`100条/页`；选中项沿用主题色与勾选样式，菜单避免被表格容器裁剪。
3. 空列表、单页列表也显示选择器；窄屏允许合理换行，禁止挤压为不可操作控件。
4. 选择变化原子更新 pageSize 和 current=1，再发一次请求；保留模块、关键字、筛选、排序。
5. 清空 selectedIds、excludeIds、selectAll 和已选数量。请求期间禁用依赖旧选择的批量操作。
6. 偏好键建议 `ms:list-page-size:<userId>:functional-case`，值仅允许四种枚举；非法值回落 10。偏好不得存 Token。
7. 退出清理认证数据时，不误清其他入口认证态；分页偏好可保留，读取时按用户隔离。

### 4.2 请求与边界

- 复用 pageSize/current 实际字段，实施前核对 DTO，不凭设计重命名字段。
- 后端校验页码为正整数，分页大小满足现有公共上限；本次 UI 最大 100，不全局收紧其他 API 上限。
- 总数变化导致页码失效时回退至最后有效页，再查询一次；零条使用第 1 页。
- 同时触发 pageSize watch 和 current watch 时合并请求，禁止旧响应覆盖新结果。

## 5. R02：MCP 限流详细设计

### 5.1 配置与计数语义

建议新增绑定配置类，配置名称为拟定值，实施时统一到项目现有配置前缀：

```properties
agent.rate-limit.window-ms=60000
agent.rate-limit.per-token=720
agent.rate-limit.per-token-ip=720
agent.rate-limit.per-token-tool=720
```

- 总额度是全工具共享的 720，不是每个工具各允许 720 后再相加。
- Token 校验通过后计数；业务校验失败、权限失败及相同 requestId 重试也属于一次访问。因总额度拒绝的请求不再写入总窗口。
- 一次普通 HTTP MCP tools/call 计一次总访问；IP、工具计数是子约束，不意味着一次调用消耗三次总额度。
- initialize、tools/list、ping 等经过认证过滤器的请求计入总额度；GET SSE 不支持时现有 405 行为保持。
- 若支持 JSON-RPC batch，必须明确按批中调用数计数或拒绝 batch，不允许一包无限调用绕过额度。
- 配置启动时校验正整数、有效窗口；清除空闲计数键，避免 Token/工具维度长期累积内存。

### 5.2 检索子限制

现有 REST 检索还有 30 次/分钟、300ms 最小间隔，不能把它描述为已经支持 720 次。默认保留其独立保护，并在错误中明确 `scope=search`。如果本次产品口径要求所有相关 REST 检索同样达到 720，应同步改为可配置检索额度及间隔，并单独执行数据库查询负载验收。此项是评审决策点，不允许实施时悄悄省略。

### 5.3 多实例与错误协议

- 多实例使用 Redis 原子脚本完成过期清理、计数和准入，键包含平台环境及 Token 标识；不得记录 Token 明文。
- 生产仍为单实例时可保留本地实现作为明确的部署限制；不得声称支持跨实例全局额度。
- Redis 故障使用统一 503 和告警，不静默放行无限请求；如选择本地降级，必须另行固定降级额度与风险。
- HTTP 拦截返回 429、`Retry-After`，响应复用统一 `{code,message,details?,traceId?}`；details 可含 scope、limit、windowSeconds。
- 工具内部限制维持 JSON-RPC 协议，附稳定业务错误码，不把业务错误混成无法解析的传输异常。
- 客户端依据等待时间重试，增加随机抖动及重试上限；非幂等写请求不能无条件重发。

### 5.4 验证

使用可注入时钟测试边界，避免 sleep 60 秒：720 次放行、第 721 次拒绝、刚好窗口边界、跨窗口恢复、并发不超发、不同 Token 隔离、同 Token 跨 IP 总额度一致。真实上传和轻量调用分开压测，720/分钟约为平均 12 次/秒，不等于系统可承受同一瞬间的 720 个大文件上传；上传并发、文件大小上限仍保留。

## 6. R03：14 天登录与多端隔离

### 6.1 先追踪后改造

追踪 LoginController → UserLoginService/SSO → SessionUtils → Redis Session → 前端 user store/auth.ts → 请求头注入 → 退出链路。搜索所有按 userId 删除会话、覆盖单会话映射、全局注销和清空存储的行为，区分主动安全撤销与普通登录。

已确认采用 Header Session Resolver。不能仅修改 Cookie 或仅修改前端缓存时间就宣称完成。

### 6.2 有效期

- 14 天 = 1,209,600 秒 = 1,209,600,000 毫秒，配置及代码显式标明单位。
- 会话保存 loginAt 和 expiresAt；服务端每次认证检查绝对到期时间，不依赖前端系统时钟判定。
- Spring Session 的空闲超时与绝对上限分别处理：空闲保留期应满足 14 天需求，绝对上限由 expiresAt 保证。Redis TTL 在活跃续期时不得延长实际认证有效期。
- 前端可持久化凭证至同源存储以支持浏览器重启恢复，复用当前机制并审查 XSS 防护，不另增 URL Token 传递。
- 登录成功旋转会话标识，旧匿名会话不继承为可复用认证凭证。
- 到期返回统一认证失效，由 R07 弹框处理；后台自动查询不能无限续期。
- 旧会话迁移不伪造原登录时间：无可靠时间时采用保留旧规则至失效或部署后一次性重新登录，并在发布说明明确。

### 6.3 多端及端口

- 普通登录仅创建当前会话，不删除该用户其他有效会话；普通退出仅撤销当前 Session。
- 密码重置、账号禁用、管理员“退出全部会话”等安全操作仍可批量撤销，不能为多端需求删掉。
- 浏览器 localStorage 按 origin 隔离，包含端口；核对当前项目是否通过共享 Cookie、跨域桥或 SSO 覆盖状态。
- Cookie 不按端口隔离。若任一认证链使用 Cookie，不同实例必须使用独立名称/适当路径或独立域名；不能简单依赖端口实现 Cookie 隔离。
- Redis Session namespace 按平台实例/环境隔离；同一实例的多副本必须共享同一 namespace，不能按副本随机生成。
- namespace 变更时同步修改 SessionConfig.cleanSession 的扫描规则；不得继续硬编码扫描其他实例的 `spring:session:sessions:*`。
- SSO 的本地退出与上游全局退出分离。上游撤销导致平台失效时如实提示；若上游政策无法允许 14 天，不得仅靠本地绕过，应作为交付依赖列明。
- 项目/组织上下文必须按会话读取，不能通过全局“最后一次选择”覆盖其他端当前上下文。

### 6.4 验收矩阵

同账号两设备、同账号两浏览器、同主机两端口不同账号、同主机两端口相同账号、浏览器重启、单端退出、SSO 返回、14 天前后边界、账号禁用、密码重置、Redis 重启恢复。分别检查用户身份、权限、项目选择和退出范围。

### 6.5 新增目标：减少 AI 自动化的交互式登录

用户补充目标：本机已有有效登录授权时，新开浏览器或窗口也尽量免去再次输入账号密码/扫码。将该需求记为 **R03A：受信任本机登录复用**，属于 R03 的扩展验收项；14 天配置本身不能实现跨浏览器共享。

#### 6.5.1 支持边界

| 场景 | 推荐机制 | 是否还需交互登录 |
|---|---|---|
| 同浏览器、同配置、同源新标签页/新窗口 | 读取现有存储，服务端校验当前身份 | 凭证有效时不需；本次已观察新标签页复用 |
| 自动化重启同一专用浏览器配置 | 持久化配置或受保护的 auth state，启动先验有效性 | 有效时不需；过期才进入恢复 |
| 自动化创建新的隔离 context | 为指定账号、环境装载经验证的授权状态，或通过登录交换建立独立 Session | 有效且获授权时不需 |
| Chrome 与 Edge 等不同浏览器 | 本机登录代理＋浏览器扩展/受控自动化启动器＋服务端交换 | 完成首次设备信任后，后续可静默；未安装接入组件的浏览器不能自动支持 |
| 同主机不同端口的平台实例 | 显式环境映射及目标实例签发会话 | 已受信且账号映射允许时不需；禁止直接复制跨实例 Session |
| 隐身/无痕或禁用扩展的配置 | 仅在明确允许且可接入代理时使用 | 默认回到普通登录，不承诺天然共享 |
| 本机存在多个有效账号 | 按任务绑定账号选择授权 | 不随机选“最近凭证”；无法确定时要求选账号 |
| 只有外部系统或窄权限 MCP Token | 按凭证用途和权限判断 | 不自动转换成完整网页登录权限 |

普通网页无法读取其他浏览器/配置的 localStorage。“检测本机任意有效凭证”在实现上应收敛为“查询本机代理中已登记、与目标平台和账号匹配且服务端仍有效的授权”，不扫描浏览器数据库、密码库或无关应用。

#### 6.5.2 第一阶段：自动化专用登录状态复用

1. 自动化启动器固定 browserProfileId，不为每次运行随机创建无状态浏览器。
2. auth state 索引至少包含 platformInstanceId、origin、environmentId、userId、role、profileId、expiresAt；不同账号与环境分别保存。
3. 复用前调用目标系统身份校验，确认账号、权限、环境及剩余有效期；有文件不等于有效。
4. 无效后只清理匹配项，优先走受信任设备交换，再回到正常登录；同一个恢复过程加锁，避免并发任务重复弹登录。
5. 普通业务会话错误与真实“测试登录功能”用例分开。登录测试显式标记 forceFreshLogin，使用干净 context，禁止自动跳过被测登录步骤。
6. 认证状态含敏感信息，保存在当前 OS 用户受限目录、排除版本控制和通用制品上传；不得把 auth state 放入截图/trace 公共附件或打印日志。
7. 并行任务使用独立 context；仅共享经过校验的基础身份，不共用可变页面、项目选择或正在执行的表单。

此阶段优先减少日常自动化登录次数，但不作为“任意浏览器跨配置自动登录”完成证据。

#### 6.5.3 第二阶段：本机可信登录代理

新增组件：LocalLoginBroker（当前操作系统用户内运行）、Chrome/Edge 扩展或受控启动器、服务端 DeviceGrantService、网页登录交换入口。优先采用扩展 Native Messaging 与命名管道，不发布未认证的 localhost 凭证 HTTP 服务。

首次启用流程：

1. 在已登录的目标平台页面由用户选择“在本机为该账号启用自动登录”。
2. 本机代理创建设备密钥对，私钥使用 Windows 当前用户保护存储/凭据库保护，服务端只保存公钥和授权元数据。
3. 后端基于当前有效会话登记设备、用户、平台实例、允许环境、权限范围、来源登录时间及授权到期时间；不要求保存账号密码。
4. 用户可在个人凭证/设备管理页查看、命名、禁用本机授权；代理不得自行扩大账号或环境范围。

后续静默登录流程：

1. 新浏览器先校验自己的 Session；有效则直接进入，不依赖代理。
2. 无本地 Session 时，前端/启动器为目标 origin、用户与本次浏览器创建 challenge、state 和 PKCE 参数。
3. 代理查找匹配授权，用设备私钥签名 challenge；服务端验证签名、有效期、账号状态、撤销状态、环境与用途。
4. 服务端返回一次性、短有效期的登录授权码（建议 30～60 秒），绑定客户端/来源/账号和 codeChallenge。
5. 新浏览器携带 codeVerifier 兑换自己的 Session 与 CSRF；并发兑换只能成功一次。长期设备凭证和原浏览器 Session 不下发给其他页面。
6. 新会话绝对有效期不得超过当前 14 天授权周期；换浏览器或交换会话不重置周期。设备授权到期或全部来源授权失效且不允许续期时，恢复交互登录。
7. 写入新浏览器的认证状态后重新读取身份并检查目标业务权限，成功后才恢复任务。优先内存/POST 交接；如使用回调 URL，仅传一次性码并消费后清理，不携带长期 Session/Token。

#### 6.5.4 拟新增 API 与数据

接口名称为设计值，尚不存在，实施时对齐当前认证协议：

| 接口 | 调用方 | 核心校验 |
|---|---|---|
| `POST /auth/device-grants` | 已登录页面登记设备公钥 | 有效登录、CSRF、用户启用意图、环境与范围 |
| `GET /auth/device-grants` | 本人设备管理 | 仅本人或明确管理权限；不返回秘密 |
| `POST /auth/device-grants/{id}/revoke` | 本人撤销本机授权 | 所有权、CSRF、撤销派生会话策略 |
| `POST /auth/device-login/challenges` | 新浏览器/启动器 | origin/实例白名单、nonce、state、速率限制 |
| `POST /auth/device-login/authorize` | 本机代理 | 设备签名、授权/账号状态、目标环境、PKCE 绑定 |
| `POST /auth/device-login/exchange` | 新浏览器 | 一次性码、codeVerifier、客户端与有效期；原子消费 |

新增设备授权记录至少含 id、userId、instanceId、deviceId/publicKey、allowedOrigins/environmentIds、sourceAuthAt、expiresAt、status、createdAt、lastUsedAt、revokedAt；浏览器会话关联 grantId，设备撤销可定位派生会话。一次性 challenge/code 放 Redis，使用 TTL 和原子状态转换防重放。索引覆盖 userId/status、deviceId、expiresAt；沿用实际 Flyway 迁移规则。

普通退出当前浏览器时暂停当前配置的自动登录并注销当前会话，避免退出后立即被重新登录；不撤销其他端。提供独立的“退出本机所有浏览器/撤销设备信任”和“退出全部设备”。账号禁用、密码重置等安全操作使相应设备授权及派生会话失效。设备授权管理需记录安全审计，不记录私钥、授权码及 Session 原文。

#### 6.5.5 必须补齐的跨浏览器验收

- 旧 Edge 已登录→新 Edge 窗口；旧 Edge→Chrome；浏览器重启；自动化新 context；多个任务并行恢复。
- 账号 A/B 同时有效时，任务绑定 A 只能得到 A；测试/生产、`.cn`/`.net`、不同实例端口不能错误串用。
- 私钥复制到另一 OS 用户、未信任扩展、伪造 origin/签名、重复授权码、PKCE 不匹配必须拒绝。
- 设备授权撤销、账号禁用、14 天到期后，新浏览器不得继续免登录；切换浏览器不得续成无限期。
- 当前浏览器退出后不自动反弹登录，其他端不被退出；broker 不可用时降级正常登录且提示明确。
- 每次自动恢复记录脱敏的来源 grantId、目标实例、userId、结果和 traceId；不采集浏览器其他站点凭证。

#### 6.5.6 官方技术依据

- [MDN：localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)：存储受 origin 约束，不能作为跨浏览器共享服务。
- [Playwright：Authentication](https://playwright.dev/docs/auth)：支持复用认证状态，状态文件含敏感内容，必须受保护。
- [Chrome：Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) 与 [Edge：Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions-chromium/developer-guide/native-messaging)：扩展与本机组件通信并限制允许的扩展来源。

## 7. R04：用例导出修复

### 7.1 现有接口及职责

以下为应用路由，外部网关是否增加 `/api` 以现有客户端配置为准：

| 接口 | 职责 | 改造检查 |
|---|---|---|
| `POST /functional/case/export/excel` | 创建 Excel 导出 | 范围、字段、权限及任务返回 |
| `POST /functional/case/export/xmind` | 创建 XMind 导出 | 同范围契约，格式独立校验 |
| `GET /functional/case/export/columns/{projectId}` | 导出字段 | 项目权限与自定义字段 |
| `GET /functional/case/check/export-task` | 现有任务检查 | 核对能否按任务恢复；不足时扩展 |
| `GET /functional/case/download/file/{projectId}/{fileId}` | 下载文件 | 文件归属、项目权限、文件状态 |
| `GET /functional/case/stop/{taskId}` | 现有停止任务 | 当前用户所有权与幂等处理 |
| `/ws/export` | 导出通知 | 认证、关联 taskId、重连及丢消息 |

现有停止接口为 GET；本次先保证兼容，不静默改协议。如治理为 POST，需要同步前端、兼容期与 API 测试。

### 7.2 复现与故障定位步骤

1. 使用隔离项目建立含普通文本、中文、富文本、多步骤、自定义字段的用例集。
2. 记录脱敏后的创建请求、响应、taskId、WebSocket 消息及下载请求；日志按 traceId/taskId 关联。
3. 检查导出权限、selectAll/excludeIds、字段映射、异步线程异常、文件生成与 MinIO 上传。
4. 检查任务完成消息是否早于监听建立；检查 WS 认证是否与 Header Session 对齐。
5. 检查 Blob 响应是否为 JSON/HTML 错误被保存成 Excel；检查代理路径及 Content-Disposition。
6. 给已确认根因补回归测试，再修复；不以猜测替代复现记录。

### 7.3 范围契约与状态

- 明确区分 SELECTED（具体 ID）与 FILTERED（筛选条件＋排除 ID）；后端重新校验所有 ID 所属项目和可见权限。
- 跨页全选不携带当前 pageSize 作为导出限制；除筛选条件外，还必须固定记录集合、排序和内容版本；快照及撤权规则见第 19 节。
- 对未知字段、非法格式、空导出范围返回可理解的校验错误；字段白名单约束，不接收任意数据库列名。
- 保留现有 DTO，若不足再新增字段并给出旧参数兼容转换；禁止仅修改前端参数而遗漏后端。
- 状态统一映射为 QUEUED、RUNNING、SUCCEEDED、FAILED、CANCELLED、EXPIRED；这是目标语义，优先适配已有枚举，不直接重复新增。
- 创建返回 taskId；完成包含 fileId、fileName、实际条数及到期时间；失败保存安全消息与 traceId。
- 固定顺序为 HTTP 幂等创建任务并返回 taskId → 认证状态查询 → 可选 WS 通知加速。禁止等待 WS open 后才创建任务。轮询从 3 秒逐步退避至 10 秒，仅查询未完成任务；WS 失败不影响创建和恢复。
- 现有检查只返回 PREPARED 任务标识，不能恢复成功/失败结果；必须补按 taskId 查询及本人任务恢复入口。拟新增 `GET /functional/case/export/tasks/{taskId}`，必须补控制器、服务、权限、状态存储和前端调用；接口名需遵循项目约定。
- 前端卸载停止监听及轮询，重新进入可恢复本人未完成任务；服务重启后的中间任务明确恢复或标记失败，不永久 RUNNING。
- 文件下载设置正确 MIME、UTF-8 文件名和附件响应头；跨域时暴露必要响应头。
- Blob 错误先识别 JSON 错误协议，交给 R07；只有真实文件才创建 object URL，下载后释放 URL。
- 导出量大时分批读取/流式写文件，避免全部用例常驻内存；写入失败清理临时文件，保留任务失败记录。
- XLSX 检查公式注入与富文本转换；XMind 校验结构、层级和软件兼容。文件过期应返回明确提示并支持重新导出。

### 7.4 数据与迁移

已确认 ExportTaskManager 使用现有 export_task 表，优先复用并按缺失字段做增量迁移，不新建重复任务表。目标字段语义包括 taskId、ownerId、projectId、format、参数快照、status、fileId、count、safeErrorCode、traceId、createdAt、finishedAt、expiresAt，并设置必要索引；需映射已有 createUser/state 等字段而非直接重复新增。迁移脚本遵循仓库实际 Flyway 版本规则；本文不虚构可直接执行的版本号。线程池改为受 Spring 管理的有界池，任务失败和空结果均终结任务并提供查询；临时文件清理失败独立告警及重试，不覆盖已成功的业务终态；多实例不能依赖本进程 WS Map 推送。

## 8. R05：批量按钮常驻

- 将选择数量控制的 v-if/v-show 改为固定布局；按钮可用性通过 disabled 和 tooltip 表达。
- 权限控制先于选择控制：无权限沿用隐藏/禁用规范，有权限但无选择显示禁用。
- 建立操作元数据：权限码、是否依赖选择、最小/最大数量、是否允许全选所有结果、是否二次确认、loading。

## 9. R06：隐藏模型相关控件

### 9.1 能力控制

- 复用现有能力/功能开关；确无统一能力时拟新增 `features.llm-ui-enabled=false`，由后端返回可供当前用户读取的能力快照。
- 能力未加载或失败时相关入口默认隐藏，不短暂闪现。开关仅描述服务是否启用，权限仍独立校验。
- 控制菜单、路由、按钮、快捷键、空态引导、右键菜单、批量项、详情动作、模型选择框和后台预加载请求。
- 前端统一封装 capability 判断，不用文案字符串或正则“AI”决定是否隐藏。
- 后端对应模型业务接口在关闭时返回稳定的 FEATURE_DISABLED 语义；保留管理配置和历史数据，避免删除历史记录。
- 已打开旧路由显示功能未启用并提供返回入口，禁止继续初始化模型客户端。

### 9.2 保留与隐藏的边界

| 类型 | 处理 |
|---|---|
| 站内 AI 生成、AI 编译/执行、依赖模型的助手和对话 | 默认隐藏并拦截调用 |
| 普通手工编写、导入、导出、手工执行和结果查看 | 保留 |
| 外部 Agent 通过 MCP 读写用例、上传证据、提交结果 | 保留原权限和限流 |
| 历史 AI 生成/执行数据的普通只读查看 | 原则上保留；入口是否依赖模型单独核对 |
| 无需模型的规则处理或自动化工具 | 按能力判断，不按 AI 名称直接隐藏 |

交付控件清单必须逐项给出：页面、组件路径、控件名称、依赖接口、开关条件、处理方式及回归证据。

## 10. R07：凭证失效弹框与错误协议

### 10.1 处理链路

HTTP/业务响应 → 错误归一化 → 判断凭证归属 → 单例提示管理 → 当前页失败状态 → 用户确认 → 登录或凭证配置 → 恢复读取。

- 复用 axiosTransform、checkStatus、auth.ts 的现有并发保护；禁止重复创建会话过期处理器。
- 统一读取 HTTP 状态及业务 code，不凭 message 字符串猜测过期。
- 兼容历史业务错误码，后端新增稳定码前需盘点消费者，不能全局把数字 code 改字符串而破坏现有客户端。

### 10.2 状态决策

| 情况 | UI 行为 | 后续动作 |
|---|---|---|
| 当前网页会话过期/撤销 | “登录已过期，请重新登录”单例弹框 | 清当前入口认证态，确认后登录，记录站内返回地址 |
| 当前网页凭证无效 | “登录状态已失效，请重新登录” | 同上，不向用户展示原始凭证 |
| 集成系统凭证失效 | “连接凭证已失效，请更新后重试” | 有权限时提供配置入口，不退出网页会话 |
| 无项目/操作权限 | 明确无权访问或无权操作 | 不循环跳登录，不一律跳走导致编辑丢失 |
| 429 | 明确频率限制及可重试时间 | 不当作凭证失效 |
| 网络/超时/5xx | 安全通用提示和重试 | 保留错误状态及 traceId |
| 登录页面的账号密码错误 | 表单错误 | 不弹全局会话过期框 |

### 10.3 弹框生命周期

- IDLE → SHOWING → REDIRECTING → IDLE；同一轮并发失败只创建一个弹框。
- 会话被判失效后取消后台轮询及等待中的只读请求，避免持续报错。
- 返回地址仅允许站内路由，避免开放重定向；不保存带 Token 的 URL。
- 编辑草稿优先暂存非敏感内容，不自动提交；重新登录后询问或按既有交互恢复。
- 重新认证后仅自动恢复读取，不自动重放删除、导入、提交结果等写操作。
- Blob 下载、上传及 WS 认证失败走相同错误语义；WS 不无限重连无效会话。
- 空态仅用于成功返回且 total=0；失败保留 error 状态，显示失败及重试按钮。
- traceId 同时进入日志与安全提示，不向用户暴露堆栈、SQL、内部路径或 Token。

## 11. R08：列表自动刷新与一致性

### 11.1 统一触发规则

| 触发 | 行为 |
|---|---|
| 首次进入 | 请求当前条件最新数据 |
| keep-alive 重新激活、从详情返回 | 按 dirty/stale 标记刷新，达到陈旧阈值也刷新 |
| 新增/编辑/删除/移动/关联/执行等成功 | 使关联列表、模块计数和统计失效并刷新 |
| 导入等异步任务完成 | 以任务完成为准刷新，不在受理成功时误报数据已更新 |
| 切换项目/组织/模块/筛选/排序 | 更新查询 key，页码按规则回到 1，清选择 |
| 页面重新可见/窗口重新获得焦点 | 合并触发刷新，避免两事件各发一次 |
| 其他标签页或 MCP 写入 | 标签页通知/服务通知标记 dirty；至少在重新激活时刷新 |
| 页面持续停留且外部写入 | 优先通知；缺失通知时建议可配置 30 秒补偿，只在可见且在线时执行 |

30 秒为建议默认值，不代表已具备实时推送。产品若要求更严格可见时延，应明确目标并选择通知链路，不能用“始终最新”代替一致性定义。

### 11.2 查询状态与竞态

- 先盘点 useTable、useTableStore、现有 vue-query 使用；每个列表选一个数据源管理器，不同时保留 watch、事件和 query 三套加载。
- queryKey 包含 userId、projectId、模块、筛选、排序、页码和条数；无关页面不共享同一 key。
- 使用请求序号或 AbortController，旧响应不得写入新条件状态；主动取消不弹网络错误。
- 同一事件批次合并刷新，mutation 成功后失效一次；清理 onActivated/onMounted 双重请求。
- 手动刷新与后台刷新分别呈现：首次加载展示 loading，后台刷新保留当前数据并标记刷新中。
- 删除最后一条时修正页码；刷新后清除不存在/不再允许操作的选择，跨条件切换清空全部选择。
- 正在编辑时刷新列表不重置未保存表单；写操作与刷新按顺序执行，避免读到提交前快照。
- failed、permission-denied、empty、success 显式区分；失败不得将上次旧数据标记为最新。
- 组件卸载注销监听、计时器及请求；离线暂停，恢复联网后按规则刷新。

### 11.3 关联失效关系

- 用例变更：用例列表、模块计数、详情、关联计划/评审统计按实际影响失效。
- 执行结果变更：执行列表、用例执行状态、计划进度与报告相关统计失效。
- 缺陷变更：缺陷列表、关联用例缺陷数失效。
- 项目/权限变更：清理当前用户相关缓存，重新校验当前项目与操作权限。
- 外部 MCP 变更如无服务事件，不假装前端已感知；通过激活刷新和可见页补偿覆盖。

## 16. 发布、迁移与回滚

### 16.1 发布顺序

1. 完成需求口径与页面清单，复现导出/登录问题并冻结接口契约。
2. 优先实现认证错误协议和兼容后端，再发布前端弹框；旧客户端仍能读取既有 code/message。
3. 发布登录策略和会话隔离配置，明确是否需要用户重新登录。
4. 修复导出全链路，验证后开启新任务恢复能力。
5. 上线分页、常驻按钮、模型能力开关及列表刷新，逐页面验收。
6. 在隔离环境完成 720 次限流和上传负载验证，再提高生产额度。
7. 发布后观察认证失败、429、导出失败、数据库连接、存储错误和列表请求量。

### 16.2 回滚策略

- 限流额度配置可回退至原值；保留独立配置项，不回滚其他业务数据。
- 模型 UI 开关可独立恢复，但未配置模型服务时不得自动开启。
- 会话 namespace 变更回滚会影响已有会话可见性，发布前记录新旧值，必要时明确要求重新登录，不跨环境复制会话。
- 导出任务结构使用向后兼容的新增字段；新任务状态旧版本无法识别时，先等待或安全终止在途任务再回滚。
- 数据库结构回滚按项目规范执行；不直接删表、删文件或清空 Redis 作为通用回滚步骤。
- 前端与后端分批回滚时确保接口版本兼容；保留失败任务和关联日志便于排查。

### 19.2 导出权限、幂等和状态机

源码确认的修复项：停止接口只有 taskId，归属注解却引用 #projectId；服务层未先检查任务所有者。完成导出按用户/项目最新 PREPARED 回写，创建检查与插入分离，Kafka 停止消费无条件更新状态。不得仅列为待检查项。

1. 创建、查询、停止、订阅、下载均校验当前身份、项目权限及对象归属。停止先按 taskId 读取任务，再校验本人或明确管理权限和可停止状态。不存在/无权对象返回安全错误，不能信任客户端 userId/projectId。
2. 创建新增 requestId，数据库唯一约束绑定 ownerId、projectId、operation、requestId；摘要包含格式、范围、字段及选项。同键同参返回原 taskId，同键异参返回冲突；重放重新授权。fileId 由服务端生成或验证唯一绑定，不能作为权限证明。
3. 创建响应丢失时保留原 requestId 重试/查询，不生成新键盲目重建。前端 disabled 不能代替服务端幂等。
4. 任务先持久化，事务提交后由有界池领取。提交被拒绝写入可查询 FAILED；落库后进程崩溃留下的孤立 QUEUED 由恢复机制处理，不永久悬挂。
5. 工作线程始终携带确定 taskId，不再查询“最新任务”。QUEUED→RUNNING→SUCCEEDED/FAILED，QUEUED/RUNNING→CANCELLED 均使用预期状态和版本条件更新。EXPIRED 表示成功文件超过下载期，原完成事实保留。
6. 取消与成功由数据库条件更新裁决：取消先成功则阻止后续发布并清理孤立文件；成功先提交则停止返回已完成。CANCELLED 表示发布被阻断，物理线程退出单独跟踪；迟到停止消息不能覆盖成功。
7. 重启首版采用明确失败策略：任务记录 workerId、leaseUntil/heartbeat、version，仅终结租约过期的中间任务，不能在一个副本启动时误杀其他副本的任务；迟到工作者不能覆盖终态。重试创建新任务并关联原任务。
8. Excel/XMind 的查 ID、空集、生成、上传均进入统一异常边界。创建时可判定空集则拒绝；已建任务遇空集终结 FAILED，安全码语义为 EXPORT_EMPTY。临时文件清理失败独立告警/重试，不覆盖业务终态或原错误。

### 19.3 创建、查询及 WS 协议

保留创建路由和旧 taskId 返回形式，增量扩展 DTO。新增任务详情返回 taskId、state、stateVersion、format、实际条数、文件元数据、expiresAt、安全错误和 traceId；本人任务恢复接口支持项目过滤及稳定分页。旧 check/export-task 只作兼容，不能恢复成功/失败结果。

WS 仅加速通知。拟新增 POST /functional/case/export/tasks/{taskId}/ws-ticket，由已认证 HTTP＋CSRF 申请一次性票据，建议有效期 60 秒，绑定用户、项目、任务、用途和允许 Origin。握手原子消费，存储跨副本共享，重连重新申请。过滤链须将专用握手交给票据认证；不能匿名放行，也不能只在被通用过滤器拒绝之后才校验。长期 Session/Agent Token 不进 URL，短票据日志脱敏。

连接不可变绑定 taskId/ownerId；客户端仅允许规定的心跳，禁止传入 fileId 转发消息或伪造 EXEC_RESULT。同任务多标签页使用连接集合，关闭仅移除当前 connectionId，不能误删新连接。推送携带任务和状态版本，前端通过认证查询确认结果。多实例通知可用事件总线，丢消息或无总线时由轮询保证恢复。

createSocket 覆盖 error、提前 close、建议 10 秒超时，失败释放计时器/监听/连接；已连接后断线转状态查询。提示对象允许尚未初始化，重复/乱序事件按版本丢弃。受理后关闭字段弹窗并展示任务状态，不把通知失败说成创建失败。

### 19.4 内容快照、下载与容量

保存查询参数不足以冻结数据。受理快照阶段固定 ID、稳定排序、内容 revision、步骤及自定义字段内容；优先引用不可变版本，缺少版本化读取则物化内容。不能仅存 ID 再读取实时正文。冻结阶段使用一致性读或版本复核，冲突明确拒绝；不跨文件生成持有长事务。快照未完整固定前不宣称已就绪。

创建、领取和下载重新授权；内容修改仍输出固定版本，删除或权限范围失效首版拒绝发布/下载并给安全原因，不能悄悄少导出。网页与 MCP 共用快照、状态、权限、取消、文件服务。下载为认证请求或任务绑定的短授权，兑换时重新授权；错误报告同样受控。

继承旧计划首版 100,000 条/任务上限，超限拒绝；发布前固定并验证每用户/全局并发、队列长度、文件大小、执行超时、文件/任务保留期及清理周期，未固定为发布阻断项。生成分批/流式，下载避免完整 byte[] 加载大文件。ZIP、XLSX、XMind 分别核验文件名、MIME、内容、实际条数和打开结果。到期清理检查引用并保留审计，孤立文件可重试回收。

### 19.5 SSO 和 R03A 分期

SSO 目标键为 instanceId＋本地 sessionId，保存对应上游凭证并维护用户撤销索引。同步改 save/get/refresh/delete/bridge 调用，新登录不得覆盖另一端凭证或 needReauth。普通退出清理当前本地会话，上游 revoke 是否影响其他端必须实测；安全批量撤销同时覆盖设备授权。旧 userId 单键不能可靠归属时，不复制到多个会话，采用重新认证并记录迁移影响。

R03A 分 A：自动化状态复用，B：跨浏览器独立会话兑换。A 复制认证状态可能共用同一 Session，不能证明单端退出隔离；需要隔离的任务采用 B 或独立登录。B 未交付时 R03A 不算完成，但不阻止其他已独立验收项分批发布，也不成为个人 MCP 直连前置条件。

B 须固定协议版本及 challengeId/nonce、grantId、目标 instanceId/origin、clientId、账号、PKCE challenge、issuedAt/expiresAt 的规范化签名输入；账号从授权记录取，不接受浏览器任意指定。challenge/授权码原子消费并校验用途；签名算法固定且有测试向量，不允许自由降级。设备登记需证明私钥持有，扩展来源和环境白名单受控。

授权期限继承可靠 sourceAuthAt，兑换及重新登记不得无限续期。密钥轮换须有效授权和持有证明，丢失时重新交互认证。撤销禁止新兑换并使派生 Session 失效；当前配置退出后暂停自动恢复，提供用户主动恢复入口。B 交付包含安装包来源/签名、升级回滚、卸载私钥与授权处理及浏览器矩阵。

### 19.6 能力、限流和刷新边界

站内生成/对话/模型执行开关与证据核验器独立；关闭站内入口不关闭门禁。核验器不可用进入待核验，不降级发布通过。外部 MCP 权限保持独立，测试关闭入口后的有效证据审核和核验故障。

分布式限流使用环境＋Token ID 键和统一服务端时间来源，原子裁决总额度及子额度。已认证请求即使被子额度拒绝仍占总额度，总额度拒绝不写窗口；与第 5 节计数语义一致。Retry-After 向上取整为正秒数。首版拒绝 JSON-RPC batch，若后续支持必须逐调用计数。REST 搜索保护独立披露，Node 和原生客户端均验证错误/重试行为。

刷新逐页列出列表/统计失效关系；补偿查询增加抖动、退避、不可见/离线暂停和恢复去重。隔离压测前固定响应时间、错误率、请求并发和数据库负载阈值，并记录改造前后数据，不用“30 秒一次”代替容量结论。
